# Fox 性能与产品待办

更新时间：2026-07-28

## 1. 大 Chunk 优化专项

当前生产构建中的主要大块来自 PPTX 渲染、Shiki 语言与主题、WASM、知识图谱布局、Mermaid，以及仍然较大的工作台和设置模块。优化目标不是调高 `chunkSizeWarningLimit` 隐藏提示，而是降低首屏下载、解析和执行成本。

### 第一批：测量与低风险拆分

1. 引入 `rollup-plugin-visualizer`，保存每次生产构建的依赖体积报告。
2. 为知识图谱、PPTX、PDF、DOCX、表格预览保持独立动态入口，只在进入对应页面后加载。
3. Mermaid 仅在 Markdown 实际包含 Mermaid 代码块时加载；知识图谱布局算法仅在图谱页面加载。
4. 对重型预览器增加鼠标悬停预加载，但不在应用启动时预加载。

### 第二批：Shiki 与 Markdown

1. 将 Shiki 改为小型语言白名单，默认只包含 Fox 常用的 TypeScript、JavaScript、Python、Rust、JSON、Shell、Markdown、HTML 和 CSS。
2. 未命中的语言按需动态注册，并用普通代码块作为加载期间的稳定回退。
3. 统一 Shiki 的导入入口和版本，消除重复语言包、主题包与 WASM 实例。
4. 将 Markdown 扩展能力按内容特征加载，避免普通文本回答携带 Mermaid 等解析器。

### 第三批：业务模块边界

1. 拆分 `workbench.tsx` 为聊天外壳、时间线、输入框、右侧面板和对话弹窗，各模块保持独立入口。
2. 设置中心按页面拆分，不再由一个 `settings-pages` 模块承载全部设置页。
3. 浏览器、子智能体、知识图谱和文件预览等非首屏能力保持懒加载。
4. 对稳定的 vendor 依赖设置明确的 Rollup chunk 边界，避免业务修改导致大型缓存块频繁失效。

### 验收指标

- 冷启动首屏不加载 Office、图谱、Mermaid 和全量 Shiki。
- 主入口压缩前单块优先控制在 500 KB 以下；确实无法拆分的独立查看器允许例外并记录原因。
- 对话、设置、知识库和预览路由分别记录首次打开耗时及交互可用时间。
- 每次拆分后执行前端测试、生产构建，并人工验证对话流式输出和各格式预览。

## 2. 用户头像

当前预置头像目录：

`apps/desktop/public/avatars/defaults/`

首版方案：

1. 通过头像选择弹窗展示预置资源。
2. 本地偏好只保存稳定的头像资源 ID，不保存绝对路径。
3. 未选择时继续显示账户头像或用户名首字母。
4. 侧边栏、个人资料和设置页复用同一个头像解析函数，避免显示不一致。

后续版本再支持用户上传、裁剪、替换和删除自定义头像；自定义资源保存到 Fox 管理目录，不写入应用安装目录。

## 4. Agent 与知识库优先计划

完整排序、竞品依据和完成度定义见 [Fox 产品与稳定性审计](./FOX_PRODUCT_AUDIT_2026-07-27.md)。当前按重要性与紧急度执行：

A1-A6 的完整实施设计见 [Fox Agent A1-A6 实施方案](./FOX_AGENT_A1_A6_IMPLEMENTATION_PLAN.md)。后续按 A1 到 A6 顺序逐项开发和验收，不并入模型路由、自动化或远程 Runtime。

1. P0：Agent 工作闭环、长期记忆。
2. P0：知识库运营入口、检索参数与命中过程、Chunk 管理。
3. P1：会话生命周期、运行可观测性、解析/OCR 管理、检索评估、版本权限审计。
4. P1/P2：子 Agent、扩展源、模型路由、连接器同步、图谱治理。
5. P2/P3：自动化与远程 Fox Runtime。

“Yuxi 后端已有接口”不等于“Fox 桌面端已完成”。每项验收必须同时检查桌面入口、权限/错误态、真实数据联调、自动测试和用户可见反馈。

文档预览增强和 EPUB、音视频、CAD 等长尾格式暂时冻结，不进入近期排期。

## 2. 目标信息架构

「设置 → 模型」改名为 **「模型与 Agent」**，路由 `settings-models` 不变。页面从上到下：

```
模型与 Agent                                   [添加服务]
  管理模型服务，并为每个 Agent 选择用哪个服务。

默认
  └ 默认模型            [DeepSeek 官方 · deepseek-chat ▾]

模型服务                                    3 个服务
  └ DeepSeek 官方   默认   4 个模型 · api.deepseek.com
       [Fox ✓已实测] [Pi ✓已实测] [Codex 可用·未实测] [dsh ✓已实测]   ⋯
  └ Kimi Code       2 个模型 · api.kimi.com
       [Fox ✓已实测] [Pi 可用·未实测]   缺少 Responses / Messages 入口
  └ 本地 Ollama      未填写 API Key
       [Fox 可用·未实测] [Pi 可用·未实测]

Agent 使用配置                     外部 Agent 需要先启用
  └ Fox     已就绪       DeepSeek 官方 · deepseek-chat                    [查看]
  └ Pi      已就绪       DeepSeek 官方 · Messages · deepseek-chat   [验证] [更改] ⬤
  └ Codex   本机已有配置可导入   在电脑上找到 Codex 的登录             [导入…] ○
  └ dsh     已安装，未配置       选择一个支持 Anthropic Messages 的服务 [配置] ○
  └ ...     未安装              Fox 运行时里没有这个 Agent             [了解] ○
  └ ...     检测失败            没能读取配置，请重试                  [重试] ○
```

- **「模型服务」**每个服务只配置一次。服务行下面是 Agent 匹配标签：
  - `✓ 已实测`：这个服务里给该 Agent 用的入口，按当前「协议 + 地址 + 模型 + Key」验证通过过（`external_model::verified()` 返回真）。
  - `可用 · 未实测`：有匹配的入口，但还没验证过。
  - 不匹配的 Agent 不出标签。如果有已启用的 Agent 不匹配，行尾用一句灰字说明「缺少 Responses 入口」「缺少 Messages 入口」。
  - Fox 用服务的主地址；Pi 匹配任意入口；Codex 要 Responses；dsh 要 Messages（`provider_protocol::supports`）。
- **「Agent 使用配置」**每个 Agent 一行，状态互斥，按以下优先级取一个：
  1. `read_failed` 检测失败
  2. `not_installed` 未安装（Fox 能不能启动它；还要区分「电脑上有但 Fox 运行时缺」，见 3.3）
  3. `ready` 已就绪：有绑定，模型请求这一层验证通过
  4. `configured_unverified` 已配置，未验证（作为「已就绪」的子状态显示：标签变成「待验证」）
  5. `native_importable` 本机已有配置可导入：没有绑定，真实 HOME 里有白名单内的配置
  6. `installed_unconfigured` 已安装，未配置
  - Fox 没有安装这一说，只会是 `ready` 或 `installed_unconfigured`（没有默认模型时文案改成「未配置」）。
- 「设置 → Agent」页的「Agent 驱动」组精简为：「新会话使用的 Agent」+ 各 Agent「默认权限」+ 一行入口「模型和连接在『模型与 Agent』里配置 →」。外部 Agent 的开关、状态、Pi 配置来源**全部移到**「模型与 Agent」页。
- 修改 Agent 在系统里自己的配置文件（显示差异、备份、恢复）另设入口，**本期不做**。

## 3. 页面与交互

### 3.1 「模型服务」列表

服务行（复用 `.fox-settings-provider` 的结构）：

- 第一行：图标、名称、`默认` 胶囊；右侧是连接状态（已连接 / 不可用 / 未检测 / 未连接，和现在一样）和 `⋯` 菜单（编辑、设为默认、测试连接、删除）。
- 第二行：`4 个模型 · api.deepseek.com`；没有 Key 时写「未填写 API Key」。
- 第三行：Agent 匹配标签（`.fox-agent-chip`，高 20 px，圆角胶囊）。
  - 已实测：`Pi ✓ 已实测`，success 色的点 + 文字。
  - 未实测：`Codex 可用 · 未实测`，muted 色。
  - 开发者模式下，鼠标悬停标签时 title 显示 `openai-responses · https://… · gpt-5 · 2026-11-04 12:30`。
- 点整行进入**页内编辑表单**（3.2），不再弹 Dialog 或 Sheet。

空状态：「还没有模型服务。点「添加服务」开始，先选你想让哪些 Agent 使用它。」

### 3.2 添加 / 编辑：一个页内表单

点「添加服务」或某个服务行后，「模型服务」组的位置换成表单。页头动作变成「取消 / 保存」，标题下方加一行面包屑「模型服务 / 添加服务」。其他组（默认、Agent 使用配置）这时收起，表单关闭后再展开。添加和编辑用**同一个组件** `ServiceForm`，编辑时第一步默认折叠成一行摘要（「目标：Fox、Pi、dsh · 预设：DeepSeek 官方」，旁边有「更改」）。

**第一步：选目标和预设**（参考 CC Switch）

- 「这个服务给谁用」：四个可多选的卡片，Fox（默认选中）、Pi、Codex、DeepSeek（dsh）。未启用的外部 Agent 也能选，卡片上注「未启用」。
- 「从预设开始」：预设网格。按所选目标过滤和排序：能覆盖全部目标的排在前面，覆盖不全的标注「需要补充 Messages 地址」。最后一格是「自定义」。
- 预设数据从 `settings-pages.tsx` 移到 `service-presets.ts`，结构扩展为：
  ```ts
  type ServicePreset = {
    id: string; name: string; icon: string
    endpoints: Array<{ apiType: ApiType; baseUrl: string }> // 第一个是 Fox 主地址
    modelPlaceholder: string; contextWindow: number; maxOutputTokens: number; supportsImageInput: boolean
    trusted?: boolean // 与 external_model::trusted() 一致的官方入口
  }
  ```
  只填仓库里已有、能确认的入口：`deepseek`（三种）、`openai`（completions + responses）。其他预设只有主地址，**不要编地址**。

**第二步：填必填项**（只列所选目标真正需要的）

| 字段 | 何时出现 | 说明文案 |
|---|---|---|
| 服务名称 | 总是 | 预填预设名 |
| API Key | 总是（编辑时占位「已安全保存 · 留空保持不变」） | 「Key 保存在系统凭据库；Agent 使用时由 Fox 写进它的私有配置，不会写进你自己的 HOME。」 |
| 默认模型 | 总是 | 「填写服务商提供的模型 ID」，用预设的 `modelPlaceholder` 作占位 |
| 服务地址 | 选了「自定义」，或选了 Fox / Pi 但预设没有 completions / messages 入口 | — |
| Responses 地址 | 选了 Codex，但预设里没有 `openai-responses` 入口 | 「Codex 需要 OpenAI Responses 地址」 |
| Messages 地址 | 选了 dsh，但预设里没有 `anthropic-messages` 入口 | 「DeepSeek（dsh）需要 Anthropic Messages 地址」 |

字段下面是**测试连接**行：按钮「测试连接」。结果按入口分行显示，每行写「Fox / Pi 用的入口：连接正常 · 312 ms」或「dsh 用的入口：连接失败，请检查地址和 Key」。开发者模式下把失败行换成 `model.connection_failed · HTTP 401 · https://…/anthropic`。

**高级设置**（默认折叠，摘要行写「Chat Completions · 上下文 128K · 最大输出 8K · 3 个入口」）

- 协议入口列表：每行写协议名、地址、模型（留空用默认模型）、「独立 Key」开关，以及删除按钮。**不再有**「用作 X 默认协议」开关，绑定改到 Agent 那边做。
- 模型列表：页内可编辑的行（模型 ID、显示名、上下文、最大输出、图片输入、设为默认），去掉 `ProviderModelDialog`。
- 图标、设为默认服务、清除已存 Key（仅编辑时）。

底部：编辑时左侧「删除服务」，右侧「取消 / 保存」。保存时如果地址和已有服务重复，沿用 `DUPLICATE_SERVICE_URL_TEXT`「这个服务地址已经添加过了」。

保存后：回到列表，提示「模型服务已保存」。如果第一步选了还没绑定的外部 Agent，再弹一条提示：「要让 Pi 使用这个服务吗？」[使用]。点「使用」调 `agent_binding_save`，**不自动验证**。

### 3.3 「Agent 使用配置」列表

每行左边是 Agent 名和状态；中间一句说明；右边是动作按钮和启用开关（Fox 没有开关）。

| 状态 | 状态文案 | 说明句 | 动作 |
|---|---|---|---|
| `ready` | 已就绪 | `DeepSeek 官方 · Messages · deepseek-chat`；验证过的层数小字写在后面「模型请求通过 · Agent 有输出」 | 验证、更改 |
| `configured_unverified` | 待验证 | `DeepSeek 官方 · deepseek-chat · 还没有验证` | **验证**（主按钮）、更改 |
| `native_importable` | 本机已有配置可导入 | 「在这台电脑上找到了 Codex 的登录配置。」 | 导入…、改用模型服务 |
| `installed_unconfigured` | 已安装，未配置 | 有能匹配的服务时：「选择一个模型服务」；没有时：「还没有支持 Anthropic Messages 的服务」 | 配置（没有匹配服务时是「添加服务」） |
| `not_installed` | 未安装 | A：「Fox 运行时里没有这个 Agent。」<br>B（电脑上找到了，但 Fox 不能启动）：「电脑上装了 Codex，但 Fox 需要用自带的运行时启动它。请重新安装或修复 Fox。」<br>C（已安装但运行时不完整，如缺 pi-gate）：「这个 Agent 的运行时不完整，Fox 无法启动它。请修复 Fox 外部运行时。」 | 无（开关禁用） |
| `read_failed` | 检测失败 | 「没能读取这个 Agent 的配置，请重试。」 | 重试 |
| 检测中 | 检测中… | — | — |

- 开发者模式下，`read_failed` / `not_installed` 行多一行等宽小字：错误码 + 路径（例如 `agent_backend_pi_gate_missing · C:\Program Files\Fox\sandbox-runtime\0.1.8\pi-gate\pi-gated.cmd`）。非开发者模式**不出现**错误码、路径、环境变量名、JSON。
- 页面打开时只调一次 `agent_config_overview`（只读，见 4.2）。窗口重新获得焦点时可以再调（只读，成本低）。**不再**自动验证，也**不再**自动写文件。
- 启用开关：打开时调 `agent_enable_set`，不触发验证。打开后如果状态不是 `ready`，说明句后面加「启用后需要先配置才能在对话里使用」。

**更改 / 配置**：在行下方原地展开绑定表单（`AgentBindingForm`）：

- 「来源」：分段控件「Fox 模型服务 / 本机配置」。没有本机配置时，「本机配置」禁用，title 写「这台电脑上没有找到 X 的配置」。Pi 复用现有的来源选择（`login_source`），Codex 和 dsh 也用同一套（见 4.5）。
- 选了「Fox 模型服务」时：
  - 服务：下拉，只列能匹配这个 Agent 的服务，每项后面标「已实测 / 未实测」。
  - 入口：同一个服务里有多个匹配入口时才出现（例如 Pi 可以用 Completions，也可以用 Messages）。
  - 模型：下拉，选项是这个服务的模型；入口自己配了 `modelId` 时以入口为准，作为默认选中。
- 选了「本机配置」时：显示导入预览（3.4）。
- 底部按钮：「保存」（只写绑定）、「保存并验证」（写完绑定再跑 3.5）、「取消」。

### 3.4 导入预览（Codex / Pi / dsh 共用）

点「导入…」或在绑定表单里选「本机配置」后展开。

- 标题：「从这台电脑导入 Codex 配置」
- 「要导入的内容」：勾选列表，每项写友好名 + 去向，例如：
  - ☑ 登录信息（auth.json）
  - ☑ 模型与地址设置（config.toml）
  - dsh 是：☑ DeepSeek API Key、☐ Magpie 网关 Key、☑ ACP 预设
  - 非开发者模式只显示友好名；开发者模式在后面加灰字路径 `~/.codex/auth.json → <私有 HOME>/.codex/auth.json`。
- 「用在哪里」：单选三项：
  1. 「所有现有项目，并在新项目中继续使用」（默认）
  2. 「所有现有项目」
  3. 「只在不选项目的对话中使用」
- 「冲突」：预览接口（4.4）返回已经有自己登录的项目，例如「2 个项目里已经有 Codex 登录：Fox-Agent、毕业论文」。下面单选：「保留它们（推荐）」/「覆盖，先备份原文件」。没有冲突时这一块不显示。
- 底部：「导入」/「取消」。成功后提示「已导入到 5 个项目，2 个保留原有登录」，绑定的来源设为 `native`，状态变成「待验证」。

### 3.5 分层验证结果

点「验证」后，行下方展开阶梯（`VerificationLadder`），四层依次执行。前一层失败，后面的层就不跑，标「未进行」：

| 层 | 文案（进行中 / 通过 / 失败） | 做什么 | 耗时 |
|---|---|---|---|
| 1 配置已保存 | 正在检查配置… / 配置已保存 / 配置不完整：缺少 API Key | 本地检查：绑定存在、服务和入口存在、Key 存在、协议匹配；不联网 | <50 ms |
| 2 模型请求通过 | 正在请求模型… / 模型请求通过 · 312 ms / 模型请求失败，请检查地址、模型和 Key | `ModelServiceClient::test_output()`；通过后 `record_verified_connection` | ≤90 s |
| 3 Agent 有输出 | 正在启动 Agent… / Agent 有输出 / Agent 没有输出，请查看 Fox 外部运行时是否完整 | 在临时目录用受限权限起一次 Agent 会话，发「只回复 OK」，收到非空文本就算通过 | ≤120 s |
| 4 工具调用通过 | 正在测试工具调用… / 工具调用通过 / 工具调用没有完成 | 在同一会话里让 Agent 读取临时目录里的 `fox-verify.txt` 并回复里面的随机串；Fox 审批对这个只读调用自动放行 | ≤120 s |

- 阶梯右上角有「停止」，调 `agent_config_verify_cancel`。
- 结果按「Agent + 来源 + 协议 + 地址 + 模型 + Key revision + 运行时版本」记录（见 5.2），下次打开页面直接显示上次结果和时间：「上次验证：今天 12:30」。
- 开发者模式：每层失败时多一行等宽错误码（`agent_verify.model_failed · HTTP 401`），可以展开查看脱敏后的 stderr 尾部（沿用 `run.failed.diagnostic` 的脱敏函数，≤4 KiB）。非开发者模式只有上表里的文案。
- 「已就绪」的判断标准是第 2 层通过（和现在发送前的门槛 `external_login` 要求「已验证」一致）。第 3、4 层是补充信息，不卡发送。

pub fn external_login(database: &Database, backend: AgentBackend) -> Option<UnifiedLogin> {
    let binding = database.agent_binding(backend).ok()??;              // 没有绑定 → None

CREATE TABLE agent_bindings (

### 8.1 Rust 单测（`cargo test -p fox-agent-backend`、桌面 crate `cargo test`）

## 10. 待确认 / 风险

1. **页面归属**：本方案把「Agent 使用配置」放进「模型」页（改名「模型与 Agent」），「设置 → Agent」只留默认值。如果希望 Agent 配置仍然放在 Agent 页，组件不用改，只是挪个位置。
2. **第 3、4 层验证的成本**：每次要起一个真实 Agent 进程，Windows 上冷启动可能超过 30 s。所以默认点「验证」只跑到第 2 层，「完整验证」做成次级按钮。样式稿里两个按钮都画了。
3. **启用状态改由 Host 保存**：发送路径可以顺带改成由 Host 拒绝（新码 `agent_backend_user_disabled`，原来只在前端本地用），也可以留到下一期。
4. **PATH 检测**（`install.via = system`）只是为了给出更准确的提示，Fox **从不**用 PATH 上的程序启动 Agent，原则不变。

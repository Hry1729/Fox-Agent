# 诊断与故障排查

> 状态：当前<br>
> 适用版本：Fox 0.1.0<br>
> 维护范围：桌面运行、Runtime、模型、知识库、MCP 与数据维护<br>
> 最后更新：2026-07-29

## 目标与范围

本文面向开发、测试和支持人员，提供可重复的故障收集和分层处理流程。目标是先保护用户数据，再判断故障层级，最后通过可验证的最小修复恢复服务。

## 首要原则

1. 不要求用户提供 API Key、Token、MCP 环境变量或完整项目源码。
2. 涉及数据库、恢复和缓存手工处理前先创建备份。
3. 优先使用应用内诊断和维护命令，不直接删除应用数据目录。
4. 记录时间、会话 ID、Run ID、操作步骤和可见错误，不只记录“卡住了”。
5. 真实知识库故障与 Fox 本地故障分开验证。

## 诊断信息收集

### 应用内诊断

设置中的“数据与诊断”可导出脱敏 JSON：

```text
<Fox 数据目录>/exports/fox-diagnostics-<timestamp>.json
```

内容包括：

- Fox 和 SQLite Schema 状态。
- Runtime 状态、版本、最近错误和有限 stderr。
- 模型服务连接状态。
- 知识库服务连接状态。
- MCP Server 状态和脱敏错误。
- 隐私声明。

明确不包括：对话正文、项目文件内容和凭证明文。Runtime 诊断行最多保留 512 个字符，并对 Authorization、Bearer、API Key、Token 等标记做脱敏。

分享诊断文件前仍需人工检查，避免第三方服务错误消息携带未被识别的敏感字段。

### 复现记录模板

```text
Fox 版本：
Windows 版本：
安装包或开发态：
发生时间（含时区）：
当前 Agent / 模型：
Conversation ID：
Run ID：
操作步骤：
预期结果：
实际结果：
是否刷新后恢复：
是否重启后恢复：
诊断文件：
```

## 分层检查

### 1. 窗口与前端

- 窗口是否能响应最小化、最大化和关闭。
- DevTools 是否有模块加载、Hook、Worker、WASM 或渲染异常。
- 当前路由是否仍可切换。
- 是整个页面无响应，还是单个运行状态不更新。

### 2. Tauri Host

- Command 是否返回统一错误码。
- Runtime 初始化是否成功。
- SQLite Migration、待恢复备份或缓存恢复是否阻塞启动。
- 文件选择器、Credential Manager 或子进程是否被系统策略拦截。

### 3. SQLite

- `PRAGMA integrity_check` 是否为 `ok`。
- `schema_migrations` 最大版本是否与程序一致；当前代码版本为 13。
- 最新 Run 是否进入终态。
- Event 序号和消息是否已经持久化。

### 4. Runtime

- ready 握手的协议、版本和能力清单是否通过。
- Sidecar 是否崩溃、被杀死或超时。
- stdout 是否混入非 JSONL 文本。
- Runtime 工具目录与 Host 清单是否一致。

### 5. 外部服务

- 模型连接测试是否通过。
- 知识库健康、认证和版本是否可用。
- MCP 命令能否启动、`tools/list` 是否在 15 秒内返回。
- 网络代理、防火墙、证书和服务端日志是否异常。

## 故障速查

### `ECONNREFUSED · 127.0.0.1:5010`

这是目标端口无服务监听。若当前选择 Fox 通用助手，先确认模型供应商而不是知识库服务被误设为必需依赖；若使用知识助手，则检查知识库容器、端口映射和健康接口。

### `Pi Runtime dependencies are missing`

开发环境从工作区根目录执行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd runtime:test
```

生产安装包出现该错误通常表示错误启动了源码 Runtime，或 Sidecar 资源未被打包，应重新检查 `tauri.conf.json` 和安装包内容。

### 消息只在刷新后出现

数据库已有完整回复说明执行和持久化成功，重点检查 listener 注册、会话匹配、事件序号、Reducer 去重和运行完成后的状态归并。数据库也没有回复时再查 Sidecar/远程游标恢复。

### Run 长期 queued/running

- 查询是否等待用户补充或审批。
- 检查 Sidecar/远程 Worker 是否已经终止。
- 启动时 `repair_interrupted_runs` 应修复异常退出遗留状态。
- 不要手工把 Run 标成 completed；完成状态必须有真实终态事件和消息。

### MCP 请求超时

Fox 当前每次调用会启动 stdio MCP 进程，生产超时为 15 秒。检查命令路径、参数、环境变量、Server 是否向 stdout 输出了非 JSON-RPC 日志，以及 `initialize`/`tools/list` 是否符合协议。

### 知识库文件预览失败

```powershell
$env:FOX_KNOWLEDGE_TOKEN = "<token>"
pnpm.cmd knowledge:verify-preview -- --base-url http://127.0.0.1:5010 --kb-id <kb-id> --file-id <file-id>
```

若契约失败，先修服务端 HEAD/Range；若契约通过，再查本地缓存、文件大小限制、第三方查看器和取消逻辑。

### 缓存持续增长

预览缓存默认上限 500 MB，可配置范围 250 MB 至 5 GB。应用启动和维护会清理超过 24 小时的 `.part`、孤儿文件和超限的未租用 LRU 项。使用“清理未使用预览缓存”，不要在文件正在预览时直接删除缓存目录。

### 备份恢复后无法启动

检查数据目录中的：

- `restore-pending.foxbackup`
- `restore-staging/`
- `restore-rollback/`

启动时程序会先恢复上次中断的 rollback，再验证并应用 pending 包。手工介入前完整复制数据目录；详见迁移备份文档。

## 安全升级条件

出现以下情况停止自动修复并保留现场：

- SQLite `integrity_check` 失败。
- 恢复失败且 rollback 也失败。
- 诊断中出现疑似未脱敏凭证。
- 未授权路径被工具访问。
- 两个 Run 同时修改同一文件并产生冲突。
- 安装包或 Sidecar 哈希与发布记录不一致。

## 故障关闭标准

- 根因已定位到具体层和代码路径。
- 有自动化回归或明确人工复现步骤。
- 刷新、重启和旧数据恢复路径已验证。
- 诊断与错误提示不会泄露敏感信息。
- Issue 记录受影响版本、修复版本和残余风险。

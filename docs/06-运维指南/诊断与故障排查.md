# 诊断与故障排查

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：桌面启动、启动降级、Runtime、外部 Agent、模型、知识库、MCP 与数据维护<br>
> 最后更新：2026-10-25

> 复核状态（2026-10-25）：「Fox 无法启动」「启动降级状态」「运行环境：完整性级别」「外部 Agent 会话」以及 SQLite、MCP 相关条目已对照 `main@763a019` 的 `lib.rs`、`startup_failure.rs`、`database/migration_backup.rs`、`local_knowledge_storage.rs`、`maintenance.rs`、`mcp.rs`、`runtime_host/mod.rs`、`crates/fox-agent-backend/src/{host_routing,external,sandbox}.rs` 与 `crates/fox-agent-backend/docs/sandbox.md` 复核。「知识库文件预览失败」「`ECONNREFUSED`」等条目沿用 2026-07-30 的内容，未重新验证。

## 目标与范围

本文面向开发、测试和支持人员，提供可重复的故障收集和分层处理流程。目标是先保护用户数据，再判断故障层级，最后通过可验证的最小修复恢复服务。

## 首要原则

1. 不要求用户提供 API Key、Token、MCP 环境变量或完整项目源码。
2. 涉及数据库、恢复和缓存手工处理前先创建备份。
3. 优先使用应用内诊断和维护命令，不直接删除应用数据目录，也不删除 `fox.db`。
4. Windows 上从普通目录（Medium 完整性）运行 Fox，见下文「运行环境：完整性级别」。
5. 记录时间、会话 ID、Run ID、操作步骤和可见错误，不只记录“卡住了”。
6. 真实知识库故障与 Fox 本地故障分开验证。

## Fox 无法启动

主库打不开、迁移失败、迁移前自动备份失败，或 setup 阶段的其他错误，都不会降级运行：Fox 停止启动并报告错误（`startup_failure.rs`）。

- Windows：弹出标题为「Fox 无法启动」的错误对话框，确定后进程以退出码 1 结束。
- 其他平台：没有对话框，只有标准错误输出里的一行 `fox.startup error setup_failed message=…`（Windows 也会写这一行）。

对话框内容有两种：

| 类型 | 文案要点 | 典型原因 |
| --- | --- | --- |
| 数据库打不开 | 「无法打开 Fox 数据库：<fox.db 路径>」「原因：…」「启动已停止，数据库文件没有被删除」，以及升级前自动备份所在目录 `<data>/backups` | 文件损坏或不是 SQLite；迁移失败；「数据库升级前的自动备份失败，已停止升级，数据库未改动：…」；「数据库外键完整性检查失败，以下记录引用了不存在的数据：<表> → <父表>（N 行）」 |
| 其他 setup 错误 | 「Fox 启动失败：<原因>」，以及「数据目录：<路径>」 | 数据目录无法创建、待恢复备份应用失败、Runtime 或其他组件初始化失败 |

处理步骤：

1. 记下对话框全文（含路径），关闭所有 Fox 进程。
2. 完整复制数据目录（至少 `fox.db`、`fox.db-wal`、`fox.db-shm` 和 `backups/`）作留档。不要删除 `fox.db`。
3. 按原因处理：
   - 自动备份失败：检查 `<data>/backups/` 是否可写、磁盘空间，然后重新启动。
   - 数据库损坏、迁移失败或非 `agents` 的外键违规：用 `backups/fox-pre-migration-<时间>-v<旧版本>.db` 或 `.foxbackup` 恢复，步骤见[迁移、备份与恢复](迁移备份与恢复.md#迁移前自动备份)。
   - 有 `restore-pending.foxbackup` / `restore-rollback/`：见下文「备份恢复后无法启动」。
   - Windows 上出现「拒绝访问」（os error 5）：先确认是否从带 Low 完整性标签的目录运行（见下节）。
4. 仍无法解决时，把对话框文本、启动日志和 Fox 版本交给维护人员。

在 Fox 之外删除了 `agents` 行（例如用 `sqlite3`）**不再**导致无法启动：迁移外键检查放过父表为 `agents` 的孤立行，启动时由 `repair_missing_agent_references` 修复引用，日志为 `fox.database warn missing_agent_references_repaired …`。详见[迁移、备份与恢复 · 启动修复缺失的 Agent 行](迁移备份与恢复.md#启动修复缺失的-agent-行)。

## 启动降级状态

以下问题不阻止启动，Fox 以降级状态继续运行，等到用户实际使用相关功能时才报错：

| 问题 | 表现 | 日志 / 错误码 | 处理 |
| --- | --- | --- | --- |
| 本机资料库根目录不可写、是文件或配置的路径无法解析 | 资料库只读或为空，界面提示「知识库路径不可写：<路径>」；已配置路径时**不会**改用默认目录 | `configured_storage_unresolvable`、`startup_storage_unwritable`；`local_knowledge.storage_path_unwritable` | 修复该目录权限，或在「设置 → 资料库 → 本机存储」用「修改位置」/「恢复默认位置」（`local_knowledge_storage_path_reset`），然后重启 |
| 预览缓存目录 `<data>/cache/knowledge-preview` 是文件或不可用 | 启动正常；打开预览时报带路径的错误 | `fox.knowledge_preview warn startup_recovery_deferred`；`knowledge.preview_cache_dir_invalid` | 关闭 Fox，移走同名文件或修复权限 |
| Kernel 锁目录 `runtime-sessions/kernel-run-locks` 是文件 | 启动不检查；启动 Run 时报带路径的错误 | — | 关闭 Fox 后移走同名文件 |
| `agents` 行在 Fox 之外被删除 | 受影响会话改用通用助手，专家绑定变为 removed，数字同事暂停 | `missing_agent_references_repaired`、`bundled_expert_restored` | 无需处理；需要该专家时重新导入 |
| 外部 Agent 后端被管理员关闭（`FOX_EXTERNAL_BACKENDS`） | 只能新建 Fox 会话；已绑定该后端的会话只读，不启动运行时 | `agent_backend_disabled` | 调整环境变量后重启 |

代码：`lib.rs`、`local_knowledge_storage.rs`（`resolve_startup_root`）、`local_knowledge.rs`（`open_for_startup_root`、`open_degraded`）、`maintenance.rs`（`recover_knowledge_preview_cache_at_startup`）。更完整的启动步骤见 [Tauri 后端架构 · 启动降级与失败报告](../02-架构/Tauri后端架构.md#启动降级与失败报告)。

## 运行环境：完整性级别

Windows 上必须从普通目录运行 Fox 的 exe（进程为 Medium 完整性，SID `S-1-16-8192`），例如 `D:\fox-test\`。不要从带 Low 完整性标签的目录（部分下载目录、解压目录）运行：进程会被降为 Low，写不了 Medium 标签的 `%LOCALAPPDATA%\Fox\state` 等目录，表现为「拒绝访问」（os error 5）或外部 Agent 会话报 `sandbox_unavailable`，与代码缺陷无关（`crates/fox-agent-backend/docs/sandbox.md` 13.25 结论）。

测试和复现前先确认完整性级别，例如在 PowerShell 中运行 `whoami /groups`，看「Mandatory Label」一行是否为 `Medium Mandatory Level`；或用 `GetTokenInformation` 读取进程令牌。

## 诊断信息收集

### 应用内诊断

「设置 → 数据与关于 → 诊断」可「重新诊断」、复制脱敏诊断摘要，或「导出诊断包」（命令 `diagnostics_export`）为脱敏 JSON：

```text
<Fox 数据目录>/exports/fox-diagnostics-<timestamp>.json
```

内容包括：

- Fox 和 SQLite Schema 状态。
- Runtime 状态、版本、最近错误和有限 stderr。
- 模型服务连接状态。
- 知识库服务连接状态。
- MCP Server 状态和脱敏错误。
- 隐私声明。

明确不包括：对话正文、项目文件内容和凭证明文。Runtime stderr 最多保留最近 80 行（`STDERR_LIMIT`），每行最多 512 个字符，并对 Authorization、Bearer、API Key、Token 等标记做脱敏。

分享诊断文件前仍需人工检查，避免第三方服务错误消息携带未被识别的敏感字段。

### A0 工作状态诊断

开发者工具可按 Conversation ID 调用：

- `diagnose_work_state({ conversationId })`：只读检查多活动 Goal、多运行中 Task、完成 Task 缺 Evidence、blocked 缺原因、事件序列/引用和 Evidence 有效性。
- `export_work_trace({ conversationId })`：导出 `fox-work-trace-<conversation>-<timestamp>.json`，用于复盘 Goal -> Task -> Evidence 和 12 类 Work Event。

Trace 导出刻意不包含 Runtime Event 正文、工具输入/结果、对话正文、项目文件、API Key、Token 或 MCP 环境变量。它会保留 Goal/Task 标题、Evidence 摘要及 Run/事件/工具的关联元数据，因此对外分享前仍需检查业务敏感信息。

### 复现记录模板

```text
Fox 版本：
Windows 版本：
安装包或开发态：
运行目录及完整性级别（Medium / Low）：
发生时间（含时区）：
当前 Agent（Fox / pi / DeepSeek）与模型：
Conversation ID：
Run ID：
操作步骤：
预期结果：
实际结果：
是否刷新后恢复：
是否重启后恢复：
诊断文件：
```

## 分层检查

### 1. 窗口与前端

- 窗口是否能响应最小化、最大化和关闭。
- DevTools 是否有模块加载、Hook、Worker、WASM 或渲染异常。
- 当前路由是否仍可切换。
- 是整个页面无响应，还是单个运行状态不更新。

### 2. Tauri Host

- Command 是否返回统一错误码。
- Runtime 初始化是否成功。
- 是否出现「Fox 无法启动」；SQLite Migration、迁移前自动备份或待恢复备份是否阻塞启动。
- 是否处于启动降级状态（资料库只读、预览缓存推迟恢复）。
- 文件选择器、Credential Manager 或子进程是否被系统策略拦截。

### 3. SQLite

- `PRAGMA integrity_check` 是否为 `ok`。
- `schema_migrations` 最大版本是否与程序一致；当前为 97（`database/mod.rs` 的 `DATABASE_SCHEMA_VERSION`）。
- `PRAGMA foreign_key_check`：父表为 `agents` 的孤立行是启动修复后保留的历史，可以忽略；其他父表的违规会阻止下次升级迁移。
- 对异常会话运行 `diagnose_work_state`，再按需导出 Work Trace；不要直接手改工作表状态。
- 最新 Run 是否进入终态。
- Event 序号和消息是否已经持久化。

### 4. Runtime

- ready 握手的协议、版本和能力清单是否通过。
- Sidecar 是否崩溃、被杀死或超时。
- stdout 是否混入非 JSONL 文本。
- Runtime 工具目录与 Host 清单是否一致。

### 5. 外部 Agent（pi、DeepSeek、Codex）

- 会话的 `agent_backend` 是什么（创建后不可改）。Codex 已恢复可选；新建 Codex 会话不再被拒绝。
- `FOX_EXTERNAL_BACKENDS` 是否把该后端关掉了（`agent_backend_disabled`）。
- 后端是否已安装到受管运行时目录（`agent_backend_not_installed`）。外部 Agent 不再依赖 SRT；SRT 未安装只会影响 Fox Agent 的 Host 命令，不应阻止 pi / dsh / Codex 启动。
- 外部会话发送前必须绑定项目（`agent_backend_project_required`），且暂不支持附件（`agent_backend_attachments_unsupported`）。
- Fox 重启后，上次未结束的外部 Run 会被标为中断（`agent_backend_host_restarted`），其未决审批标为 `cancelled`。
- 错误码含义见[错误与状态参考](../04-技术参考/错误与状态.md#外部-agent-后端)。

### 6. 外部服务

- 模型连接测试是否通过。
- 知识库健康、认证和版本是否可用。
- MCP 命令能否启动、`initialize` / `tools/list` 是否在 15 秒内返回。
- 网络代理、防火墙、证书和服务端日志是否异常。

## 故障速查

### `ECONNREFUSED · 127.0.0.1:5010`

这是目标端口无服务监听。若当前选择 Fox 通用助手，先确认模型供应商而不是知识库服务被误设为必需依赖；若使用知识助手，则检查知识库容器、端口映射和健康接口。

### `Pi Runtime dependencies are missing`

开发环境从工作区根目录执行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd runtime:test
```

生产安装包出现该错误通常表示错误启动了源码 Runtime，或 Sidecar 资源未被打包，应重新检查 `tauri.conf.json` 和安装包内容。

### 消息只在刷新后出现

数据库已有完整回复说明执行和持久化成功，重点检查 listener 注册、会话匹配、事件序号、Reducer 去重和运行完成后的状态归并。数据库也没有回复时再查 Sidecar/远程游标恢复。

### Run 长期 queued/running

- 查询是否等待用户补充或审批。
- 检查 Sidecar/远程 Worker 是否已经终止。
- 启动时 `repair_interrupted_runs` 把 Legacy 路径遗留的 Run 标为 `interrupted`（`runtime.application_restarted`）；Kernel Authoritative 路径的 Run 由 `recover_kernel_runs_detached` 恢复；外部 Agent 的 Run 标为中断（`agent_backend_host_restarted`）。
- 不要手工把 Run 标成 completed；完成状态必须有真实终态事件和消息。

### MCP 请求超时

Fox 通过连接池复用 stdio MCP 进程和 HTTP MCP Session（配置变化会让旧连接失效），单次请求超时为 15 秒（`mcp.rs` 的 `TIMEOUT`）。检查命令路径、参数、环境变量、Server 是否向 stdout 输出了非 JSON-RPC 日志，以及 `initialize`/`tools/list` 是否符合协议。

### 知识库文件预览失败

```powershell
$env:FOX_KNOWLEDGE_TOKEN = "<token>"
pnpm.cmd knowledge:verify-preview -- --base-url http://127.0.0.1:5010 --kb-id <kb-id> --file-id <file-id>
```

若契约失败，先修服务端 HEAD/Range；若契约通过，再查本地缓存、文件大小限制、第三方查看器和取消逻辑。

### 缓存持续增长

预览缓存默认上限 500 MB，可配置范围 250 MB 至 5 GB。应用启动和维护会清理超过 24 小时的 `.part`、孤儿文件和超限的未租用 LRU 项。使用“清理未使用预览缓存”，不要在文件正在预览时直接删除缓存目录。

### 备份恢复后无法启动

检查数据目录中的：

- `restore-pending.foxbackup`
- `restore-staging/`
- `restore-rollback/`

启动时程序会先恢复上次中断的 rollback，再验证并应用 pending 包。手工介入前完整复制数据目录；详见迁移备份文档。

## 安全升级条件

出现以下情况停止自动修复并保留现场：

- SQLite `integrity_check` 失败。
- 恢复失败且 rollback 也失败。
- 诊断中出现疑似未脱敏凭证。
- 未授权路径被工具访问。
- 两个 Run 同时修改同一文件并产生冲突。
- 安装包或 Sidecar 哈希与发布记录不一致。

## 故障关闭标准

- 根因已定位到具体层和代码路径。
- 有自动化回归或明确人工复现步骤。
- 刷新、重启和旧数据恢复路径已验证。
- 诊断与错误提示不会泄露敏感信息。
- Issue 记录受影响版本、修复版本和残余风险。

## 目标与范围

本文描述 Windows x64 的当前构建链。发布由三部分组成：Vite 前端、Bun 编译的 Runtime Sidecar、Tauri/Rust 主程序与安装包。

## 构建关系

```mermaid
flowchart LR
  FE["tsc + Vite"] --> Tauri["Tauri build"]
  Runtime["Bun compile Sidecar"] --> Tauri
  Tauri --> EXE["Fox 主程序"]
  Tauri --> NSIS["NSIS 安装包"]
  Tauri --> MSI["MSI 安装包"]
```

根命令 `pnpm.cmd tauri:build` 依次执行 `prepare:office`（`scripts/prepare-officecli.mjs`）、`runtime:build`，再执行桌面端 `tauri build`。Tauri 自身还会通过 `beforeBuildCommand` 执行 `prepare-officecli.mjs`、`prepare-windows-runtime.mjs` 和前端 build。

内置 PiNative 是主线；外部 Pi、Codex（codex-acp）、dsh 已在阶段三恢复为可选后端（经 ACP），Codex / DeepSeek 的 Kernel 适配器已删除。Fox 不用沙箱：运行时打包脚本（`build-runtime-package.py`）不再打包 `srt\` 和 `acp-bridge\`，遇到这两个目录直接拒绝。当前 pin 的运行时包是 0.1.7（B5，不带 srt；构建见 [Windows 安装包与受管运行时](../windows-bundled-sandbox-installer.md)）。

## 发布前准备

1. 工作区无意外生成文件和敏感配置。
2. `package.json`、`pnpm-lock.yaml`、Cargo 版本和 Tauri `version` 一致或已按发布策略更新。
3. Bun、Node、pnpm、Rust MSVC、C++ Build Tools 可用。
4. 预期的应用图标存在于 `apps/desktop/src-tauri/icons/`。
5. Runtime 依赖已经由根目录 pnpm 安装。

## 分步构建

### 前端

```powershell
pnpm.cmd --dir apps/desktop build
```

输出目录：`apps/desktop/dist/`。

### Runtime Sidecar

```powershell
pnpm.cmd runtime:build
pnpm.cmd runtime:smoke
```

输出：

```text
services/agent-runtime/dist/fox-agent-runtime-x86_64-pc-windows-msvc.exe
```

构建脚本会建立临时 bundler workspace、实体化 pnpm 符号链接依赖、复制 Runtime 协议文件，使用 `bun build --compile --target=bun-windows-x64 --windows-hide-console` 生成临时 EXE，成功后再替换正式文件。失败不会破坏上一次可用产物。

### Tauri 主程序和安装包

```powershell
pnpm.cmd tauri:build
```

典型输出：

```text
apps/desktop/src-tauri/target/release/fox-desktop.exe
apps/desktop/src-tauri/target/release/bundle/nsis/Fox_<version>_x64-setup.exe
apps/desktop/src-tauri/target/release/bundle/msi/Fox_<version>_x64_en-US.msi
```

当前 `bundle.targets` 为 `all`。历史构建曾出现 WiX `light.exe` 失败而 NSIS 成功的情况，因此必须按本次时间戳和哈希识别产物，不能把目录中的旧 MSI 当作新构建结果。

## 安装包验收

在干净或隔离的 Windows 用户环境验证：

1. 首次安装和首次启动。
2. 引导页、用户资料和默认头像。
3. 模型供应商配置与凭证保存。
4. Fox 通用助手流式对话、取消、审批和重启恢复。
5. 项目文件夹授权、读取、写入和命令审批。
6. 附件保存与历史恢复。
7. 知识库登录、绑定、检索、引用跳转、文档预览和下载。
8. 插件中心、Skills、MCP/OpenAPI 配置与健康状态。
9. 本地知识导入、检索、引用、删除和缺少向量资源时的降级。
10. 专家包、工作流、团队和数字同事的创建、触发、取消与恢复。
11. Goal/Task/Evidence、Plan/Review/Acceptance、重启/中断、Evidence 失效、`diagnose_work_state` 和 `export_work_trace`。
12. 诊断导出、备份、恢复和缓存清理。
13. 从上一个正式版本覆盖安装，旧数据库自动迁移（先生成迁移前自动备份）。
14. 单 Pi：新会话固定 Pi 并落库 `fox`；旧外部会话可读但执行拒绝；核对直接 IPC、Schema v98 升级与原生文件备份。阶段二还需完整重启、损坏文件、显式重置、隔离及中断场景验收。
15. 启动降级：资料库目录不可写时应用仍能启动并提示。

录屏、测试输出和人工签收必须对应本次安装包哈希，不得复用历史构建素材。发布基线与完整命令见 `docs/05-开发指南/Agent能力测试基准.md`。

## Tauri 资源

`tauri.conf.json` 将 Runtime 源文件（`pi-runtime.mjs`、`fake-runtime.mjs`、`protocol.mjs` 等）和 `services/agent-runtime/dist/*` 打入 `agent-runtime/` 资源目录；另外打包 `resources/officecli/*`、`resources/pdf-renderer/*`、离线评测 fixtures、向量模型发布公钥 `models/trusted-release-keys/fox-release-2026.json` 以及 `zvec_c_api.dll`。生产模式优先启动编译后的 Sidecar EXE；若资源缺失，Host 会报告 `bundled Fox Runtime executable was not found`。

修改 Runtime 文件清单时，需要同步 `tauri.conf.json` 和 `build-sidecar.mjs` 的复制列表。

## 构建变体与打包命令

根 `package.json` 提供三个打包入口，产物语义不同，不能互相代替：

| 命令 | bundles / config | 默认执行权威 |
| --- | --- | --- |
| `pnpm tauri:build` | `bundle.targets = "all"`（NSIS + MSI） | **Authoritative** |
| `pnpm tauri:build:windows` | `--bundles nsis` + `tauri.installer.conf.json`（补入 `resources/windows-runtime/*.dll`） | **Authoritative** |
| `pnpm tauri:build:kernel-preview` | `--bundles nsis` + `tauri.kernel-preview.conf.json`（`features: ["kernel-default"]`） | **Authoritative** |

预览包使用独立 `productName`（Fox Kernel Preview）与 `identifier`（`com.fox.agent.kernel-preview`），可与正式版并存安装。2026-09-29 起普通开发和构建也默认 Authoritative，Legacy 仅通过显式 `FOX_KERNEL_MODE=legacy` 启用；现有安装产物需要更新后才采用新的默认。见[当前状态与核验基线](../01-项目概览/当前状态与核验基线.md)的「执行权威的层次」。

安全相关的构建事实：`apps/desktop/src-tauri/tauri.conf.json` 的 `app.security` 已配置 `csp` 与 `devCsp`；预览配置未覆盖 `app.security`，按 Tauri 的配置合并语义应沿用基础 CSP（本轮未运行预览包实测）。

## 共享运行时与退休资源

旧外部驱动的安装目录、ACP 命令和配置仍可能保留兼容数据，但不是当前发布的驱动入口。安装外部程序或修改 `FOX_EXTERNAL_BACKENDS` 不能恢复准入。

Windows SRT 已删除（B2）。升级安装时，`enable-sandbox.ps1` 第 5 步会卸载旧版 Fox 自己安装的 SRT（以安装回执证明归属；别的程序装的 SRT 保留），第 6 步从本次安装的版本目录删除 `srt\` 和 `acp-bridge\`。脚本和安装目录名里的 “sandbox” 只是历史命名（`%ProgramFiles%\Fox\sandbox-runtime` 存放外部 Agent 的受管运行时），与沙箱无关。Pi Runtime 与 Kernel worker 按当前构建脚本打包；不能沿用已删除的 Codex / DeepSeek Kernel 适配器说明。

**阶段二与 C gap 未完成。** 现有定向测试、SDK 测试和 Legacy 映射证据不构成阶段二发布依据，见[单 Pi 主线状态](../01-项目概览/单Pi主线状态.md)。v98 已引入原生映射，不再适用阶段一“无迁移、无需备份”的旧回退说明。

## 验收运行环境

- Windows 上必须从普通目录（Medium 完整性）运行构建出的 exe，例如 `D:\fox-test\`；不要直接从带 Low 完整性标签的下载 / 解压目录运行，否则会出现与构建无关的「拒绝访问」（见[诊断与故障排查 · 运行环境：完整性级别](诊断与故障排查.md#运行环境完整性级别)）。
- 验收多个实例时用 `FOX_DATA_DIR` 隔离数据目录（WebView 数据随之隔离）。
- 覆盖安装验收要确认：有待执行迁移时 `<data>/backups/` 出现 `fox-pre-migration-…-v<旧版本>.db`；数据库无法打开时出现「Fox 无法启动」对话框而不是静默退出。

## 发布状态说明

本仓库当前**没有**代码签名、更新服务器和 SBOM 流程：`tauri.conf.json` 中不存在 `updater`、`pubkey` 或签名相关字段。也没有 GitHub Release/自动发布工作流；`.github/workflows/windows-ci.yml`（job：`desktop-build`、`agent-runtime`、`rust-host`、`agent-backend`、`vector-runtime-smoke`、`onnx-runtime-smoke`；`workflow_dispatch` 支持 `targeted` / `rust_test_filter` 定向模式）只做测试与构建校验，不产出发布包。

## 常见故障

### Sidecar 构建找不到依赖

从根目录执行 `pnpm.cmd install --frozen-lockfile`。构建脚本会从 Runtime 本地或工作区 `node_modules` 查找 Pi 与传递依赖。

### `runtime-contract.mjs` 无法解析

确认它仍位于 `services/agent-runtime/src/`，并包含在 `build-sidecar.mjs` 的复制列表中。

### Tauri CLI 模块缺失

不要硬编码 `node_modules/@tauri-apps/cli/tauri.js` 路径。重新安装锁定依赖，并通过 `pnpm.cmd --dir apps/desktop exec tauri --version` 验证本地 bin。

### MSI 失败

保留完整 WiX 日志并确认 NSIS 是否成功。本次发布若要求 MSI，则不能用旧文件补位；若只发布 NSIS，要在发布说明明确交付范围。

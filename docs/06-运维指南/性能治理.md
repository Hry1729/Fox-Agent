> 适用版本：Fox 0.1.x<br>
> 维护范围：启动、前端 Chunk、对话历史、Runtime / Kernel、外部 Agent、SQLite 与文件预览<br>

## 目标与范围

Fox 的性能目标不是隐藏构建警告，而是降低首屏下载、解析与执行成本，保持流式对话稳定，并限制大历史、大文件和缓存对内存与磁盘的影响。

## 主要风险

- PPTX、PDF、DOCX、Excel 查看器。
- AntV G6 图谱与布局算法。
- Shiki 语言/主题和 WASM。
- Mermaid 与 Markdown 扩展。
- `workbench.tsx` 和设置页的大型业务模块。
- 大会话的消息、Event、Reasoning、Tool 与 Artifact。
- 知识库原文件缓存和大型 Blob。
- Runtime Session 与长期历史维护。

## 启动预算

冷启动路径不应加载或执行：

- Office/PDF 查看器。
- 知识图谱和布局算法。
- Mermaid（除非当前内容实际包含 Mermaid）。
- 全量 Shiki 语言和主题。
- 非当前设置、智能体或知识库详情页面。

启动测量至少分成：

1. 进程启动到 WebView 可见。
2. Vite/静态资源加载到首屏可交互。
3. SQLite 打开、迁移前自动备份（仅有待执行迁移时）、Migration、种子写入与缺失 Agent 行修复、维护恢复。
4. Runtime 初始化。
5. 外部服务状态刷新。

不要用单一“白屏几秒”指标混合这些阶段。

升级后的首次启动会多出一次 `VACUUM INTO` 迁移前备份（`database/migration_backup.rs`），耗时与 `fox.db` 大小成正比；测量升级启动时要把它单独记出来。资料库和预览缓存的启动恢复不会阻塞启动：出问题时降级运行，等使用时才报错（见[诊断与故障排查 · 启动降级状态](诊断与故障排查.md#启动降级状态)）。

当前 production build 的硬门槛（`apps/desktop/scripts/check-bundle-budget.mjs`）为：入口脚本 gzip 不超过 **240 KiB**，入口及 `modulepreload` JavaScript 的 gzip 总和不超过 **316 KiB**。预算从 220 KiB 逐步上调过（运行中指示、语言契约与审批界面、运行中补充输入框），每次上调的原因写在脚本注释里，新的上调也必须在那里写明原因。`pnpm build` 依次执行 `tsc`、`vite build`、`check-bundle-budget.mjs` 和 `check-build-isolation.mjs --mode=release`，也可在已有产物上单独运行 `pnpm check:bundle`。

## 前端 Chunk

当前查看器已按文件类型动态导入，但生产构建仍可能报告超过 500 KB 的 Chunk。治理顺序：

1. 已接入构建体积可视化；每次桌面端 production build 生成 `apps/desktop/dist/bundle-stats.html`，用于保存和比较模块归属与压缩体积基线。
2. 保持 PDF、DOCX、Excel、PPTX、G6、Mermaid 和 Shiki 独立入口。
3. 对设置中心、工作台和右侧工具面板做路由/组件分包。
4. Shiki 默认只加载 TypeScript、JavaScript、Python、Rust、JSON、Shell、Markdown、HTML 和 CSS 等常用语言。
5. 未知语言按需加载，期间使用普通代码块回退。
6. 只有用户有打开意图时才预加载重型查看器。

禁止仅提高 `chunkSizeWarningLimit` 使告警消失。

## 对话与历史

- SQLite 是历史事实源，首屏不加载完整会话历史。
- 消息和 Event 采用分页，较早消息按需加载。
- FTS5 用于会话、项目、Agent 和消息搜索，不在前端遍历全部正文。
- Reducer 通过稳定 ID 和序号去重，避免重复事件扩大状态。
- Reasoning 和工具过程完成后可以保留，但不应重复渲染相同块。
- Sidebar、WindowTitlebar、Timeline、Composer 与单条 Assistant Message 设独立 memo 边界；传入回调与空集合保持稳定引用，Runtime/Composer Context 分离，避免流式帧触发无关区域。
- Runtime Event、Artifact、Attachment 和 Agent 先建立稳定索引，再按 Run/Message 查找，禁止在每条消息内重复扫描完整集合。
- 大 Artifact 只保存元数据和文件路径，不写入消息 JSON。

A0 已覆盖 500 个历史 Task 的 SSR P95 基线；Goal 快照 P95 小于 50 ms、浏览器端首次渲染 P95 小于 120 ms、单次状态事务 P95 小于 20 ms 仍需补齐真实浏览器持续基准。

## SQLite

- 为排序、外键、状态和常用过滤建立索引。
- 写入多表状态使用短事务。
- 启动恢复设置最大扫描范围，禁止遍历全部历史 Event。
- 遇到 busy 采用有界重试，不允许无限循环。
- 大列表返回分页 DTO，不把全部记录序列化到前端。
- 一致性快照使用 `VACUUM INTO`（应用内备份 `Database::backup_to` 与迁移前自动备份都是如此），写到临时文件后再改名；迁移前备份只保留最新 5 份，避免 `backups/` 无限增长。
- SQLite 使用 WAL 与 5 秒 busy timeout。

## Runtime

- Runtime 与 Host 使用本机 JSONL，不占用本地端口。
- stdout 只承载协议，减少解析失败和日志复制。
- 每个 Run 可取消，终止后清理审批等待和子进程资源。
- Session 用于执行恢复，不用作 UI 历史读取源。
- 避免把完整工具输出重复写入模型历史；只保留模型需要的摘要和 Fox 审计记录。
- Kernel Authoritative 是默认路径。不同会话的 Run 与模型请求没有应用自设的并发上限（`FOX_KERNEL_RUN_CAPACITY`、`FOX_KERNEL_CHILD_RUN_CAPACITY`、`FOX_KERNEL_MODEL_REQUEST_CAPACITY` 已不生效），Host 只按 Run 身份防重复启动；Legacy 路径保留单 Worker 顺序执行。本机资源不足或供应商限流时按有界重试结束，不增加隐藏队列。
- Kernel 默认供应商重试与轮次重试各最多 5 次（`runtime_host/kernel_host.rs`）。

## 外部 Agent

- 外部 Agent（pi、DeepSeek Harness、Codex）每个会话一个后端进程，由 Fox 直接启动；不再经过 srt 沙箱或 ACP 桥，首轮开销主要是后端进程启动。切换 DeepSeek 原生权限或完全访问会在下一轮重启后端。Fox Agent 的 Host 命令才经过 SRT。
- 事件先写入 `run_events` 再通过 `fox://runtime-event` 推送，和 Fox 会话共用前端去重逻辑。
- 外部 Agent 的性能基线本次没有测量。

## 文件预览

### 缓存

- 默认上限：500 MiB（`maintenance.rs` 的 `KNOWLEDGE_PREVIEW_CACHE_LIMIT`），保存在 `app_settings.knowledge_preview_cache_limit_bytes`。
- 可配置范围：250 MiB 至 5 GiB。
- 超限时淘汰未租用的 LRU 项。
- 启动时重置异常退出遗留租约；缓存目录不可用时只记录 `startup_recovery_deferred`，不阻塞启动。
- 删除超过 24 小时的 `.part` 文件。
- 孤儿缓存会在维护中回收。

### 读取

- Rust 单次 Range 上限为 4 MB。
- 图片与 Office 原件有文件大小和 ZIP 安全检查。
- 切换文档时使用 AbortSignal 取消旧请求。
- Blob URL 和第三方查看器在卸载时释放。
- PDF/PPTX 单页渲染，翻页后再处理下一页；避免一次渲染整份大文档。
- DOCX 在可识别分页时逐页展示，否则采用受限连续滚动；不能把渲染器生成的单个连续 DOM 错当成源文档只有一页。

## 图谱与动画

- G6 图谱只在知识图谱页加载。
- 节点较多时限制默认节点数和深度，提供搜索、聚焦和增量展开。
- 缩放时避免 CSS transform 与 Canvas 缩放叠加造成模糊。
- 动画在页面不可见、窗口最小化或用户开启减少动画偏好时降频/暂停。
- WebGL/Rive/OGL 实例在卸载时销毁，避免 GPU 资源泄漏。

## 测量建议

每次性能改造记录：

| 指标 | 场景 |
| --- | --- |
| 启动到首屏可交互 | 空库、历史大库各一次 |
| 首次打开对话 | 10、1,000、10,000 条消息样本 |
| 流式增量延迟 | 短回复和长回复 |
| 首次打开设置/智能体/知识库 | 冷加载和二次加载 |
| 查看器加载 | PDF、DOCX、XLSX、PPTX 各取小/大文件 |
| 内存峰值与释放 | 切换 10 份文档后 |
| 缓存收敛 | 超过上限后 LRU 清理 |
| 构建 Chunk | 压缩前、压缩后、模块归属 |

桌面端已集成 `rollup-plugin-visualizer`、构建后包体预算检查，并在 Timeline 与 Composer 外层接入 React Profiler 标记；真实浏览器自动化采集和跨设备持续基准平台仍属于待办。

## 回归门槛

- 冷启动不加载 Office、图谱、Mermaid 和全量 Shiki。
- 普通聊天不因知识库预览依赖而增加明显初始化成本。
- 取消和页面切换后网络、Timer、Worker、Blob 与第三方实例被释放。
- 大历史加载不会冻结 UI，分页和搜索可用。
- 调小缓存上限后立即收敛，活动租约不被删除。
- 性能优化不改变流式、恢复和文件预览正确性。

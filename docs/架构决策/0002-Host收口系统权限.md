# 0002：Host 收口系统权限

> 状态：已接受<br>
> 决策日期：2026-07-29 之前形成，2026-07-29 补录<br>
> 影响范围：文件、命令、附件、知识库、MCP 与凭据

## 背景

Agent Runtime 会处理模型输出、项目内容、知识库文本和外部工具结果，这些输入都可能不可信。如果 Runtime 可以直接写任意文件、运行命令、读取凭据或调用 MCP，模型错误和 Prompt Injection 会直接扩大为系统权限问题。

## 决策

由 Tauri/Rust Host 统一收口具有系统副作用或敏感数据访问的能力。

- Runtime 只能调用能力清单中声明的工具。
- 只读项目工具也必须限制在已授权项目根目录内。
- 写文件、编辑文件、命令执行和 MCP 调用由 Host 执行。
- 工具执行前由 `tool_guard` 根据类别、路径和策略决定是否需要审批。
- 凭据保存在系统 Keyring 或 Host 管理范围内，不传入前端和普通工具结果。
- 所有工具结果都应限制大小并形成可诊断记录。

## 后果

正面影响：

- 权限策略和审计集中在一个可信边界。
- Runtime、模型供应商和 MCP 服务可以替换而不改变系统权限模型。
- 用户能够在执行前理解高风险操作。

成本与风险：

- 新工具需要同时实现 Runtime 声明、Host 执行、协议映射和测试。
- Host 与 Runtime 的协议必须版本化并保持兼容。
- 审批 UI、取消和恢复链路增加了状态复杂度。
- 审批并不自动保证安全，参数和输出仍需验证。

## 未采用方案

- **给 Runtime 完整系统权限**：实现简单但无法建立可信安全边界。
- **仅依赖模型自我约束**：模型输出不是安全控制。
- **所有工具都每次询问用户**：会产生审批疲劳，应按风险采用 `none`、`preflight`、`policy` 和 `always` 分级。

## 后续要求

- OpenAPI 和 Hooks 必须复用 Host 安全边界。
- MCP 调用需要域名、工具、参数、频率和响应大小限制。
- 所有新工具必须包含越权路径和拒绝流程测试。

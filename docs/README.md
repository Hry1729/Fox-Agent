## 事实来源优先级

文档与实现不一致时，按以下顺序核实：

1. 当前分支的代码、数据库迁移和自动化测试。
2. 版本化协议、配置文件和生成清单。
3. 本目录中的常青架构与技术参考文档。
4. GitHub Issues、Milestones 和已接受的架构决策。
5. `归档` 中的历史计划、研究和实施状态。

发现偏差时，不应只修正文档或只修代码。先确认预期行为，再让实现、测试和文档恢复一致。

## 维护规则

- 文件名使用中文；保留行业通用缩写，如 API、MCP、Runtime、SQLite。
- 对外统一使用“知识库服务”，只有解释代码路径或兼容字段时使用 `Yuxi` 实现名称。
- 路线图描述未来，架构文档描述当前稳定边界，技术参考必须贴近代码事实。
- 每项公共接口变更必须同步更新相关参考文档和测试。
- 不在文档中记录真实 API Key、Token、Cookie、内部地址或用户数据。
- 历史文档只有在内容被完整吸收并完成链接检查后才能移入归档或删除。

具体写作约定见 [文档编写规范](文档编写规范.md)。

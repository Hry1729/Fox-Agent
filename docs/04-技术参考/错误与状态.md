# 错误与状态参考

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：`ApiResponse` 错误格式、错误码、Run / 审批 / 外部 Agent 状态<br>
> 最后更新：2026-10-28（单 Pi 分支同步；本轮未复跑产品测试）

> 复核状态（2026-10-25）：错误码表由脚本对 `main@763a019` 的 `apps/desktop/src-tauri/src`、`crates/` 下 `.rs` 文件做**静态扫描**得到（取出现在 `ApiResponse::failure`、错误构造、`code`/`Err` 上下文中的 `前缀.名称` 字符串和 `agent_backend_*` 常量），再人工剔除事件类型、文件名和字段名。没有运行时验证每个码都能被触发；个别码可能只在测试或防御分支中出现。外部 Agent、审批状态、启动失败三节逐条对照了代码。

## 结论

- 普通 Tauri 命令失败时返回 `{ ok: false, error: { code, message, retryable } }`；前端按 `code` 决定交互，不要匹配 `message` 文本。
- Fox 自身的错误码是 `前缀.名称`（如 `conversation.run_active`）；外部 Agent 后端的错误码是 `agent_backend_*`，沙箱错误码是 `sandbox_*`，二者都没有点号。
- 错误码没有集中的编译期枚举，分散定义在各模块；新增错误必须复用已有前缀，避免同义码。
- 被中断的 Run 留下的未决审批：显式取消、会话关闭、Fox 退出 / 重启标为 `cancelled`；其他中断、Run 结束和启动修复标为 `expired`（详见「审批状态」）。

## API 错误格式

```ts
type ApiError = { code: string; message: string; retryable: boolean }
```

定义在 `apps/desktop/src-tauri/src/database/models.rs`（`ApiError`、`ApiResponse::failure`）。`message` 是给用户看的中文提示；`retryable=true` 只表示可以由用户重试，不表示 Host 会自动重放。

## 单 Pi 与阶段二错误

| 错误 / 状态 | 当前含义 | 处理 |
| --- | --- | --- |
| `agent_backend_retired` | 请求退休外部驱动，或试图执行其历史会话 | 保留历史，用户可另建受支持会话；不改绑旧行、不用环境变量重启旧驱动 |
| `kernel_engine_retired` | Kernel 配置的引擎不是受支持的 Pi | 核对配置与候选构建；不静默替换已冻结身份 |
| `session.native_*` | 原生会话路径、文件、身份、目录或打开状态错误 | 保留文件和数据库映射，记录具体码；Host 跨请求重建边界未闭合 |
| `runtime.process_crashed` / `runtime process closed stdout` | 既有 Legacy 桌面记录的进程失败 | C gap 未关闭，需定位并复测 |
| `provider.request_failed: 404 model route not found` | 既有恢复轮次的模型端点失败 | C gap 未关闭，核对请求与供应商路由，未确定根因 |

本轮仅核对源码和既有记录，未重新触发这些错误。[阶段二完整边界](../01-项目概览/单Pi主线状态.md#c-gap-与未验证项)。

## 外部 Agent 后端

当前路由只支持 `fox`。旧 `pi/codex/deepseek` 会话可读但执行拒绝。新错误码和历史码需分开；下表中的旧启动、权限和 ACP 错误保留供旧记录解读，不是启用退休后端的操作指南。事实源为 `host_routing.rs`、`kernel_model_config.rs`、`pi-runtime.mjs`。

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `agent_backend_invalid` | 不支持的后端值，或会话记录的后端无法识别；也用于对 Fox 会话调用外部专用操作 | 修正请求；记录损坏时保留现场 |
| `agent_backend_hidden` | 旧隐藏策略的兼容码；当前退休列表决定是否可运行 | 不把 HIDDEN 为空理解为外部驱动可用 |
| `agent_backend_disabled` | 旧管理员禁用策略的兼容码；当前退休后端主要返回 `agent_backend_retired` | 不能通过改环境变量启用退休驱动 |
| `agent_backend_misrouted` | 请求指向的后端与会话冻结的 `agent_backend` 不一致（错投），拒绝而不改绑 | 前端按会话记录重发 |
| `agent_backend_entry_unsupported` | 该入口对外部后端无意义（如知识库 / Kernel 的 resume） | 不对外部会话调用该入口 |
| `agent_backend_not_yet_wired` | 历史码，当前代码不再产生，保留给旧界面识别 | — |
| `agent_backend_lookup_failed` | 旧兼容码；当前冻结值读取失败可进入 Fox fallback，显式退休请求仍拒绝 | 核对实际错误码与数据库现场，见路由源码 |
| `agent_backend_immutable` | 数据库触发器拒绝修改 `conversations.agent_backend`（v95） | 后端只能在创建时选择 |

## 启动失败

启动失败不经 `ApiResponse`，而是由 `apps/desktop/src-tauri/src/startup_failure.rs` 报告：日志行 `fox.startup error setup_failed message=…`，Windows 上弹出标题为「Fox 无法启动」的对话框，随后以退出码 1 结束。文案与处理见[诊断与故障排查 · Fox 无法启动](../06-运维指南/诊断与故障排查.md#fox-无法启动)。

## Run 状态

`runs.status` 没有数据库 CHECK，取值由 Repository 写入：

```mermaid
stateDiagram-v2
    [*] --> queued
    queued --> awaiting_confirmation: 请求工作模式确认
    awaiting_confirmation --> queued: 批准并释放同一 Run
    awaiting_confirmation --> cancelled: 拒绝工作模式
    queued --> running
    queued --> cancelled
    running --> cancelling
    cancelling --> cancelled
    running --> completed
    running --> failed
    running --> interrupted
    interrupted --> running: resume/recovery
```

- 终态：`completed`、`failed`、`cancelled`、`interrupted`。远程知识库 Run 的 `interrupted` 可能被恢复。
- 活动判断包含 `queued`、`awaiting_confirmation`、`running`、`cancelling`。
- `awaiting_confirmation` 是实际持久化状态：`commands/mod.rs` 在工作模式需要确认时调用 `database/repositories.rs::save_pending_work_mode_dispatch`，执行 `UPDATE runs SET status = 'awaiting_confirmation'` 并写入 `pending_work_mode_dispatches`。批准后 `release_pending_work_mode_dispatch` 将同一 Run 恢复为 `queued`；拒绝后 `reject_pending_work_mode_dispatch` 将其改为 `cancelled`，错误码为 `work_mode.declined`。待确认期间不派发 Runtime，刷新或重启不会自动批准。
- 这条生命周期在 `pending_work_mode_dispatch_survives_restart_and_resolves_the_same_run` 等测试源码中有覆盖；2026-10-26 仅核对源码，未执行测试。
- 中断码（`runs.error_code`）常见值：`runtime.application_restarted`（启动修复 Legacy 路径遗留 Run）、`runtime.application_exit`（Fox 退出）、`runtime.process_crashed`、`agent_backend_host_restarted`、`agent_backend_session_closed`。

Kernel Authoritative 是默认执行路径（未设置 `FOX_KERNEL_MODE` 时）。Kernel 另有 `kernel_runs.state`（无 CHECK），包括 `waiting_approval`、`approval_expired`、`budget_exhausted`、`cancelling` 等，应按 Kernel Snapshot 读取，不从事件文案猜测。批次交付的 `leased` 表示外部请求可能已经发送，不等于模型响应已完成；失联或响应落库失败保留不确定事实，禁止自动重播。

## 审批状态

`approvals.status`：`pending`、`approved`、`denied`、`cancelled`、`expired`（迁移 1 的 CHECK）。只有 `pending` 可以转为其他状态。未决审批在 Run 离开运行状态时按下表结束（`database/repositories.rs`）：

| 触发 | 结果 | `decision_json.reason` |
| --- | --- | --- |
| 用户取消 Run（`mark_run_cancelling`） | `cancelled` | `run_cancellation_requested` |
| Run 以 `cancelled` 结束 | `cancelled` | `run_cancelled` |
| Run 中断，中断码为 `agent_backend_session_closed`（会话关闭、归档或移入回收站） | `cancelled` | `conversation_closed` |
| Run 中断，中断码为 `agent_backend_host_restarted` 或 `runtime.application_exit`（Fox 退出 / 重启） | `cancelled` | `app_restarted` |
| Run 以其他中断码中断（如 Runtime 崩溃） | `expired` | `run_interrupted` |
| Run 以 `completed` / `failed` 结束 | `expired` | `run_completed` / `run_failed` |
| 启动修复 Legacy 路径遗留 Run（`repair_interrupted_runs`） | `expired` | `application_restarted` |
| 同一会话开始新 Run | `expired` | `new_run_started` |
| Kernel Authoritative 路径：所属工作已结算或 Tool Call 已终结 | `expired` | `owner_settled`（`kernel_projection.rs`） |

依据：`approval_cancel_reason_for_interruption`、`end_pending_approvals_for_interrupted_run`、`cancel_pending_approvals_for_run`、`expire_pending_approvals_for_run`（`database/repositories.rs`），代码注释注明「会话关闭 / Fox 退出」改为 `cancelled` 是 2026-10-20 的用户决定。Kernel 侧的 `kernel_approvals.state` 另有 `expired`，在会话权限策略变更时由触发器写入。

审批等待使用已落库请求时间与冻结预算的绝对截止时刻，重新进入等待不会刷新时限；过期批准不得领取执行或新增会话授权。

## 消息与工具状态

消息从 `sending` / `streaming` 到 `completed`，Run 失败或中断时投影为 `failed` / `interrupted`。Tool Call 常见为 `pending`、`running`、`completed`、`failed`、`interrupted`、`cancelled`、`denied`、`expired`。

## Runtime Host 状态

`RuntimeStatus.state` 是诊断字符串，常见为未初始化、ready、busy、unavailable/error。业务判断优先使用 `available`、`activeRunId` 和数据库 Run 状态，不要把展示字符串写成强枚举。

## 重试规则

- 参数、权限、认证和不支持能力通常不可自动重试。
- 网络瞬断、远端 5xx、Runtime 进程崩溃可有限重试，并保留退避和次数（Kernel 默认供应商与轮次各最多 5 次）。
- 写入、命令、MCP 等有副作用操作不得盲目自动重放。
- 事件投影失败先从 Run 快照 / 数据库恢复，不能重复追加文本。

## 诊断要求

错误记录应包含 code、run/conversation/tool 标识、阶段和脱敏上下文。`runtime_diagnostics` 提供协议、版本、stderr tail（最多 80 行）、Session 数和恢复次数；`diagnostics_export` 导出支持包，禁止包含 API Key 和 Token。

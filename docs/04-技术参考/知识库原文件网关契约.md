# 知识库原文件网关契约

> 状态：生效<br>
> 适用版本：Fox `0.1.x`<br>
> 维护范围：知识库远程原文件预览与下载接口<br>
> 最后更新：2026-07-29

## 目标与边界

本文定义 Fox 预览和下载远程原文件时，知识库服务必须提供的后端契约。

知识库服务负责 MinIO 对象定位、用户鉴权、源文件版本身份和字节流传输。Fox 不接收 MinIO 凭据、Bucket 名称、内部对象键或服务器文件路径。

当前契约只要求经过身份验证的原文件网关。Office 服务端转换和派生预览任务已经退役，不属于本契约。

## 接口

知识库服务应提供或扩展以下接口：

```text
HEAD /api/workspace/knowledge/download?kb_id={kb_id}&file_id={file_id}&variant=original
GET  /api/workspace/knowledge/download?kb_id={kb_id}&file_id={file_id}&variant=original
```

每次请求都必须验证当前用户身份，并确认用户同时具有目标知识库和目标文件的访问权限。

## HEAD 响应

必须返回：

```text
Content-Length: {原始对象字节长度}
Content-Type: {原始媒体类型}
Accept-Ranges: bytes
X-Source-Revision: {稳定且不透明的版本标识}
X-File-Name: {UTF-8 原始文件名}
```

建议返回：

```text
ETag: {不透明的对象 ETag}
Last-Modified: {HTTP 日期}
X-Version-Id: {存在时返回 MinIO versionId}
Content-Disposition: attachment; filename*=UTF-8''...
```

Fox 只使用 `X-Source-Revision` 判断源文件版本，不会自行组合 ETag、文件大小或最后修改时间。

版本标识建议按以下优先级生成：

1. 不可变的 MinIO `versionId`。
2. 上传、同步或首次流式读取时持久化的内容 SHA-256。
3. 在 SHA-256 尚未持久化前，由知识库服务基于不透明 ETag、大小和最后修改时间生成的临时兼容版本。

Multipart ETag 必须被视为不透明值，不得当作 MD5 使用。

## Range 响应

Fox 每次请求一个字节范围：

```text
Range: bytes={start}-{end}
If-Range: {X-Source-Revision 的值}
```

合法请求必须返回：

```text
HTTP/1.1 206 Partial Content
Content-Length: {end - start + 1}
Content-Range: bytes {start}-{end}/{完整长度}
Accept-Ranges: bytes
```

响应体必须只包含请求范围内的精确字节。存在 `Range` Header 时，服务不得静默返回 `200` 和完整文件。

如果 `If-Range` 中的版本与当前源文件不一致，请求必须明确失败，不能把不同版本的字节拼接为同一个响应。建议返回稳定的 `409` 或 `412`，并包含机器可读错误码。

非法或无法满足的范围应返回：

```text
HTTP/1.1 416 Range Not Satisfiable
Content-Range: bytes */{完整长度}
```

## 流式传输要求

- 将 MinIO 字节流直接传入 HTTP Response，不得先把完整对象读入应用内存。
- 使用有界缓冲与背压。
- 客户端断开连接后及时停止上游 MinIO 读取。
- 保留原始字节长度和媒体类型。
- 不得通过 JSON 或 Base64 封装二进制内容。
- 本机 HTTP 与远程 HTTPS 部署必须使用同一契约，不要求 Fox 与知识库服务共享文件系统。

## 安全要求

- 每次 HEAD、完整 GET 和 Range GET 都重新执行权限校验。
- `file_id` 必须属于请求中的 `kb_id`。
- 不得暴露 Bucket、对象键、文件路径、MinIO 凭据或不受限制的预签名 URL。
- 清理响应文件名，并使用 RFC 5987 `filename*` 编码非 ASCII 文件名。
- 日志可以记录用户、知识库、文件、操作、结果、字节数和耗时，但不能记录文件内容或凭据。
- 根据部署环境限制请求频率、响应大小和超时时间。

## 错误语义

错误响应应具有稳定的 HTTP 状态和机器可读错误码，至少覆盖：

| 场景 | 建议状态 |
| --- | --- |
| 未登录或身份失效 | `401` |
| 无知识库或文件权限 | `403` |
| 文件、对象或知识库不存在 | `404` |
| 源文件版本不匹配 | `409` 或 `412` |
| Range 非法或越界 | `416` |
| 上游对象存储暂时不可用 | `502` 或 `503` |

错误信息不得包含内部对象路径和凭据。

## 验收测试

1. 授权用户可以 HEAD 并下载 DOCX、XLSX、PDF、图片和中文文件名文件，大小及字节与原件完全一致。
2. 未授权用户无法通过修改 `kb_id` 或 `file_id` 访问对象。
3. `bytes=0-1023`、中间范围、末尾不足范围和单字节范围均返回精确的 `206`。
4. 反向、溢出、越界和格式错误的 Range 返回稳定错误，不返回完整对象。
5. 过期 `If-Range` 被拒绝，响应中不会混入不同版本数据。
6. 大文件使用有界后端内存完成流式传输。
7. 客户端取消后，上游 MinIO 读取能够停止。
8. 本机 HTTP 与远程 HTTPS 的契约行为一致。
9. 对象缺失和知识库删除返回稳定、机器可读的错误。
10. 同一文件的并行 Range 请求互不污染，也不会修改源文件。

## Fox 侧使用原则

- Fox 先通过 HEAD 获取版本、长度、文件名和 Range 能力。
- 缓存身份必须包含知识库、文件和 `X-Source-Revision`。
- Range 数据到达后验证长度和 `Content-Range`，不接受静默降级的完整响应。
- 版本变化时废弃旧缓存，不继续拼接旧分片。
- 下载凭据和内部地址不写入前端可见状态。

## 已退役能力

以下能力不再作为知识库后端要求：

- LibreOffice 转换 Worker。
- 服务端 Office 转换或派生 PDF 预览任务。
- Preview Job 去重和 Renderer 版本缓存键。
- 依赖派生 PDF 的引用页码补充流程。

退役原因与兼容处理见 [知识库版式转换退役记录](../归档/知识库后端/知识库版式转换退役记录.md)。

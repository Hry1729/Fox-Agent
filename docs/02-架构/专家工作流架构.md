# 专家工作流架构

> 状态：生效
> 适用版本：Fox `0.1.x`
> 维护范围：专家 Workflow、Stage、Gate、恢复与证据
> 最后更新：2026-08-24
> 数据库 Schema：v30
> 包 Schema：`.foxexpert` v2 / Workflow v1

## 定位

专家 Workflow 是能力包携带的声明式状态机，不是第二套任务系统。每个 Workflow Run 原子创建或复用一个空的 `host:work-mode-gate` Goal，每个 Stage 映射一个 `work_tasks` Task，Stage 完成仍要求 `task_evidence` 中存在 Host 校验为 `valid` 的证据。SQLite 保存检查点，Runtime 只提出并执行下一步。

该语义复用 LangGraph 的持久检查点与中断恢复做法，以及 Dify 的节点输出类型、有限重试和失败分支做法；Fox 保留自己的 Goal/Task/Evidence 与 Host 权限边界。

## 声明契约

包 Schema v2 的 `workflow` 包含：

- 稳定 `id`、SemVer `version`、标题和说明；
- `inputSchema` 与最终 `outputSchema`；
- 1-20 个有序 Stage；
- 每个 Stage 的指令、输出 Schema、验收条件、停止条件、`none/user_approval` Gate；
- 每 Stage 1-5 次的硬重试上限。

所有 JSON Schema 使用 Rust `jsonschema` 校验器编译。单 Schema 最大 32 KiB，禁止外部 `$ref`，只允许本包内 `#...` 引用，避免安装或运行时的网络解析与供应链漂移。

## 状态与检查点

`expert_workflow_runs` 保存冻结的 Workflow JSON、专家绑定、包 Hash、输入、最终输出和当前 Stage；`expert_workflow_stage_runs` 保存 Stage/Task 映射、尝试次数、阶段输出和错误；`expert_workflow_gate_decisions` 保存每次 Gate 的请求与用户决策。

```text
pending -> awaiting_gate -> queued -> running -> completed
                                  \-> queued (未耗尽重试)
                                  \-> failed (重试耗尽)
awaiting_gate --rejected--> cancelled
```

启动、Gate、Stage 开始、Stage 完成、失败重试、取消和最终 Goal 收口均在 SQLite 事务内执行。应用重启后通过 active Workflow Snapshot 恢复；既有会话绑定继续使用冻结的专家包快照，升级能力包不会改写运行中的定义。

## Runtime 与 UI

Runtime 提供六个 Host 工具：`workflow_snapshot_get`、`workflow_start`、`workflow_stage_start`、`workflow_stage_complete`、`workflow_stage_fail`、`workflow_cancel`。会话身份和 owner Run 由 Host 注入，模型不能指定其他会话或扩大工具权限。

桌面端在 Goal 卡中显示 Workflow 版本、当前 Stage、尝试预算和待处理 Gate。Gate 决策写入 Host 后，下一次会话加载从持久检查点继续。

## 失败边界

- 输入、Stage 输出或最终输出不满足 Schema 时不推进检查点。
- Stage 无有效 Evidence 时不能完成。
- 同一会话只能有一个 active Workflow；已有非空或非 Host 占位 Goal 时拒绝启动。
- Gate 拒绝或用户取消会终止 Workflow，并将未完成 Task 收口为终态。
- 重试耗尽后 Workflow 失败、Goal 进入 `blocked`，错误原因持久化。

## 验证

自动化覆盖包 v1/v2 兼容、Schema 与外部引用拒绝、输出校验、空 Host Goal 复用、Gate、重启恢复、阶段检查点、Evidence、有限重试和最终 Goal 完成/阻塞。

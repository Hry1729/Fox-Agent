# Fox 单 Pi 主线与 SDK 原型 · 接入契约（冻结版 2026-10-27）

本文件是执行方案第四节的落地版本，由集成人员冻结。各开发单元在并行编码前以本文件为准；改变任何一条含义都必须先说明数据库、冻结绑定、恢复与历史兼容的影响，并由集成人员统一修改。

基线：`main` = `0285c758a399047dcb7eac23d7c5f20342c8118e`，多驱动保留分支 `archive/multi-agent-20261027` 指向同一提交。执行分支由集成人员创建，未推送远端。

## 一 驱动标识与"单一受支持路径"

| 概念 | 取值 | 谁能写 |
| --- | --- | --- |
| 会话表 `conversations.agent_backend` | `fox` / `pi` / `codex` / `deepseek` | 只在创建时写入一次，之后不可变（v95 触发器） |
| Kernel 模型引擎 `engine_id` | `pi` / `codex` / `deepseek_harness` | 每次 Run 冻结（`kernel_runs.engine_id`） |
| 产品界面上的驱动名 | `Pi` | 显示层文案，不等于存储标识 |

冻结决定：

1. **新会话一律写入 `agent_backend = 'fox'`。** 该值不是"驱动名称"，它是 Fox 内置路由的存储标识；这条内置路由在本版本内固定使用 Pi SDK 与 `engine_id = 'pi'`。不允许把 `fox` 全量替换成 `pi`：`agent_backend = 'pi'` 历史上表示另一条外部 Pi ACP 路径，替换会把新会话送到旧 ACP 实现。
2. **`pi` / `codex` / `deepseek` 在本构建中退休（retired）。** 三条外部驱动不再能被环境变量、存量偏好、直接 IPC 或界面重新启用。退休不等于删除数据：历史记录保留原值、原冻结标识，可读、可显示。
3. 退休驱动的执行入口一律返回明确拒绝，**不静默换驱动执行**。拒绝码：
   - 新会话请求退休驱动：`agent_backend_retired`
   - 已有会话（冻结为退休驱动）请求启动/取消/审批：`agent_backend_retired`（会话只读）
   - 请求里出现未知值：`agent_backend_invalid`（保持不变）
   - 错投（请求指定了与会话不同的后端）：`agent_backend_misrouted`（保持不变）
4. `FOX_EXTERNAL_BACKENDS` 不再有任何放宽能力。它仍被解析以便识别旧部署的取值，但对退休驱动恒为"关闭"；未知条目仍单独报告，绝不当作"全部打开"。
5. `FOX_KERNEL_ENGINE` 只接受 `pi`。`codex` / `deepseek_harness` 返回 `kernel_engine_retired`，退出码非 0，不回落到另一个模型适配器。未设置时默认 `pi`。
6. **Yuxi 远程知识库与远程专家明确保留（2026-10-27 确认）。** `agents.runtime_type = 'yuxi'` 的远程运行时、远程资料连接和这些专家的会话都属于受支持能力，不属于本次退休范围。退休只针对会话级外部驱动（`pi` / `codex` / `deepseek`）。Yuxi 会话的 `agent_backend` 仍是 `fox`，因此照常运行；不得因为"单 Pi 主线"关闭远程知识库或远程专家。唯一的约束仍然是方案第一节那句：另一套**本地** Agent 执行循环不能成为旁路——Yuxi 是远程服务，不是本地旁路。
7. 旧数据识别能力保留：`AgentBackend::parse`、`legacy.rs` 的 run 级映射、数据库 CHECK 约束、`engine_id` 枚举与反序列化都不改。"可读"不等于"可运行"。

## 二 状态归属（不可交叉覆盖）

| 状态 | 唯一负责人 |
| --- | --- |
| 模型消息、工具调用上下文、压缩记录、活动分支 | Pi `SessionManager`（阶段二原型会话） |
| 专家身份、专家与固定聊天关系、资料绑定 | Fox 数据库 |
| 聊天展示记录、引用、文件结果、业务状态 | Fox 数据库与既有存储 |
| 工具准入、资料权限、取消、执行结果 | 既有 Fox Host 工具路径 |
| 一轮内继续生成、工具调用与后续生成 | Pi SDK 会话 |

Fox 可以保存 Pi 事件的展示副本；**展示副本不得在每次发送时反向覆盖 Pi 已压缩的上下文**。旧 SQLite 历史只用于有明确条件的首次导入或恢复。

## 三 会话映射字段（阶段二原型，先冻结形状）

复用 `runtime_sessions`。已经足以承载的字段直接复用，缺失的按增量迁移补齐。至少能可靠关联：

| 需要关联的东西 | 现有承载 | 结论 |
| --- | --- | --- |
| Fox conversation ID | `runtime_sessions.conversation_id` | 复用 |
| Fox runtime session ID | `runtime_sessions.id` | 复用 |
| 专家身份 / 绑定版本 | 专家绑定字段 | 复用，原型内固定 |
| Pi session ID | `native_session_ref`（新增，允许 NULL） | 新增字段 |
| Pi 受控会话文件路径 | `native_session_path`（新增，允许 NULL） | 新增字段，Host 决定或校验 |
| 存储格式版本 | `format_version`（新增，默认 1 = 旧 Fox JSON） | 新增字段；2 = Pi 原生 JSONL |
| 上下文代次 | `context_generation`（新增，默认 1） | 新增字段，区分重置前后 |

约束：

- 会话文件必须位于 Fox 管理的用户数据目录；**路径由 Host 决定或校验，不接受模型或调用方指定任意恢复路径**。
- 凭据不写入会话映射、日志、测试快照、上下文。
- Host 与文件系统之间不存在跨系统事务，必须定义成功顺序与失败补偿：先落文件、再提交数据库映射；反向顺序会产生"数据库说可恢复、实际文件不存在"的记录。
- 只有 C 修改迁移与 schema version，其他工作包提交需求。

## 四 执行权与原型入口

- 同一个聊天同一时刻只有一个有效写入者；复用 Host 现有运行准入与锁，不新增分布式锁。
- 原型的同一次运行只能由 Pi SDK 推进模型循环；不得再由 Kernel coordinator 推进同一工具批次。
- 原型入口只控制**新原型会话**，不改变现有运行的冻结 authority。仅设置 `FOX_KERNEL_MODE=legacy` 跑通旧聊天**不算**完成原型。
- 本次不引入第三套通用 authority 框架。

## 五 工具边界

- 原型只注册完成目标需要的 Fox 工具：`list_knowledge_bases`、`search_knowledge`、`read_knowledge_document`，全部经 Host bridge 执行。
- 显式排除未经 Host 授权的 Pi 默认文件、Shell、网络工具；不得为了"能跑"把 `noExtensions` / `noSkills` 打开去加载用户全局目录。
- 隐藏工具 ≠ 授权。执行端必须独立校验 `conversation` / 专家绑定 / `knowledgeBaseId` / `documentId`。

## 六 测试规格（新增/修改的断言）

单一驱动准入（`crates/fox-agent-backend` `host_routing`）：

1. 新会话在 `FOX_EXTERNAL_BACKENDS` 为 `all`、`pi,codex`、`1` 等任何取值下都只能得到 `fox`。
2. 请求 `pi` / `codex` / `deepseek` 得到 `agent_backend_retired`，不是静默改成 `fox`。
3. 冻结为退休驱动的历史会话：`session_access` = 只读，`route` 在任何入口都拒绝，历史值原样读回。
4. 错投、未知值、查找失败的错误码与消息不变。
5. 迁移 SQL 仍然只做增量；不改写历史行。

单一引擎（`fox-desktop` `kernel_model_config`）：

6. `FOX_KERNEL_ENGINE` 未设置或为 `pi` → `pi`。
7. 为 `codex` / `deepseek_harness` → 拒绝，错误文本包含 `kernel_engine_retired`。
8. 旧 `engine_id` 记录仍可反序列化读取。

界面收敛（`apps/desktop`）：

9. 新会话不再渲染四驱动选择；只有一个选项时不渲染没有选择意义的交互。
10. 历史 Codex / DeepSeek / Pi 会话显示原绑定与只读状态，不被改标为 Pi。
11. 模型供应商选择保持可用。

> 状态：生效
> 适用版本：Fox `0.1.x`
> 维护范围：Supervisor Team、Member Child Run、预算与取消
> 最后更新：2026-10-28（单 Pi 分支同步；本轮未复跑产品测试）
> 数据库 Schema：当前 v98（`expert_team_runs` 由 v31 引入）
> 包格式：`.foxexpert` Schema v3 / Team Schema v1

> 适用范围（2026-10-28）：本文的 Host 能力对应受支持的 `fox` 会话。本地驱动为 Pi；旧外部后端只读，Yuxi 远程能力保留。驱动和阶段状态见[单 Pi 主线状态](../01-项目概览/单Pi主线状态.md)。下文专项合同及历史测试证据沿用各自注明的时间，本轮不扩展验收结论。

## 采用的编排模型

Fox 采用 Supervisor/Manager 模式：当前主 Run 是 Lead，保留用户上下文和最终决策；每个 Member 是一个真实 A5 Child Run，而不是在主 Prompt 中扮演多个角色。首版严格串行，一名 Member 终止后才允许启动下一名；并行、mailbox 和共享任务领取不在 E3 v1 的语义内。

设计参考：

- [OpenAI Agents SDK manager / agents-as-tools](https://github.com/openai/openai-agents-python/blob/main/docs/agents.md)：Manager 保留控制权，专家在受限子执行中返回结果。
- [LangGraph supervisor](https://github.com/langchain-ai/langgraph-supervisor-py)：Supervisor 负责路由和上下文控制，Worker 不共享完整主状态。
- [LangGraph Send](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/workflows-agents.mdx)：Worker 使用独立状态并向上聚合结果。
- [AutoGen BaseGroupChat save/load](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_base_group_chat.py)：团队状态必须可保存、恢复和取消。

这些项目只提供已验证的编排语义。Fox 不引入第二套 Python/图 Runtime，持久化、权限、预算与取消仍由 Tauri Host 和 SQLite 负责。

## 包契约

Schema v3 包可增加严格的 `team`：

```json
{
  "schemaVersion": 3,
  "resources": {
    "tools": [
      "team_snapshot_get", "team_start", "team_member_start",
      "team_collect", "team_cancel", "read", "grep"
    ]
  },
  "team": {
    "schemaVersion": 1,
    "id": "delivery.review-team",
    "version": "1.0.0",
    "title": "交付审查团队",
    "strategy": "supervisor",
    "members": [{
      "id": "reviewer",
      "name": "Reviewer",
      "agentId": "fox-general",
      "role": "独立审查",
      "instructions": "检查 Lead 指定的交付并返回证据。",
      "allowedTools": ["read", "grep"],
      "budget": {
        "maxDurationMs": 60000,
        "maxTotalTokens": 8000,
        "maxOutputTokens": 2000,
        "maxToolCalls": 10
      }
    }]
  }
}
```

安装时（`apps/desktop/src-tauri/src/expert_teams.rs::parse_team` 与 `expert_packages.rs`）校验：

- Team `schemaVersion` 必须为 1，包 `schemaVersion` 必须 ≥ 3；
- `version` 为 SemVer，`strategy` 只能是 `supervisor`；
- 1–8 个唯一 Member，`agentId` 只校验 ID 格式；
- Member 工具必须是 Fox 已知工具，且属于包 `resources.tools` 声明范围；包必须声明全部 5 个 Team 工具；
- 预算在 Host Child Run 上限内：时长 1 秒–15 分钟、总 Token 256–200,000、输出 Token 64–32,768 且不超过总 Token、工具调用 0–100。

Member 禁止再次获得 Child Run 或 Team 委派工具，A5 深度上限（`MAX_CHILD_DEPTH = 1`）继续提供第二道防线。

Member 的 Agent 是否存在在安装时不检查，而是在 `team_member_start` 创建 Child Run 时检查：`create_child_run` 只接受 `agents` 中存在、`runtime_type='pi'` 且 `agent_kind` 为 assistant / expert / worker 的 Agent，否则启动失败。

## 状态与执行

`expert_team_runs` 冻结绑定 ID、包 Hash、Team 定义、Lead Run、目标、显式上下文和聚合结果。`child_run_delegations` 增加 `team_run_id/team_member_id/allowed_tools_json`，成员身份与 Child Run 一一对应。

执行顺序（实现在 `runtime_host/mod.rs`；原 Kernel 路径的 `kernel_delegation.rs` 已在 B1 删除，成员 Run 一律走 PiNative）：

1. `team_start` 验证当前冻结专家快照并持久化 Team Run。
2. `team_member_start` 从冻结 Team 读取 Agent、角色、指令、工具和预算，创建独立 Conversation/Run/Runtime。同一成员不能启动两次；仓储层要求同一 Team 没有 queued / running 成员才能启动下一个（串行）。成员输出 Token 预算不能超过冻结的模型最大输出。Kernel 路径把 Child 启动登记为 Host Action，在当前工具结算后再启动 Child Runtime。
3. Host 将父级工具 Scope 与 Member `allowedTools` 取交集；Runtime 目录裁剪后，preflight 与 execute 仍分别强制检查。
4. `team_collect` 返回有界结果与 token/tool 使用量；全部声明 Member 终止后才生成最终聚合并结束 Team。
5. `team_cancel` 或父 Run 取消会先传播到活跃 Child Runtime，再终止 Team 状态。

SQLite 是唯一事实源。应用重启后 Team、成员身份、预算、状态与已回传结果可恢复；Runtime Session 只负责继续执行，不保存产品真相。

## 专家行缺失时的启动修复

`agents` 行可能在 Fox 之外被删除（例如用 `sqlite3` 命令行删除，命令行默认 `foreign_keys=OFF`，不会级联）。`Database::open` 在写入内置 Agent 和内置库专家之后调用 `Database::repair_missing_agent_references`（`apps/desktop/src-tauri/src/database/repositories.rs`）。与 Team 相关的行为：

- 内置库（bundled）专家的行先由 `seed_bundled_experts` 按随包目录重建，Team 定义随包恢复。
- 本机专家不会恢复：引用它的会话改回 `fox-general`，它的 active 绑定改为 `removed`，所以这些会话不再有可用的 Team 快照。
- `expert_team_runs` 和 `child_run_delegations` 等历史运行记录不改动，保留原 Agent ID。
- 冻结 Team 里某个 Member 的 `agentId` 指向已删除的 Agent 时，该成员在启动时失败（见上文 Agent 检查）；修复步骤不改写冻结 Team。

迁移结束时的外键检查对父表为 `agents` 的孤立引用放行，交给这一步处理；其他外键问题仍会中止启动，并给出中文可读错误。

## 首版边界与验收

- 串行 Supervisor，不宣称支持并行协商、mailbox 或共享任务抢占。
- Member 只看到冻结角色说明、Lead 目标和显式传入的有界 Context，不继承主对话全文。
- 自动化覆盖包 Schema、嵌套委派拒绝、串行约束、成员 Scope、预算、结果聚合、数据库重开恢复和 Runtime 工具目录一致性（`expert_teams.rs`、`database/repositories/expert_teams.rs` 中的单元测试）。专家行缺失的启动修复由 `database/repositories/bundled_capabilities.rs` 的 `missing_agent_row_tests` 覆盖；这些测试不专门构造 Team 场景。

桌面工作进度卡展示 Team 版本、成员回传数、当前成员和状态，并允许用户停止活跃团队。

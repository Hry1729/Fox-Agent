# 专家团队架构

> 状态：生效
> 适用版本：Fox `0.1.x`
> 维护范围：Supervisor Team、Member Child Run、预算与取消
> 最后更新：2026-08-24
> 数据库 Schema：v31
> 包格式：`.foxexpert` Schema v3 / Team Schema v1

## 采用的编排模型

Fox 采用 Supervisor/Manager 模式：当前主 Run 是 Lead，保留用户上下文和最终决策；每个 Member 是一个真实 A5 Child Run，而不是在主 Prompt 中扮演多个角色。首版严格串行，一名 Member 终止后才允许启动下一名；并行、mailbox 和共享任务领取不在 E3 v1 的语义内。

设计参考：

- [OpenAI Agents SDK manager / agents-as-tools](https://github.com/openai/openai-agents-python/blob/main/docs/agents.md)：Manager 保留控制权，专家在受限子执行中返回结果。
- [LangGraph supervisor](https://github.com/langchain-ai/langgraph-supervisor-py)：Supervisor 负责路由和上下文控制，Worker 不共享完整主状态。
- [LangGraph Send](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/workflows-agents.mdx)：Worker 使用独立状态并向上聚合结果。
- [AutoGen BaseGroupChat save/load](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_base_group_chat.py)：团队状态必须可保存、恢复和取消。

这些项目只提供已验证的编排语义。Fox 不引入第二套 Python/图 Runtime，持久化、权限、预算与取消仍由 Tauri Host 和 SQLite 负责。

## 包契约

Schema v3 包可增加严格的 `team`：

```json
{
  "schemaVersion": 3,
  "resources": {
    "tools": [
      "team_snapshot_get", "team_start", "team_member_start",
      "team_collect", "team_cancel", "read", "grep"
    ]
  },
  "team": {
    "schemaVersion": 1,
    "id": "delivery.review-team",
    "version": "1.0.0",
    "title": "交付审查团队",
    "strategy": "supervisor",
    "members": [{
      "id": "reviewer",
      "name": "Reviewer",
      "agentId": "fox-general",
      "role": "独立审查",
      "instructions": "检查 Lead 指定的交付并返回证据。",
      "allowedTools": ["read", "grep"],
      "budget": {
        "maxDurationMs": 60000,
        "maxTotalTokens": 8000,
        "maxOutputTokens": 2000,
        "maxToolCalls": 10
      }
    }]
  }
}
```

安装时校验 SemVer、1–8 个唯一 Member、Agent 是否存在、工具是否为 Fox 已知工具、Member 工具是否属于包声明范围，以及预算是否在 A5 Host 上限内。Member 禁止再次获得 Child Run 或 Team 委派工具，A5 深度上限继续提供第二道防线。

## 状态与执行

`expert_team_runs` 冻结绑定 ID、包 Hash、Team 定义、Lead Run、目标、显式上下文和聚合结果。`child_run_delegations` 增加 `team_run_id/team_member_id/allowed_tools_json`，成员身份与 Child Run 一一对应。

执行顺序：

1. `team_start` 验证当前冻结专家快照并持久化 Team Run。
2. `team_member_start` 从冻结 Team 读取 Agent、角色、指令、工具和预算，创建独立 Conversation/Run/Runtime。
3. Host 将父级工具 Scope 与 Member `allowedTools` 取交集；Runtime 目录裁剪后，preflight 与 execute 仍分别强制检查。
4. `team_collect` 返回有界结果与 token/tool 使用量；全部声明 Member 终止后才生成最终聚合并结束 Team。
5. `team_cancel` 或父 Run 取消会先传播到活跃 Child Runtime，再终止 Team 状态。

SQLite 是唯一事实源。应用重启后 Team、成员身份、预算、状态与已回传结果可恢复；Runtime Session 只负责继续执行，不保存产品真相。

## 首版边界与验收

- 串行 Supervisor，不宣称支持并行协商、mailbox 或共享任务抢占。
- Member 只看到冻结角色说明、Lead 目标和显式传入的有界 Context，不继承主对话全文。
- 自动化覆盖包 Schema、嵌套委派拒绝、串行约束、成员 Scope、预算、结果聚合、数据库重开恢复和 Runtime 工具目录一致性。

桌面工作进度卡展示 Team 版本、成员回传数、当前成员和状态，并允许用户停止活跃团队。

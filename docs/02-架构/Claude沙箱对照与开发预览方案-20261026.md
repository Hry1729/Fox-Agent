# Claude 沙箱对照与 Fox 开发预览方案

核对日期：2026-10-26。Fox 基线为 `ed580473`，本轮改动位于 `fix/sandbox-onboarding-20261026`。结论：Fox 缺少网络权限协商和开发预览流程。继续追加固定地址，不能覆盖完整开发任务。

## 已核对的差异

Claude Code 官方文档把沙箱边界放在 Shell 命令及其子进程；文件工具、Web 工具、MCP 和 hooks 不在这层边界内。新域名可触发授权，授权可只用于当前会话，也可保存。部分模式支持给单条命令附加允许访问的主机。不兼容命令有单次沙箱外重试入口。[Claude Code 沙箱文档](https://code.claude.com/docs/en/sandboxing)

Fox 当前对整个外部 ACP Agent 进程套用沙箱，模型请求、原生配置、Shell 和子进程因此共用这层边界。启动通过普通 srt CLI，写入固定设置；没有连接网络请求回调或运行中的配置更新通道。依据：`crates/fox-agent-backend/src/sandbox.rs` 的 `SrtLauncher`、`to_srt_settings`，以及安装包中 srt 0.0.80 的 `dist/cli.js` 与 `sandbox-manager.js`。

srt 库本身接受网络授权回调；没有回调且不匹配规则时拒绝连接。CLI 还提供 `--control-fd`，可让 Host 更新网络规则。[授权实现](https://github.com/anthropics/sandbox-runtime/blob/main/src/sandbox/sandbox-manager.ts)、[CLI 更新通道](https://github.com/anthropics/sandbox-runtime/blob/main/src/cli.ts)

平台不能混为一谈：本次读取的 Claude Code 官方文档仍注明原生 Windows 不启用该 Bash 沙箱；独立 srt 项目的 Windows 支持是 alpha。Fox 安装包固定为 srt 0.0.80；上游 main 的版本为 0.0.81。新版 Windows 的 `--allow-loopback` 会开放所有本机回环端口，不能用它实现“仅开放当前项目的一个预览端口”。[srt Windows 说明](https://github.com/anthropics/sandbox-runtime#local-servers-on-windows)

## Windows 实测

脚本：`scripts/test-sandbox-local-preview.mjs`。使用本机已安装的 Fox runtime 0.1.3 / srt 0.0.80。测试申请空闲端口，不占用用户的 8080；本次为 53160，相邻测试端口为 53161。没有修改全局网络安装设置。

| 场景 | 监听服务 | Host HTTP 访问 | 沙箱直接连接 | 沙箱经代理访问自身端口 | 经代理访问另一个端口 |
|---|---|---|---|---|---|
| 默认拒绝 | 成功 | 200 | EACCES | 403 | 403 |
| 精确授权 127.0.0.1:53160 | 成功 | 200 | EACCES | 200 | 403 |
| Host 回调仅批准 53160 | 成功 | 200 | EACCES | 200 | 403 |

证据：`.test-target/local-preview-1792992916905/results.json`。三个夹具进程均正常退出。早先两次夹具准备失败分别是没有指定库调用所需的 srt-win 路径，以及重复请求 Program Files 的 ACL 写权限；修正夹具后得到上表结果。

这验证了真实 Windows srt 的监听、HTTP 回访和精确授权。它没有验证完整 Fox 对话、浏览器渲染、Playwright 或 WebSocket。此前“allowLocalBinding=false 因而 Windows 服务不能启动”的判断不成立；0.0.80 的该选项只接到 macOS 路径，Windows 的主要限制在出站连接。

## 建议实施的完整流程

1. **Host 管理网络授权。** 为 srt 接入独立控制通道。网络请求携带会话、目标主机和端口，进入 Fox 审批；批准后更新当前代理并继续请求。重复请求合并，支持当前会话和当前项目的保存范围。拒绝、超时和通道断开都返回明确原因。
2. **Host 管理项目预览。** 登记当前项目启动的服务、进程和端口；校验确属本次任务后，开放对应回环端口。提供打开、停止、端口占用处理和会话结束清理。浏览器使用专用会话，由 Host 访问已登记地址。不要依赖 Agent 猜测系统浏览器路径。
3. **区分模型与开发网络需求。** 已确认模型端点随配置来源授权；依赖仓库、Git 服务等使用项目网络规则。新增域名仍走权限协商。不能把“仅放行模型 API”当作开发工作负载的完整网络策略。
4. **保留跨后端差异。** Pi 可以进一步接入工具级执行边界；其他 ACP 后端要先确认能否可靠拦截工具执行。不能直接把整套 Agent 移出沙箱，也不能向用户宣称已有统一的单命令提权能力。

交付条件应按任务验证：创建网页 → 安装依赖 → 启动服务 → Agent 访问 → 浏览器打开 → WebSocket 热更新 → 停止服务；同时验证未授权相邻端口仍不可访问、拒绝不会挂起、重启后授权范围正确、其他项目不能继承本次临时权限。还需分别验证 Pi 与 DeepSeek，不能用一项夹具成功替代全部后端验收。

## 本轮已完成的范围

- Pi 原生配置来源选择；已就绪状态也保留导入入口。
- 显示当前配置的供应商、模型和精确端点。
- 经确认后，新项目复用配置；源文件变化后重新确认。
- 模型无进展 120 秒、工具无进展 600 秒后明确失败并终止进程；待审批期间暂停计时。
- 加入先选项目、再多次切换 Agent、最后发送的回归。该路径保持项目绑定；用户报告的实际页面问题尚未复现。

上述改动不等于网络协商和开发预览流程已经实现。安装包验收与完整真实模型/UI 验收需要分别记录。

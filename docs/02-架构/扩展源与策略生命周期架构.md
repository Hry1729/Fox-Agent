# 扩展源与策略生命周期架构

> 状态：生效
> 适用版本：Fox 0.1.x
> 维护范围：stdio MCP、Streamable HTTP MCP、OpenAPI Connector、声明式 Lifecycle Hooks 与扩展健康状态
> 最后更新：2026-08-24

## 目标与复用结论

A6 把原有一次性 stdio MCP 升级为统一扩展源执行边界，并增加 OpenAPI 3.x 工具投影和声明式生命周期策略。实现参考以下开源项目的协议或设计语义：

- [Model Context Protocol Streamable HTTP 规范](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-03-26/basic/transports.mdx)：复用 POST JSON-RPC、JSON/SSE 双响应、`Mcp-Session-Id` 与协议版本协商语义。
- [MCP TypeScript SDK Client 文档](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/client.md)：参考长生命周期 Client/Transport 和关闭语义。
- [OpenAI Codex Hook Runtime](https://github.com/openai/codex/blob/main/codex-rs/core/src/hook_runtime.rs) 与 [Hook Schema](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/schema.rs)：参考明确生命周期边界和结构化结果；Fox 不开放命令或脚本 Hook。
- [Microsoft Kiota](https://github.com/microsoft/kiota)：参考 OpenAPI operation 到可调用客户端的映射边界。Fox 当前只需要受限运行时投影，因此没有引入完整代码生成器。

Fox 没有复制第三方源代码，也没有新增 Agent 框架或第二事实源。连接、策略、健康和审计仍由 Rust Host 与 SQLite 管理。

## 统一扩展源

`mcp_servers` 是兼容命名下的扩展源注册表，`transport` 决定执行适配器：

| transport | 配置 | 执行模型 |
| --- | --- | --- |
| `stdio` | `command`、`args`、Keyring 环境变量 | 一个源对应一个持久子进程与 MCP Session |
| `streamable_http` | `endpoint_url`、Keyring Header | 持久逻辑 Session；POST JSON-RPC，响应可为 JSON 或 SSE |
| `openapi` | OpenAPI JSON/YAML、可选 `endpoint_url` 覆盖、Keyring Header | 动态生成工具 Schema，调用固定服务基址下的 operation |

每个连接按“源配置 + 凭据摘要”生成指纹并进入进程内连接池。保存、启停、删除或凭据变化会使旧连接失效；应用退出统一关闭进程。同一源的请求串行化，避免 MCP request id、Session ID 或 stdio 流交叉。

## Streamable HTTP MCP

初始化、`tools/list` 和 `tools/call` 均使用 POST JSON-RPC。Host：

- 发送 `Accept: application/json, text/event-stream`；
- 保存服务端返回的 `Mcp-Session-Id`，后续请求带回；
- 初始化后发送 `notifications/initialized`，后续请求携带协商后的 `MCP-Protocol-Version`；
- 同时解析单 JSON、JSON-RPC batch 与 SSE `data:` 事件；
- 禁止 HTTP 重定向，15 秒超时，响应累计上限 10 MiB；
- 拒绝凭据覆盖 `content-type`、`accept`、Session 或协议版本等保留 Header。

Fox 没有实现已废弃的旧版“独立 GET SSE 端点”传输，也暂未实现 MCP OAuth、Resource 和 Prompt 协议。

## OpenAPI Connector

Host 接受最大 2 MiB 的 OpenAPI 3.x JSON/YAML。每个非 deprecated operation 通过 `operationId` 生成工具名；缺少 `operationId` 时由 method/path 生成确定性名称。Path、Query、Header 参数和 JSON request body 合并为顶层 object input schema。

首版安全与兼容边界：

- 只允许 HTTP/HTTPS；调用只能落在显式 `endpoint_url` 或规范 `servers[0].url` 的固定基址下；工具参数不能替换主机。
- 禁止重定向和 TRACE；单次请求 15 秒超时，响应上限 10 MiB。
- 只解析文档内 `$ref`；拒绝外部引用，并限制展开深度和工具总数 200。
- 支持 path/query/header 参数和 JSON request body；暂不支持 cookie、multipart、文件上传、callback、webhook 或任意认证脚本。
- 凭据只存 OS Keyring，诊断、数据库、审批详情和模型上下文不保存密钥值。

响应作为不可信结构化工具结果返回，非 2xx 状态保持可见但不被解释为执行成功。

## 声明式 Lifecycle Hooks

Hooks 保存在 `lifecycle_hooks`，支持四个事件：

| 事件 | 允许动作 | 触发位置 |
| --- | --- | --- |
| `before_run` | `annotate` | Host 分派 Primary/Child Run 前 |
| `before_tool` | `block`、`require_approval`、`annotate` | 所有 Host、工作、记忆、知识、附件、Child Run、MCP/OpenAPI 工具执行前 |
| `after_tool` | `annotate` | 工具结果返回时 |
| `after_run` | `annotate` | Run 进入完成、失败或取消终态时 |

Matcher 支持逗号或 `|` 分隔的精确名称，以及前缀、后缀、包含型 `*` 通配。Hook 按 `priority` 排序；`block` 默认拒绝，`require_approval` 强制本次调用进入审批且不复用会话持久授权，`annotate` 只附加策略说明。

每次命中写入 `lifecycle_hook_executions`。审计只保存 Hook、Run、Tool Call、结果和输入键名，不保存完整工具参数或用户正文。Fox 不加载任意 Hook 脚本，也不把 Runtime 或第三方扩展的生命周期回调直接透传到 Host。

## 健康状态

扩展源测试和真实 list/call 都更新统一健康字段：`status`、`last_error`、`last_checked_at`、`last_latency_ms`、`tool_count`、`consecutive_failures`。成功会清零连续失败数；失败递增并保留可诊断错误。健康状态用于设置页和诊断，不自动绕过审批或扩大权限。

## 权限与故障隔离

1. Runtime 只看见 Host 根据 Assistant、Expert、Child Agent scope 交集筛出的扩展工具。
2. `call_mcp_tool` 继续由 Host 审批；Hook 只能进一步阻断或要求审批，不能降低既有策略。
3. Schema 无效、未知工具、超限响应、协议错误或连接失败只隔离当前源，不阻止 Fox 启动。
4. stdio 子进程和 HTTP 输出均视为不可信；凭据不进入 Runtime Prompt。
5. 用户显式配置的本地或私网扩展地址允许访问，因此用户必须信任该源；Fox 不从工具参数接受临时 URL，也不跟随重定向。

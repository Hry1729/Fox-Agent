# Fox 总体架构

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：Fox 进程、领域边界、依赖方向和系统级数据流<br>
> 最后更新：2026-10-24

## 目标与范围

本文面向参与 Fox 开发的产品、前端、Rust、Runtime、知识库和测试工程师，说明桌面应用的系统边界、进程关系、领域拆分和故障隔离方式。字段级协议不在本文重复维护，详细入口见[架构文档导航](架构文档导航.md)。

四 Agent 改造已完成并合入 `main`：会话创建时绑定一个外层 Agent 后端，内置 Fox（默认，即 Kernel / FoxBackend）、DeepSeek Harness（dsh，实验）和 pi，三者都在同一个会话、审计和界面体系里；外部 Agent 经 ACP v1 接入。Codex 已实现但暂时隐藏；用户自行接入其他 ACP Agent 的「自定义 ACP Agent」通用入口是**待办 / 规划中**。细节见 [Agent Runtime 架构 · 外层 Agent 后端](Agent运行时架构.md#外层-agent-后端四-agent)。

A0-A6 与 E1-E4 首版已落地：完整工作闭环、会话生命周期、受治理 Memory、Span/Evaluation、独立 Child Run、持久 MCP/OpenAPI、声明式 Hooks、版本化专家包、Workflow、Supervisor Team 与数字同事均由 Host/SQLite 承接。

## 系统全景

```mermaid
flowchart LR
    U["用户"] --> UI["React 19 / Vite 前端"]
    UI -->|"Tauri invoke / event"| HOST["Rust Tauri Host"]
    HOST --> DB[("SQLite fox.db")]
    HOST --> FS["应用数据目录与授权项目"]
    HOST --> ROUTER{"Runtime Adapter"}
    ROUTER -->|"pi"| PI["Node.js Pi Runtime Sidecar"]
    ROUTER -->|"yuxi"| YRUN["远程 Agent Runtime"]
    PI --> MODEL["模型 Provider"]
    PI -->|"Host Tool 请求"| HOST
    YRUN --> KB["知识库服务 / Yuxi"]
    HOST -->|"HTTPS + Bearer Token"| KB
    HOST -->|"stdio / HTTP JSON-RPC"| MCP["MCP Server"]
    HOST -->|"HTTP"| OPENAPI["OpenAPI Source"]
    HOST --> KEY["系统 Keyring"]
    HOST -->|"ACP v1（srt 沙箱）"| EXT["外部 Agent：dsh / pi（Codex 隐藏）"]
    EXT --> MODEL
```

上图的 `Runtime Adapter` 分支只服务外层后端为 `fox` 的会话。Fox 会话默认由 Kernel / Authoritative 执行（`FOX_KERNEL_MODE` 未设置即是）；`FOX_KERNEL_MODE=legacy` 只用于调试和兼容旧 Run。

## 当前组件职责

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| React 前端 | 页面、交互、事件归并、预览器、恢复展示 | 直接访问 SQLite、保存密钥、执行本地命令 |
| Tauri Host | 业务命令、持久化、权限检查、进程管理、远程服务适配 | 模型推理、把前端状态作为事实源 |
| Runtime Adapter | 模型/远端会话、流式事件映射、工具声明、恢复检查点 | 产品数据所有权、绕过 Host 权限 |
| 外层 Agent 后端路由（`crates/fox-agent-backend`） | 会话绑定的后端、四个 Host 入口的路由、外部 Agent 的启动、沙箱、ACP 连接、原生权限、能力声明 | 改变会话已绑定的后端；把外部会话交给 Fox 运行时 |
| 外部 Agent（dsh / pi / Codex） | 在沙箱内自行执行模型循环和工具 | 读写 Fox 数据库；在未授予时获得完全访问 |
| Pi Runtime | 当前本地 Runtime 的 Pi SDK、Prompt/Profile/Planner Harness | 定义 Fox 对话产品架构 |
| SQLite | 会话、消息、Run、事件、权限、配置与缓存索引的事实源 | 保存 API Key、存放大文件正文 |
| 知识库服务 | 远程 Agent、知识检索、原文件、图谱 | Fox 本地项目权限和本地会话事实 |

最重要的兼容边界是 Conversation，而不是 Pi Session。Conversation 先绑定外层 `agent_backend`（`fox` / `deepseek` / `pi` / `codex`），`fox` 会话再绑定 `agent_id`，Host 根据 Agent 的 `runtime_type` 选择适配器。所有适配器最终写入同一 SQLite 模型并输出同一前端事件，因此接入新 Runtime 不应增加第二套聊天界面或消息表。

## 当前运行路径

### Fox 本地助手（Kernel / Authoritative）

```mermaid
sequenceDiagram
    participant UI as 前端
    participant H as Tauri Host
    participant D as SQLite
    participant R as Pi Runtime Adapter
    participant M as 模型服务
    UI->>H: run_start
    H->>D: 创建用户消息与 queued Run
    H->>R: prompt(JSONL)
    R->>M: 模型流式请求
    M-->>R: 文本/推理/工具事件
    R-->>H: runtime_event 或 tool.execute
    H->>D: 持久化事件和投影状态
    H-->>UI: fox://runtime-event
```

### 知识库远程助手

Tauri Host 通过 `YuxiRuntimeHost` 创建远程 Thread/Run、消费 SSE 或轮询状态，并映射为同一 `fox://runtime-event`。前端不理解远端协议差异；SQLite 仍保存 Fox 会话、消息和恢复所需游标。

### 外部 Agent（dsh / pi）

Tauri Host 的 `ExternalBackendHost`（`apps/desktop/src-tauri/src/external_backend.rs`）从 Fox 管理的运行时目录启动外部 Agent，经 ACP v1 建立会话，把 Agent 的消息、工具和审批请求映射为同一 `fox://runtime-event`，并写入同一 SQLite 会话。Agent 在 srt 沙箱里执行工具；审批经 ACP `session/request_permission` 由 Host 作答。Codex 走同一路径，但新会话暂时不能选择。

未来新增本地或远程 Runtime 时，也必须收敛到相同的 `StartRunResult`、Runtime Event、取消、恢复和 Host 权限契约。

## 依赖方向

```text
React Feature
  -> desktopClient / Tauri Command
    -> Host Service / Repository
      -> SQLite、受管文件、Keyring、Runtime Adapter、外部服务
```

- React 不直接访问数据库、Keyring、文件系统或模型 Provider。
- Command 处理输入校验和路由；可复用持久化规则进入 Repository。
- Runtime 不直接修改 SQLite，也不能依据 Prompt 扩大项目或知识范围。
- Provider 差异收敛在 Model Profile 和 Runtime Adapter，不扩散到消息 UI。
- 外部文本始终是不可信数据；Prompt 是纵深防御，Host 才是权限边界。

## 数据所有权

- `fox.db` 是产品事实源；前端状态可重建。
- `runtime-sessions/*.json` 是本地 Runtime 会话恢复检查点，不替代消息表。
- 远端 Thread/Run 是远程执行投影，Fox 仍保存本地 Run、事件和关联 ID。
- `attachments/`、知识预览缓存和下载文件保存二进制；SQLite 只存路径、摘要和状态。
- API Key、知识库 Token、MCP 环境变量与 HTTP 扩展 Header 使用系统 Keyring。

## 启动与恢复

1. `lib.rs` 解析 `FOX_DATA_DIR` 或系统应用数据目录。
2. 应用待执行备份恢复，打开数据库并运行迁移。
3. `repair_interrupted_runs` 修复异常退出留下的运行状态。
4. 创建 Runtime、附件、知识缓存和 Skills 目录。
5. 初始化本地 Runtime Host 与知识库 Runtime，并恢复远程未完成 Run。
6. 重置知识预览租约并执行缓存清理。
7. React 从数据库快照重建导航、对话和工作状态，再合并实时事件。

## 故障边界

- Sidecar 崩溃：Host 标记运行失败或受限重启 Worker；历史事件仍在 SQLite。
- 前端刷新：通过 Conversation Detail、消息和事件重建，不依赖遗漏的窗口事件。
- 知识库离线：本地助手继续可用；远程 Agent 与知识能力返回服务错误。
- 扩展源超时或协议错误：Host 使当前连接失效并更新健康状态，调用结果记录为工具失败，不影响其他源和 Fox 启动。
- 数据损坏或升级：通过备份/恢复与迁移测试处理，不允许 Runtime 直接改库。
- 运行完成但 Conversation 已删除：停止投影和远程恢复，不向不存在的对话追加错误卡片。

## 安全边界

- 项目路径和写入/命令由 Tool Guard/Tool Host 强制检查。
- 知识访问范围由 Conversation Binding 与 Agent Scope 的交集决定。
- Runtime 声明工具不等于获得执行权限；Host Handler 和审批必须同时存在。
- Keyring 是密钥事实源，诊断、事件和 Prompt 只使用脱敏配置。
- 用户内容、项目文件、知识文档、MCP 输出和远端响应都按不可信数据处理。

详细设计见[项目与权限架构](项目与权限架构.md)和[安全架构](安全架构.md)。

## 当前限制与规划

- Legacy Primary Run 采用单 Worker 队列；Kernel 的独立会话与 Child Run 不设应用自身的同时运行数量上限。每个 Child Run 仍使用独立 RuntimeHost/Sidecar，深度、授权、取消和文件写入边界不变。
- Pi 是 Fox 会话当前的本地 Adapter。外部 Agent 内置 dsh 和 pi；Codex 已实现但隐藏；「自定义 ACP Agent」通用入口待办 / 规划中。
- 四 Agent 方案阶段 4（Legacy 与 Shadow 路径清理）尚未开始。
- A0-A6 的工作图、Span、Plan/Review/Acceptance、Memory、Child Run、HTTP MCP、OpenAPI 与受限 Hooks，以及 E1-E4 专家能力首版均已实现；后续按已知限制做增量增强。
- Tauri `app.security` 已同时配置 `csp` 与 `devCsp`；剩余工作是对新增外部内容逐项收紧白名单并补充策略回归，而非从零制定 CSP。详见[安全架构](安全架构.md)。
- 知识库服务仍保留代码名 `yuxi`，产品文案统一称“知识库服务”。

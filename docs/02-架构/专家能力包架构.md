## 安装单元

Fox 使用扩展名为 `.foxexpert` 的声明式 JSON 文件。首版包不包含可执行脚本、安装 Hook 或外部引用；提示词等文本以内嵌文件形式保存，因此导入前可以完整审计，也不需要解压不受信任的归档。

```json
{
  "schemaVersion": 1,
  "id": "fox.docs-reviewer",
  "version": "0.1.0",
  "name": "文档审查专家",
  "compatibility": { "foxVersion": ">=0.1.0, <0.2.0" },
  "agent": { "systemPrompt": "./prompts/system.md" },
  "resources": {
    "skills": ["docs-review"],
    "tools": ["read", "grep"],
    "mcpServers": [],
    "knowledgeReferences": []
  },
  "permissions": { "project": "read_only" },
  "workflow": null,
  "files": {
    "./prompts/system.md": {
      "sha256": "<lowercase-sha256>",
      "content": "Review documents with evidence."
    }
  }
}
```

`id` 是稳定包身份，`version` 使用 SemVer。Schema v1 保持冻结；Schema v2 可以内嵌 E2 Workflow v1；Schema v3 可以再声明 E3 Team v1。Manifest 只表达需求，`permissions` 不会在安装时转化为 Host 授权。完整契约见[专家工作流架构](专家工作流架构.md)和[专家团队架构](专家团队架构.md)。

## 校验边界

导入按“解析 → 完整性 → 兼容性 → 资源 → 权限预览 → 用户确认 → 事务安装”执行：

- 严格 Schema，未知字段直接拒绝；当前接受包 Schema v1/v2/v3（`PACKAGE_SCHEMA_VERSION = 3`），包最大 2 MiB、1–32 个文件，单文件最大 256 KiB（`apps/desktop/src-tauri/src/expert_packages.rs`）。
- 文件路径必须以 `./` 开头，禁止绝对路径、反斜线、`..`、ADS、控制字符和 Windows 设备名。
- 每个文件必须提供与 UTF-8 内容一致的小写 SHA-256；整个包再使用排序键的 canonical JSON 计算 SHA-256。
- 校验 Fox SemVer 兼容范围、Agent、Skill、Tool、MCP 和知识引用是否存在。
- 同一 `id + version` 内容不同视为篡改冲突；普通安装禁止降级，降级只能通过已存历史版本的显式回滚。
- Preview 时的当前 Hash 会传回安装事务做乐观并发校验，状态变化时要求重新预览。

这些约束借鉴 Claude Code 插件 Manifest 的相对路径、SemVer 和冲突规则，以及 Dify/Codex 的安装前校验和来源透明原则；Fox 没有复用它们的可执行脚本能力。

## 持久化与运行时

`agents` 增加 `package_source/package_id/package_hash`；`expert_package_versions` 保存每个不可变版本的原始包、Hash、创建时间和激活状态。安装和升级在同一个 SQLite 事务中同时更新专家当前定义、版本状态和 Skill 配置。

已安装包在普通专家编辑器中只读，可以复制为 `local` 专家再修改。升级或回滚只影响之后创建的绑定；既有 `conversation_expert_bindings.package_snapshot_json` 和 `package_hash` 保持冻结，保证历史会话可复现。

运行时继续使用编译后的 `package_manifest_json`，工具、MCP、知识和项目权限仍由 Host Capability、项目授权和审批收口，不信任包内 Prompt。

`agents.package_source` 的取值决定启动时谁会改写这一行：

| `package_source` | 来源 | 启动时 |
| --- | --- | --- |
| `local` | 用户在专家中心新建或复制 | 从不被覆盖 |
| `imported` | 导入的 `.foxexpert`，或随应用分发的内置库专家（`package_manifest_json.bundledLibrary = "agency-zh-fox-v1"`，版本记录 `source = 'builtin'`） | 内置库专家由 `seed_bundled_experts` 按随包目录同步 |
| `remote` | 远程同步 | 不被内置库同步覆盖 |

`seed_bundled_experts`（`apps/desktop/src-tauri/src/database/repositories/bundled_capabilities.rs`）每次启动执行：已安装同一版本则保留用户的回滚和 Skill 选择；有新随包版本时写入新版本并把旧 active 版本改为 `historical`。

## 专家行缺失时的启动修复

`agents` 行可能在 Fox 之外被删除（例如 `sqlite3` 命令行，默认 `foreign_keys=OFF`，`expert_package_versions` / `agent_runtime_config` 的 `ON DELETE CASCADE` 不会执行）。当前处理：

1. **迁移的外键检查**：`apps/desktop/src-tauri/src/database/migrations.rs` 的 `check_foreign_keys_after_migration` 对父表为 `agents` 的孤立引用放行，留给下面的修复步骤；其他外键问题仍中止启动，错误为 `SQLITE_CONSTRAINT_FOREIGNKEY`，消息是中文可读文本「数据库外键完整性检查失败，以下记录引用了不存在的数据：…」。
2. **内置库专家重建**：`seed_bundled_experts` 发现行缺失但包版本已安装时，按随包目录重新写入 `agents` 行，保留已有包版本历史，把随包版本设为 active，并写日志 `fox.database warn bundled_expert_restored id=… version=…`。`is_builtin=1` 的内置 Agent 由 `seed_builtin_agents` 的 `INSERT OR IGNORE` 补回。
3. **本机专家引用修复**：`Database::repair_missing_agent_references`（`apps/desktop/src-tauri/src/database/repositories.rs`）在种子写入之后运行。被删的本机 / 导入专家不会恢复：
   - 以它为 Agent 的会话改为 `fox-general`，会话和消息保留；
   - 它的 active 会话绑定改为 `removed` 并写入 `deactivated_at`，快照保留；
   - 使用它的 active 数字同事改为 `paused`；
   - 删除它遗留的 `agent_runtime_config` 和 `expert_package_versions` 行（Fox 自己删除时本来就会级联删除），避免重新导入同一包版本时触发唯一约束冲突；
   - 委派、Workflow / Team 运行、图评审等历史记录不改动；
   - 写日志 `fox.database warn missing_agent_references_repaired ids=… conversations=… bindings=… colleagues=… cascaded=…`；没有需要修复的行时什么也不做。
4. **无法恢复的启动错误**：`apps/desktop/src-tauri/src/startup_failure.rs` 记录 `fox.startup error setup_failed`，在 Windows 上弹出「Fox 无法启动」对话框后以退出码 1 退出，不再进入 tauri 的 panic。

历史绑定（`removed` / `replaced`）和委派记录仍保留原 `expert_id`，会继续出现在 `pragma_foreign_key_check` 结果中；这是有意保留的历史数据，不影响启动。前端 localStorage 中保存的新会话默认 Agent 如果指向被删的本机 Agent，不在这次修复范围内。

## 桌面交互

专家中心支持：

- 导入 `.foxexpert`，展示安装/升级动作、版本、包 Hash、Fox 兼容性、缺失资源和项目权限请求。
- 导出本地或已安装专家；本地专家会被转换为 Schema v1 包。
- 查看不可变版本历史并显式回滚。
- 将已安装包复制为可编辑的本地专家。

## 关键错误码

以下为 `expert_packages.rs` 中的主要错误码（另有 `expert.package_storage`、`expert.package_not_found`、`expert.package_version_not_found`、`expert.package_resource_scan_failed` 等存储与查找类错误码）。

| 错误码 | 含义 |
| --- | --- |
| `expert.package_invalid` | Schema、边界、路径或 Hash 校验失败 |
| `expert.package_incompatible` | Fox 版本不满足兼容范围 |
| `expert.package_resources_missing` | 必需 Skill、Tool、MCP 或知识不存在 |
| `expert.package_version_conflict` | 同版本不同 Hash，或身份冲突 |
| `expert.package_downgrade_forbidden` | 普通导入尝试降级 |
| `expert.package_state_changed` | 预览到安装之间当前版本已变化 |

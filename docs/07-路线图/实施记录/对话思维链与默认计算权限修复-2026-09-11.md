# 对话思维链与默认计算权限修复

日期：2026-09-11。基于用户提供的两张重复过程卡截图、固定头像和 AGV 附件读取日志。

## 问题与修复

1. **同一任务重复过程卡。** 原时间线为每条 assistant 续接消息都渲染一次整个 Run 的事件。因此工具调用后新增一条模型消息，就会新增一张相同步数的过程卡。点击展开本身没有启动新模型任务。现在同一 Run 的连续 assistant 消息合并为一个展示行，保留文字、首条位置和稳定组件身份；操作仍关联最后一条真实消息 ID，数据库消息不删除，不跨用户消息合并。
2. **长思考展开卡顿。** 原实现将全部思考再次解析为 Markdown，关闭时卸载详情，实时更新还会读取布局来滚动。现在首次打开才挂载详情，之后关闭保留状态；思考按每页约 4000 字符的纯文本显示，实时预览仅保留最近 800 字符。分页边界保留完整 Unicode 代理对，未闭合 Markdown 不再吞掉文字。
3. **固定头像。** 对话中的旧小狐、输入框装饰、定时轮换和庆祝动画移除，改用用户提供的 fox.png 原图，圆形裁切、居中 cover、无内边距。其他页面仍使用的图片资源不做全局清理。
4. **状态行动画。** AI Elements 的 Chain of Thought 组件已在源码中，Radix、Motion 和动画样式依赖也已安装。这里采用原生 CSS 的三个动态圆点和折叠过渡，完成时移除圆点，遵守减少动态效果设置。没有为此再加入第三方库。[AI Elements 文档](https://elements.ai-sdk.dev/components/chain-of-thought)说明其组件结构；动画使用 transform/opacity，符合 [Motion 性能文档](https://motion.dev/docs/performance)的建议。
5. **专家卡浅粉色。** 实际计算样式确认透明 OKLCH 混色偏向粉色。卡片背景改用不透明中性卡片变量，边框使用中性边框变量，深浅主题一致。
6. **计算工具被默认助手过滤。** 上一版虽实现 attachment_compute 并加入数据专家白名单，却遗漏内置默认助手白名单；运行时会取二者交集，真实默认助手因此看不到计算工具。新增工具并通过内置助手启动更新路径修复已有数据库。回归测试共享实际数据库白名单，覆盖默认助手、数据专家、无项目及显式禁止工具的情况。不会覆盖正在运行任务的冻结权限；升级后需要重新发起任务。

“读取表格看看内容”先调用读取工具是合理的；整表统计、去重、分组和算术继续反复读取文本不合适。现在 XLSX 首次读取同时返回由工作簿清单产生的工作表目录，包括名称、Unicode 字符偏移和短预览；模型可以直接跳到第二张表，也可以用已有计算工具检查所有表并执行代码。目录最多 64 项，名称最多 256 字符、预览最多 400 字符，并明确标示截断，保持原文件、解压和文本大小限制。

## 验证

- 前端回归：217 项通过；另补长思考未闭合 Markdown 的可见性和内容规模回归。
- Node 工具选择与 Host 契约：25 项通过，包含默认助手权限被遗漏的反向复现。
- Rust：默认助手已有数据库升级 1 项、Host 工作表目录与跨会话拒绝 1 项、Office 读取 16 项通过/1 项忽略。
- Kernel 协调回归：70 项通过/2 项忽略。包含已有无项目代码执行与结果回读路径。
- 新编译 Windows worker：17 项通过/1 项跳过。
- 真实 RuntimeTimeline 组件的合成界面：同一 Run 8 条 assistant 消息从 8 张过程卡变为 1 张。增加第 9 条消息、30 次流式更新、收起再展开，仍保留第 2 页和详情展开状态。长思考展开时 DOM 节点由 1864 降为 448，思考正文仅 4000 字符，无 1000 个 Markdown 段落节点。
- 相同界面夹具的四次展开/收起采样：修改前 61.5/28/33.2/22.7 ms，修改后 44.1/25.2/22.9/20 ms；修改前记录到一次 56 ms 长任务，修改后该次采样未记录到长任务。这是浏览器开发环境样本，不是全设备性能保证。
- 默认 1280×720 和最小 760×560 窗口检查：对话内容无水平溢出；头像 28×28、圆角 50%、cover；状态点有 1.2 秒动画且完成时消失；专家卡浅色背景为纯白，深色使用中性卡片变量。验收页顶部测量原始 JSON 自身允许横向滚动，不属于产品界面。
- Impeccable 检查未发现本次修改新增的规则告警；旧样式文件其他区域的告警未扩展处理。

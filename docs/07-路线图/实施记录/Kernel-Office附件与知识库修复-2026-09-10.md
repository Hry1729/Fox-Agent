# Kernel Office 附件、知识库选择和项目读取修复（2026-09-10）

本轮继续处理新 Kernel 验收版的三项用户反馈。更新包同时包含上一轮七项界面与流式记录修复。

## 原因与处理

| 反馈 | 已确认的原因与处理 |
| --- | --- |
| 聊天框不能添加 Excel，担心 PowerPoint 同样不可用 | 文件选择器只列出 PDF、TXT、MD、DOCX；附件读取器也缺少 Excel 与 PowerPoint 解析。本轮增加 XLSX、PPTX、CSV、TSV 选择，并让 read_attachment 真正返回 Office 文本。项目内 read 也可提取 DOCX、XLSX、PPTX 内容。 |
| 已导入文档的知识库仍显示待导入，无法选择 | 选择器只看 activeIndexGeneration。关键词索引不需要向量 generation，因而被错误禁用。改用 Host 返回的 textIndexReady / vectorIndexReady；区分空库、待解析、处理中和可用状态，统一弹窗与斜杠菜单。 |
| 知识库旁问号点击无反应 | 原问号是装饰图标。本轮改为可点击、可键盘聚焦的说明入口，增加刷新；导入运行期间自动更新目录。刷新不再清空本次尚未保存的勾选。 |
| ls、find 被回复为冻结策略拒绝 | 工具定义允许省略 path，表示项目根目录。旧 Runtime 会补默认值，新 Kernel 直接进入 Rust 检查时未补默认值，合法请求因缺少 path 失败。现统一在授权检查内补默认值，仍校验冻结根目录及实际文件句柄。原 Host 又把所有资源错误都改写为策略拒绝；现保留项目读取失败原因，其他资源错误不转发可能含敏感内容的远程正文。 |

用户提供的是模型回复，并非该 run 的原始调用记录；未取得另一台电脑的数据库。本机已复现并修复上述省略路径场景，不能据此断言用户那次失败只有这一种原因。

## 内容读取范围

- XLSX 保留工作表名称、单元格地址、共享字符串对应关系、数值和布尔值，按工作簿中实际顺序读取。公式只返回保存的缓存结果并标注未重算；数值使用原始存储值，包括日期序列数。
- PPTX 按演示文稿实际页序提取文字；DOCX 提取正文等文字。此功能不是图像 OCR 或完整 Office 版式分析。
- ZIP 解析沿用大小、条目数、校验和与路径检查，新增 XML 深度、元素数与文本量限制；不启动 Office，不执行公式，不读取外部关系文件。
- 旧版 DOC、XLS、PPT 二进制文件仍需另存为 DOCX、XLSX、PPTX。单个聊天附件仍限 5 MiB，附件提取文本限 1 MiB；项目文件读取仍限 8 MiB，显示结果按现有上下文预算截断。
- 已经入库的旧解析结果不会自动重写；如需使用新的 Excel 单元格对应关系，可在知识库页面重新解析该文档。

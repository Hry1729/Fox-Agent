# 附件大结果与运行状态修复

本次修复处理工具详情展开卡顿、读取大表格后任务中断、引用项换行、文件类型图标和工作动画缺失。

## 原因与行为

- 工具详情原先把完整 JSON 交给语法高亮组件。大结果会生成大量文本节点和高亮节点。现在超过 6000 字符的输入、输出使用纯文本分页，当前页限制高度，保留前后翻页。
- 用户提供的记录中，单个工具结果紧凑序列化后为 1,922,916 UTF-8 字节，正文重复存储在 content 与 details。Kernel worker 的请求上限为 1,048,576 字节，超出会报 `Kernel request exceeds frame limit`。这是该结果无法继续投递的明确条件；原记录没有包含运行器终止错误日志。
- `read_attachment` 默认每次返回 12000 个 Unicode 字符，最多 24000 个，返回 `hasMore`、`nextOffset`、`totalCharacters`。模型工具说明要求继续读取完整数据后再统计。正文从 details 中移除，Legacy 与 Kernel 使用相同的分页返回结构。已有 5 MiB 文件与 1 MiB 提取文本上限保留。
- 项目、知识库与附件合并成一行，显示前三项；其余通过省略按钮悬浮查看名称、点击展开操作。电子表格和演示文件使用对应图标。
- 蓝色边框光效原来仅绑定首页焦点，现在也绑定运行状态。角色入场动画不再持续占用 transform，避免覆盖循环动作。
- XLS 使用 calamine，PPT 使用 office_oxide 读取正文；上传入口放开 XLS/PPT。公式使用文件保存结果，未重算；不执行宏。旧 DOC 仍需转为 DOCX。此处是聊天附件/项目读取支持，并未扩展本地知识库导入筛选器或 Office 编辑工具的格式范围。

开发与发布前端均来自 apps/desktop 的同一套产品组件。发布构建输出 dist，开发环境由 Vite 提供页面；发布隔离检查确认验收页面及测试控制器未进入正式包。此次查到的是数据量和组件状态/样式问题，不能据此保证其他电脑的所有运行故障均已解决。

## 验证

- 前端 215 项通过，800 个断言；包含百万字符工具结果的渲染数量限制。
- 实际产品组件的隔离浏览器验收：约 264 万字符结果只渲染当前 6000 字符，页面共 136 个元素，翻页有效；760×560 下引用项同一纵坐标，行宽与滚动宽均为 714 像素，无横向溢出。工作状态切换后光效退出，角色动画时长恢复空闲状态。该验收使用模拟运行状态，并非用户电脑上的 Tauri 实测。
- 中文 XLS 两个工作表、B2=123.5、C3 中文内容读取通过；Apache POI 真实 PPT 两页正文读取通过，无母版占位文字。样本仅保存在 output/runtime-ui-20260910/fixtures 隔离目录。可设置 FOX_LEGACY_OFFICE_FIXTURES 后运行 ignored 验收测试。
- Rust Unicode 分页可完整拼回原文，旧重复结果超过 1 MiB，而每个分页结果低于上限；非法偏移被拒绝。
- Kernel coordinator 72 项首次通过，1 项由于移除 details.text 后旧断言不匹配，改为检查模型正文及去重后单独复测通过；另有 1 项需要原生 Codex 环境而跳过。
- Runtime 适配与续跑 34 项通过；新增附件参数转发测试后 host-tools 共 17 项通过。重建 Windows worker 测试 17 项通过，1 项跳过。
- 发布前端构建、体积检查、验收代码隔离检查通过。安装包另行记录构建结果与校验值。

旧版测试样本及读取器来源：[Apache POI PPT 样本](https://github.com/apache/poi/blob/trunk/test-data/slideshow/basic_test_ppt_file.ppt)、[calamine](https://docs.rs/calamine/0.36.1/calamine/)、[office_oxide PPT reader](https://docs.rs/office_oxide/0.1.10/office_oxide/ppt/struct.PptDocument.html)。XLS 样本为自建中文虚拟数据，不含用户表格。

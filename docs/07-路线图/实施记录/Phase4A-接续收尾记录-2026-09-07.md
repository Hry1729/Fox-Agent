## 2. 本次实现

- 正式 Host 委托共用协调器；Runtime 事件在正式数据库成功投影后，进入同一观察入口。保留启动失败/crash 的委托入口；父、子与数字同事 Host 共用观察注册表。
- 删除 Host 内部平行 ShadowContext 管理与墙钟冒充单调时钟的实现。比较及持久化按观察操作串行化，Legacy 执行路径不因 Shadow 失败而中断。
- v53 增加独立语义检查点表。使用纯控制器 rehydrate 恢复状态、工具、批次、审批期限、retry/compaction、模型请求锚点；比较事实、冻结权限及未齐备的真实批次/结果一并保存。
- 检查点和 diff 在同一个 SQLite 事务中提交。保存失败转为 Failed；关闭与失败状态不能重启成健康空上下文；缺少语义检查点的历史记录拒绝伪恢复。
- Pi turn_start/message_start 提供模型请求 begin/settle；message_end 提供真实 batchId/sourceOrder。批次比较等待独立 Legacy 工具事实齐备，支持事实/结果乱序和中途观察器重启。
- 修正跨批次累计比较；重复工具观察幂等，冲突事实拒绝；重复相同工具结果不重复解析审批。
- 权限模式、项目根及已有作用域授权在启动时冻结并进入身份哈希；规范工具目录负责基础分类，范围授权按同一 scope 规则匹配，而不是复制 Legacy 的 allow/approval 结果。
- 新增严格只读门信号。诊断返回最新 100 个 Pi Run（包括缺少观察记录者） 的 kernelShadowGate；空样本、未关闭、缺实际批次或模型生命周期、任意非 Match、checkpoint/diff 不一致、可执行 outbox 非空均不得通过。

恢复检查点不是可执行日志。上述路径不派发工具、不重发审批、不租赁 outbox；Legacy 仍是唯一执行权威。

## 4. 结论与边界

本记录区分工程收尾与生产退出验收。受控样本门通过，不等于全部实际工作负载“零安全差异”；门结果显式保留 productionRolloutApproved=false 和 authoritativeEnabled=false。

测试夹具中的 read preflight 是受控应答，不是实际 Tauri 审批界面。真实远程模型、Graph 完整 UI、动态 Hook、计划/Expert 限制和授权在运行期间变化，仍需真实业务样本覆盖审阅。基础冻结权限的比较不能被描述成所有安全策略已经等价。

旧版本已有 diff 但无语义检查点的 Run 不会被补造为空白健康状态；其门信号会阻止通过。新实现不自动修改旧观察结论，也不自动打开任何 Kernel 权威或 4B 开关。

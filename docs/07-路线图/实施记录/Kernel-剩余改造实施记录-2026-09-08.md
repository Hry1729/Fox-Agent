## 原生引擎、重新审批恢复与发布检查（2026-09-09，最新）

用户要求完成剩余改造后，本轮完成以下本地工程工作。生产切权、远端 CI、安装与真实企业服务仍需要对应环境的证据，不能以本地测试替代。

- **原生模型适配**：新增 Codex App Server 与 DeepSeek Harness 公开单次 LLM API 适配，均进入已有一次性 worker 和 Host 冻结配置、审批、资源执行、工具结果屏障及上下文压缩。不是把 Pi 的名称替换为其他 Engine。DeepSeek 包固定为 `0.1.2-rc.1`；Codex 固定本机绝对路径和文件 SHA-256，并探测必要协议能力。
- **身份与兼容**：v61 将模型配置和初始输入插入约束扩展到三个规范引擎名，并要求 Run、绑定列、绑定 JSON 与模型配置一致。读取继续核对内容哈希与适配器版本；旧 Pi 配置省略新增默认字段，保持原序列化哈希。旧 `deepseek-harness` 标识仅作为解析兼容别名，新运行使用 `deepseek_harness`。
- **原生边界**：Codex 独立临时环境、无原生资源工具；代理固定模型、工具目录、输出预算和一次请求，不允许原生重试。真实双工具 Host 测试发现第一次动态调用即中断会丢失第二个提案，现保留完整单次响应后交给 Host；因此当前 Codex 模型预览会等待这一轮响应缓冲完成。原生推理条目和不透明状态在 Host 历史保留。Harness 只装配公开 LLM API，不安装其 Agent Loop、存储与资源执行器；当前图片输入明确拒绝，不静默丢弃。不支持的原生 profile override 明确报错。
- **子进程回收**：Windows Host 用 Job Object 包含当前 worker 及其原生子进程，释放、取消或超时会一并回收。真实后代进程退出测试通过，不按名称终止其他用户程序。
- **打包修复**：把 Harness 与必要 peer 依赖纳入临时打包树；Pi/Harness 同名不同版本依赖保留各自版本。SDK 的动态版本文件读取在单文件程序中失败，现仅在临时打包副本内替换为从同一包清单读取的原版本常量，并严格校验固定版本和替换位置；不改已安装 SDK。
- **恢复方式**：原入口增加“重新审批后继续”，默认仍只读。新 Run 保留原请求与核对记录、清空旧授权、冻结 Ask 权限，并保留原引擎；旧任务不复活、不重放旧租约。实际写文件链路验证：批准前执行器不运行，重新批准后只写入一次，旧终态保持不变。
- **Office 对账**：文件编辑与 Office create/edit/merge/render 对原 `output` 路径独立读回，Office read/validate 对原 `file` 路径读回；先验证原连接定义哈希。隔离查询测试验证替代路径无效、摘要来自目标输出、查询不会自动确认、定义变化后拒绝查询。测试用已有输出字节模拟结果丢失，不宣称 OfficeCLI 或真实文档业务执行已验收。
- **界面与 CI**：真实组件的浏览器隔离检查验证默认只读、未保存时禁用、保存后切换重新审批和提交反馈，机械检测无发现。CI 文件补充 Kernel 核心、生成协议一致性、JavaScript 契约与打包 worker 检查；尚未推送或执行远端 CI。

## 对账查询、人工确认与恢复入口补齐（2026-09-09，前序批次）

用户明确要求修复三处缺口后完成以下开发。此前“恢复入口缺失”的结论为历史状态；现在已具备受限工程闭环，真实企业系统与桌面实装验收仍单列。

- 入口：当前 Kernel 任务终止且有未确认的已派发操作时，对话内显示“核对与恢复”。按操作展示原始输入、查询方式、查询证据、人工结论与依据。查询本身不自动选中“已执行”；结论未保存、仍不确定或已创建恢复任务时禁用继续按钮。只展示与当前 Run 匹配的终态快照。
- 外部查询：文件读取/写入支持对原目标独立读回 SHA-256 和字节数，限制在冻结项目范围内、最多 8 MiB；写入可与原提交正文比较。匹配只能证明当前文件内容，不能证明原操作执行者；读取失败或文件缺失不能当作“未执行”。连接器操作仅查询原冻结连接定义，用户选择并提交查询条件后，通过独立有界连接调用当次列表明确声明 `readOnlyHint=true` 且 `destructiveHint=false` 的工具，并校验参数 schema；不信任 UI 传来的只读标记。查询最长 15 秒，证据截断会明确标记并保存完整结果摘要。
- 人工确认：提供“已执行”“未执行”“仍不确定，暂不恢复”，要求填写依据。保存为 user_confirmation，不生成或改写 tool.completed、审批决定或原执行凭据。新查询使旧确认失效，必须重新确认。
- 持久化：v60 新增核对事件与恢复关联表。查询、确认、恢复记录追加保存；使用版本检查与事务，拒绝旧页面、跨会话/操作、活动任务或已有后续消息的请求。同一源任务最多创建一个恢复任务；创建失败不遗留半个新任务或消息。
- 恢复：逐项确认后，“继续只读核验”创建关联的新 Run，携带核对记录并沿用正常 Host 启动链路。权限在创建事务内冻结为 Kernel authoritative / Rust / read_only，清除旧授权 grants；不改变会话权限及进程默认 Legacy，不重新派发旧租约、不复活旧终态。恢复阶段只读，用于核验与说明后续步骤；不承诺自动续做旧写入或外部交易。已有的 Host 启动故障处理与重启流程仍负责安全终止不完整准备。

### 实现范围

- Host 在首次模型请求和工具批次续跑前检查冻结上下文预算，通过独立 worker 命令执行压缩；Pi 自动压缩仍关闭。仅选取较旧的纯文本对话，保留首次用户请求、当前用户请求、最近 8 条消息以及所有工具调用、工具结果、审批凭据、图片和 thinking。原始历史与工具执行事实不改写，只建立模型输入视图。
- 输入、来源索引、来源摘要、冻结模型配置摘要和结果视图摘要随 append-only Kernel 事件持久化，并在同一事务校验状态、单一派发归属和取消意图。摘要作为标明可能失真的对话笔记，不能成为审批依据，也不作为助手回复展示。
- 压缩调用无工具，结果仅接受有界文本与用量；用量进入原有累计统计。压缩耗时计入执行预算，独立检查模型超时；普通模型请求的计时在实际派发时开始。陈旧写入不能夺取派发归属或回退已累计执行时间。
- 重启后，未派发输入可继续；已提交结果经过校验后复用。已派发而结果未提交的请求以 `kernel.context_compaction_uncertain` 停止，不自动重播。取消优先，事务失败不会产生半提交视图。
- 每次模型投递最多 4 轮，次数跨重启保留。按 UTF-8 字节保守估算预算，摘要上限 512–8192 字节；不可压缩的工具密集历史、单条超大消息或 4 轮后仍超限，明确报 `kernel.context_compaction_insufficient`。当前没有模型专属 tokenizer，因此不承诺所有供应商上下文必定容纳。

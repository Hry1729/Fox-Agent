# 已知限制

> 状态：维护中<br>
> 适用版本：Fox `0.1.x`<br>
> 维护范围：当前产品与工程限制<br>
> 最后更新：2026-08-21

本文件记录已确认但尚未解决的限制，不代替 GitHub Issue。准备修复的事项应建立 Issue 并在此添加链接。

## Agent 与任务

- A0 只交付 Goal -> Task -> Evidence 最小闭环；没有 Task 级审批、Plan 修订/版本历史、独立 Reviewer 或 Acceptance 实体，这些属于 A1 及以后。
- A0 的 `trace_id/span_id` 是可空关联字段，不提供完整 Run Span 树或诊断产品；旧 Runtime 的 Trace 覆盖允许不完整。
- 长期记忆、完整会话分支、评估体系和原生子 Agent 仍在路线图中。
- Runtime 能力清单当前声明 `dynamicModelSwitch: false`，运行中动态切换模型没有稳定协议保证。
- 真并发子 Agent 尚未建立调度、隔离和冲突处理模型。
- 每个会话当前最多一个 active Expert，不支持多专家并行或 Lead/Member 团队。
- 已有用户/助手消息后不能在原会话热切换或移除专家；产品会创建新的 Assistant + Expert 草稿。
- 远程历史会话继续保留兼容读取；五个内置 Expert 主会话由迁移 v20 自动转换，迁移 v21 冻结已有绑定在升级时可见的专家执行包。
- 知识库服务提供的远程 Expert 当前只把 Fox 可见的名称、公开描述和资源元数据注入本地运行时，不复用远端私有 System Prompt，也不会转交远端执行器；需要完整远端行为时仍走兼容历史会话。
- 专家能力包目前是本地运行时结构，还没有独立安装、签名、升级和市场协议。
- 专家详情工作记录仍按基础 Assistant 聚合，尚未增加按专家绑定的统计查询。

## 多模态与附件

- 附件上传和文本类读取已可使用；图片理解取决于模型配置、Runtime 能力声明和供应商协议，仍需跨供应商验收。
- 不支持的文件类型可能只能作为附件保留，不能保证模型理解其内容。

## 知识库服务

- 远程智能体、知识库、原文件和知识图谱依赖外部知识库服务的可用性与接口兼容性。
- 服务不可用时本地 Fox 能力应降级可用，但远程列表和历史任务恢复可能暂时缺少最新状态。
- 远程 Office 文档采用 Fox 客户端预览，不提供在线编辑和完全一致的 Office 排版保证。
- 引用定位受服务返回的页码、文档结构和源文件映射质量影响。

## 前端与性能

- 生产构建仍存在部分超过 500 kB 的 Chunk，知识图谱、Mermaid、Office 预览和语法高亮是主要来源。
- `Workbench` 和部分大型页面承担较多状态编排，继续扩展前需要逐步拆分路由和业务边界。
- 大型 DOCX、PPTX、XLSX 和复杂知识图谱仍可能产生明显内存和渲染压力。

## 平台与安全

- 当前主要开发和人工验证环境是 Windows；其他桌面平台需要独立完成安装、文件选择、Keyring、图标和打包验收。
- Tauri 配置当前 `csp` 为 `null`。在引入外部内容和 Web 预览时必须持续限制渲染边界，并在正式安全加固阶段配置合适的 CSP。
- MCP 与命令执行具有较高风险，即使经过审批也需要限制参数、工作目录、响应大小和审计记录。

## 数据与兼容

- SQLite 是本地事实源，但跨版本降级不能简单依赖数据库逆向迁移，应通过备份恢复流程处理。
- Runtime Session、远程任务和 SQLite 之间的恢复链路复杂，新增状态必须同时考虑异常退出与旧版本事件。
- 历史阶段文档中的接口、进度和路径可能已经过时；完成常青文档迁移前需要结合当前代码核实。

## 明确延期

- Office 在线编辑与多人协同。
- 费用统计与计费结算。
- 用户上传自定义头像。
- 无限制的自动脚本 Hooks。
- 默认开启的高并发多 Agent 执行。

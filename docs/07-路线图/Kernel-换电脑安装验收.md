# Kernel 换电脑安装验收

这份流程用于本地验收包，不表示正式发布。安装包版本为 0.1.0，最终文件校验值以交付目录 `SHA256SUMS.txt` 为准。测试包不含本机模型密钥、用户数据库或业务文件。

## 安装与首次启动

1. 把整个测试包复制到另一台 Windows x64 电脑，先解压到可写目录。建议使用 Windows 11；本轮没有验证旧版 Windows。没有 WebView2 Runtime 时，安装器会联网获取它，因此此包不能称为完全离线安装包。
2. 双击 `Fox_0.1.0_x64-setup.exe` 安装。记录安装路径。安装包未做发布签名；如被组织策略阻止，不要绕过策略，把提示记录下来。
3. 安装结束先不要自动运行。打开 PowerShell，进入测试包目录，运行下方命令，把示例路径换成实际安装位置。若策略不允许运行脚本，请由设备管理员按本单位要求处理，不改变系统脚本策略。

```powershell
.\Start-IsolatedFox.ps1 -ExePath 'C:\Users\你的用户名\AppData\Local\Fox\fox-desktop.exe' -Mode authoritative
```

启动脚本只为新进程设置模式和独立数据目录。测试数据位于脚本旁 `TestData`；模式、程序校验值和 PID 记录在 `last-launch.json`。普通快捷方式不会采用本脚本的进程设置；未另设环境变量时默认使用 Legacy。本流程请一直使用脚本。

4. 在新窗口中配置你允许用于测试的模型。只输入合成测试内容。该安装包包含 Pi、DeepSeek Harness 适配代码；原生 Codex 还需要该电脑额外具备兼容的 Codex 程序，本脚本默认只测试 Pi。

可用下面的只读检查核对安装文件是否齐全、是否与交付包一致。它不会启动程序，会在测试包旁生成 `installed-files-result.json`；文件一致仍不等于所有功能通过。

```powershell
.\Verify-InstalledFiles.ps1 -InstallDirectory 'C:\Users\你的用户名\AppData\Local\Fox'
```

## 基本任务与审批

1. 新建一个空的测试文件夹作为项目。先发“只回答 17 加 29 的结果，不调用工具”，确认能得到结果。
2. 要求在测试项目创建 `approval-check.txt`，内容为 `FOX-ACCEPTANCE-ONE`。审批卡出现时先不批准，检查文件还不存在；再批准一次，检查文件内容。不要为整个项目开启永久放行。
3. 发一个可持续执行的合成任务，点击取消，确认任务停止且不会继续写入。
4. 退出测试实例后，用同一脚本、同一模式重新启动。确认历史和审批记录仍可查看。待审批任务重启后的处理以实际状态为准，不应自动扩大权限。

## 切回 Legacy 演练

1. 先等待测试任务结束或取消，并完全退出测试实例。
2. 使用同一数据目录启动旧模式：

```powershell
.\Start-IsolatedFox.ps1 -ExePath 'C:\Users\你的用户名\AppData\Local\Fox\fox-desktop.exe' -Mode legacy
```

3. 新建对话，再做一次纯文本任务。记录 `last-launch.json` 的模式和新任务 ID。重新打开之前的新 Kernel 对话，确认历史仍在。数据库级自动检查另行验证旧 Run 的绑定不被改写；仅凭界面回复正常不能证明绑定规则通过。
4. 如需再次试新模式，退出后用 `-Mode authoritative` 启动。不要降级数据库、删除租约或手工改写 Run 的 authority/engine。

## 结果不确定与重新审批

这项需要可控的执行中断夹具，不能靠在业务写入途中随意杀进程来造故障。只有隔离测试任务显示“结果不确定”时，才执行以下步骤：先查询原操作结果，核对文件或服务回执，填写依据，保存确认，再选择只读恢复或重新审批。重新审批创建的新任务必须再次出现审批，旧审批不应自动放行。记录原任务 ID、新任务 ID，以及批准前后真实文件状态。

普通安装测试未触发该状态时填“未覆盖”，不要填“通过”。同样，v60→v61 迁移需要事先准备的可公开测试数据库或脱敏备份；全新安装不等于升级迁移验收。

## 记录与构建

填写测试包中的 `验收记录.md`，并保留错误提示与截图。无需发送模型密钥或完整业务数据库。

Windows 安装包构建入口为 `pnpm tauri:build:windows`。构建前从已安装的 Visual Studio x64 CRT 再分发目录准备运行库；可用 `FOX_WINDOWS_CRT_DIR` 显式指定目录。安装器配置单独加载，避免给普通 Cargo 测试或其他平台增加 Windows DLL 要求。本轮 Zvec 下载受网络限制，构建显式复用了已验证的同版本本机预构建目录；新的构建机仍需能取得匹配的官方 Zvec 库。

### 3.4 C02 网页与连接器（方案 §4 C02 / §8 K4，**仅后端**）

**数据（v110）**
- `companion_tool_grants(companion_id, server_id, tool)`：授权身份 = 联系人 × 连接器实例 × 工具。`server_id='@web'` 是内置网页能力对（`web_search`/`web_read`），其余为 `mcp_servers.id`（OpenAPI 用其稳定操作名，与目录一致）。
- `runs.companion_tools_snapshot`：本轮能力快照（JSON 数组，`web_search` / `mcp:<server>:<tool>`），**写一次**。

**授权闸（一处规则，多处入口）**
- `database/repositories/companion_capabilities.rs`（新文件）：
  - `ensure_granted_on(connection, run, tool, input)`：基础白名单（文件/笔记）直接放行；网页/连接器工具要求 **当前授权有效 ∧ 本轮快照包含**。三类拒绝文案区分「未启用 / 已撤销（旧批准不恢复）/ 下一轮才生效」。
  - `current_capability_ids_on`：授权 ∩ 已安装且启用的连接器（停用/删除的服务不授权任何工具）。
- 入口 1（预检/执行）：`companion_workspace::check_run_tool` 原 `allows_tool` 硬拒绝改为调用上述闸；它被 `ensure_runtime_tool_allowed` 在 legacy 与 native（`native_tool_batch::validate_tool_policy`，claim 后还会再验一次）两条链路统一调用。
- 入口 2（**批准领取处**）：`repositories.rs::claim_approved_tool_call` 在查到 approved 记录后、置 running 前重查同一规则。等待审批期间撤权、批准后执行前撤权、**重启恢复**（`recovering_host_tool_call` 也走这里）全部被拦；被拦调用按既有 CAS 模式落 `failed` 并写明原因（卡片可见），审批被 claim，不复活。
- 目录：`start_run_inner` 冻结快照并把 `allowedTools` 扩成「白名单 + 已授权网页工具 + （有任意 MCP 授权时）list_mcp_tools/call_mcp_tool」；`execute_mcp_tool_request` 的 `list_mcp_tools` 分支对私聊按快照过滤服务器与工具名（第三个工具既不出现在目录，也过不了执行闸）。
- 事件入口（tool.started/… 无 input）对 `call_mcp_tool` 退化为「有任意 MCP 授权」检查——精确工具已在执行入口验过。
- 命令：`companion_capabilities_get`（网页开关状态 + 连接器实时工具列表；停用/不可达显示原因，不假装可调）、`companion_capability_set`（单个工具授权/撤权）。均已注册。

**stdio 边界**：授权只表示「允许 Fox 调用这些工具」，不构成本机进程的文件隔离。前端面板必须如实写出这句话（mockup s09 的 boundary 文案），验收不记为文件隔离通过。

# Fox 联系人 P0 至 P2 实施方案

日期：2026 年 11 月 7 日。状态：用户已确认采用本次展示的 Rakazo 消息组件，并将 P0 至 P2 全部纳入本期方案；已纳入 M2 复审提出的六项关键契约。本期尚未按新方案实施，不代表开发或验收完成。

以 OpenMausBot 为主要产品参考，结合 Rakazo 的可移植实现。联系人气泡和悬停操作采用已展示的 Rakazo 组件，审批卡与提问卡沿用已确认的 OpenMausBot 纵向选项布局。保留 Fox 的本机运行、联系人身份、私有笔记、项目授权和现有权限体系。

本期交付 C00 至 C07：消息组件、聊天搜索、网页与指定连接器、本机定时任务、独立模型、文件与成果、提醒、消息引用与收藏。为接通已选消息组件中的操作，表情反馈和手动标为未读也纳入其中。P3 的群聊、联系人交接、语音和模板分享全部后置，先不做。云电脑、远程沙箱和新的服务端部署体系不在本期范围内。

本文件是 P0 至 P2 的统一实施入口。较早的 [聊天体验优化简案](联系人聊天体验优化简案-20261107.md) 保留设计来由；其消息组件选型和交付范围以本文件为准。本轮只更新方案，不修改 Fox 产品代码。

## 1 当前基础与范围

本次源码核对使用 `worktrees/fox-contacts-m2-20261106`，基线为 `5c8cdf3f` 加核对时尚未提交的聊天体验及笔记确认改动。本次保存提交包含这些既有改动和方案文档；方案中新增的六项契约仍待实现。

已有基础：固定私聊、联系人资料、私有主笔记与专题、共享偏好确认、项目授权与撤权、附件副本、文件导入导出、未读计数、联系人置顶、归档恢复、删除与保留目录、模板采用，以及上下文修复与重置。它们不计入新增功能。

已有工作区实现包含按条送达、输入框上方工作状态、隐藏工具过程、纵向提问和审批卡。此次在这些行为之上接入已选 Rakazo 气泡与悬停操作，不丢弃已完成的状态与历史处理。已有实现和验证范围见 [实施与验证](validation/contact-chat/实施与验证.md)。这些证据对应此前实现；新组件接入后的 Windows 桌面交互需重新验收。

本次复审基线仍为上述 M2 工作树及当前未提交改动，不采用旧 main 的能力判断。消息分页、调度恢复、后台归属、工具授权、模型解析和未读语义的实现约束见第 8 节。现有调度和未读机制仅作为改造基础，不能原样接入就算完成。

## 3 P0 接入已选消息组件

### C00 气泡与悬停操作

视觉基准为用户已选择的 [Rakazo 独立预览](references/rakazo/index.html)，以其中的气泡轮廓、左右排布、正文留白、连续消息间距及气泡旁操作栏为准。采用上游组件及必要适配，不再重新设计一套相似气泡。

主题适配保留这一视觉关系：用户消息与联系人消息有清楚的背景层次，操作图标安静，菜单和焦点清楚。颜色变量、中文字体、图标及弹层接到 Fox 现有组件体系；保留联系人真实头像与身份。移植后的浅深主题均与预览对照。无需引入 Rakazo 的整套全局 CSS、账号系统或后端。

前端实现分为三个部分：

1. **气泡和消息正文。** 从 Rakazo `MessageView` 中移植文本气泡的结构与样式，Fox 继续提供 Markdown、代码块、链接、附件和产物打开能力。用户靠右、联系人靠左；每条已完成回复一个气泡。保留原有中途回复，按真实消息边界送达，历史重开后顺序一致。生成中的进度仍由输入框上方状态表达。
2. **悬停栏和菜单。** 以 `MessageHoverMetadata` 的显隐及定位为基础，适配 `MessageHoverActions`。鼠标悬停或键盘聚焦时显示，打开菜单后保持显示；关闭菜单或按 Escape 后正确返回焦点。操作栏不挤动正文、不遮挡相邻气泡；窄窗口和触屏采用可点击的下方入口。时间跟随操作栏显示。
3. **现有工作状态和卡片。** 保留当前联系人的工作头像、真实执行状态和停止能力。提问、权限审批、笔记确认继续使用已选纵向选项卡，保留已处理结果。工具名称、参数、日志和内部推理不进入私聊气泡。

P0 先接通复制与时间展示。P2 接通其余操作后，本期最终操作栏为“表情、引用回复、更多”；更多菜单提供复制、收藏或取消收藏，联系人消息另提供标为未读。尚未接通的操作在阶段版本中不展示。P0 的复制以当前气泡为单位，不把同一轮的其他气泡一起复制。

后端工作：沿用 Fox 真实消息、运行事件及决策记录，修正当前按消息行分页与按用户行取事件之间的不一致。按窗口涉及的 Run 补齐整轮投影依赖，并确定稳定的气泡身份；事件缺失时的合并降级气泡不得写入永久引用、收藏、表情或成果来源。该工作是 C00 的必交付项，也是 C01、C05 至 C07 的前置条件，具体规则见 K1。不为视觉变化复制一套聊天正文。

P0 验收：已选预览与 Fox 实际组件对照；浅深主题及 320、768、1024、1440 像素宽度下可用；悬停和菜单不引起气泡跳动；键盘可操作；复制只取当前气泡；三条中途回复与最终回复在分页、补页及重开后保留相同分段和身份；工具过程仍隐藏；提问与审批实际可处理，历史回执正确。普通对话保留此前确认的时间按需显示，不套用联系人气泡布局。

## 4 P1 补齐搜索和办事工具

### C01 聊天搜索

入口放在联系人聊天顶部。第一版只搜索当前联系人的可见消息，结果包含正文片段、时间和来源，点击后载入对应历史位置并高亮。没有结果时说明搜索范围。日期筛选可与关键词组合。

当前 `search_conversations` 和全局搜索会排除联系人私聊。新增联系人搜索应查询原消息；不把私有笔记混入聊天搜索，也不将联系人私聊直接塞回普通对话列表。跨联系人搜索可作为后续入口，并在每个结果上显示联系人。

前端工作：搜索输入、结果列表、空状态、历史定位和高亮。

后端工作：当前联系人范围的消息查询、分页、消息定位；沿用已有消息数据，不另存一份权威正文。用户消息、中途回复与最终回复都可搜索，结果粒度与页面上的气泡一致。查询和定位共用同一消息引用，不能只查询最终回答而漏掉中途消息。OpenMausBot 的 SQL 使用 Node SQLite，Fox 需改为现有 Rust/SQLite 查询。其上游还会搜索工具活动；Fox 私聊隐藏工具过程，因此本期仅搜索用户可见正文。

验收：能找到数周前的中文报价；重开后仍定位同一气泡；同名联系人不串结果；`%`、`_` 等输入按普通文本处理；命中尚未载入的旧消息时能打开。分页切掉用户行、保留回复行的样本也必须定位准确，补页后不合并、不改 ID。

### C02 网页查询与指定连接器

先交付两个清楚的能力：查公开网页，使用用户已配置且为该联系人启用的连接器。联系人资料增加“可用能力”，说明已启用、未连接或不可用的原因。聊天中的能力说明必须与本轮真正可用的工具一致。

当前联系人白名单主要包含文件与笔记工具。Fox 普通运行链路已有网页搜索、网页读取、MCP 和 OpenAPI 连接器，但联系人仍需接入，不能把安装成功或专家模板声明当成可调用成功。

前端工作：能力列表、连接状态、启用选择；继续使用已选的聊天内确认卡。

后端工作：保存联系人 × 连接器 × 工具的明确允许集合，不能只授权到服务器。将该集合与已安装且启用的工具取交集，生成本轮目录。通用 `call_mcp_tool(serverId, tool, arguments)`、原生工具入口和审批恢复均执行同一工具级授权规则；OpenAPI 使用稳定的操作标识对应具体工具。发送消息、修改远端资料等动作继续走现有审批流程。

本轮目录快照不延长已撤销权限的有效期。待审批调用被撤权后不得执行；已经批准但尚未执行的调用在进入执行时也须使用当前授权。已开始的外部调用按现有取消能力处理，界面如实说明已开始，不宣称撤权能回滚外部副作用。授权与执行规则见 K4。

本地 stdio MCP 由本机进程执行，联系人选择工具只能限制 Fox 调用哪些工具，不能使该进程自动获得 Fox 文件工具同等的目录隔离。资料页应明确这种执行方式及其权限边界；本期不为此新增沙箱体系，也不把审批通过写成文件隔离保证。

本批不一并开放通用命令、任意文件访问、所有 MCP 工具或完整桌面控制。确有办公任务需要脚本、浏览器或桌面操作时，另列所需工具和工作范围。尤其在 Windows 上，应先验证 Fox 实际链路，不把其他项目的 macOS 支持当成 Windows 可用。

验收：联系人搜索并引用网页；同一连接器只启用两个工具时，第三个工具既不出现在目录里，也不能经通用入口调用；涉及修改的示例在批准后执行，拒绝后不执行；等待审批期间撤权及批准后执行前撤权均阻止调用；重启恢复审批也遵循当前授权。stdio 的验收只证明工具调用范围，不记为文件隔离通过。

## 5 P2 完成持续工作与消息管理

### C03 本机定时任务

用户可以在聊天中提出“每个工作日早上 9 点整理这个目录”，也可以在资料页创建。保存后显示任务卡：联系人、做什么、什么时候执行、下次执行时间，以及暂停、修改、立即运行、删除。

C03 分成两个必须完成的后端部分。**C03a 调度持久化与恢复**：到期领取与待派发记录原子落库、Run 与触发记录启动对账、崩溃恢复测试。**C03b 联系人后台运行接入**：建立联系人、执行会话、回报私聊与任务运行之间的持久关系，接入笔记和文件边界、联系人级排队及审批回报。现有数字同事调度、预算和记录可作为基础，不能直接视为这两部分已经具备。

后台任务使用独立执行上下文，结果回到固定私聊。执行会话不占用固定私聊的 `conversations.companion_id`，也不通过删除该字段的唯一约束解决绑定。后台运行的联系人身份从专用持久关联解析，相关提示、笔记、目录和工具检查共用这一身份。需要用户决定时，私聊显示关联到原任务 Run 和原审批的待处理卡。

本机语义：Fox 运行且电脑唤醒时才能按时执行。按本机时区显示和计算计划，保存时明确时区。默认跳过错过的周期，在任务记录中说明，并提供“现在运行一次”；错过的单次任务也保留为未执行，不能伪装成已完成。不自动修改系统电源设置。

前端工作：任务卡、任务列表、运行记录、失败和待确认入口。

后端工作：按 K2 建立并使用后台归属链，按 K3 修正调度状态恢复。交互聊天与全部后台任务在同一联系人范围内串行；Host 现有会话级互斥只能作为基础，不能代替联系人级排队。运行开始前按 K5 确定本次模型，记录联系人资料与能力快照；授权撤销仍按 K4 立即约束尚未执行的调用。任务结果按稳定来源关系回写私聊，任务报告不自动转为长期笔记。

暂停计划只阻止后续派发；停止当前运行使用现有停止操作。归档与删除需处理该联系人的全部前台及后台运行，包括排队和待审批运行：先阻止新派发、请求停止并等待终态，再完成归档或删除。恢复归档后由用户重新选择启用计划，不自动补跑历史周期。详细生命周期见 K2。

验收：用本机短周期任务验证自动触发和正确回报；验证到期领取、待派发、运行中断三个阶段的重启行为，不持续卡在 `overlap_skipped`，不因恢复创建第二个同次 Run。前台与后台同时请求时按联系人排队；后台可使用本联系人的笔记和目录，不能落入普通会话的无联系人路径；审批回报能控制原后台调用；归档与删除覆盖所有关联运行。不能只验证“立即运行”或正常退出后的重启。

### C04 独立模型

资料页默认显示“跟随全局”，可覆盖为某个已配置的模型服务。只影响该联系人下一轮；运行中的任务继续使用已选模型。选中的模型不可用时给出明确提示，不静默换成另一个模型。

前端工作：资料页提供“跟随全局”及已配置服务和模型的选择，显示不可用原因。初版不实现聊天中自然语言换模型。

后端工作：持久化服务与模型引用，不另存密钥。交互聊天和 C03 定时任务共用一次有效模型解析，将同一结果用于发送前可用性与连通性预检、图片能力检查、预算装配、Worker 初始化以及实际请求。Run 创建后固定本次选择，排队、重试及恢复不得重新读取全局模型替换它。旧联系人无覆盖值时继续跟随全局。共享 Worker 不得因切换某个联系人的模型而改掉其他会话的模型，具体契约见 K5。

这是对首版 D1“使用全局模型”的后续扩展，不是首版缺陷。Rakazo 的模型匹配工具可供以后自然语言换模型使用，其 Prisma、密钥和多租户模型不搬进 Fox。

验收：两只联系人分别调用两个配置的模型并核对实际请求；全局模型未配置或不可达、独立模型可用时，联系人仍能发送；全局与独立模型图片能力相反时按独立模型判断；改变全局模型后，跟随者的后续运行变化、独立设置者不变；运行中或排队时改设置不改变已有 Run；重启后保持选择。

### C05 文件与成果

资料页增加“文件与成果”，分清“我提供的文件”和“联系人生成的结果”。每条显示名称、更新时间和来源消息，提供打开、另存为、回到消息。继续保留打开工作目录入口。

前端工作：资料页列表、分类、来源跳转、打开和另存入口，以及空列表和文件缺失状态。

后端工作：复用 Fox 已有附件、产物和文件预览，补足联系人、消息和产物的关联查询；定时任务产出也进入同一列表。后台产物的列表、打开、另存与来源跳转都必须在后端按 K2 核验任务 Run、执行会话、联系人和回报私聊的归属链，不能仅凭前端传入的联系人 ID 或文件路径判断。来源跳转复用 C01 的稳定气泡定位。手工放入目录但没有消息记录的文件仍通过现有工作目录入口访问，不编造来源。首期不引入云盘、在线协同编辑或新的文件同步服务。删除联系人时沿用已经确认的保留工作文件规则。

验收：同一文件交给两只联系人后仍能区分副本；后台产物重启后可找到并跳回正确来源；使用另一联系人的产物 ID 或伪造归属调用时拒绝打开或导出；另存原件前由用户选目标；缺失文件给出明确状态。

### C06 提醒

保留未读入口、置顶和全局通知，但改造当前仅统计 `completed` 回复行的规则。未读单位为已持久化且已送达的联系人气泡，中途消息也计数；整轮取消、失败或中断不撤销已送达消息的未读资格。未送达的流式草稿和可替换预览不计数。新增联系人设置：全部提醒、仅需要处理、静音。侧栏区分“有新消息”“正在工作”“需要你确认”。

前端新增设置和状态表达，后端持久化联系人偏好，并与现有通知事件合并。默认沿用当前全局通知行为；全部提醒包含新消息、任务结果及需处理事项，仅需要处理只弹出提问和确认提醒，静音关闭该联系人的主动弹窗和声音。系统通知受操作系统及全局通知设置约束；三种模式均保留侧栏未读数和待处理标记。先做好桌面提醒，不引入手机推送服务。

Rakazo 更多菜单中的“标为未读”在本项接通，仅用于联系人发来的可见消息。手动未读独立保存覆盖起点，不倒退已有自动已读游标；该起点及其后的已送达联系人气泡按未读显示。用户下次主动打开并阅读对应位置后清除覆盖，当前画面的自动已读更新不能立即抵消这次操作。自动已读必须基于实际可见的气泡阅读位置，窗口有焦点或加载了最新消息都不代表已经读到。打开聊天、阅读消息不清除尚未处理的提问和审批，详见 K6。

验收：一个联系人静音不影响另一个；重复刷新不重复提醒；两条中途回复送达后取消运行，未读仍对应这两条气泡；用户停在旧历史时，新消息不能只因窗口有焦点而被标为已读；手动未读重启后保留，后续实际阅读能正确清除；阅读不消除待处理事项，恢复历史也不把已处理的卡片变回待处理。

### C07 引用回复 收藏与表情

引用针对一条可见气泡。点击“引用回复”后，输入框上方显示原作者与短摘要，可取消引用。发送后的新消息带引用区，点击可回到原气泡。附件消息使用文件名及附件类型作为摘要；代码和长消息在引用区截短，原文仍可定位。

收藏是用户自己的消息标记，适用于用户消息和联系人回复。在更多菜单中收藏或取消收藏，资料页提供当前联系人的收藏列表。列表显示摘要与时间，点击复用搜索的历史定位。收藏不自动写入联系人笔记，也不改变模型记忆。

表情反馈用于接通已选组件中的表情按钮。首期使用预览中的六个表情，同一用户对一条消息保存一个选择；再次点击同一表情取消，选择另一个则替换。结果显示在对应气泡旁，重启后保留。本期不做多人计数、模型自动表情或表情驱动的自动任务；表情不替代审批选择。

前端工作：接通 Rakazo 操作栏、引用草稿与引用区、收藏列表、表情选择和选中状态。外观沿用已选组件，交互回调接到 Fox。

后端工作：按同一气泡引用保存回复关系、收藏和用户表情。引用关系与新消息一起落库；发送给模型时附上明确标注的引用原文或摘要，并沿用现有上下文长度预算。不能只在界面显示引用、实际请求却缺少它。历史引用始终作为用户引用的数据，不提升为系统指令。源消息不可用时给出“原消息不可用”，保留已发送的引用摘要，不跳到同位置的其他消息。

验收：引用中途气泡后，实际请求包含该条内容；返回历史时能定位原气泡；取消草稿引用后不带入下一条消息；收藏和表情在重开数据库后保留；引用不读取另一联系人的私聊；附件和长消息的摘要可读；取消收藏或表情后重启不恢复旧标记。

### 共用消息定位

当前 `contactReplies` 可能返回回复消息 ID，也可能返回运行事件投影的 `group.key`。P0 按 K1 修正其依赖和稳定身份，C01 完成后端查询与历史定位后，C05 至 C07 复用同一规则。页面暂未载入目标消息时，先加载对应历史片段及所需 Run 依赖，再定位和高亮。

## 8 开工必须落实的六项契约

以下约束针对 M2 基线 `5c8cdf3f` 加本次聊天体验未提交改动，属于 C00 至 C07 的实施内容。它们不改变已确认的产品范围，也不要求另建通用调度平台或沙箱体系。

### K1 稳定气泡身份与完整投影依赖

当前历史查询按消息行分页，运行事件依赖用户行是否落在窗口内；`contactReplies` 在缺少投影事件时可退回整条回复，气泡数量与 ID 因而变化。依据：[历史事件查询](../../apps/desktop/src-tauri/src/database/repositories.rs) 第 8587 至 8629 行、[气泡投影](../../apps/desktop/src/features/companions/chat-message-model.ts) 第 19 至 30 行。

实施约束：

- 以窗口中实际出现的消息所属 Run 为集合，补齐这些 Run 的整轮投影依赖，不再要求对应用户行也在本页。只补相关 Run，不读取整段会话的全部事件；相邻页合并时按持久键去重。
- 同一条已送达气泡在实时显示、历史分页、补页、搜索定位和重启后使用同一身份。稳定身份源于持久化回复或 Run 内的持久事件身份，不使用 UI 顺序、文本内容或临时合并结果生成。
- 缺失依赖时可以显示加载或降级内容，但不得将临时气泡写入引用、收藏、表情、已读位置和成果来源。依赖补齐并取得稳定身份后才开放这些操作。该限制不妨碍复制当前可见文字。
- 事件、决策和产物按它们实际依赖的 Run 一并核对，避免正文恢复了、审批回执或成果来源仍缺失。

验收使用真实历史查询与真实投影函数串联：把分页边界放在用户行与回复行之间，比较完整加载、分批加载和重启后的气泡身份及文本；验证永久标记不会落到临时降级身份上。此项在 P0 完成，C01 与 C05 至 C07 均依赖它。

### K2 后台运行归属与联系人级排队

现有数字同事创建独立普通会话，联系人目录保护却从执行会话的 `companion_id` 取身份；固定私聊又受唯一索引约束。现有 Host 排队按会话互斥。依据：[数字同事创建](../../apps/desktop/src-tauri/src/database/repositories/digital_colleagues.rs) 第 16 行、[目录检查](../../apps/desktop/src-tauri/src/companion_workspace.rs) 第 140 行、[唯一索引](../../apps/desktop/src-tauri/src/database/migrations.rs) 第 8176 行、[Host 排队](../../apps/desktop/src-tauri/src/runtime_host/mod.rs) 第 1652 行。

| 对象 | 明确职责 |
| --- | --- |
| 联系人 | 拥有身份、笔记、工作目录、能力配置及串行执行范围 |
| 执行会话 | 承载任务上下文；通过后台任务关联确认所属联系人，不占用固定私聊唯一绑定，也不混入普通对话列表 |
| 回报私聊 | 联系人的唯一固定私聊，展示结果与待处理卡；不是后台实际执行的会话 |
| 任务运行 | 关联任务、触发记录、Run、执行会话、所属联系人及回报私聊；提供审批和产物的来源依据 |

持久关联必须在派发前成立。Host 从持久记录解析有效联系人身份，前台私聊和后台任务共用该身份解析入口。提示上下文、笔记读写、目录检查、能力授权及预算都取这个身份，不能只在任务表新增外键。已标识为后台任务却缺少归属关系时停止执行，不能退回无联系人限制的普通路径。

同一联系人同一时刻只允许一个 Run 获准执行，覆盖前台私聊和不同执行会话的后台任务；不同联系人继续按现有全局并发上限运行。审批回答作用于原 Run，不另开一轮来代替。待审批运行仍占用该联系人的执行位置，后续请求显示等待；终态后释放。重启时先按 K3 对账，再恢复排队。

结果回报记录来源 Run 并使用稳定回报身份，恢复投递时不得重复新增结果。审批卡保留原 Run、工具调用和审批 ID，私聊操作须命中原后台调用。产物的列表、打开、导出和来源跳转均核对这条持久归属链，再沿用现有文件访问检查；不能信任前端任意组合的联系人、Run 和产物 ID。

归档和删除先停止新派发，取消该联系人的排队任务，并对运行中及待审批的任务发出停止请求；确认所有关联运行终止后，再执行原有归档或删除流程。不能只检查固定私聊是否空闲。停止尚未完成时保留“正在停止”状态，不提前清理目录。归档恢复不自动启用计划；删除清单列出任务与关联运行，工作文件继续遵循已确认的保留规则。

### K3 到期领取与重启恢复

当前到期游标更新与触发创建分开持久化。启动修复可将普通运行改为 `interrupted`，而触发记录依靠正常终态事件同步，留下活动触发时会继续命中重叠跳过。该问题针对这条状态不一致路径，不表示所有运行每次重启都会失败。依据：[到期领取与重叠判断](../../apps/desktop/src-tauri/src/database/repositories/digital_colleagues.rs) 第 558、724、936 行、[启动修复](../../apps/desktop/src-tauri/src/database/repositories.rs) 第 1429 行。

到期领取在同一数据库事务中推进计划游标并写入待派发记录，复用现有 `scheduleId + scheduledFor` 幂等键。若按错过周期、暂停或配额规则不执行，也须持久化相应结论；不能仅推进游标而没有本次领取记录。此处扩展现有触发记录即可，不引入独立消息队列服务。

启动恢复按同一次触发对账：

| 持久状态 | 恢复行为 |
| --- | --- |
| 领取事务未提交 | 回滚后仍可重新领取，不留下半条计划状态 |
| 已持久化待派发，尚无 Run | 按当前任务状态及既定派发规则继续创建唯一 Run，或写明跳过原因 |
| 已有 Run，尚未派发 | 复用原 Run，按 Host 可恢复状态继续排队；不再次创建 Run |
| Run 已终止，触发仍标记活动 | 同步触发终态并释放联系人执行位置，不再持续返回 `overlap_skipped` |
| Run 被判定为执行中断 | 记录中断结果，不自动重跑已经可能产生外部副作用的整次任务；用户可重新运行 |
| Host 确认可继续恢复的 Run 或审批 | 保留原身份，核验当前归属与授权后走既有恢复流程，不统一误标为失败 |

需要三组真实数据库与 Host 恢复测试：领取事务提交前后、Run 建立但尚未派发、执行中断且终态投影未完成。断点后的重启要验证计划、触发、Run 和联系人占用状态一致。目标是不漏记、不重复创建执行，不承诺外部系统副作用的全局恰好一次。

### K4 工具级授权与撤权

当前通用 MCP 路径主要检查允许服务器；stdio 由 `Command` 启动本机进程。依据：[MCP 调用](../../apps/desktop/src-tauri/src/runtime_host/mod.rs) 第 8093 行、[stdio 启动](../../apps/desktop/src-tauri/src/mcp.rs) 第 267 行。以下是 C02 开放前必须实现的规则，不将尚未开放的联系人能力描述为已经发生越权。

授权身份为联系人、连接器实例及该实例中的工具标识。目录过滤和实际调用均使用该集合；工具别名或通用调用包装不能绕过工具粒度检查。工具被卸载、停用或从目录移除后，不因旧名称仍存在而继续可用。

本轮实际可调用集合不得超过开始时的能力快照，同时必须服从执行时仍有效的授权。等待审批、批准后尚未执行以及重启恢复时，都在实际执行入口检查这一条件。撤权使相关待执行请求失效，卡片显示明确原因；重新授权后须重新发起，不复活旧批准。已经开始的调用按既有停止能力处理，不把撤权等同于已发生动作的回滚。

前台与后台共用该授权规则，后台先通过 K2 解析联系人。参数只在入口校验一次；授权在异步等待后重新检查是状态检查，不在内部层层重复验证同一参数。

对 stdio MCP，授权的含义是“允许 Fox 调用指定工具”。该进程可能使用其本机账号和自身配置允许的资源，Fox 文件工具的根目录检查不自动覆盖它。UI 和验收记录明确这一边界；本期不增加云电脑、容器或新的进程沙箱。

### K5 一次解析的有效模型快照

当前发送预检、图片能力和 Worker 初始化均有读取全局模型的入口。只替换最终请求会产生前后不一致。依据：[发送预检](../../apps/desktop/src-tauri/src/commands/mod.rs) 第 2923 行、[图片能力与 Worker 初始化](../../apps/desktop/src-tauri/src/runtime_host/mod.rs) 第 2132、3606 行。

一次发送或任务运行在前置检查前解析有效模型：联系人独立设置优先，无覆盖时使用全局设置。解析结果包括服务与模型身份、协议与地址、图片能力、上下文与输出限制，以及按现有凭证机制使用的引用，不另存明文密钥。

同一结果传给可用性和连通性预检、图片验证、预算、Worker 初始化和实际请求。Run 建立后冻结这次配置；运行排队、重试或可恢复的重启都沿用它。配置更新只影响随后新建的 Run。原服务或凭证失效时按原模型报错，不静默换到全局模型。

前台聊天和后台任务共用解析。共享 Worker 的启动或会话配置不得要求另一个全局模型必须可用，也不得用修改共享全局配置的方式切换单个联系人。定向检查覆盖这些入口及真实请求，不把“请求里的 model 字段正确”当作整条链路通过。

### K6 气泡级未读与实际阅读位置

当前计数只含 `completed` 助手消息行，游标只前进；自动更新依据页面可见和焦点，不检查目标气泡是否进入视口。依据：[未读计数与游标](../../apps/desktop/src-tauri/src/database/repositories/companions.rs) 第 98、376 行、[自动已读](../../apps/desktop/src/features/companions/context.tsx) 第 51 行。

计数以 K1 的稳定气泡为单位：一条已持久化且已送达的联系人气泡计一次，包括中途回复和后台回报。运行取消、失败或中断不抹掉已经送达的气泡；尚未送达的草稿、内部推理和可替换预览不计数。审批待处理状态单独维护，不能用未读数代替。

自动阅读位置只依据实际显示给用户的稳定气泡更新。页面处于活动状态且目标内容进入可见阅读区域后，才可报告阅读；停在历史上方、后台页或仅有窗口焦点不能清掉下面未见的消息。已读推进不能跨过尚未看到的未读区间，也不能直接使用“最后一条已加载消息”的 ordinal。

手动未读保存独立起点，覆盖该气泡及之后的已送达联系人气泡，不把自动已读游标倒退。设置操作发生的当前阅读状态不能立即清除它；下一次主动打开并阅读对应位置后，再清除该覆盖并按实际阅读进度更新。两类状态都需持久化，旧消息的已读进度在升级时转换到稳定气泡顺序，不默认把全部历史改成未读。

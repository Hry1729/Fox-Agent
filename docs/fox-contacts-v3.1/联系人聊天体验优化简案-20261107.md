# Fox 联系人聊天体验优化简案

日期：2026 年 11 月 7 日。状态：早期聊天体验简案，保留原有设计说明。用户后续已确认采用展示的 Rakazo 消息组件；本简案已并入 [联系人 P0 至 P2 实施方案](联系人功能补全方案-20261107.md)，组件选型、交付范围和验收以该统一方案为准。

目标：联系人私聊呈现为连续收发消息的聊天界面。消息气泡和悬停操作参考 Rakazo；审批卡与提问卡采用 OpenMausBot 提问卡的布局，视觉沿用 Fox 的主题与联系人身份。普通对话同步调整时间显示。

1. **工作状态放在输入框上方。**

   固定在输入区上方，左侧显示当前联系人的头像，右侧显示短状态，例如“正在阅读笔记”“正在整理文件”。顶部标题栏继续显示联系人名字和资料入口。

   仅在当前联系人有未结束任务时出现。任务完成、取消或失败后隐藏，不常驻“空闲”或“已完成”。失败原因留在对应消息处。等待用户确认时显示“等你确认”，保留确认卡，头像停止忙碌动画。

   状态来自真实执行事件。使用联系人的头像，避免所有联系人都显示同一个通用小狐。输入区只保留这一处状态。

2. **双方正文都使用气泡。**

   用户消息靠右，联系人消息靠左。每次实际回复对应一个气泡，中途回复和最终回答按顺序排列。例如“我先看一下资料”“发现了两处问题”“已经处理好了”分别成为三条消息。

   中途消息在任务结束后仍然保留，重新打开历史时保持相同顺序和分段。按真实消息边界分段，不按句号或字数硬拆。连续来自同一联系人的消息紧凑排列，避免重复堆叠姓名和头像。

3. **按条送达，保留必要排版。**

   联系人生成一条回复后，显示一个完整气泡；生成期间通过输入框上方的状态反馈进度。气泡内保留加粗、链接、列表和代码块，不再沿用普通对话中整轮回答不断增长的展示方式。代码块和表格保持完整。

   Rakazo 支持气泡内流式更新；本方案采用按条送达，这是 Fox 本次的交互选择。

4. **联系人私聊不展示工具过程。**

   不展示工具调用名称、参数、日志、调用次数或过程折叠栏，也不提供“查看过程”入口。工具执行本身不生成聊天气泡；联系人实际发出的中途说明继续显示为气泡，模型内部推理不转成聊天消息。

   输入框上方的工作状态提供简短进度。附件和最终文件结果继续可打开；需要用户决定的权限审批和笔记确认卡仍直接可操作。

5. **时间与操作图标按需显示。**

   普通对话的消息时间默认隐藏，与现有操作图标同步在悬停或键盘聚焦时显示，切换时不挤动正文。联系人气泡采用同样的规则。触屏保留可访问的时间与操作入口。

6. **审批卡与提问卡统一采用聊天内选项卡样式。**

   已确认的视觉参考是对比图右上角的 OpenMausBot 提问卡：柔和底色、圆角、简短标题与说明、纵向排列的可点击选项。卡片靠联系人一侧嵌在消息流中，颜色和字体适配 Fox 的浅深主题。

   提问卡沿用“问题 + 补充说明 + 纵向选项 + 自由回答输入框”的结构，选项可带 A、B、C 等标识。

   审批卡使用相同布局：标题用自然语言询问是否执行，说明写清操作对象及必要影响，下方纵向列出当前操作实际支持的选择。例如权限审批可显示“仅允许这一次”“拒绝”，支持持久授权的操作才显示对应选项；笔记确认按实际动作显示“确认移动”“暂不移动”等。审批卡默认不放自由回答框。

   选择后保留所选项和处理结果，卡片留在聊天记录中。审批范围与执行规则沿用现有能力，本轮调整呈现方式。

实现以现有消息分段、完成事件和状态数据为基础，为联系人增加专用展示分支。普通对话的正文与过程展示保持现有规则。

验收重点：连续三条中途回复与最终回复均独立保留；联系人实时聊天和历史消息都不显示工具过程或其入口；工作状态只属于当前联系人且结束后消失；切换联系人或重新打开历史不串消息、不重复气泡；时间悬停显示且布局不跳；审批卡与提问卡使用已选的纵向选项布局，选择结果在重新打开历史后仍可见；长文本、代码、附件和确认卡在窄窗口及浅深主题下可用。

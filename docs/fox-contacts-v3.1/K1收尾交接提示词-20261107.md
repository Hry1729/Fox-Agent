## 2. 必须修复的三个缺陷

### 缺陷 A：Rust 与 TS 的分段规则不一致（重试事件）

TS 侧 `apps/desktop/src/features/chat/run-status-facts.ts:325` 的 `runtimeStatusNotice` 会在以下事件切段：

- `run.retrying`
- `run.retry.completed`
- `run.phase` 且 `phase === 'request_sent'`，且同一 Run 之前出现过 `run.retrying`

Rust 侧原先没有这些边界，导致有重试的 Run 实时显示两个气泡、落库后变成一个，身份发生变化。

**已改了一部分**：`contact_bubbles.rs::boundary_event` 现在接收 `(event_type, payload, retried)`，`delta_segments` 维护 `retried` 标记。**还没加测试**。请补一个重试用例：一次 `run.retrying` 之后的 `request_sent` 必须把前后两段分开，且第一段不回吞第二段。

### 缺陷 B：一条消息的分段写入没有事务

`ensure_window` 已改为每条消息一个 `unchecked_transaction()`（`project_source` 内全部写入，失败整体回滚）。请确认并补一个「中途失败不留半条消息」的测试；`project_assistant` 的 early-return 依赖「有任意一行就跳过」，半写状态一旦出现就永久丢段，这点必须在测试里固定住。

### 缺陷 C：按页回填不够

C06 未读数、C01 搜索需要整个私聊的气泡；未查看过的历史没有行。方案要求「在该私聊回填完成前，不做任何永久操作」，按页回填无法给出这个信号。

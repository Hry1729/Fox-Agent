# 开发环境搭建

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：Fox 工作区、桌面端、Tauri 后端、Agent Runtime 与外部 Agent 后端 crate<br>
> 最后更新：2026-10-25（按 `package.json`、根 `Cargo.toml`、`.github/workflows/windows-ci.yml` 核对）

## 目标与范围

本文帮助新工程师在 Windows 上装好依赖、启动桌面端，并跑通和 CI 一致的基础检查。Fox 以 Windows x64 桌面端为唯一发布目标；其他平台没有经过验证的构建基线。

## 工作区结构

```text
Fox-Agent/
├─ apps/desktop/                 # React 19 + Vite + Tauri 2 桌面端
│  ├─ src/                       # 前端
│  ├─ tests/                     # 前端 Bun 测试
│  └─ src-tauri/                 # Rust Host（fox-desktop）：SQLite、Kernel 接线、工具、外部后端胶水
├─ crates/
│  ├─ fox-agent-kernel/          # Kernel 决策核（Rust）
│  ├─ fox-engine-protocol/       # Host 与引擎共用的协议类型（Rust，JS 版由脚本生成）
│  └─ fox-agent-backend/         # 外层 Agent 后端：ACP 客户端、沙箱、路由（feature `acp`）
├─ packages/fox-engine-protocol/ # 协议的 JS 生成物与测试
├─ services/agent-runtime/       # Node/Bun Agent Runtime（Pi worker、Sidecar、离线 Eval）
├─ scripts/                      # 协议生成、契约校验、Rust 测试包装、启动脚本
├─ vendor/                       # 本地补丁依赖（如 zvec-rust-sys）
├─ docs/                         # 项目文档
├─ package.json                  # 根脚本入口
├─ pnpm-workspace.yaml           # pnpm 工作区声明
└─ Cargo.toml                    # Cargo workspace
```

根 `Cargo.toml` 的 `members` 包含 `apps/desktop/src-tauri` 和三个 crate，但 `default-members` **不含**桌面 Host。所以在仓库根执行不带 `-p` 的 `cargo test` 只会测三个 crate；桌面 Host 要用 `scripts/test-desktop-rust.ps1`（见[测试指南](测试指南.md)）。

## 工具要求

仓库没有 `engines`、`rust-toolchain` 或 `.nvmrc` 这类机器可读的最低版本声明。下表是 CI（`windows-ci.yml`）实际使用的版本，本地请优先对齐它：

| 工具 | 用途 | CI 使用的版本 |
| --- | --- | --- |
| Windows 10/11 x64 | 开发与发布平台 | `windows-latest` runner |
| Node.js | Vite、Runtime、脚本 | 22（`actions/setup-node`） |
| pnpm | 唯一的包管理器 | 11.7.0（与根 `packageManager` 一致） |
| Bun | 前端测试、编译独立 Runtime | 1.3.14（CI 固定这个版本） |
| Rust MSVC 工具链 | 桌面 Host 与 crate | `stable`（`dtolnay/rust-toolchain@stable`），未固定具体版本 |
| PowerShell 7.4+ | `scripts/test-desktop-rust.ps1` 要求 `#requires -Version 7.4` | runner 自带 `pwsh` |
| Microsoft C++ Build Tools | Windows 原生链接（含 SQLite、ONNX 等） | runner 自带 |
| WebView2 Runtime | 运行 Tauri WebView | 桌面运行依赖 |

## 安装依赖

在仓库根目录执行：

```powershell
corepack enable
corepack prepare pnpm@11.7.0 --activate
pnpm.cmd install --frozen-lockfile
bun --version
rustup default stable-x86_64-pc-windows-msvc
```

- 只用 pnpm。`pnpm-lock.yaml` 是依赖事实来源；CI 在安装后检查 `pnpm-lock.yaml`、`pnpm-workspace.yaml`、`package.json`、`apps/desktop/package.json` 没被改写，并检查只有一份 React。
- 必须在根目录安装。开发态 Host 会向上查找工作区 `node_modules` 里的 Pi 依赖，只在 `apps/desktop` 安装不够。

## 启动方式

### 仅启动前端

```powershell
pnpm.cmd dev
```

等价于 `pnpm --dir apps/desktop dev`（先生成头像，再 `vite --host 127.0.0.1`）。Vite 固定监听 `http://127.0.0.1:1421`，开启了 `strictPort`，端口被占时不会换端口。

### 启动完整桌面应用

```powershell
pnpm.cmd tauri dev
```

`tauri.conf.json` 的 `beforeDevCommand` 先运行 `scripts/prepare-officecli.mjs`，再运行 `scripts/start-desktop-dev.mjs`：

- 1421 端口空闲：启动本项目的 Vite。
- 1421 已被**本项目**的 Vite 占用：直接复用。
- 1421 被其他程序或其他工作树占用：报错退出，不会结束对方进程。

Fox 会话默认走 Kernel / Authoritative 路径。只有显式设置 `FOX_KERNEL_MODE=legacy` 才走 Legacy，Legacy 只用于调试和兼容旧 Run（`apps/desktop/src-tauri/src/runtime_host/kernel_authority.rs`）。`kernel-default` feature 只为兼容旧的构建命令保留，不再改变默认值。

### 开发常用环境变量

| 变量 | 作用 | 事实源 |
| --- | --- | --- |
| `FOX_DATA_DIR` | 替代默认应用数据目录；数据库、附件、Runtime Session、缓存都写到这里 | `apps/desktop/src-tauri/src/lib.rs` |
| `FOX_RUNTIME_MODE=fake` | 仅 debug 构建、且未设置 `FOX_RUNTIME_SCRIPT` 时，Runtime 脚本改用 `fake-runtime.mjs`。它对 Kernel worker（`--kernel-worker`）是否同样生效，本次**未核实** | `runtime_host/mod.rs` `runtime_script_path` |
| `FOX_RUNTIME_SCRIPT` / `FOX_RUNTIME_EXECUTABLE` | 指定 Runtime 脚本或已编译 EXE（EXE 优先） | `runtime_host/mod.rs` |
| `FOX_KERNEL_MODE` | 只接受 `legacy` 或 `authoritative`；未设置即 Authoritative；其他值报错 | `runtime_host/kernel_authority.rs` |
| `FOX_KERNEL_ENGINE` | Fox 会话内部 Kernel 使用的模型引擎：`pi`（默认）、`codex`、`deepseek_harness` | `kernel_model_config.rs` |
| `FOX_KERNEL_WORKER_STDERR=inherit` | 把 Kernel worker 的 stderr 直接输出，诊断用 | `runtime_host/kernel_model_worker.rs` |
| `FOX_PI_ACP_PROGRAM` / `FOX_DSH_PROGRAM` / `FOX_CODEX_ACP_PROGRAM` | 开发时指定外部 Agent 后端程序，代替 Fox 管理的运行时目录 | `crates/fox-agent-backend/src/launch.rs` |
| `FOX_EXTERNAL_BACKENDS` | 管理员开关，只能强制关闭外部后端 | 见 [Agent 运行时架构 · 外层 Agent 后端](../02-架构/Agent运行时架构.md#外层-agent-后端四-agent) |

示例：用隔离数据目录启动（假 Runtime 的适用范围见上表）。

```powershell
$env:FOX_DATA_DIR = "$env:TEMP\fox-development-data"
$env:FOX_RUNTIME_MODE = "fake"
pnpm.cmd tauri dev
Remove-Item Env:FOX_RUNTIME_MODE, Env:FOX_DATA_DIR
```

## 外部服务与外部 Agent

- Fox 自己的 Agent 需要可用的模型供应商，在 设置 → 模型 里配置。API Key 存在系统凭据库（Keyring），不能写进 `.env`、SQLite、日志或测试夹具。
- 外部 Agent（pi、DeepSeek Harness、Codex）只从 Fox 管理的运行时目录启动，未安装时返回 `agent_backend_not_installed`，开发时可用上表的 `FOX_*_PROGRAM` 变量指定程序。Fox 不再套外层 SRT。
- 知识库服务不是启动 Fox 的硬依赖。

## 首次验证

和 CI 对齐的最小检查（从仓库根目录执行）：

```powershell
pnpm.cmd contract-fixtures:verify
bun test ./apps/desktop/tests --path-ignore-patterns "**/a0-performance.test.tsx"
pnpm.cmd build
cargo test -p fox-agent-kernel -p fox-engine-protocol
pnpm.cmd protocol:check
cargo test -p fox-agent-backend --features acp
pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite
```

需要验证生产 Runtime 时再执行 `pnpm.cmd runtime:build` 和 `pnpm.cmd runtime:smoke`。完整命令和每个 CI job 的对应关系见[测试指南](测试指南.md)。

## 常见故障

### `tauri` 不是内部或外部命令

确认是在根目录安装的依赖，然后执行 `pnpm.cmd --dir apps/desktop exec tauri --version`。项目依赖的是本地 `@tauri-apps/cli`，不要依赖全局 CLI。

### `Pi Runtime dependencies are missing`

在根目录重新执行 `pnpm.cmd install --frozen-lockfile`。

### 端口 1421 被占用

`start-desktop-dev.mjs` 会报 “Port 1421 is occupied, but it is not the current Fox project's Vite server”。先结束占用的进程，或切到对应的工作树。不要只改一处端口：`apps/desktop/vite.config.ts`、`tauri.conf.json` 的 `devUrl`、`start-desktop-dev.mjs` 必须一起改。

### `test-desktop-rust.ps1` 报 PowerShell 版本

脚本要求 PowerShell 7.4 及以上，请用 `pwsh` 运行，不要用 Windows PowerShell 5.1。

### 测试 exe 出现“拒绝访问”或 `sandbox_unavailable`

人工测试打包出来的 exe 时，必须从普通目录（Medium 完整性）运行，例如 `D:\fox-test\`。不要从带 Low 完整性标签的目录（部分下载、解压目录）运行，否则进程会降为 Low，写不了 `%LOCALAPPDATA%\Fox\state`。详见[调试指南](调试指南.md#windows-人工测试必须以-medium-完整性运行)。

- `pnpm.cmd install --frozen-lockfile` 不改依赖文件。
- `http://127.0.0.1:1421` 能在开发态打开，`pnpm.cmd tauri dev` 能启动 Fox 窗口。

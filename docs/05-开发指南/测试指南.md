# 测试指南

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：前端、Agent Runtime、Rust Host、Kernel、外部 Agent 后端、契约与人工复测<br>
> 最后更新：2026-10-25（命令按 `package.json`、`.github/workflows/windows-ci.yml`、`scripts/test-desktop-rust.ps1` 核对）<br>
> 测试规模、CI 结构和人工复测的全貌见[可观测性与测试架构](../02-架构/可观测性与测试架构.md)；本文只讲“改了什么就跑什么、怎么跑”。

## 结论

- CI 只有一个工作流 `.github/workflows/windows-ci.yml`，全部在 `windows-latest` 上运行，push 到 `main` / `master`、pull request 和手动触发都会跑。
- 手动触发时可以开启**定向模式**（`targeted`），只跑过滤后的 Rust Host 测试和 Runtime 打包检查，用来快速复核某一处修复。
- 本地跑测试的命令和 CI 保持一致：桌面 Host 用 `scripts/test-desktop-rust.ps1`，外部 Agent 后端用 `cargo test -p fox-agent-backend --features acp`，前端用 `bun test`。
- 安装包、真实模型、真实外部 Agent 的验证不在 CI 里，靠人工复测，记录在 `crates/fox-agent-backend/docs/sandbox.md`（目前到 13.29）。
- Windows 上人工测试打包出来的 exe 时，**必须从普通目录（Medium 完整性）运行**，见下文。

## CI 的 job 与本地等价命令

所有命令从仓库根目录执行。

| CI job（超时） | 步骤 | 本地等价命令 | 定向模式 |
| --- | --- | --- | --- |
| `desktop-build`（20 分钟） | 契约 Fixture 校验与自测 | `pnpm.cmd contract-fixtures:verify`、`pnpm.cmd contract-fixtures:test` | 跳过整个 job |
| | 前端测试（排除性能基线） | `bun test ./apps/desktop/tests --path-ignore-patterns "**/a0-performance.test.tsx"` | |
| | 性能基线单独串行 | `bun test ./apps/desktop/tests/a0-performance.test.tsx --max-concurrency=1` | |
| | 构建与类型检查 | `pnpm.cmd build`（`tsc` + `vite build` + 体积预算 + release 隔离检查） | |
| | profile 变体 | `pnpm.cmd --dir apps/desktop build:profile` | |
| `agent-runtime`（60 分钟） | Runtime 全量测试 | `pnpm.cmd runtime:test`（即 `node --test test/*.test.mjs`） | 跳过 |
| | 编译独立 Runtime | `pnpm.cmd runtime:build` | 执行 |
| | 打包后的 Kernel worker 测试 | `$env:FOX_KERNEL_WORKER_BINARY = "<repo>\services\agent-runtime\dist\fox-agent-runtime-x86_64-pc-windows-msvc.exe"; node --test services/agent-runtime/test/pi-kernel-worker.test.mjs` | 执行 |
| `rust-host`（45 分钟） | Kernel 与共享协议 | `cargo test -p fox-agent-kernel -p fox-engine-protocol` | 跳过 |
| | 协议生成物检查 | `pnpm.cmd protocol:check`、`pnpm.cmd protocol:test` | 跳过 |
| | 桌面 Host 测试（不带 Zvec） | `pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite -TimeoutSeconds 1800` | 执行，按过滤器 |
| | Host 性能基线 | `pwsh ./scripts/test-desktop-rust.ps1 -Mode Performance -TimeoutSeconds 300` | 跳过 |
| `agent-backend`（45 分钟） | 外部 Agent 后端（ACP） | `cargo test -p fox-agent-backend --features acp --no-fail-fast` | 跳过 |
| `vector-runtime-smoke`（10 分钟） | Zvec 离线 Smoke（缺官方 DLL 时显式跳过） | `./scripts/zvec-offline-smoke.ps1` | 跳过 |
| `onnx-runtime-smoke`（15 分钟） | ONNX 离线 Smoke（缺完整模型包时显式跳过） | `./scripts/onnx-offline-smoke.ps1` | 跳过 |

说明：

- `test-desktop-rust.ps1` 的 Suite 和 Performance 模式默认用 `--no-default-features` 编译（不带 Zvec、本地 Embedding），加 `-DefaultFeatures` 才带默认特性。它要求 PowerShell 7.4+。
- 两个 Smoke job 是资源门控的：仓库没有官方 `zvec_c_api.dll` / `.lib`，或没有完整的 `manifest.json + model.onnx + onnxruntime.dll` 时，job 成功结束但在摘要里写明“未伪造 Smoke 成功”。所以 job 绿色不等于做过真实 Smoke。
- 各 job 失败时会用 `.github/scripts/ci_failure_summary.py` 把失败测试名写进 job 摘要；Rust Host 的完整日志作为 artifact `rust-host-test-logs` 上传。
- 只改文档的提交，提交信息末尾加 `[skip ci]`。

### 定向模式（targeted）

在 GitHub Actions 页面手动运行 “Windows CI”，或用 GitHub CLI：

```powershell
gh workflow run windows-ci.yml --ref main -f targeted=true -f rust_test_filter="runtime_host::delivery window_resize"
```

- `targeted=true` 时只运行：`rust-host` 里的桌面 Host 测试（按 `rust_test_filter` 过滤），以及 `agent-runtime` 里的 `runtime:build` 和打包 Kernel worker 测试。
- 跳过：桌面 bun、前端构建、`agent-backend`（ACP）、Zvec / ONNX Smoke、Kernel 核心和协议的 cargo 测试、协议检查、Runtime 全量测试、Host 性能基线。
- `rust_test_filter` 是空格分隔的 libtest 名称过滤器（子串，命中任一即运行）；留空表示跑整个 Host 套件。默认值是 `runtime_host::delivery window_resize`。
- 定向模式只用来复核某处修复。改了前端、外部 Agent 后端或协议时，它不能代替完整 CI。

本地的对应写法：

```powershell
pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite -TestFilter 'runtime_host::delivery','window_resize'
```

## 按模块的常用命令

### 前端

```powershell
bun test ./apps/desktop/tests
bun test ./apps/desktop/tests/<文件名>.test.ts
```

测试在 `apps/desktop/tests/`，以模型、工具函数和部分组件测试为主。

### Agent Runtime

```powershell
pnpm.cmd runtime:test
node --test services/agent-runtime/test/<文件名>.test.mjs
```

### 桌面 Rust Host

```powershell
pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite
pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite -TestFilter 'local_knowledge'
pwsh ./scripts/test-desktop-rust.ps1 -Mode Suite -DefaultFeatures
```

脚本负责设置 `LIBSQLITE3_FLAGS` 和 DLL 搜索路径，并只在当前 PowerShell 进程里生效。不经过脚本直接运行 `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml` 可能缺这些设置，结果和 CI 不一致。

### Kernel 与共享协议

```powershell
cargo test -p fox-agent-kernel -p fox-engine-protocol
pnpm.cmd protocol:check
pnpm.cmd protocol:test
```

改了 `crates/fox-engine-protocol` 的类型后，先运行 `pnpm.cmd protocol:generate` 重新生成 JS 产物，再跑 `protocol:check`。

### 外部 Agent 后端（`crates/fox-agent-backend`）

```powershell
cargo test -p fox-agent-backend --features acp
```

- 必须带 `--features acp`；不带时 ACP 客户端和进程启动代码不参与编译。
- `sqlite-tests` feature 额外运行 `tests/host_routing_sqlite.rs`（需要 C 编译器），默认不开，CI 也不开。
- 真实后端测试默认关闭：`FOX_TEST_REAL_ACP=1` 打开真实 pi / Codex / dsh 测试，`tests/sandbox_srt.rs` 的真实 srt 测试标了 `#[ignore]`，需要 `FOX_TEST_REAL_SRT=1` 加 `--include-ignored` 才运行（只加 `--include-ignored` 不设变量会失败）。CI 不设置这两个变量。
- 同一套测试在 Linux 和 Windows 上的计数口径不同，见 `crates/fox-agent-backend/docs/sandbox.md` 12.6 节。

### 离线 Eval 与契约

```powershell
pnpm.cmd runtime:eval
pnpm.cmd contract-fixtures:verify
pnpm.cmd knowledge:verify-preview:test
```

离线 Eval 的口径、Manifest 和对外表述见 [Agent 能力测试基准](Agent能力测试基准.md)。离线 Eval 和 Sidecar Smoke 不在 CI 里。

### Sidecar 构建与 Smoke

```powershell
pnpm.cmd runtime:build
pnpm.cmd runtime:smoke
```

### 真实知识库契约（只在有测试服务时）

```powershell
$env:FOX_KNOWLEDGE_TOKEN = "<token>"
pnpm.cmd knowledge:verify-preview -- --base-url http://127.0.0.1:5010 --kb-id <kb-id> --file-id <file-id>
```

## 改了什么跑什么

| 变更 | 最低要求 |
| --- | --- |
| 纯样式或页面 | `pnpm.cmd build` + 相关前端测试 + 人工看页面 |
| 前端状态、Reducer、Hook | `bun test ./apps/desktop/tests` + `pnpm.cmd build` + 刷新恢复验证 |
| Tauri Command、数据库、迁移 | `test-desktop-rust.ps1 -Mode Suite`（至少按模块过滤）+ 旧库升级 + 备份恢复 |
| Kernel 决策、Host 接线 | `cargo test -p fox-agent-kernel` + Host 定向测试 + 打包 Kernel worker 测试 |
| 引擎协议 | `protocol:generate` → `protocol:check` / `protocol:test` + Kernel 与 Host 测试 |
| Runtime、Prompt、Model Profile | `pnpm.cmd runtime:test` + `pnpm.cmd runtime:eval` + 目标模型的开发环境 Smoke |
| 外部 Agent 后端、路由、沙箱、凭据 | `cargo test -p fox-agent-backend --features acp` + 相关 Host 测试 + Windows 人工复测 |
| 工具权限、审批 | Host 测试 + 人工审批 / 拒绝 |
| 知识库预览 | 前端测试 + Host 测试 + 契约测试 + 大文件取消 |
| 发布配置 | 完整 CI + `tauri:build:windows` + 安装包人工验收 |

## 人工复测

自动化测试覆盖不到的部分（真实外部 Agent、沙箱、安装包、界面）靠人工复测。每一批修复都会在 `crates/fox-agent-backend/docs/sandbox.md` 第 13 节写一份“最小 Windows 复测清单”，目前最新是 **13.29**（删除本机专家行后启动崩溃的修复）。复测结论也记在同一节。

### Windows 人工测试必须以 Medium 完整性运行

- 从普通目录运行 exe，例如 `D:\fox-test\`。
- 不要从带 Low 完整性标签的目录（部分下载目录、解压目录）运行。否则进程会降为 Low，写不了 Medium 标签的 `%LOCALAPPDATA%\Fox\state`，出现和被测修复无关的“拒绝访问”（os error 5）或 `sandbox_unavailable`。13.25 曾因此误判一项回归。
- 不确定时，用 GetTokenInformation 确认进程完整性级别是 `S-1-16-8192`（Medium）。
- 涉及数据的项目，开始前先关闭 Fox 并备份数据目录里的 `fox.db`。

### 对话回归清单

1. 新会话发送后，用户消息立即出现。
2. 模型增量持续到达，不依赖刷新。
3. 思考、工具和审批在完成后仍保留。
4. 重启 App 后，历史和状态与 SQLite 一致。
5. 取消运行后，不再收到属于旧 Run 的增量。
6. 切换会话时，旧事件不会写入新会话。
7. 外部 Agent 会话：权限选项、审批、取消在重启后保持一致。

## 数据与迁移测试

- 使用临时 `FOX_DATA_DIR`，不要操作日常 `fox.db`。
- 迁移只能追加；验证幂等、外键和唯一约束、恢复后的路径重定位。迁移前会自动备份（保留 5 份）。
- 破坏性演练前先备份，恢复后执行 `PRAGMA integrity_check`。

## 已知缺口

- 安装包构建和安装验收不在 CI 中。
- 离线 Eval、Sidecar Smoke、Markdown 链接检查不在 CI 中。
- 没有浏览器端组件或端到端自动化（无 Playwright / Cypress / Puppeteer）；`apps/desktop/scripts/` 下的 smoke 脚本是手工诊断用。
- CI 只跑 Windows。`#[cfg(unix)]` 的测试（例如本机资料库目录权限降级）在 CI 里从未执行。
- 真实外部 Agent 和 srt 沙箱的测试默认关闭，靠人工复测。
- 没有跨 Provider 的真实模型 Eval Runner。

# 测试指南

> 状态：生效<br>
> 适用版本：Fox 0.1.0<br>
> 维护范围：前端模型、Runtime、Rust Host、外部契约与发布回归<br>
> 最后更新：2026-09-22<br>
> 基线、成熟度口径（已实现/已提交/已推送/已发布/已验收）与证据分级见[当前状态与核验基线](../01-项目概览/当前状态与核验基线.md)。

## 目标与范围

Fox 的风险集中在跨进程事件、SQLite 恢复、文件权限、外部服务契约和大型文档预览。测试应覆盖实时路径与刷新恢复路径，不能只验证页面最终能显示。

## 测试分层

| 层级 | 当前工具 | 主要范围 |
| --- | --- | --- |
| 前端模型测试 | Bun Test | Event Reducer、附件、文档活动、预览模型与数据源 |
| Runtime 测试 | Node Test | JSONL 协议、事件映射、会话、工具目录、适配器契约 |
| Agent 离线评测 | Node Runner + JSON Fixture | 模型画像、工具契约、注入隔离和意图回归 |
| Rust 单元/集成测试 | Cargo Test | SQLite、命令、权限、Runtime Host、MCP、知识库、维护功能 |
| 脚本契约测试 | Node Test | 知识库原文件 HEAD/Range 契约 |
| Sidecar 冒烟 | 编译 EXE + Node 驱动 | 独立 Runtime 握手、会话、流式事件和退出 |
| 人工桌面验收 | Tauri dev/release | 窗口、流式 UI、审批、恢复、文件预览与安装包 |

## 常用命令

从工作区根目录执行。

### 前端测试

```powershell
bun test ./apps/desktop/tests
```

当前测试文件位于 `apps/desktop/tests/`，主要覆盖：

- `runtime-event-reducer.test.ts`
- `knowledge-preview-source.test.ts`
- `knowledge-preview-model.test.ts`
- `document-activity.test.ts`
- `attachment-content.test.ts`
- `agent-initialization.test.ts`
- `project-access-dialog-state.test.ts`

文件会随功能增加；以目录和当前测试输出为准，不以本列表作为完整清单。

### Runtime 测试

```powershell
pnpm.cmd runtime:test
```

底层命令为 `node --test test/*.test.mjs`，测试目录位于 `services/agent-runtime/test/`。

### Agent 离线评测

```powershell
pnpm.cmd runtime:eval
```

当前评测位于 `services/agent-runtime/evals/`，包含：

- 模型与 Provider 适配矩阵；
- BFCL 风格 Runtime Tool Contract；
- SWE-bench 风格编码 Agent 能力链；
- AgentDojo 风格 Prompt Injection 隔离；
- Fox Planner 与 Goal 意图回归。

2026-08-24 基线为 5 个套件、35/35。它验证的是 Fox Harness 的确定性契约，不等同于官方 BFCL、AgentDojo、SWE-bench 或其他模型排行榜成绩。

完整的基准身份、35 条用例构成、对外引用口径和真实模型评测方法见[Agent 能力测试基准](Agent能力测试基准.md)。

### 真实模型质量评测

修改 Model Profile、System Prompt、Runtime Contract、Planner 或 Tool Catalog 后，除离线 Eval 外，还必须使用目标模型运行受控 Smoke。至少覆盖普通问答、粘贴文本不误建 Goal、明确 Goal 请求、多文件工具任务、真实审批、知识引用、reasoning 隔离和取消/恢复。

每个模型必须记录 Provider/API、精确模型 ID、Prompt Hash、Tool Catalog Hash、Runtime Commit、采样配置、重复次数、任务成功率、工具与参数准确率、Goal 误触发/漏触发、引用正确率、推理泄漏、延迟和 Token。真实模型结果不得与离线 35/35 合并成一个分数。

### Rust 测试

```powershell
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

指定测试名称：

```powershell
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml preview_cache
```

显示被捕获输出：

```powershell
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml -- --nocapture
```

### 知识库预览契约测试

```powershell
pnpm.cmd knowledge:verify-preview:test
```

该测试不访问真实服务，只验证参数、URL 和响应头规则。

### 真实知识库契约

仅在有测试服务和 Token 时执行：

```powershell
$env:FOX_KNOWLEDGE_TOKEN = "<token>"
pnpm.cmd knowledge:verify-preview -- --base-url http://127.0.0.1:5010 --kb-id <kb-id> --file-id <file-id>
```

脚本验证原文件 `HEAD`、`Accept-Ranges: bytes`、`X-Source-Revision` 和严格 `206 Content-Range`，不会调用 Office 转换。

Rust 还保留可选真实服务测试变量：

- `FOX_TEST_YUXI_URL`
- `FOX_TEST_YUXI_TOKEN`
- `FOX_TEST_YUXI_PREVIEW=1`
- `FOX_TEST_YUXI_KB_ID`
- `FOX_TEST_YUXI_FILE_ID`

这些变量只用于本地/受控环境，不能提交真实值。

### Sidecar 构建与冒烟

```powershell
pnpm.cmd runtime:build
pnpm.cmd runtime:smoke
```

冒烟测试会启动 `services/agent-runtime/dist/fox-agent-runtime-x86_64-pc-windows-msvc.exe`，完成初始化、创建会话、发送 faux prompt、接收增量与完成事件，然后正常关闭。

## 对话回归清单

1. 新会话发送消息后，用户消息立即出现。
2. 模型增量持续到达，不依赖刷新。
3. Reasoning、Tool 和审批在完成后仍保留。
4. 关闭并重启 App 后，SQLite 历史与状态一致。
5. 取消运行后不再接收属于旧 Run 的增量。
6. 切换会话时旧事件不会写入新会话。
7. 需要用户补充时显示交互抽屉，提交后恢复运行。

## 数据与迁移测试

- 使用临时 `FOX_DATA_DIR`，不要操作日常 `fox.db`。
- Fixture 同时包含空库、历史会话、运行中 Run 和异常 Event。
- 验证迁移幂等性、外键/唯一约束、恢复后的内部路径重定位。
- 破坏性演练前创建 `.foxbackup`，恢复后执行 SQLite `PRAGMA integrity_check`。

## 已知缺口

「门禁存在」与「门禁通过」是两件事，必须分开记录：

### 已存在（可核对的路径）

- `.github/workflows/windows-ci.yml`，5 个 job：`desktop-build`（20 分钟）、`agent-runtime`（60 分钟）、`rust-host`（45 分钟）、`vector-runtime-smoke`（10 分钟）、`onnx-runtime-smoke`（15 分钟）。触发条件为 push 到 `main`/`master`、pull request 与手动 dispatch。
- `desktop-build` 覆盖契约 Fixture 校验、桌面测试（性能基线单独串行）、前端构建与 profile 变体隔离检查。
- `rust-host` 覆盖 `fox-agent-kernel` + `fox-engine-protocol`、协议生成 `--check`、协议 JS 测试和 Rust Host 测试（含 `--no-default-features` 路径）。
- `agent-runtime` 覆盖 Runtime 测试、Sidecar 构建，并用真实打包 worker 跑一次 Kernel worker 测试。
- 两个 smoke job 是**资源门控**的：仓库缺少官方 `zvec_c_api.dll`/`.lib` 或缺少完整 ONNX `manifest.json + model.onnx + onnxruntime.dll` 时，job 显式跳过并写明「未伪造 Smoke 成功」。

### 尚未通过或尚未纳入（不得写成已完成）

- **本次核验未联网、未运行远端 CI**，因此只记录「job 存在」，不记录任何「CI 通过」结论。远端是否对当前 HEAD 跑过、结果如何需另行核对。
- 安装包构建与安装包验收不在 CI 中；`tauri:build` / `tauri:build:windows` / `tauri:build:kernel-preview` 仍需人工执行并留痕。
- Sidecar Smoke（`runtime:smoke`）、离线 Eval（`runtime:eval`）、Markdown 链接检查、`git diff --check` 尚未全部进入同一持续门禁，属发布回归清单的人工步骤。
- 仓库尚无统一 `test` 根脚本，完整矩阵需要逐条执行。
- 前端目前以模型/工具函数测试为主，**缺少浏览器端组件与端到端自动化**。检查范围：根 `package.json`、`apps/desktop/package.json`、`services/agent-runtime/package.json` 三份清单中均无 Playwright/Cypress/Puppeteer；`apps/desktop/scripts/` 下的 `prof-smoke.mjs`、`realapp-smoke.mjs`、`webview2-smoke.mjs`、`html-preview-smoke.mjs` 是手工/诊断脚本，未接入 CI。
- 尚无跨 Provider 的真实模型 Eval Runner 和版本化结果库。
- 最低受支持 Node、Rust、Bun 与 Windows 版本尚未固化。
- 跨平台（非 Windows）测试未建立。

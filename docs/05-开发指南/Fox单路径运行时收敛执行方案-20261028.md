## 一 目标与范围

新 Run 只走一条正式路径：**一个 Legacy sidecar 进程里运行多个 Pi `AgentSession`，Pi 推进 Agent 循环和上下文压缩；Fox Host 负责准入、批内工具调度、审批、执行台账、取消和恢复。**

完成标准：

1. 新 Run 只有一个入口，`FOX_KERNEL_MODE` 不再影响新 Run。
2. 混合工具批次按“只读前缀最多 4 个并行，写入和未知工具作屏障”执行，顺序由 Host 控制。
3. 至少 2 个会话可以同时运行，互不阻塞、互不串话；同一会话不并发写入。
4. 进程重启后，打开会话前先与 Host 台账对账；结果不明的调用不会自动重做。
5. Kernel 模型 Worker、Kernel 循环和 Kernel 压缩已删除（约 4163 行，见附录 A）；旧 Kernel Run 只保留可读的历史和受控的中断状态。

不在范围内：Yuxi 和 ACP 外部 backend（盘点确认它们不经过 `state.worker`，见 PART-B §Q1.4）、联系人功能本身、通信协议和进程模型之外的重写。

### 一次工具批次的完整流程

1. Pi 产出 assistant 消息。第一个 `beforeToolCall` 调用 `tool_batch.register`，内容包括 run_id、代次、全部 call_id、工具名、源顺序和原始参数摘要。Host 落盘后返回确认，后续钩子等待同一个 Promise。
2. 准备阶段中，没有执行的位置会收到 `tool_execution_end`，适配层随即调用 `tool_call.close(reason, isError)`。
3. Pi 启动 `Promise.all`，每个受管工具的 `execute` 调用 `tool_call.execute`，提交 call_id 和 **SDK 转换后的有效参数**。审批绑定的是有效参数。
4. Host 先按屏障规则等待前序位置结算，再领取调用、检查取消状态、重新验证审批，然后执行并提交完整结果，最后把结果返回给代理。
5. 中止时，代理调用 `tool_call.cancel` 并抛错。Host 保留已产生的结果作为证据，但这个结果不会以成功形式回到 Pi。
6. `turn_end` 时，适配层把从未出现过事件的位置关闭为 `not_started`。

## 三 不变量

1. 每个会话代次只有一个 Pi 写入者。同一会话同一时刻只有一个活动 Run。
2. Pi 只能调用受管代理。sidecar 创建会话时 `tools: []`，内置的文件和 Shell 执行器不可用。
3. `beforeToolCall` 只等待登记，不等待任何结算。
4. Host 先提交结果再返回 Pi。只存在于 Pi JSONL 而 Host 没有提交记录的结果，按一致性错误处理。
5. 取消之后的返回一律为失败。
6. 已领取、结果不明的写入、命令和外部请求不自动重做，也不用新 call_id 重做。
7. 打开会话时先对账，再接受新的提示。
8. 正确性不依赖 Pi 内部行为：`transformMessages`、订阅顺序、`entry_appended`、`durationMs` 都只能用于诊断。
9. 带新路由的记录在旧二进制上安全失败；新二进制读旧记录时，规范 JSON 和 `binding_hash` 保持不变。
10. 模型请求、压缩、重试、中止后的空转请求和工具耗时都计入同一份 Host 预算。

### S3 打开时对账与恢复（4–6 天）

改动：

- `pi-runtime.mjs` 的打开路径（`SessionManager.open`，约第 1019 行）：在接受新提示之前，扫描活动分支上的孤立 toolCall，向 Host 查询 `tool_call.facts`，然后按下表处理。

| --- | --- | --- |
| 已提交 | `appendMessage` 补交原结果 | 可以继续 |

## 五 停止条件

| 阶段 | 触发条件 | 处理 |
| --- | --- | --- |
| S2 | 仓库内复现不了 P1 的时间线，或审批无法绑定有效参数 | 停止迁移，保留 Kernel，修订适配方案 |
| S2 | 某个现有工具必须使用 Pi 内置执行器 | 先把该工具改为受管代理；做不到就不开放 `PiNative` |
| S3 | P4 形态的“branch 后补交”失败 | 改为 `branch()` 回到 assistant 之前（D7 备选） |
| S3 | 两种补交方式都无法得到合法上下文 | 该 Run 只能标为 interrupted，不能继续；如果这种情况在测试中频繁出现，暂停 S5 |
| S4 | 进程级状态无法按 Run 隔离 | 改为 N 进程池（D1 备选），协议不变 |
| S5 | 离线 faux 夹具中，热会话首字或整轮耗时比 Kernel 慢超过 10% | 暂停切换，先定位原因（10% 为初始门槛） |

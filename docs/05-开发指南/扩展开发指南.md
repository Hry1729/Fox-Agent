# 扩展开发指南

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：页面、Tauri Command、模型供应商、Skills、MCP、Runtime 工具与外部 Agent 后端<br>
> 最后更新：2026-10-28（单 Pi 分支同步；本轮未复跑产品测试）

## 目标与范围

本文说明如何在不绕过 Fox 数据、安全和恢复边界的前提下扩展能力。优先选择已有扩展点；只有现有契约不能表达需求时才增加新的 Host/Runtime 协议。

## 新增前端功能

推荐结构：

```text
apps/desktop/src/features/<domain>/
├─ <domain>-pages.tsx            # 页面组合
├─ use-<domain>.ts               # 状态、Command 与事件生命周期
├─ <domain>-model.ts             # 纯状态转换
└─ <domain>-*.tsx                # 领域组件
```

步骤：

1. 在 feature model 定义可独立测试的状态与转换。
2. 通过 API adapter 调用 Tauri Command，不在纯展示组件中直接 `invoke`。
3. 在 Hook 中注册/释放 Tauri listener、Timer、AbortController 和第三方实例。
4. 复用 `components/ui/`、`components/ai-elements/` 和现有 CSS Token。
5. 为加载、空、错误、取消、刷新恢复与窄窗口提供状态。
6. 为重型页面使用动态导入。

## 新增 Tauri Command

1. 在 `database/models.rs` 定义 request/response，前端结构统一 `camelCase`。
2. 在 Repository 或领域模块实现核心行为，不把全部逻辑堆入 Command。
3. 在 `commands/mod.rs` 做输入校验、权限校验和稳定错误映射。
4. 在 `lib.rs` 的 `generate_handler!` 注册命令。
5. 在前端 client 增加唯一调用入口和 TypeScript 类型。
6. 添加 Rust 测试及前端调用/恢复测试。
7. 更新 Command 与错误参考文档。

涉及路径、网络或凭证时，必须使用已有规范化、HTTPS/局域网判断、系统凭证库与路径授权能力。

## 新增模型供应商

Fox 自己的 Agent（Kernel 路径）的连接协议只有两种：

- `openai-completions`
- `anthropic-messages`

自 v97 起，一个供应商可保存多份协议（`protocol_profiles`），连接测试支持 Completions、Messages 和 Responses。旧外部驱动协议映射保留兼容；协议连接测试成功不代表退休驱动恢复，也不等于 Pi 全部协议组合已通过桌面验收。详见[智能体与模型架构](../02-架构/智能体与模型架构.md)。

供应商配置包含 URL、协议、多个模型、上下文长度、最大输出、图片能力和默认模型。模型 API Key 以规范化 Base URL 为键保存到系统凭据库，服务名为 `com.fox.agent.model`，同一 Base URL 的 Fox 和各外部 Agent 共享同一把 Key；协议单独配置的 Key 用 `fox-protocol:<provider>:<profile>` 作键。

新增协议需要同步修改：

1. `model_service.rs` 的连接测试、URL 规则和请求格式。
2. `commands/mod.rs` 的协议枚举与参数范围。
3. 数据库默认供应商/模型和迁移策略。
4. Runtime 的 Provider 注册与 Sidecar bundler 导入。
5. 设置页面协议选择、默认值与错误提示。
6. 单元测试、真实连接测试和 Runtime adapter contract。

不要仅在前端加一个下拉项；Runtime 不认识的协议必须被 Host 拒绝。

## 新增 Skill

Fox 从应用数据目录的 `skills/<skill-id>/SKILL.md` 扫描 Skill。文件最大 128 KB，目录下必须存在 `SKILL.md`。

示例：

```markdown
---
id: research
name: 研究助手
description: 使用证据完成研究任务
version: 1.0.0
required_tools: [read, grep, search_knowledge]
---

先确认问题范围，再收集证据并标明来源。
```

约束：

- ID 只能包含字母、数字、`-`、`_`。
- ID 必须唯一；重复 ID 会标记为无效。
- 正文不能为空。
- `required_tools` 必须属于 `skills.rs` 的支持目录。
- Skill 只有在有效且由具体 Agent 启用时才注入提示词。

新增工具后若希望 Skill 声明该工具，还需要更新 `SUPPORTED_TOOLS` 并添加校验测试。

## 新增 MCP Server

MCP 支持两种传输（`mcp.rs` 的 `transport`）：本机 `stdio` 和 `streamable_http`。共同参数：

- 协议初始化版本：`2025-03-26`。
- 工具枚举：`tools/list`。
- 工具执行：`tools/call`。
- 单次请求超时：生产 15 秒。
- 最大工具数：200。
- 环境变量保存在 Windows Credential Manager，服务名 `com.fox.agent.mcp`。
- `call_mcp_tool` 始终需要用户审批。

MCP Server 配置包括名称、命令、参数、环境变量和启用状态。Server 必须返回合法 object 类型 `inputSchema`；Fox 会拒绝未声明的工具。

旧版独立 GET+SSE MCP、MCP Resource / Prompt / OAuth 仍未实现（见[已知限制](../07-路线图/已知限制.md)）。上面“15 秒 / 200 个工具”的数字沿用原文，本次没有逐条核对。

## 新增 Runtime 工具

这是高风险跨进程改动，必须同步更新：

1. 工具契约（`RUNTIME_TOOL_CATALOG`）的事实源已移到 `crates/fox-engine-protocol/src/lib.rs`，由 `pnpm protocol:generate` 导出到 `packages/fox-engine-protocol/`，`runtime-contract.mjs` 只是重新导出。改完运行 `pnpm protocol:check`。
2. Runtime 工具实现与注册顺序。
3. `apps/desktop/src-tauri/src/runtime_host/protocol.rs` 的能力验证，以及 Kernel 路径的 `runtime_host/kernel_gateway.rs` `SUPPORTED_TOOLS`。
4. Rust Host 的请求分派、参数校验、审批和审计记录。
5. Skill 支持目录（若允许 Skill 声明）。
6. 专家工具清单、内建 Agent 默认 `allowedTools` 与插件中心卡片说明。
7. JS/Rust 契约测试与 Sidecar smoke。

工具需要明确：

- category：`project-read`、`project-write`、`attachment`、`process`、`knowledge`、`skill` 或 `mcp`。
- execution：`runtime`、`host` 或 `remote`。
- approval：`none`、`preflight`、`policy` 或 `always`。

主机写入、命令和 MCP 调用不能通过提示词“约定安全”，必须由 Rust Host 执行权限和审批。

## 复用 Pi 工具与工具扩展

Fox 使用 `tool-adapter.mjs` 隔离 Fox Tool Definition 与 Pi Custom Tool。已有 Pi 工具若提供 `name/label/description/parameters/execute`，可以复用其名称、说明和参数 Schema，也会保留 `promptSnippet`、`promptGuidelines`、`prepareArguments` 和 `executionMode`；Pi TUI 的 `renderCall/renderResult` 不进入 Fox Headless Runtime，工具也不能默认继承原执行权限。

Host 执行模式示例：

```js
import { adaptPiToolToFox } from './tool-adapter.mjs'

const foxTool = adaptPiToolToFox(piTool, {
  source: 'vendor/package-name',
  hostExecutor: ({ tool, toolCallId, input, signal }) =>
    requestHost('tool.execute', { tool, toolCallId, input }, signal),
})
```

接入要求：

1. 核对扩展许可证以及与 `@earendil-works/pi-* 1.4.0` 的 API 兼容性。
2. 默认使用 Host executor；文件写入、命令、网络和凭据能力不得直接在 Runtime 执行。
3. 在 `RUNTIME_TOOL_CATALOG`、Rust Host Handler、Skill 支持目录和插件目录中注册稳定工具名。
4. 只有随应用发布并完成代码审查的纯 Runtime 工具才能设置 `execution: runtime, trusted: true`。
5. 只注册工具的同步 Pi Extension 可使用 `collectTrustedPiExtensionTools`；依赖生命周期 Hook 的扩展需要单独实现 Fox Extension Adapter。
6. 增加工具转换、重复名称、未知 Schema、审批、取消和 Host 拒绝测试。

禁止根据用户提供的本地路径直接 `import()` 扩展模块。适配器只负责接口和执行边界转换，不提供 JavaScript 沙箱，也不代表扩展已获得信任。

Pi 版本升级只修改 `pi-adapter.mjs`、三个锁定依赖和必要的适配测试。不得在其他 Runtime 源文件新增 `@earendil-works/pi-*` 直接导入；若上游扩展依赖新的生命周期 Hook，应扩展 Fox Adapter，而不是绕过 Host 权限边界。

通用 Host 能力放在 `apps/desktop/src-tauri/src/runtime_host/capability_tools.rs`，不要塞入基础文件写入模块 `tool_host.rs`。新增网络工具必须实现协议限制、DNS 与每次重定向的 SSRF 校验、超时、响应大小上限、凭据隔离和审批；新增进程工具必须使用程序名与参数数组直接启动，禁止拼接 Shell 字符串，并限制工作目录、超时和输出大小。非零测试/检查退出码应作为结构化结果返回，只有启动失败、超时或协议错误才作为工具执行失败。

当前 `web_search` 默认可直接使用 DuckDuckGo HTML 搜索，不要求用户注册额外搜索 API Key。以下 Host 环境变量仅用于覆盖默认搜索或接入 Fox 托管服务：

| Provider | 环境变量 |
|---|---|
| Brave Search | `BRAVE_API_KEY` |
| Tavily | `TAVILY_API_KEY` |
| Exa | `EXA_API_KEY` |
| SearXNG | `FOX_SEARXNG_URL` |

这些值不得出现在 Tool Schema、Tool Input、审批 Request、Run Event 或日志中。`provider=auto` 按 Brave、Tavily、Exa、SearXNG 顺序选择首个已配置 Provider，均未配置时使用 DuckDuckGo。公共 HTML 搜索只能作为开箱即用兜底，需保留限流和页面结构变化的错误提示；后续 Fox 托管搜索网关应继续复用相同工具协议。

## 新增 Runtime 能力字段

当前 Capability Manifest 版本为 2（`crates/fox-engine-protocol` `CAPABILITY_MANIFEST_VERSION`），包含流式文本、取消、Reasoning、Session Resume、Tool Approval、图片输入、Steering、上下文压缩、动态模型切换、`workLoop` 和工具目录。Host 继续兼容 v1，但 v1 不开放 Work Tool。

破坏性字段变化应提升 Manifest 版本，并在 Rust crate 修改后重新生成 JS，同时更新握手校验、降级策略和测试。旧 Runtime 能力缺失时，前端应禁用入口，而不是运行时失败。

## 新增知识库能力

知识库服务由 Rust 适配，前端不直接持有 Token。新增原文件或检索能力时：

- 先定义服务端契约和版本标识。
- Host 校验会话已绑定目标知识库。
- 下载和预览支持取消、限流、大小上限及 `.part` 原子写入。
- 远程响应视为不可信输入。
- 更新真实契约校验脚本和测试。

若需求需要修改外部知识库后端，应单独记录后端契约，不把尚未实现的服务端能力写成 Fox 当前能力。

## 外部驱动扩展边界

当前单 Pi 分支不提供外部驱动或自定义 ACP Agent 的新增入口。旧枚举、ACP 兼容命令和配置仍可能存在，但 `BackendSwitch` 在入口拒绝退休后端；清空 HIDDEN 列表或修改环境变量不能启用。

新增驱动属于新的架构决策，需要重新确定路由、权限、持久会话、升级与验收契约。旧四 Agent 方案与 `crates/fox-agent-backend/docs/` 只供历史追溯，不是当前扩展步骤。模型供应商、Skills、MCP 和 Host 工具继续使用本页对应扩展点。

当前优先项为阶段二与 C gap，见[单 Pi 主线状态](../01-项目概览/单Pi主线状态.md)。

## 扩展验收

- 能力可发现、可配置、可禁用。
- 配置与凭证分离。
- 失败、超时、取消、拒绝和重启恢复有定义。
- Runtime/Host/SQLite/UI 数据一致。
- 未支持能力能清晰降级。
- 自动测试和常青文档同步。

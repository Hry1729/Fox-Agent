# 术语表

> 状态：生效<br>
> 适用版本：Fox `0.1.x`<br>
> 维护范围：产品、架构和界面统一术语<br>
> 最后更新：2026-10-28（单 Pi 分支同步；本轮未复跑产品测试）

## 结论

Fox 里有两层“Agent”，最容易混淆：

- **会话后端**（`agent_backend`）：创建时冻结；当前只准入 `fox`，其余旧值保留为只读历史。
- **Fox 会话内的 Agent**（`agent_id`）：只在 `fox` 会话里有意义，指 Assistant / Expert / Worker 等配置记录，由它的 `runtime_type`（`pi` / `yuxi`）决定走本地还是远程。

另有 Kernel 的 `engine_id`：当前只执行 `pi`，`codex` / `deepseek_harness` 仅作为历史值保留。它与会话后端、Runtime 类型、执行权不同。

## Agent 与执行

| 术语 | 定义 |
| --- | --- |
| Fox | 本项目的桌面智能体产品；也是默认且目前唯一可用的外层 Agent 后端 `fox`（由内置 PiNative 执行；Kernel 执行循环已删除）。 |
| 外层 Agent 后端（`agent_backend`） | v95 的会话冻结标识；新会话为 `fox`，旧 `pi/codex/deepseek` 只读，不能改绑。 |
| 外部 Agent | 本文指旧会话后端 `pi/codex/deepseek`；本分支已退休，不能执行。Yuxi 远程服务不在此列。 |
| DeepSeek Harness（dsh） | 已退休的外部驱动；其 Kernel 模型引擎也不再执行。历史记录保留。 |
| pi | 当前本地 SDK 与 Kernel 引擎；旧 `agent_backend=pi` 则是已退休的外部 ACP 路由，两者不能混用。 |
| Codex | 已退休的会话级外部驱动和 Kernel 模型引擎；历史值仍可读，不表示可执行。 |
| 自定义 ACP Agent | 计划中的通用入口：用户自行安装 ACP Agent 并填写启动命令。**尚未实现**。 |
| ACP | Agent Client Protocol。Host 使用官方 Rust 库 `agent-client-protocol` 作客户端。 |
| srt | 旧的沙箱运行时（sandbox-runtime）。已在 A1、B2 删除，Fox 不再用沙箱；仅在旧机器升级时用于卸载 Fox 当年安装的 SRT。 |
| Fox Job | Fox Host 运行命令的进程容器：Windows 用 Job Object，其他平台用进程组；只负责超时、取消和清理整棵进程树，不限制文件和网络访问。 |
| 审批四档 | 只读 / 询问 / 自动 / 完全访问。存储为 `permission_mode`（`allow` 即「自动」）加 `conversations.full_access`。 |
| 前缀规则 | `permission_rules` 中按命令 token 前缀匹配的项目规则（allow / ask / block）；复合命令逐段检查。 |
| 原生权限 | 旧外部 Agent 自己的权限选项。当前退休后端无可用执行入口；内置本地执行使用项目权限与 Host 审批。 |
| 完全访问 | 旧外部驱动的权限/授予概念；本分支不提供对应的新会话入口，兼容数据保留。 |
| `FOX_EXTERNAL_BACKENDS` | 旧部署取值解析与诊断变量，不能重新启用退休驱动。 |
| Kernel | Fox 会话的执行决策核（`crates/fox-agent-kernel`）。 |
| 执行权（ExecutionAuthority） | 每个 Fox Run 冻结的执行模式：`Authoritative`（默认）或 `Legacy`。选择顺序：已冻结绑定 > `FOX_KERNEL_MODE` > Authoritative。 |
| Legacy | `FOX_KERNEL_MODE=legacy` 时的旧执行路径，只用于调试和兼容旧 Run。 |
| Shadow | Legacy Run 上挂的 Kernel 观察路径，只写 shadow 表；清理属于四 Agent 方案阶段 4，尚未开始。 |
| `engine_id` | Kernel 模型引擎标识，当前仅 `pi` 可执行；其他引擎配置返回 `kernel_engine_retired`。 |
| Agent Runtime | 独立 Node 进程（`services/agent-runtime`），负责模型循环、Prompt 组装和工具请求，不直接拥有 Fox 产品状态。 |
| Runtime Host | Tauri/Rust 中启动 Runtime、协调 Kernel、执行 Host Tool 和持久化状态的组件（`apps/desktop/src-tauri/src/runtime_host`）。 |
| Sidecar | 随安装包分发、由 Tauri 管理的 Runtime 可执行进程。 |
| Runtime Session | Runtime 保存的执行上下文检查点（`runtime-sessions/`），不是会话事实源。 |
| JSONL 协议 | Host 与 Runtime 之间一行一个 JSON 对象的进程通信协议。 |
| 引擎协议 | Kernel 与模型引擎 worker 之间的协议（`crates/fox-engine-protocol`、`packages/fox-engine-protocol`）。 |
| 能力清单 | Runtime 初始化时声明的协议版本、流式、恢复、审批、多模态和工具能力集合。 |
| 能力声明（外部 Agent） | 外部后端按“审批覆盖 / 沙箱范围 / 取消能力 / 可观测性”四个维度声明的能力，显示在后端栏。 |

## Fox 会话内的 Agent

| 术语 | 定义 |
| --- | --- |
| 智能体（Agent 记录） | Assistant、Expert 与 Worker 的统一配置记录，可以来自本机或知识库服务。 |
| `runtime_type` | Agent 记录的运行类型：`pi`（本地）或 `yuxi`（远程知识库 Agent）。 |
| Assistant（助手） | Fox 会话的基础执行者；使用 `primary/chat_selector`。 |
| Expert（专家） | 按会话绑定的专业 Persona 与能力包；使用 `inline/expert_center`。 |
| Worker（工作成员） | 只供工作流或父 Agent 调度的隐藏子智能体；使用 `child/hidden`。 |
| 专家绑定 | 会话与 Expert 之间可恢复、可追踪的独立绑定；不改变基础助手。 |
| 专家能力包 | `.foxexpert` 包；Run 启动时组装专家 Prompt、Skills、Tools、MCP 和知识资源描述，不能扩大 Host 权限。 |
| Fox 通用助手 | 内置的默认 Assistant。 |
| 知识助手 | 由知识库服务提供的远程 Agent（`runtime_type = yuxi`）。 |
| Child Run | 父 Run 委派出的独立子运行，深度 1，有时长上限，权限取交集。 |
| Execution Profile | 决定一个 Run 能看到哪些工具、能否写入、能否委派以及验证策略的配置。 |

## 会话与工作

| 术语 | 定义 |
| --- | --- |
| 工作台 | Fox 主窗口的整体交互容器，代码入口为 `Workbench`。 |
| 项目 | 用户授权给 Fox 的本地目录，以及关联的会话和权限。外部 Agent 会话必须绑定项目才能运行。 |
| 项目权限 | Fox 会话的项目权限模式：只读 / 询问 / 允许。在 设置 → Agent →「项目权限」管理。 |
| 会话 | 用户与 Agent 持续交互的产品级记录，是消息、运行和附件的容器。 |
| 消息 | 会话中的用户输入、助手回复或结构化内容。 |
| Run | 一次用户请求对应的执行实例，有排队、运行、等待、完成、失败或取消等状态。 |
| 工具 | Agent 可请求的具体操作，如读取文件、写文件或查询知识库。 |
| Host Tool | 必须回到 Tauri Host 执行的工具。 |
| 固定能力工具 | `git_read`、`test_run`、`code_check`、`format_code`：由 Host 生成固定的程序和参数运行，不经 Shell。 |
| 审批 | 用户或策略对工具调用作出的允许、拒绝或等待决定。 |
| Goal / Task / Evidence | 工作闭环中的目标、工作项和证明 Task 已执行的事实（工具调用、文件差异、测试结果、产物或用户确认）。 |
| Graph Lead | 有界只读任务图：最多 3 个节点、深度 1。 |
| Reviewer | 隐藏的只读审查者，只能使用 `read` / `ls` / `find` / `grep`。 |
| Acceptance | Host 对节点或 Goal 的最终验收。 |
| 产物（Artifact） | Agent 生成或修改的可交付结果；中文界面和文档优先称“产物”。 |
| 引用 | 回复与资料、网页或其他来源之间的可追溯关联。 |
| Trace | 关联 Run、事件和工具调用的诊断标识。 |

## 资料、扩展与数据

| 术语 | 定义 |
| --- | --- |
| 本机资料库 | Fox 自己的本地资料库（界面侧栏模式名为「资料」），独立 SQLite + ONNX + Zvec。 |
| 知识库服务 | Fox 连接的外部知识与远程 Agent 服务，代码模块名保留为 `yuxi`。 |
| 知识库 | 知识库服务中的资料集合，可以绑定到会话。 |
| 知识图谱 | 知识库服务提供的实体、关系、标签和统计数据的图形化视图。 |
| 预览缓存 | 远程原文件的本地受控缓存，位于 `<data>/cache/knowledge-preview`。 |
| 附件 | 用户随消息上传、由 Fox 管理的文件副本。 |
| 模型供应商 | 提供模型 API 地址、协议、密钥和模型目录的服务配置；一个供应商可以配多个协议（`protocol_profiles`，v97）。 |
| 默认模型 | 未被 Agent 或会话覆盖时 Fox 会话使用的模型。 |
| Skill | 可发现、可启停的能力说明或工作流扩展。 |
| MCP | Model Context Protocol，连接外部工具服务；调用仍受 Fox 配置和审批控制。 |
| 策略（声明式 Hooks） | 生命周期 Hook，在插件中心「策略」或 设置 →「插件」→「策略」管理。 |
| 产品事实源 | 决定用户可见状态的权威数据源，即 `fox.db`（schema v98）。 |
| 启动降级 | 可恢复的启动问题（资料库存储、预览缓存、缺失的 Agent 行）不阻止启动，以只读 / 不可用 / 推迟报错 / 修复处理。 |
| 「Fox 无法启动」 | 无法降级的启动错误（如主库打不开）在 Windows 上弹出的系统对话框标题；非 Windows 只记日志。 |

## 用词约定

- “本机”指 Fox 桌面端及本地进程；“知识库服务”指外部服务。
- “后端”必须说明是 Tauri Host、外层 Agent 后端、Agent Runtime 还是知识库服务。
- 说“pi”时要说明是外部 Agent `pi`、`runtime_type = pi` 还是 `engine_id = pi`。
- “工作过程”指可审计的事件与工具步骤，不称为模型的完整思维链。
- “恢复”指从 SQLite、Runtime Session 或远程状态重新构造一致状态，不等同于刷新页面。

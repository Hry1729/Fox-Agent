## 2. 结论成熟度与证据分级

### 2.1 成熟度词汇（不可互相代替）

| 词汇 | 含义 | 反例（不能这样写） |
| --- | --- | --- |
| 已实现 | 当前 `main` 源码里存在该行为，且能从代码路径读出 | 只有设计文档或方案 |
| 已提交 | 该改动在某个 Git 提交中 | 只在某人工作区 |
| 已推送 | 该提交在远端仓库 | 只看本地 `origin/*` 引用 |
| 已发布 | 有对外可获取的发布物，能指出版本与哈希 | 本地 `target/` 里有 exe |
| 已验收 | 有与**该发布物哈希**对应的验收记录 | 单元测试通过；旧版本录屏 |

「测试通过」不等于「已验收」；「已提交」不等于「已推送」；「已推送」不等于「已发布」。

### 2.2 证据分级

从低到高：

1. **源码实现**：读当前 `main` 的源码或配置。
2. **定向测试**：针对该行为的自动化测试（bun / `node --test` / `cargo test`）。
3. **GUI 手工验收**：在真实桌面界面操作并留痕（如 `crates/fox-agent-backend/docs/sandbox.md` 第 12、13 节的复测清单与结论）。
4. **真实云模型验收**：使用真实供应商凭据的端到端任务。
5. **安装包验收**：在干净或隔离环境安装带哈希的安装包后验收。
6. **跨平台 / 生产验收**：非 Windows 平台或真实企业环境验收。

低层级证据**不能**推出高层级结论。

### 2.3 关于「没有某能力」的判断范围

写「Fox 没有 X」时，必须同时写清检索范围。例：

> 在 `apps/desktop/src-tauri/src/lib.rs` 注册的命令名与 `apps/desktop/src-tauri/src/yuxi/`、`apps/desktop/src/features/knowledge/` 内检索 `upload`，只命中会话附件上行 `upload_thread_attachment`；未逐文件检查全部前端目录。

## 4. 执行层次（最易混淆，务必分清）

“默认用什么执行”有多个**互不相同**的层次：

```text
0) 外层 Agent 后端 conversations.agent_backend: fox | deepseek | pi | codex
   - 会话创建时冻结，之后不能更换
   - 新会话：FOX_EXTERNAL_BACKENDS（只能强制关闭）> 设置「新会话使用的 Agent」> fox
   - codex 在 AgentBackend::HIDDEN 中：新建被拒（agent_backend_hidden），已有会话照常
   - deepseek / pi / codex 经 ACP v1 由 ExternalBackendHost 启动；以下 1)–5) 只适用于 fox 会话

1) Agent.runtime_type: "pi" | "yuxi"
   → 本地 RuntimeHost（Kernel / Sidecar）或远程 YuxiRuntimeHost

2) ExecutionAuthority（每个 Run 冻结在 run_control_bindings）
   select() 优先级：已冻结绑定 > FOX_KERNEL_MODE > Authoritative
   - 未设置环境变量 → 新 Run = Authoritative
   - 只有显式 FOX_KERNEL_MODE=legacy → 新 Run = Legacy（仅调试和兼容旧 Run）
   - 非法值报错，不回退

3) engine_id（Kernel 路径）: pi | codex | deepseek_harness
   由 FOX_KERNEL_ENGINE 指定，缺省 pi；与 0) 的 agent_backend 无关

4) kernel_mode: legacy | authoritative（shadow 只写 shadow 表）

5) Execution Profile: legacy | durable_v2_shadow | durable_v2 |
   graph_readonly_preview | graph_reviewer_v1
```

源码依据：

- 0)：`crates/fox-agent-backend/src/port.rs`（`AgentBackend`、`HIDDEN`）、`crates/fox-agent-backend/src/host_routing.rs`、`apps/desktop/src-tauri/src/commands/agent_backend_routing.rs`、`apps/desktop/src-tauri/src/external_backend.rs`。
- 2)：`apps/desktop/src-tauri/src/runtime_host/kernel_authority.rs::select`。`apps/desktop/src-tauri/Cargo.toml` 的 `kernel-default` 特性只为旧构建命令兼容保留，不决定默认执行权；`tauri.kernel-preview.conf.json` 与根 `package.json` 的 `tauri:build:kernel-preview` 仍引用它。
- 3)：`apps/desktop/src-tauri/src/kernel_model_config.rs`。

**因此**：「pi」可能指外部 Agent `pi`、`runtime_type = pi` 或 `engine_id = pi`，写文档时必须说明是哪一个；pi **不是**第三种执行权模式。

5) 中的 Profile 名单沿用 2026-09-22 的记录，本次没有逐项核对。

## 7. 维护规则

1. 基线变化（新代码提交、schema 版本、默认执行层次、Agent 可见性、CI 结论、发布状态）时**只改本页 §1、§4、§6** 和文首结论，不要在各主题文档里复制同一段话。
2. 每次核验后更新「最后更新」，并在 §1 写明本轮实际使用的核验方式。
3. 写「某能力不存在」时，在同处写明检索范围（§2.3）。
4. 提升某结论的成熟度时，同时给出证据层级和可核验凭据（提交号、CI run、测试输出、安装包哈希）。
5. 区分完整 CI 和定向 CI；定向 CI 通过不能写成“CI 通过”。
6. 历史评审、契约与测试证据不因本页更新而删除或改写，只在其目录或本页 §6 增加状态说明。

# 产品概览

> 状态：生效<br>
> 适用版本：Fox `0.1.x`<br>
> 维护范围：产品定位、用户、核心场景与能力边界<br>
> 最后更新：2026-10-25

## 结论

Fox 是 Windows 优先的桌面智能体工作台（发布目标与 CI 都是 Windows）。每个会话在创建时选定一个 Agent，之后不能更换：

- **Fox**（默认）：Fox 自己的 Kernel，默认执行路径是 Kernel / Authoritative；
- **DeepSeek Harness（dsh，实验）** 和 **pi**：外部 Agent，经 ACP v1 接入，在沙箱里运行；
- **Codex**：已实现但暂时隐藏，新会话不能选，已有 Codex 会话照常可用。

会话、消息、运行、审批、权限和用户配置都由 Tauri/Rust Host 保存在本地 SQLite（`fox.db`，当前 schema v97）里；不论选哪个 Agent，界面、审计和恢复走同一套体系。用户自行接入其他 ACP Agent 的「自定义 ACP Agent」入口**还没有实现**（待办）。

当前事实以代码为准，基线见[当前状态与核验基线](当前状态与核验基线.md)；Agent 选择与路由见 [Agent Runtime 架构 · 外层 Agent 后端](../02-架构/Agent运行时架构.md#外层-agent-后端四-agent)。

## 目标用户

- 需要在本地项目中阅读、修改和验证文件的开发者。
- 需要结合本机资料库或组织知识库完成问答、检索和资料阅读的知识工作者。
- 希望统一管理模型供应商、Agent、Skills、MCP 和专家的高级用户。
- 需要追踪任务过程、证据和产物的小型团队。

## 核心场景

### 本地项目协作

用户把一个本地目录添加为项目，会话绑定项目后：

- **Fox 会话**：在项目权限（只读 / 询问 / 允许）范围内读文件、搜索、写文件和运行受控工具。所有系统操作由 Tauri Host 执行和审批，Runtime 不直接拥有系统权限。生产构建中没有经过验证的命令后端，任意 Shell 命令保持拒绝；`git_read`、`test_run`、`code_check`、`format_code` 这类固定能力工具由 Host 生成固定的程序和参数来运行。
- **外部 Agent 会话（dsh / pi）**：必须绑定项目才能开始运行。外部 Agent 在 srt 沙箱里自己执行工具；权限按该 Agent 自己的原生选项显示（如 pi 的只读 / 询问 / 自动），审批请求经 ACP 回到 Fox 由用户作答。完全访问是独立开关，只能在创建会话时授予，会话中只能撤销。

### 通用对话

不绑定项目时，用户可以和 Fox 通用助手进行普通问答。消息、推理过程、工具状态和最终回复通过统一事件进入前端，并写入 SQLite，应用重启后仍可查看。

### 资料与知识库

- **本机资料库**：导入、解析、分块、关键词与向量混合检索（RRF），并在回复中引用。ONNX Runtime 在 CPU 上生成向量，Zvec 负责向量索引。存储位置不可写时进入只读或不可用的降级状态，并在 设置 →「资料库」中提示。
- **知识库服务（远程，代码名 `yuxi`）**：同步远程 Agent 和知识库，查询内容和知识图谱，预览或下载原文件，并从引用跳转到资料。服务不可用时本地功能照常可用。

### 能力扩展

插件中心和 设置 →「插件」统一管理 Skills、MCP / OpenAPI 连接器和声明式生命周期 Hook（「策略」）。扩展经过能力清单、凭据隔离和审批策略进入运行，不能直接把任意脚本暴露给模型。

### 专家与自动化

专家能力包（`.foxexpert`）有版本、Hash、升级和回滚；在此之上有持久工作流、串行 Supervisor 团队和数字同事（按计划或签名 Channel 触发）。这些能力只用于 Fox 会话。

## 产品原则

### 本地事实由 Fox 掌握

会话、项目、运行状态、权限和用户配置以 `fox.db` 为事实源。Runtime Session、外部 Agent 的会话和远程服务状态只用于执行与恢复，不能替代本地事实。

### 权限在 Host 收口

Fox 会话里，写文件、运行程序、调用 MCP 等操作必须经过 Host 工具和审批。外部 Agent 会话里，Agent 在沙箱中执行，审批请求由 Host 作答，完全访问只能在创建会话时授予。模型输出、知识内容和外部工具返回都视为不可信输入。

### 过程可见，但不伪装成隐藏思维

界面展示可审计的工作步骤、工具调用、状态和来源，不声称暴露模型的内部思维。

### 简单任务保持简单

普通问答不强制进入 Goal / Task 工作模式，只有确有执行和追踪价值时才启用。

### 外部服务可降级

知识库服务离线、资料库存储位置不可写、预览缓存目录异常时，本地会话和历史记录仍然可用，并在界面上说明状态。

## 当前非目标

- 多人实时协同。
- 完整的 Office 在线编辑（只提供安全预览和下载）。
- 费用统计。
- 无界多 Agent、并行 Team mailbox、自动共享写 worktree、专用 IM Adapter。
- 让模型在没有验证过的隔离后端时执行任意 Shell 命令，或访问授权范围之外的文件。

## 待办（计划，未实现）

- 「自定义 ACP Agent」通用接入入口：用户自己安装其他 ACP Agent 并填写启动命令；Codex 以后也走这里。
- 四 Agent 方案阶段 4：Legacy 路径与 Shadow 观察路径的清理，尚未开始。
- 四 Agent 方案阶段 1 第 2 项：`test_run` 的授权没有绑定工作区修订或脚本内容，未关闭。

## 成功标准

- 发送消息后稳定看到实时过程和最终回复，无需手动刷新。
- 应用重启后，会话、运行状态、附件、引用和用户配置保持一致；启动问题能降级的不阻止启动，不能降级的给出可读原因并保留数据。
- 工具操作有清楚的权限边界、审批记录和错误反馈。
- 外部服务异常不拖垮本地会话链路。
- 新工程师能按文档完成环境搭建、定位模块、运行测试并提交变更。

## 完整 Agent 验证（C 新增）

1. 先点“验证”，检查配置和真实模型请求。原生 OAuth 来源的独立模型请求显示未执行，提示使用完整验证。
2. 点“完整验证：Agent 输出和工具调用”。同一个临时会话先回复 OK，再读取临时项目内 fox-verify.txt，回复未出现在提示词中的随机串。
3. 第三层要求收到真实非空文本。第四层同时要求已完成工具回执和匹配的随机串。只配置 Key、仅收到工具请求、文本猜测均不能代替成功结果。
4. 权限使用 Pi read_only、Codex read-only、dsh read-only。Host 仅自动批准指定验证文件的结构化读取请求，其他权限请求拒绝。会话不领取 Fox MCP 令牌，不连接用户对话工具；本项验证的是 Agent 自带读取工具。
5. 临时私有 HOME 使用已绑定服务，或复制已经导入的私有登录。用户项目和原有登录文件不变。
6. 在模型请求、会话建立、输出和工具调用期间分别点停止。进程启动阶段会等待现有 initialize 的有界清理完成；建立会话和运行期间立即进入取消路径。
7. 每层最长 120 秒。停止、超时和结束都使用 stop_for_revocation；确认进程树结束后才删除临时目录。未确认结束或未能清理应明确失败，并保留必要现场。
8. 在验证过程中更改绑定或 Key，旧会话结果应显示配置已变化，不能成为新配置的通过证据。
9. 验证时再次点击同一 Agent，返回正在验证；测试完成后退出设置再打开，可读取同一配置的最后结果。

## 与方案的实现说明

- Fox 内置 Agent 没有独立 ACP 验证入口，第 3–4 层明确跳过。
- 原生 OAuth 由真实 Agent 输出证明模型请求通过，不伪造独立 HTTP 请求。
- 临时项目使用合法保留 UUID，并放在每次验证独有的数据目录中，替代方案示意的 `verify` 项目键。
- 保存服务后的“使用”提示在页内显示，仍需用户点击才绑定；现有通知接口不支持任意按钮回调。
- 不添加引导向导、系统登录文件编辑、配置差异恢复或本机 runtime 安装器。
- CI 通过不等于真实 Agent、Windows 桌面或视觉验收通过。以上现场项目留待候选就绪后实测。

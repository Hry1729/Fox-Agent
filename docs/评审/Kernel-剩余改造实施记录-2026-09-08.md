# Kernel 剩余改造实施记录

## 授权与运行边界

本轮接续总方案剩余工程实现。保留现有 main 工作区改动，不清理或替换运行中的桌面程序。用户于本轮追加授权要求及时提交和推送，后续按已验证里程碑提交；独立 Kernel/协议库已以 `6b4f969` 推送。生产放量与工程实现分开；默认仍为 Legacy，任何既有 Run 不原地换权威。真实业务和审批 UI 证据未完成前，不自动批准生产切权。

### 受控协调入口与恢复派发

- 增加 `KernelCoordinator` 适配入口：重建 Kernel 控制器并核对同一 Run 的权威身份、引擎、权限、Profile 和全部冻结预算；事务失败不把推测状态留在内存。
- Outbox 只允许 Authoritative 领取；支持按单个待办领取，未执行的兄弟工具不提前进入不确定状态。结果提交在同一事务核对租约持有者并完成工具、批次屏障与派发记录；恢复标记也需匹配原租约持有者。
- 工具执行不持有控制器锁，传递稳定幂等键与作用于该工具的取消令牌；取消先落库再通知执行器。执行失联或结果落库失败保持 leased，不自动重跑。
- 协调入口专项 7 项通过：数据库重开后的审批、真实 Rust 文件读取、逆序完成的有序结果、重复调用不重读、失联/事务失败、伪造租约、取消迟到结果及双工具并发进入。独立 Kernel 47 项通过；桌面默认特性全量 564 项通过、0 失败、3 项原有显式忽略。
- 此入口尚未挂接默认 RuntimeHost 启动、Pi 权威模式协议与 UI。真实文件测试覆盖受控协调器，不等于真实 Tauri 会话的重启恢复或生产切权验收。

### Pi 整批结果恢复交接

- 原始引擎历史与工具提议作为 `engine.batch_checkpoint` 事件同事务提交，带内容哈希；重开后只接受同一 Run/Engine/Turn/Batch 的原记录。 checkpoint 写入失败同时回滚审批和工具提议；精确重放不新增事件，变更历史或参数拒绝。
- 共享 Rust DTO 与生成的 Node/TypeScript Schema 增加 `KernelEngineBatchCheckpoint`、`KernelBatchResumeFrame`。只接受齐全且已完成/失败的结果屏障，按原始 source order 投影；缺失、重复、取消、篡改参数、错误分类矛盾和不完整历史均拒绝，不生成未知工具的替代结果。
- 受控联测通过：首个真实 Pi 进程在工具执行前留下提议，Rust 落库并重开后恢复审批、逆序执行两个真实文件读取，再由另一个 Pi 进程消费有序持久结果；原工具没有在新进程再次执行。结果交接领取后不允许自动重播。
- 恢复计划与三种 Outbox 领取入口均禁止 `cancelling` Run 继续普通工具/模型批次，只继续排空取消动作。
- 替代 Pi 会话必须为空且空闲，关闭引擎自带重试/自动压缩，并携带 Host 取消信号；当前交接只开放模型响应，不开放本地工具执行器。后续工具批次的 Kernel 桥接、模型请求预算/终态正式接线、Tauri UI 和生产准入仍未完成。
- 本批全量回归：桌面端 566 项通过、0 失败、3 项原有显式忽略；Node 233 项通过。协议 Rust 4 项、Kernel 47 项及生成文件一致性检查通过；受控协调入口已有 9 项专项测试。没有把受控联测等同于默认生产会话恢复。

### 批次交付领取与模型预算

- 受控协调入口在同一 SQLite 事务中领取批次交付、记录 `engine.batch_dispatched` 和模型请求计时起点，再调用引擎。写入失败不调用引擎；已发送但失联的交付保持不确定状态，重开不自动重播、不刷新超时时限。
- Pi 恢复入口落实冻结的模型请求超时：取消后等待引擎退出，拒绝超时、Host 取消、未完成响应以及伪装成完成的工具提议。取消调用本身的错误被观察，不产生游离的 Promise 拒绝。
- 新增 Run 级取消令牌；引擎调用不占用协调器锁，可响应并发取消。这里的交付确认仍不是 Run 完成事件，模型响应持久化和后续批次接线继续推进。
- 当前专项回归：协调器 10 项通过（含真实 Pi 进程往返、事务失败注入、发送失联和重开超时）；Node 全量 236 项通过；Kernel 47 项通过。默认生产路径不变。

### 模型响应与后续批次闭环

- 共享 `KernelModelResponse` 绑定 Run/Turn/Batch 和交付游标，只携带新 assistant 消息。Node 不得提供替换历史或下一批身份；Host 从原检查点与持久结果构造后续批次，并重新应用权限与审批策略。
- 模型原始响应、后续工具提议及检查点或 Run 完成事件、交付租约完成在同一事务落库。外部所有者、不同 Run/游标、取消和事务失败均不能局部写入完成或新工具；失败保留不确定交付事实。
- 受控 Pi 仅安装描述与 Schema，不安装资源执行器。公开且被等待的 `message_end` 边界在模型提出工具时终止该一次性回合，早于工具准备与执行。真实进程验证只有一次 provider 请求、零工具执行开始事件；没有改 SDK 私有 Hook。
- 真实进程联测覆盖三次 Pi 进程、两次数据库重开、原批次双文件读取、新批次重新审批和文件读取、最终模型响应与 Run 完成同事务提交。取消和超时仍优先；不把受控联测等同于默认 Tauri 会话或 UI 验收。
- 全量回归：桌面 568 项通过、0 失败、3 项原有忽略；Node 238 项通过。协调器专项 11 项、共享协议 5 项、Kernel 47 项通过；生成协议一致性与差异检查通过。运行协议、错误状态和权限参考同步标记受控边界。

### 大步骤：Kernel 提交后桌面状态通知

- 带新事件的 Authoritative 决策在事务提交成功、数据库连接锁释放后发布失效通知；回滚、精确重放及 Legacy 不发布此通知。所有协调器决策、工具结果、模型批次领取与模型响应共用该提交入口。

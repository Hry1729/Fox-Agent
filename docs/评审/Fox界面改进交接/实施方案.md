## 3. 设计约束和可量化目标

### 方向

面向桌面工作中的 Fox 使用者，以“正文先于过程，恢复动作紧邻问题”为主线。ENERGY 2 / RHYTHM 2 / MOTION 1。大胆来自明确的字重、字号差与成组布局，不来自增加彩色胶囊、光晕或弹跳。

| 决策 | 原因与约束 |
| --- | --- |
| 沿用 `themes.css` 语义变量 | 保持全部既有主题，禁止改 token 值或为原型另造品牌色 |
| 系统中文字体与现有正文栈 | 不增加字体下载，保持 Windows 字形与应用一致 |
| 正文、状态摘要、过程三级 | 让答案与需要采取的动作先被看到 |
| 只有发送等当前主动作实心强调 | 避免停止、错误、审批互相抢焦点 |
| 输入框外壳固定，内部随内容长高 | 避免完成第一轮后操作入口消失 |
| 原吉祥物与侧栏原样保留 | 用户明确指定不改；原型可裁切主区，但不能伪造“已优化侧栏” |

### 产品验收目标

- 一个回合只显示一个回合级状态摘要；工具状态仍保留，展开内容不能被去重逻辑隐藏。
- `cancelled` 工具不能继续显示“正在执行/正在调用”，也不能仅因用户取消标为失败。
- 已确认到达的输出必须在取消后、刷新后、重开会话后可见；没有输出时明确写“取消前未收到输出”。
- 发送前失败保留完整草稿和附件，不创建 Run；有可达的修复入口，修复后由用户决定再次发送。
- 不把“已取消”与“所有子进程已退出”混为一谈。
- 输入框保留项目、Agent、审批模式、模型等必要上下文。运行期不可改的选项显示原因，而不是悄悄消失。
- 纯视觉变更不得破坏现有快捷键、中文输入法、附件、引用、steering 与审批语义。

### T01 / P0：先建立取消事实与回归夹具

**入口**

- `features/conversations/model/runtime-event-reducer.ts`
- `features/chat/run-phase.ts`、`run-activity-presentation.ts`
- `features/chat/timeline/fox-runtime-assistant-message.tsx`、`fox-runtime-process-view.tsx`
- `crates/fox-agent-backend/src/external.rs`、`tests/cancel_sweep.rs`
- `apps/desktop/tests/runtime-event-reducer.test.ts`、`runtime-tool-settled.test.ts`、`tool-attempt-status.test.ts`

**动作**

1. 画出事件 → reducer → 会话 detail/reload → 过程分组 → 工具卡标题/输出的数据流。按 Pi、Codex、原生、dsh 各记录一条脱敏事件序列。
2. 核对 1339 的 `resultLen > 0` 与实际持久化字段，区分输出存在但没渲染、流式字段没合并、终态覆盖文本、适配器归类错误。不要先删 UI 来掩盖状态问题。
3. 先增加失败回归：取消前流式文本、取消终态、重复终态、迟到输出、取消与完成竞争、历史重载。
4. 明确终态合并遵守现有事件版本/顺序权威；终态后不得被旧的 running 事件复活。不要用“最后到达永远赢”替代协议顺序。

**验收**：新增用例能重现各自根因；报告字段与渲染责任；不包含 API Key、个人目录或完整生产日志。

### T02 / P0：取消卡片、输出保留与真正停止

**依赖**：T01。**预期产出**：状态修复、输出投影修复、必要的适配器修复，及 Windows 进程验收。

1. 优先复用现有状态归一化与输出拼接函数。取消请求发出后可显示“正在取消…”，仅收到对应终态后显示“已取消”。按钮防连点，但不要把请求成功等同终态。
2. 工具标题、摘要、展开区使用同一个归一化事实。正常取消是 `cancelled`；真正失败保留 `failed`。不要把整个回合下所有工具一律改成取消，已完成工具仍是完成。
3. 合并部分输出与终态结果，保留顺序、避免重复。保留此前正文，取消不清空会话。结束说明使用“已取消，以上是取消前收到的输出”；此文案应是展示附注，不污染原始工具输出。
4. 没有输出时显示真实空态；正在取消时保留已有输出；清扫异常时说明仍需处理，不作“全部已停止”的承诺。
5. 等待审批时保持回合取消入口。回合取消后待审批项必须失效，迟到的批准不得执行工具；拒绝单项审批不等于取消整个回合。
6. 对 dsh 的 `inFoxJob=False` 后代追踪与权限错误单独修复。检查 runner、Job Object 生命周期与现有清扫范围。禁止为了验收主动提权、改 ACL、关闭沙箱或按名称批量杀进程。
7. 如果 Windows 边界无法安全清扫，呈现可行动的残留警告并保留审计，但该项仍算未完成，不能用提示代替进程修复。需要管理员夹具时向用户申请受控测试环境。

**必测矩阵**

| 场景 | 期望 |
| --- | --- |
| queued / running / waiting approval 时取消 | 可操作、终态一致、不遗留可批准卡片 |
| 输出已产生后取消 | 正文、输出保留，工具标题不再活动 |
| 工具已完成而回合取消 | 工具完成、回合取消，事实各归各层 |
| 重复点击、重复事件、迟到事件 | 无重复输出，不复活，不新建回合 |
| 取消失败或连接中断 | 不假装已取消，保留内容与恢复说明 |
| 刷新、退出重进、历史 detail | 与取消后的最终事实一致 |
| Pi/Codex/原生/dsh | 分别验收，不能以一个适配器代表全部 |
| dsh 取消后 3 秒与 30 秒 | 测试子进程不残留；常驻后端不误杀 |

**现有用例**：`run-phase.test.ts`、`run-failure.test.ts`、`r4-run-status-facts.test.ts`、`pending-runtime-approvals.test.ts`；Rust `cancel_sweep`。必要时扩展 `tests/acceptance/single-path-s0/p5-exec-cancel.mjs`，先核对其沙箱与夹具要求。

### T03 / P0：发送失败恢复与凭据保持

**入口**：`features/chat/send-failure-notice.ts`、`features/settings/use-model-providers.ts`、`settings-pages.tsx`、desktop-client 的实际实现、通知呈现层；Tauri `commands/mod.rs`、`model_service.rs`；`crates/fox-agent-backend/src/credential_save.rs`。

**发送失败**

1. 沿 B4-5 的真实发送链确认被拦截的是 unreachable、unverified、凭据缺失还是其他错误。保留这些区别，不能所有错误都显示“连不上”。
2. 所有发送前拒绝都到达现有 notice 通道；核查 toast 挂载、去重、生命周期、`toastNow`、工作区跳转，避免双份 toast 与双份错误横幅。
3. 输入框附近保留一处持久、简洁的恢复提示，直到用户修复或上下文改变。toast 是即时反馈，不是唯一恢复入口。
4. unreachable 文案复用已有标题与描述，动作“去设置模型服务”打开实际目标服务；设置失败/取消后能回到原会话与原草稿。
5. 复用已有“测试连接”；区分未检测、检测中、连接失败、已连接。测试成功不自动发送，不凭旧测试结果宣称新地址可用。
6. 用户再次点击发送才重试。预检不创建空 Run；正文已开始后断连属于运行失败，不能套“发送前未开始”提示。

**凭据契约**

| 输入/变更 | 要求 |
| --- | --- |
| 同 URL，`apiKey` 缺省或留空且 `clearApiKey=false` | 保持原凭据 |
| 输入非空新 Key | 受控更新；保存失败回滚 |
| `clearApiKey=true` | 明确清除，不能误写成留空保持 |
| 同一供应商改 URL 且没输新 Key | 保留该供应商已存凭据的可用性；新地址必须重新测试 |
| 重复/归一化后冲突 URL | 拒绝且不触碰另一供应商凭据 |
| 凭据库读写、记录保存、迁移任一步失败 | 不静默丢 Key，不泄露 Key，给出实际保存状态 |
| 独立协议凭据 | 不误迁移、覆盖或清除其他 profile 的凭据 |

当前默认 Key 按 URL 标识。优先在现有 `KeyPlan/save_with_keys` 事务边界内做同一供应商的受控迁移，不在本轮全面更换凭据标识协议。保留旧 URL 与新 URL 的回滚快照，验证冲突后才写入。旧凭据清理的时机要符合实际引用关系，不能删除仍被使用的凭据。发现现有架构无法满足时先提出最小迁移设计，不硬写前端补丁。

前端只显示 `credentialConfigured` 对应的“已保存 / 未配置”。不回传明文或虚构尾号；API Key 只能在用户主动输入时短暂存在表单。

**测试**：`send-failure-notice.test.ts`、`send-not-started-reason-dom.test.tsx`、`notifications.test.ts`、`settings-provider-row-menu-dom.test.tsx`、`settings-provider-duplicate-url-dom.test.tsx`，以及 `credential_save.rs` 的内存 KeyStore 事务测试。加 URL 迁移、失败回滚、显式清除和 profile 隔离用例。原生凭据库另做实机验收，使用专用测试凭据。

## 5. 4B 准入结论

- 4B 不具备“生产切权批准”条件。当前 `authoritativeEnabled=false`、`productionRolloutApproved=false` 必须保持。
- 具备的前提：决策核、协调器、v53 恢复、严格门、零副作用在受控层已就绪并被真实 Pi 联测覆盖。
- 仍需用户/真实环境批准的内容（硬前置）：
  1. 采集并审阅真实业务 Shadow 样本（最新 Pi Run 统计不自动等于全覆盖）。
  2. 真实 Tauri 审批 UI 允许/拒绝/等待取消的端到端验收。
  3. 动态 Hook、计划/Expert 限制、作用域授权运行中变化的独立策略建模或明确豁免。
  4. 默认特性（zvec）构建需在**无 fox-desktop.exe 占用**时复跑 Rust 全量与 P95（当前被运行中程序锁定）。
- 下一轮最小受控切片建议（仅设计，不实施）：见 4B 草案 §5 的 4B-1 双写只读权威——执行权仍唯一在 Legacy、双写对照不被租赁、不确定 Effect 先核验幂等键再回退。

## 7. 2026-09-08 收紧修订（代码 + 报告）

复核指出四处需收紧，已处理：

1. **模型生命周期门禁加严（代码修复）**：原门禁只校验 begin/settle 计数都 ≥1，无法拦截“两次 begin 一次 settle”这类异常序列。已将 `kernel_shadow_exit_gate`（`database/repositories/kernel.rs`）改为按 `run_events.seq` 顺序读取 `shadowModelRequest` 序列，强制严格配对：无重复 begin、无未配对 settle、无悬空 begin。新增回归测试 `gate_rejects_malformed_model_lifecycle_pairing`（两 begin 一 settle → blocking，含 `duplicate begin` 原因）与 `gate_accepts_well_formed_begin_settle_lifecycle`（干净 begin→settle 不产生生命周期原因）。因此“模型生命周期对应关系通过”以**严格配对**为准；生产 Pi（pi-runtime.mjs）在 model_streaming 前后发 begin/settle 配对。
2. **测试适配缺口（措辞与代码）**：`local_knowledge_vector::unbound_knowledge_base_resolves_the_ready_default_model` 调用受 `local-embedding` 特性门控的嵌入索引路径；在 `--no-default-features` 下行为不同、断言的错误不再成立。准确归因是“**测试与特性配置不兼容，与 4A 主路径无直接关系**”，已给该测试补 `#[cfg(feature = "local-embedding")]` 门，特性关闭时正确跳过而非失败。
3. **默认特性验证替代路线**：不必然关闭桌面程序；可尝试独立 `CARGO_TARGET_DIR` 构建输出目录避开被占用的 DLL，并处理资源路径绑定。该路线尚未验证、不保证成功（已写入 4B 草案）。
4. **安全面边界**：未建模场景（动态 Hook、计划/Expert 限制、授权运行中变化）在首批切权时**排除出切权范围或明确保留 Legacy 安全检查**，不以豁免宣称权限等价（已写入 4B 草案切权前置）。

另：dev server 报 `Port 1421 already in use` 是**上一个 Vite dev 实例（node PID 213372，`vite --port 1421 --strictPort`）残留占用**，与 Rust 编译无关；本次日志 Rust 已编译到 dev server 阶段（此前 DLL 文件锁已释放）。

## 9. 2026-09-08 第二轮收尾：生命周期回归补齐 + 默认特性全量/P95 实跑

### 9.1 实际代码修改

1. **特性条件修正**（`src/local_knowledge_vector.rs:3110`）：
   `unbound_knowledge_base_resolves_the_ready_default_model` 的门控由 `#[cfg(feature = "local-embedding")]` 改为
   `#[cfg(all(feature = "local-embedding", feature = "zvec"))]`。
   依据：`start_index_generation` 的真实索引实现只在 `all(local-embedding, zvec)` 分支存在（repositories 中 `#[cfg(not(all(...)))]` 为桩分支）；生产默认同时启用两特性。保留默认特性下原断言（"no parsed chunks"），不用 ignore 掩盖。

2. **生命周期异常回归补齐**（`src/runtime_host/shadow_reconcile_tests.rs`）：在已有“重复 begin”与“正常单对”基础上新增独立测试，每条断言**具体 blockingReason 子串**（非“整体门失败即通过”）：
   - `lifecycle_settle_without_begin_blocks`：无 begin 即 settle → `settle without an open begin`；
   - `lifecycle_dangling_begin_after_paired_pair_blocks`：正常配对后多一个未 settle 的 begin → `dangling model request (begin without settle)`；
   - `lifecycle_duplicate_settle_blocks`：begin/settle/settle 第二个 settle 无 open begin → `settle without an open begin`；
   - `lifecycle_multiple_well_formed_pairs_raise_no_lifecycle_reason`：两对正常 begin/settle（跨两轮）→ 无任何 `model request` reason；
   - `lifecycle_unknown_event_blocks`：未知 phase（frobnicate）→ `unknown model request lifecycle`。
   子条件测试经辅助 `lifecycle_gate_reasons` 注入真实 `run.phase` 事件（权威事件流经 `apply_runtime_event` 写入 run_events），影子 observer 对未知 phase 的拒绝不影响门禁裁决（门禁独立从 run_events 读取）。

   **“完整样本通过整个门”的诚实归属（第三轮修正）**：此前名为 `lifecycle_complete_sample_passes_the_whole_gate` 的手写夹具并未关闭 Run、未断言 `gate["passed"]==true`、blockingReasons 非空（缺真实 `pi-batch-*` 批次与终态比较），名实不符。已**改名**为 `lifecycle_clean_pair_raises_no_lifecycle_blocking_reason`，明确为**生命周期子条件测试**：只断言干净 begin/settle 不产生 `model request` 阻塞原因，不声明整体门通过。**整体门 `passed==true` 的权威断言**由真实跨语言联测 `real_pi_process_events_flow_through_host_database_and_shared_shadow_adapter` 承担（真实 pi-runtime 子进程 + 真实只读工具 + faux provider，经正式 SQLite 投影与共用观察入口），该测试断言 `gate["passed"]==true`、`authoritativeEnabled==false`、`productionRolloutApproved==false`，覆盖无工具/同轮多工具/工具失败后继续三个场景。

# F1 最小契约：模型交付事实与整文件替换资格（2026-09-23）

工作卡：A-F1-R1。原实现基线 `faa1ad0426851c392dd4ef9743853a44794a7124`，R1 审查基线 `fee9d4e0bb67a3b7378413c784c6d1877633bf10`。本文描述当前实现的资格计算及其证据边界，供协调者审查。

## 缺陷（根因）

`read` 在 Host 侧完整取得源文件后，登记了 `HostObservation{view_kind: FullFile, covered_whole_file: true}`。
该登记发生**工具结果边界**（`resource_gateway::execute_observed_with_budget` 的 `record(...)` →
`managed_files::execute_observed_reader` → `record_host_observation`）。而模型看到的是这份结果的**后续投影**：
Rust `kernel_compaction::bound_tool_result_content_with_storage`（头 6 000 / 尾 2 000 / 上限 9 000 字节），
Node `tool-view.mjs::modelToolResultContent` 再投影一次。

准入只读了源观察：

* `kernel_execution_admission.rs`（权威路径 :296、Legacy 路径 :1813）在 `!authorizes_whole_file_replacement()` 时补发专门替换授权；
* `kernel_projection.rs:517` 决定是否把 `wholeFileReplacement` 绑定进审批记录；
* `kernel_gateway.rs:642`（`PolicyDecision::decide` 的整文件替换闸门）；
* `runtime_host/mod.rs:9427`（`needs_replace_grant` 决定审批记录绑定）。

于是出现：**Host 读到了全文、模型没收到中间部分，但 `write_file` 仍被判定为"已全文读过"而放行整文件替换。**

## 最小契约（本轮实现）

1. **源快照持久化；模型交付资格按当前 durable 行重算。**
   `HostObservation` 只表示源事实（读工具在工具结果边界交付了多少）。历史观察仍是 append-only，不改写、不伪造"当初只读了部分"。当前实现没有新增历史模型请求或交付记录，因此重算结果不能单独证明过去某次 Provider 请求实际收到了哪些字节。
2. **Host 从 durable 行重放当前生产投影，不采信模型或工具自报。**
   新增 `kernel_compaction::model_view_keeps_every_byte(tool, is_error, content, reference, storage)`：
   对**持久化的**成功 `read` 结果跑生产投影函数；结果格式有效、存储事实已核实完整，且投影返回 `None`（一个字节都没改）时，才具备免专门确认的交付资格。
   存储事实与交付时用的是同一个：`repositories::tool_result_storage_for` 由
   `Database::tool_result_storage` 与准入侧重放**共用一份定义**（原先只写在 `Database` 方法体内，
   现抽成 `&Connection` 上的自由函数，避免模型视图与准入判定各自演化）。
   **未知或缺失存储事实不提升资格**：当前投影可能因缺少可取回的存储而保留原文，但这不能倒推先前请求也未裁剪。权威 Run 的 `kernel_tool_calls` 与由 `kernel_projection` 写入的兼容 `tool_calls` **可以同时存在**；前者是准入读取的 canonical 结果，后者提供存储事实。两行按 `(run_id, tool_call_id)` 的工具名、状态、输入和结果一致才可用于重算。`require_legacy_run_writer` 阻止 Legacy 写者修改权威 Run 的读模型，并不阻止该兼容投影。只有 `tool_calls` 的 Legacy Run 走独立分支；有 Kernel Run 却缺 canonical 行不能退回 Legacy 行取得资格。
3. **准入规则唯一化。** `model_delivery_covered_whole_file_in_tx(tx, run_id, observation)` =
   源事实（`authorizes_whole_file_replacement()`）**且** 交付事实。四处准入点全部改调它（见变更清单）。
4. **未知交付 = 无资格。** 观察对应的 durable 行缺失、两行不一致、调用失败或非终态、无 `result_json`、结果不可解析或内容为 null、工具名不符、无引用、存储事实缺失或不完整，一律返回 `false`
   → 退回既有的一次性专门替换确认（target/version/candidate 绑定、claim 时原子消费）。不新建"智能范围合并"。
5. **Node 二次投影的证据边界。** 重算始终针对 durable 原始结果，绝不针对已经投影过的帧内容；它本身不能检测 Node 对一个原本合格的小结果再作独立裁剪。Rust 与 Node 的实际帧链路须由本卡真实 worker／模拟 Provider 输入用例核验，不能仅凭重算推出历史交付事实。
6. **恢复/历史压缩后重新保守判定。** 关库重开、会话恢复、历史压缩不应把缺失或已省略的内容升格为全文资格；当前实现重算现存 durable 行。若结果行、兼容投影或存储事实后来缺失／异常，资格退回专门确认。实际恢复后首次写提案和压缩路径须由本卡独立用例证明。
7. **保守的非累计策略（明确声明）。** 同一版本多次续读不做范围累计：任一观察若在交付重放下发生省略，就不能单独授权；
   仅当某次观察的源覆盖与交付覆盖同时完整时才免专门确认。累计合并留待后续卡片。

Legacy adapter 是否直接保留全文由其实际 Host／adapter 输入证据判定。即使实际保留全文，缺少可靠的行或存储事实时本规则仍可能保守要求一次专门确认；此种额外确认不能描述为 Legacy 已发生裁剪。

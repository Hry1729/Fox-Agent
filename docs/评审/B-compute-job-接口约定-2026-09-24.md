# B：compute_job 自动交接接口约定（冻结设计，2026-09-24）

**范围与门槛。** 本文是已审冻结的接口设计，不代表实现或验收通过。仅权威 Kernel Run；`compute_job_start` 的 started/toolCall 正式结果只写一次，保留 `status/result/cancel`。Run 创建时冻结实验开关 `experimentalComputeJobNotice`，默认关；不换 Pi、不改默认并行。先交 **B1 原子通知/身份负例**，审过再交 **B2 等待/交付**。以下 Rust 短路径以 `apps/desktop/src-tauri/src/` 为根。

**B1：终态事实。** `kernel_job_execution.rs::{kernel_job_complete_attempt,kernel_job_settle_attempt,kernel_job_request_cancel}` 沿现有 attempt/进程 CAS，在同一 `IMMEDIATE` 事务写成功结果 blob、Job 终态及唯一 `kernel_job_notices` 行：`dataRootId,conversationId,runId,jobId,attempt,terminalState,finishedAt,resultRef/sha/bytes,errorCode,deliveryState,boundDispatchKey,boundInputHash`。`jobId` 唯一，同值重报无操作，冲突拒绝；现有 `kernel_job_resume` 只接受 paused，终态不可再认领。排队态取消、过期 queued/paused 的新 `kernel_job_expire_unowned` 同事务落通知。用窄表是因为现有 `kernel_effect_outbox` 的 CHECK/枚举与 `recovery.rs::plan_recovery` 将待办/leased 当执行 effect；被动通知不进入其派发与不确定队列，模型派发继续复用原 outbox。`dataRootId` 由 `app_settings` 一次性 DB UUID＋规范化数据根路径取 hash；备份复制到别的路径隔离旧通知，需显式恢复；只在当前 DB 连接联查本地 Run/Job，拒绝外部引用跨库消费。

**B2：持久等待。** `fox-agent-kernel/{state,controller}.rs` 新增非终态 `WaitingJobs`；`run.waiting_jobs` 事件冻结已结算模型回答、完整历史/游标和必要 jobId。`kernel_runs` 投影 `state=waiting_jobs,terminal_written=0,model_request_since_wall_ms=NULL,waitDeadlineWall,waitAccountedUntilWall`，旧 `runs.status=running`；SQL 仅在工具批次全部结算、无取消且 Job 均属于同 root/conversation/Run 时允许。所有 Job 必须已有正值原 `deadline_ms`；缺失则拒绝自动等待，写明 `kernel.job_deadline_missing` 阻断事实，不伪完成。有限 Run 的等待绝对截止为 `min(park时刻+原剩余Run预算,最晚Job原deadline)`；无限 Run 取最晚 Job deadline。等待计入原 Run 预算；每次唤醒/重开事务只扣 `now-waitAccountedUntilWall` 并推进该游标，时钟倒退拒绝，永不重扣或刷新截止；模型超时仅实际派发时起算。

`kernel_coordinator/live.rs::{service_round_output,commit_round_decision}` 和逐轮 `kernel_coordinator.rs::{dispatch_initial,dispatch_batch}` 在最终回答前 park，不消耗 stop-review 次数、不塞 `CONTINUATION_PROMPT`。`database/repositories/kernel.rs::kernel_commit_decision_with_dispatch_lease_and_policy` 保留 `kernel.jobs_pending` 完成保护，并拒绝终态通知尚未处理的完成竞态，持原响应重规划。`kernel_host.rs::drive_with_actions_transport` 返回明确 `Parked`（非 terminal/error），退出旧 Pi session/RPC、释放 Run lock；上层 `start_kernel_run/start_run_inner` 保留非终态状态，不触发 `settle_children(true)` 或完成回调。重启扫描及 Job 终态/截止/取消以 runId 幂等唤醒，重新持锁验身份、权限版本、取消及 Job 集；孤儿 Job paused 不自动重跑，显式恢复只用原剩余 deadline。

**绑定与模型历史。** `database/repositories/kernel.rs::{kernel_commit_continuation_model,kernel_commit_batch_dispatch}` 在模型 lease **同一事务**冻结精确输入、通知 ID/顺序与 `boundInputHash`，通知 `pending→bound`；响应事务 `bound→acknowledged`，但保留通知行及它在该输入历史中的 typed `HostJobNotice` 占位。后续帧依 `boundDispatchKey+boundInputHash+历史位置`重建此 Host 事实**一次**，只将仍 pending 的通知当新到达；hash 覆盖占位内容和顺序。最终完成须所有必要 Job 终态且通知均已确认/进入已提交历史，16 KiB 溢出 pending 不能漏过。重启可绑定 pending；bound 而响应未知沿现有 leased-model fail-closed，不重发模型或重注入。

**编码与验收。** `fox-engine-protocol/resume.rs::{KernelInitialModelFrame,KernelBatchResumeFrame,KernelRoundDirective}` 传 `hostJobNotices: Vec<HostJobNotice>`（固定 `source=fox_kernel_host`、root/conversation/Run/Job/attempt、终态、错误类别、小摘要和引用；每项≤2 KiB、每输入≤16 KiB）。`services/agent-runtime/src/{pi-kernel-batch-resume,pi-kernel-loop}.mjs` 按历史位置校验/映射为临时标准 `role:user` 文本载体 `FOX_HOST_JOB_NOTICE_V1\n<规范 JSON>`，明示 Host 工具事实与正文不可信；这只是 Provider 编码，不写用户意图/会话用户消息/`run_steering_messages`，不重复原 toolCall 结果。`background_jobs.rs::execute` 的 `status/result/cancel` 收紧到同 runId；通知不含结果正文、不扩大 F1 读覆盖。真实 Database/Host/Node＋本地固定模拟 Provider 验证慢 Job+独立读取、提前最终回答、失败/取消/超时、两种重启窗口、重复终态、预算扣减、大结果与跨范围拒绝；不跑付费 Provider/UI/任意 Shell。相邻合并与轮次费用留 C。

## 68 次失败是什么

共 117 次工具调用：49 次完成，68 次失败；界面计数与持久记录一致。它是失败调用次数，不是失败文件数。

| 次数 | 工具 / 原因 | 证据与解释 |
| --- | --- | --- |
| 62 | `call_mcp_tool → office_edit`，`kernel.policy_denied` | 所有这些事件只记录通用的冻结资源策略拒绝；没有执行结果。参数静态复核见下。 |
| 3 | Office 资源执行失败 | 2 次 `office_edit`、1 次 `office_merge`；保存的结果只剩 `kernel.resource_failed` 与通用失败文案，无法据此确定 CLI 的原始错误。 |
| 1 | `attachment_compute` | 生成的 JavaScript 引用了未定义变量 `t`，`t is not defined`；该调用未生成文件。后续另有 4 次计算成功。 |
| 1 | `write_file` | `tool.file_conflict`：没有目标文件的 Host 观察记录，不能直接写入。 |
| 1 | `read` | 尝试读取尚不存在的 `report.md`，路径解析返回 `os error 2`。 |

62 次 `office_edit` 的输入至少存在以下明确拒绝条件，合计正好 62 次：

- 28 次没有 `output`，也没有 `name`，违反编辑工具必需的输出契约。
- 33 次 `output == file`，却没有 `overwrite=true`。原文件已经存在，不能静默覆盖。
- 1 次虽然声明了覆盖，却使用 `type: "markdown"`；当前 Host 元素类型白名单不支持该类型。

模型不断尝试 `/body`、`/body/p`、带命名空间的 XPath 等节点路径，但其中大量请求尚未通过输出参数校验，修改节点路径无法解决当时的拒绝。

### Fox 需要修的错误反馈问题（本轮仅诊断）

`apps/desktop/src-tauri/src/runtime_host/kernel_gateway.rs::GatewayPolicy::decide` 将未分类的准备错误统一转成 `PolicyDecision::Deny`，文案为 `Tool is not permitted by the frozen resource policy`。因此缺参数、覆盖条件、未知元素类型等可纠正问题丢失了具体原因。

`crates/fox-agent-kernel/src/controller.rs` 的批次预检 `Deny` 分支将工具标记为失败并写事件，但不填充 `result_json`；本次 62 项在 `kernel_tool_calls` 中确实全是空结果。这进一步削弱了模型收到的纠错信息。需要与执行阶段已有的结构化拒绝结果保持一致。

建议下一批：对明确的参数错误返回结构化 `Reject`，对权限拒绝保留 `Deny`；两者都保存可读、经清理的失败结果。模型收到不可重试的权限拒绝应停止同类重试；参数错误应按具体字段修改。不能通过放宽项目边界、跳过覆盖许可或泛化自动授权来解决。

## 最后为什么整轮失败

最后错误码为 `kernel.model_retry_exhausted`，直接触发原因是模型首响应超时，而不是 68 次失败计数触发的停止。

持久事件依次记录：

1. 一次 `model_transport_failure`；无 HTTP 状态码，不能进一步断言为限流、服务端报错或本地断网。
2. 安排第 1 次重试，`maxAttempts=1`，延迟 1000 ms；随后 `run.retry.completed`，`success=true`。
3. 后续模型请求发生 `model_timeout`：`elapsedMs=60123`、`firstResponseMs=null`，推理、正文、工具参数字节数均为 0。
4. 重试预算已耗尽，运行终止。

冻结预算的 `modelFirstResponseMs=60000`，与实测 60.123 秒无首响应吻合。显示的“用时 27 分 21 秒”是整轮耗时，不是这一次请求等待时间。界面的“模型请求多次超时”是通用文案；本次证据准确地说是“一次传输失败后重试成功，之后一次无首响应超时”。这不能证明全部调用都超时。

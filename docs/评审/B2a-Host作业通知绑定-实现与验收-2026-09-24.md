## 合同与实现边界

v85 新增窄表 `kernel_model_notice_inputs` 和 `kernel_job_notice_deliveries`，不把通知放入普通 effect outbox。Host 在派发 model lease 的同一 IMMEDIATE 事务中重读当前 root、conversation、run、job、attempt 对应的 B1 终态事实及结果 blob 完整性，再绑定通知、历史位置和输入 SHA-256。事实选取按确定顺序取可容纳前缀；单项 2 KiB、一次模型输入中历史加新增通知合计 16 KiB，过大或来源不符即阻断，余项保持 pending。响应写入与同一 lease owner、原输入 hash 的通知确认处于同一事务；任何确认行数、身份、位置或完整事实冲突均回滚。pending/bound/异 root 未处理通知保留 `kernel.jobs_pending` 最终完成闸门。

持久历史保留 `role=hostJobNotice` typed 占位；Host 依据已确认的派发账本、原输入位置与顺序核验它。合法 compaction 改变当前数组下标不改变来源；重开、逐轮组帧中一次性保留该事实。Node 仅在 Pi/Provider 适配时把它编码为临时 `role=user` 的标明来源文本，既不写入用户意图/steering，也不把普通 user 文本或模型回传的同名字段升级为 Host 事实；原 `toolCall` 正式结果不重放。steering 的持久 `receivedAt` 同步到 Host 规范历史和 Node 编码，避免同轮时间戳漂移。

`input_hash` 对 Host 规范 JSON `{"modelInput":原始派发帧或directive,"modelHistory":live完整派发前历史或null,"checkpointSeq":事件序号,"historyStart":通知插入位置,"historicalHostNoticeBytes":历史通知对象字节数}` 计算 SHA-256；该 JSON 在 model lease 事务内落盘。Node 的 typed→临时 user 投影是受控 Provider 编码，不能宣称与 Pi 内存对象或 HTTP wire 逐字节相同。普通预读后状态变化在 lease 重读处安全拒绝；当前外层仍可能将该竞争作为 execution failure 终结，**尚无自动重排/唤醒**，留 B2b 处理。

# 权限与文件安全集成说明

本批把分散的 A 文件提交、B 权限与持久准入、C 命令执行接缝接入真实 Host 链路。契约依据为四智能体任务包中的 v1.4 全文及 v1.5、v1.6 补充条款；本说明不替代历史评审与证据。

## 行为变化

- 参数错误和文件匹配失败保留可恢复的具体原因，经过策略入口、持久化与模型恢复帧后仍可辨认。
- 命令状态响应不再携带内部 checkpoint 的 base64 日志。输出继续通过分页接口读取，检查点按变化和间隔持久化。
- glob 匹配使用有界算法，限制模式长度，文件遍历保留取消和预算检查。
- 普通文件写入使用 Host 实际读取所得版本作为前置条件，忽略模型自报版本的授权含义。目标变化返回冲突；提交通过原子替换完成，并保留前镜像与结算记录。版本登记在文件临界区内，失败不能被静默吞掉。
- 权限模式更新使用请求标识及版本 CAS。旧审批随策略代次失效，未消费的原意图可以重新评估；已经签发 dispatch 的意图不能借重新授权重放。
- 执行凭据由 Host 持久事实产生，接收方逐字段与权威快照核对。一次 dispatch 仅允许一次持久领取；初次拒绝、完成和不确定结果均供重复请求只读查询。
- 执行确认独立于工具调用成功与否。领取不等于启动，`Ok` 不等于启动，已经确认的外部操作不能退回“未发生”。文件与进程使用各自的阶段表示。
- 默认 Legacy 文件链也接入实际读取、凭据签发、领取和原子提交，避免只修 Kernel 而留下另一入口绕过。新 Run 默认由 Rust Host 执行只读文件工具；既有 Run 的冻结配置保持不变。

## 执行隔离边界

本批没有安装操作系统沙箱、受限用户、ACL 或防火墙规则。生产环境尚无经过验证的命令后端，因此任意 Shell 启动保持拒绝；状态查询、输出读取和取消保留。测试中的可用后端证明只在 `cfg(test)` 下存在，不能进入生产构建。

进程回收、环境变量过滤和持久回执不能替代文件与网络隔离。内部自动命令推广仍需单独完成真实隔离后端验收。交互式终端不在本批范围内。

## 文件原子性的边界

Windows 使用系统替换操作并核验保存的前镜像；POSIX 在 rename 前再次核对。跨进程不合作写入仍有非零竞争窗口，不能把这些检查表述为通用文件锁。异常路径保留日志与恢复材料，禁止自动重放不确定写入。

## 集成与证据

集成前保留主工作区与 A/B/C 输入快照，位置见工作区外的四智能体任务包 `evidence/O/completion/`。原工作树和历次契约评审不作为清理对象。

本批验收记录在同目录的集成验证报告中。单元测试、真实 SQLite 与临时文件/进程测试分别报告；它们不代表 GUI、远端 CI、跨平台发布包或操作系统沙箱验收。

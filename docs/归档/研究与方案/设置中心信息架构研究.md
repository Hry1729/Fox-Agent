# Fox 设置中心信息架构研究

> 状态：已归档；当前设置结构见 `03-产品与前端/设置中心.md`。

## 1. 参考项目结论

### Craft Agents

Craft 更接近成熟桌面产品设置中心，分类围绕普通用户使用路径展开：

- 应用：通知、更新与应用行为。
- AI：连接、默认模型、推理深度、上下文和 Workspace 覆盖。
- 外观：主题、字体、语言与图标。
- 输入：发送键和拼写检查。
- Workspace：名称、图标和工作目录。
- 权限：探索模式和执行规则。
- 标签、Messaging、快捷键和用户偏好。

值得 Fox 借鉴的是清晰的用户语言、居中的单列内容区，以及“默认值 + Workspace 覆盖”的层级。

### Kun

Kun 的设置更偏本地 Agent 与开发工具运行环境：

- 通用、模型供应商和 Agent。
- 写作、媒体生成、语音输入。
- 权限、Worktree、记忆和归档对话。
- Skills、MCP/外部工具、终端和快捷键。
- 更新、调试、移动端/IM 连接和形象工坊。

值得 Fox 借鉴的是 Runtime、工具、权限和诊断配置的完整性；不应直接照搬 Worktree、写作模式、媒体生成和移动端连接等超出 Fox 当前定位的功能。

### Yuxi

Yuxi 的设置属于服务端管理后台：

- 账户资料、API Key 和身份信息。
- Agent 沙盒环境变量。
- 默认聊天模型、快速模型、Embedding 和 Reranker。
- 内容审查。
- 用户和部门管理。
- Neo4j、MinIO、Milvus 和 API 文档等服务入口。

Fox 只应承接“连接并使用 Yuxi”所需的客户端配置。模型治理、用户组织、知识库解析和基础设施管理继续留在 Yuxi。

## 2. Fox 推荐设置分类

| 一级分类 | 建议内容 | 当前阶段 |
| --- | --- | --- |
| 应用 | 主题、语言、字体大小、界面密度、通知、启动与关闭行为 | 主题已有，其余逐步补充 |
| AI 与模型 | Fox 默认 Agent、模型连接、默认模型、上下文长度、最大输出、图片输入能力、推理深度 | 模型连接已有，补默认值和推理选项 |
| Yuxi 服务 | 服务地址、登录账户、连接状态、默认知识助手、知识模式默认行为 | 服务与登录已有，补默认助手 |
| 项目与权限 | 默认执行方式、授权项目、文件读写边界、忽略路径、命令审批策略 | 第三阶段重点 |
| 输入与对话 | 发送键、拼写检查、语音输入、附件行为、历史记录和对话默认项 | 后续产品化 |
| 扩展 | Skills、MCP Server、工具目录、启停和连接测试 | 已有 Skills 与 MCP |
| 数据与诊断 | 数据目录、备份恢复、清理、Runtime 状态、日志和诊断包 | 已有主要能力 |
| 关于与更新 | 版本、更新检查、许可证、项目主页和变更日志 | 后续补充 |

## 3. 不建议放进 Fox 的设置

- Yuxi 的 Embedding、Reranker、分块、知识图谱构建和内容审查参数。
- Yuxi 的用户、部门和服务基础设施管理。
- Kun 的 Worktree、写作模式、媒体生成、手机连接和定时任务。
- 尚未落地的多 Workspace 覆盖体系。首版保持一个会话绑定一个 Agent、一个项目和一组知识库。

## 4. 页面组织建议

设置侧边栏建议最终调整为：

1. 应用
2. AI 与模型
3. Yuxi 服务
4. 项目与权限
5. 输入与对话
6. 扩展
7. 数据与诊断
8. 关于与更新

Skills 和 MCP 在“扩展”页面中作为两个区块或二级页；模型服务归入“AI 与模型”；Yuxi 登录和用户资料归入“Yuxi 服务”。这样可以减少当前侧边栏的技术名词数量，同时保留清晰的配置边界。

## 5. 布局原则

- 设置内容使用居中的单列阅读区，推荐最大宽度 880-920px。
- 页面标题、说明和卡片内容仍左对齐。
- 同一分类内使用连续的设置区块，避免每个简单选项都单独做成卡片。
- 需要跳转、凭证或危险操作的区域才使用独立卡片。
- 智能体和知识库列表使用居中的宽内容区；文档浏览、知识图谱等工具型页面继续使用全宽布局。

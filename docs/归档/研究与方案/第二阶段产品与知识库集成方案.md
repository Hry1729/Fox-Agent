# Fox 第二阶段：产品能力与知识库接入设计和实施方案

> 状态：已归档；当前架构以常青文档和代码为准。

## 1. 阶段目标

第二阶段将第一阶段的 Runtime 验证提升为可以日常使用的 Fox 桌面 Agent，并完成本地文件权限、完整持久化、Yuxi 知识能力和 Yuxi Agent 兼容接入。

阶段完成后，用户应能：

- 管理 Fox 原生 Agent 和 Yuxi Agent。
- 创建始终绑定固定 Agent 的会话。
- 为会话选择已授权知识库。
- 在授权项目范围内读取、修改文件并审批敏感操作。
- 查看知识库、知识文件和引用来源。
- Yuxi 断开时继续使用 Fox 原生 Agent。

## 2. 本阶段范围

### 包含

- 完整的本地 Agent、会话、Run、工具和审批持久化。
- 项目和授权目录管理。
- 文件读写、Diff、命令执行与权限模式。
- 模型连接和系统凭证安全存储。
- Yuxi 服务配置、登录和连接状态。
- `YuxiKnowledgeProvider` 及首批知识工具。
- `YuxiRuntimeAdapter` 和 Yuxi Agent 列表、详情、对话。
- 附件、产物和引用元数据管理。
- Runtime 和 Yuxi 断线恢复。

### 不包含

- Fox 中创建、编辑或删除 Yuxi Agent。
- Fox 中上传知识文件、配置分块或 Embedding。
- 完整知识图谱交互和来源跳转。
- Skills、MCP 管理和其他 Runtime Adapter。
- 子 Agent、复杂工作流和定时任务。

## 3. 阶段架构

```text
Fox UI
  -> AgentService / ConversationService
  -> RuntimeRegistry
       ├── PiRuntimeAdapter
       └── YuxiRuntimeAdapter

Fox ToolRegistry
  ├── Local File Tools
  ├── Command Tools
  └── Yuxi Knowledge Tools

Fox KnowledgeService
  -> YuxiKnowledgeProvider
  -> Yuxi API
```

`RuntimeRegistry` 根据会话绑定的 Agent 选择 Runtime。知识库与 Runtime 分离：Fox 原生 Agent 和 Yuxi Agent 都可以在各自允许范围内使用知识能力，但知识库不会决定 Agent 行为。

## 4. Agent 与会话设计

Fox 对用户统一展示 `FoxAgent`，内部保留来源：

| Runtime 类型 | 用途 | 断开 Yuxi 后 |
| --- | --- | --- |
| `pi` | Fox 原生通用 Agent | 可继续使用 |
| `yuxi` | 复用 Yuxi 已有 Agent | 不可运行，历史仍可查看 |
| `future` | 未来其他 Runtime 预留 | 取决于具体实现 |

规则：

- 一个会话创建后始终绑定一个 Agent。
- 切换 Agent 会创建新会话。
- 用户只能修改 Agent 明确标记为可配置的字段。
- Fox 原生 Agent 配置由 Fox 保存；Yuxi Agent 配置以 Yuxi 为准。
- Yuxi Agent 的创建、编辑和删除继续在 Yuxi 管理端完成。

## 5. 工具与权限设计

### 5.1 权限模式

| 模式 | 行为 |
| --- | --- |
| 只读 | 允许读取、搜索和分析，禁止写入与命令执行 |
| 询问 | 写入、命令和敏感访问前弹出审批 |
| 允许 | 在授权项目和工具规则内自动执行 |

权限判断由 Fox `PermissionService` 统一完成，不能由 Pi 或 Yuxi 原始事件直接决定。

### 5.2 文件边界

- 项目是用户明确授权的文件夹。
- 所有路径在执行前规范化为绝对路径。
- 规范化路径必须位于项目根目录或明确的额外授权目录内。
- 符号链接、`..`、大小写差异和 Windows 路径前缀都需要纳入校验。
- 写入操作在 UI 展示 Diff、目标路径和工具意图。

第二阶段需要为写入、编辑和命令工具单独决策执行位置：继续由 Pi 工具执行但加强审批、迁移到 Rust ToolHost，或增加操作系统沙箱。无论选择哪种方式，都不能把 TypeScript 权限判断或 Sidecar 工作目录当作安全沙箱。

### 5.3 工具执行流程

```text
Runtime 提出 Tool Call
-> Fox ToolRegistry
-> PermissionService
-> 自动允许 / 用户审批 / 拒绝
-> Tool Executor
-> Fox 标准 Tool Result
-> Runtime 继续执行
```

只读文件工具延续第一阶段的 Pi 实现加执行前审批。写入、编辑和命令工具在完成安全评估后再启用；Fox 专属工具和 Yuxi 知识工具通过代理执行返回结果。

## 6. Yuxi Knowledge Provider

Yuxi 作为可选知识服务，首批能力包括：

- 获取用户可访问的知识库。
- 获取知识库只读详情和文件树。
- 读取已解析文档内容。
- 按指定知识库执行检索。
- 返回引用来源和基础元数据。

建议暴露给 Runtime 的工具：

- `list_knowledge_bases`
- `search_knowledge`
- `read_knowledge_document`

Yuxi 当前缺少或权限不合适的普通用户接口，需要按已有接口映射文档补充 Viewer API。Fox 不直接开放管理员知识管理 API。

Yuxi 返回的文档、检索片段和引用均视为不可信内容。它们可以影响回答内容，但不能修改系统提示词、权限模式、授权项目或工具白名单；由内容诱发的工具调用仍须通过 Fox 权限、执行前审批以及高风险工具的宿主执行或沙箱边界。

## 7. Yuxi Runtime Adapter

`YuxiRuntimeAdapter` 负责把 Yuxi Agent API 映射到 Fox Runtime 契约：

```text
Yuxi Agent / Thread / Run / SSE
-> YuxiRuntimeAdapter
-> FoxRuntimeEvent
-> SQLite + UI
```

关键处理：

- Yuxi Agent slug 与 Fox Agent ID 映射。
- Yuxi Thread ID 与 Fox Conversation ID 映射。
- Run 创建、SSE、取消、审批和恢复。
- SSE 断线后的序号续传和状态查询。
- Yuxi 不可用时将会话标记为离线，而不是删除历史。

Fox 仍只配置一个 Yuxi 服务，但内部连接配置应有稳定 ID，便于未来迁移而不修改会话结构。

## 8. 数据存储扩展

第二阶段在第一阶段基础上增加：

| 表或数据 | 用途 |
| --- | --- |
| `projects` | 授权项目和根目录 |
| `tool_calls` | 工具输入、状态和摘要结果 |
| `approvals` | 用户审批决定和时间 |
| `attachments` | 附件文件元数据 |
| `artifacts` | Agent 产物元数据 |
| `knowledge_bindings` | 会话允许使用的知识库 |
| `service_connections` | Yuxi 服务非敏感配置 |
| `agent_runtime_config` | Fox Agent 可配置运行参数 |

密钥和 Token 进入系统安全存储，SQLite 只保存凭证引用和连接状态。

## 9. 页面与交互接入

本阶段将现有静态页面接入真实数据：

- Agent 列表和详情。
- 会话列表、重命名、删除和恢复。
- 项目选择与授权目录。
- 工具审批和文件 Diff。
- 知识库列表、详情和文件浏览。
- Yuxi 服务设置和登录状态。
- 模型、Agent 和知识库选择器。

AI Elements 继续负责消息、工作过程、Tool、Confirmation、Sources 和附件等表现组件。

## 10. 实施顺序

1. 扩展 SQLite schema 和数据迁移。
2. 实现项目授权、路径校验和权限模式。
3. 跑通文件写入、Diff、审批、拒绝和恢复。
4. 接入模型连接、凭证安全存储和连接测试。
5. 实现 Yuxi Client、认证和服务状态管理。
6. 实现 `YuxiKnowledgeProvider` 和知识工具。
7. 补充 Yuxi 普通用户 Viewer API 并验证权限。
8. 实现 `YuxiRuntimeAdapter` 和 Yuxi Agent 映射。
9. 将 Agent、知识库、项目和设置页面接入真实数据。
10. 完成离线、断线重连、应用重启和数据清理测试。

## 11. 交付物

- 可日常使用的 Fox 原生 Agent。
- Yuxi Agent 查看、选择和对话能力。
- 本地项目和文件工具权限体系。
- 知识库列表、文件查看和 Agent 检索工具。
- 完整会话、工具、审批、附件和产物持久化。
- Yuxi 离线降级和恢复机制。
- 凭证安全存储与连接配置页面。

## 12. 验收标准

- Fox 原生 Agent 在 Yuxi 停止时仍能完成对话和本地文件任务。
- Yuxi Agent 会话正确绑定 Yuxi Thread，不能在会话中切换 Agent。
- 用户只能看到有权限访问的 Yuxi Agent 和知识库。
- 文件操作不能越过授权目录。
- 询问模式下，写入和命令执行必须经过审批。
- 审批、拒绝、取消和重启恢复后状态一致。
- 知识回答能够显示引用来源。
- Yuxi 断线不会破坏 Fox 本地历史，重连后可以恢复可恢复的 Run。

## 13. 主要风险

- Yuxi 当前 Lite 运行模式缺少知识和图谱路由。
- Yuxi 管理 API 权限不适合普通用户端。
- 本地文件权限规则在 Windows 路径和符号链接场景下容易遗漏。
- 两种 Runtime 的事件语义不同，可能造成 UI 行为不一致。

重点通过 Viewer API、统一事件契约、路径安全测试和 Runtime Adapter 契约测试控制风险。

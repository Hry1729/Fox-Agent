# Fox 与知识库服务 0.7.0 接口映射及运行验证

> 状态：已归档；当前接口以 `04-技术参考/知识库服务接口.md` 为准。

## 1. 验证环境

- Yuxi 地址：`http://127.0.0.1:5050`
- 健康检查：`200 OK`
- 运行版本：`0.7.0`
- 首次运行：已完成初始化（`first_run: false`）
- OpenAPI：`/openapi.json` 可访问
- 当前运行态结论：实际暴露的是 Lite 接口集，包含认证、智能体与对话接口，不包含 `/api/knowledge/*` 和 `/api/graph/*`

Fox 连接配置实现说明：

- 首版数据库只允许保存一项 Yuxi 服务配置。
- Base URL 支持本机、局域网 IP/域名和远程 HTTPS，也支持部署在反向代理子路径下。
- 用户误填到 `/api` 时会规范化回服务根地址，健康检查再拼接 `/api/system/health`。
- API Key/JWT 不进入 `fox.db`，按规范化 Base URL 隔离保存到系统凭证库。

验证状态说明：

- **已验证**：已请求运行中的服务并获得预期响应。
- **路由在线**：未登录请求返回 `401`，证明路由与鉴权正常，但尚未获得业务数据。
- **源码确认**：完整版源码中存在，当前运行实例未暴露。
- **需要补充**：现有权限或返回结构不能直接满足 Fox 普通用户端。

### 建议 Yuxi 补充的 Fox 专用只读接口

建议不要直接放开管理 API，而是在 Yuxi 增加以下按 `get_required_user` 鉴权、按知识库授权过滤的接口：

1. `GET /api/knowledge/databases/{kb_id}/viewer`
   - 返回 Fox 卡片和详情页需要的名称、描述、类型、文件数量、处理进度、更新时间。
2. `GET /api/knowledge/databases/{kb_id}/viewer/documents`
   - 返回授权用户可查看的目录树和文件处理状态。
3. `GET /api/knowledge/databases/{kb_id}/viewer/documents/{doc_id}/content`
   - 返回只读解析内容；首版不提供上传、删除、移动或下载。
4. `GET /api/graph/viewer/subgraph`
   - 与现有 `/api/graph/subgraph` 相同，但先校验用户是否可访问 `kb_id`。
5. `GET /api/graph/viewer/labels`、`GET /api/graph/viewer/stats`
   - 提供 Fox 图谱筛选和统计所需的只读数据。

## 4. 用户可配置的 Agent 字段

Yuxi 的 `configurable_items` 来自 Agent Context schema，并会按照字段的 `metadata.auth` 过滤。

普通用户当前可见的基础字段包括：

| 字段 | 作用 | Fox 首版建议 |
| --- | --- | --- |
| `system_prompt` | Agent 的角色和行为提示词。 | 仅展示，不允许临时修改。 |
| `model` | Agent 使用的模型。 | 只有 Yuxi 返回可选项时才允许会话级临时覆盖。 |
| `tools` | 当前 Agent 可调用的内置工具。 | 首版只展示；不在 Fox 中改 Agent 持久配置。 |
| `knowledges` | 当前 Agent 可使用的知识库。 | 允许会话级选择，但必须限制在返回的授权选项内。 |
| `mcps` | Agent 可用的 MCP 服务。 | 首版只展示。 |
| `skills` | Agent 可用的 Skills。 | 首版只展示。 |
| `subagents` | Agent 可调用的子智能体。 | 首版只展示。 |

管理员专属字段包括 `summary_threshold`、`model_retry_times` 等，普通用户响应中应被过滤，Fox 不应自行展示或修改。

## 5. Fox 适配层建议

Fox 不直接把页面组件绑定到 Yuxi JSON，而是定义自己的稳定领域模型：

```ts
type FoxAgent = {
  id: string
  name: string
  description?: string
  avatar?: string
  capabilities: string[]
  defaultModel?: string
  configurable: FoxAgentConfigField[]
  source: 'local' | 'yuxi'
}

type FoxKnowledgeBase = {
  id: string
  name: string
  description?: string
  fileCount?: number
  progress?: number
  source: 'yuxi'
}
```

然后由适配器完成转换：

```text
YuxiAgentResponse -> YuxiAgentAdapter -> FoxAgent -> UI
LocalAgentConfig   -> LocalAgentAdapter -> FoxAgent -> UI
```

这样做不是复制 Yuxi 的 Agent，而是让 UI 和业务逻辑不依赖某一个后端的字段命名和版本。

## 6. 运行验证结论

1. 服务连接、公开信息和首次运行检测可直接接入。
2. Agent 与会话主链路在当前运行实例中已经存在，未登录访问正确返回 `401`。
3. 当前运行实例的 OpenAPI 不包含知识库和图谱路由，属于 Lite 接口集；需要以非 Lite 模式重启 API 才能继续验证真实知识数据。
4. 即使使用完整版，现有知识库文件查看和图谱接口也是管理员权限，不满足 Fox 普通用户端，需要在 Yuxi 增加授权过滤的只读接口。
5. Yuxi 已经在 Agent 内部提供按用户权限过滤的知识库工具（列表、检索、打开文档等），因此 Fox 本地 Agent 可以通过一个 Yuxi Knowledge Provider 复用知识能力，而无需使用 Yuxi 的 Agent Runtime。
6. `/api/agent/runs/{run_id}/events` 需要携带 Bearer 令牌，Fox 应使用 `fetch` 读取 SSE 流，不使用无法方便设置 Authorization Header 的原生 `EventSource`。
7. Fox 不应通过未登录调用 `/api/auth/me` 判断登录状态；当前实测会返回 `500`。应先检查本地凭证，再带令牌调用，并把 `401/423` 作为失效状态处理。

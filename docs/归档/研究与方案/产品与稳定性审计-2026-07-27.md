# Fox 产品与稳定性审计

> 状态：已归档；这是 2026-07-27 的审计快照。

更新日期：2026-07-28

## 1. 结论

Fox 的本地对话、工具执行、知识库绑定、引用跳转和常用文档只读预览已经形成可用闭环。本轮没有发现仍在运行的业务死循环，但发现并修复了几类测试不容易覆盖的隐患：隐藏页面持续占用 GPU、旧 Run 永久轮询、知识库大结果撑大 Runtime 通道、知识库搜索框只有外观、全局 CSS 导入顺序导致组件颜色不一致，以及首屏字体负担过重。

产品能力并非“全部完成”：文档查看已经比较完整，文档协作、知识库运营、Agent 计划与长期任务仍需继续建设。下面按稳定性、文档、Agent 和知识库四部分列出证据与缺口。

## 2. 已修复的稳定性问题

| 项目 | 原风险 | 修复结果 |
| --- | --- | --- |
| Runtime 增量事件积压 | 长回复可能让终止事件长期排在大量 delta 后面 | 连续文本/推理 delta 合并，队列积压时提高每帧处理量，终止事件优先收敛 |
| 对话恢复轮询 | 固定高频轮询增加数据库压力 | 750 ms 起步并退避到 3 秒；收到推送或状态变化后恢复快速检查 |
| 陈旧 Run 永久轮询 | 数据库已切换到新 Run 时，旧闭包持续轮询且永不合并 | 检测 Run ID 变化后迁移到新 Run、合并持久化快照并停止旧轮询 |
| 知识库 SSE 缓冲 | 不完整帧可能无限增长 | 单帧和未完成缓冲限制为 2 MiB，超限返回稳定错误 |
| 知识库重试线程 | 每次退避创建操作系统线程 | 改为 Tokio 异步睡眠 |
| 远程智能体陈旧可用状态 | 服务离线后历史智能体仍可被选择 | 保留历史记录但标记不可用，服务恢复后再恢复状态 |
| DOCX 解压炸弹 | ZIP 声明尺寸可伪造，可能耗尽内存 | 对实际解压输出做硬限制，覆盖 stored 和 deflate 两种条目 |
| 附件能力不一致 | UI 接受的类型与 Runtime 真正可读类型不同 | 移除旧 `.doc`，PDF/DOCX/文本使用明确的读取与大小边界，扫描 PDF 给出 OCR 提示 |
| 隐藏 WebGL 动画 | 引导页按钮离屏或窗口隐藏后仍持续 `requestAnimationFrame` | `IntersectionObserver` 与 `visibilitychange` 暂停/恢复，卸载时清理 RAF、观察器和监听器 |
| 知识库工具大结果 | 解析文档同时复制到 `content` 和 `details`，可能撑大 Runtime JSONL 与模型上下文 | 模型文本限制 256 KiB，诊断预览限制 64 KiB；小结果保留完整结构以支持来源映射 |
| CSS 导入顺序 | 普通规则夹在 `@import` 中间，WebView 可忽略后续导入，出现粉色 hover 回退 | 所有导入移动到文件顶部，Tabs 和全局交互色统一为 Fox 淡蓝色 |

另外，知识库列表的搜索框已经接入真实过滤，遗留的“打开管理后台”按钮已经移除。

## 3. 代码健康与资源占用

### 已确认的安全边界

- Runtime 事件监听、窗口事件、预览器、WebGL、Blob URL 和异步请求都具备卸载清理或取消路径。
- Runtime 崩溃恢复是单次熔断；Yuxi SSE 重连、审批等待、命令运行和 MCP 请求都有超时或次数上限。
- 项目遍历有深度与文件数上限；工具输出、协议行、附件、图片、ZIP、备份、Range 和预览缓存均有硬限制。
- 会话历史分页读取；工具持久化结果超过 128 KiB 会摘要化，不会让 SQLite 随工具输出无限增长。
- 500 MB 文档缓存采用租约保护、LRU、孤儿文件回收和 `.part` 原子写入。

### 尚存风险

| 优先级 | 风险 | 当前证据 | 后续动作 |
| --- | --- | --- | --- |
| P1 | 首屏与大型 Chunk | 主业务块约 1.22–1.69 MB；Mermaid、PPTX、PDF Worker 约 1.00–1.37 MB | 路由分包、Shiki 白名单、按内容加载 Mermaid、隔离图谱/PPTX/WASM |
| P1 | 超大 Office 文件 | DOCX/XLSX/PPTX 需要完整文件解析，单文件上限 64 MiB | 增加服务端轻量索引/缩略图，或引入真正按页/按表读取层 |
| P1 | 扫描 PDF | PDF.js 只能读取已有文本层 | 接入知识库 OCR 或可选本地 OCR，并保留页码和置信度 |
| P2 | MCP 进程成本 | stdio MCP 按请求创建进程，隔离好但高频调用成本高 | 受控进程池、空闲回收、健康检查、每服务并发上限 |
| P2 | 可观测性 | 有运行诊断，缺少每 Run 首 token、队列深度、重试和工具耗时 | 增加本地结构化时间线与可导出指标 |
| P2 | Rust lint 债务 | 仍有未使用结构/字段告警 | 删除无用类型并将多参数调用收敛为请求对象 |

字体已从加载 7 个完整字重缩减为 Regular、Medium、Semibold、Bold，生产 CSS 约从 1.27 MB 降到 0.87 MB；仍应继续做字符子集与路由级加载。

## 4. 文档功能完成度

### 已完成

- 鉴权原件下载、本机打开、严格 Range、来源 revision、`.part` 原子写入、取消和 500 MB LRU 缓存。
- PDF 单页挂载、翻页、缩放、搜索、引用页码/摘录定位和渲染取消。
- DOCX 正文、图片、表格、页眉页脚；可识别分页时逐页，不可识别时连续视图；引用摘录滚动与高亮。
- XLS/XLSX/ODS 只读查看、多工作表与成熟预览器渲染。
- PPTX 单页查看、翻页、媒体惰性解析；ODP 使用解析内容回退。
- Markdown、文本、代码、JSON、CSV/TSV 和图片预览；长文本与表格有截断/窗口边界。
- 对话附件持久化、图片多模态、文本/DOCX/PDF 内容读取。
- 文件树、解析内容、知识图谱、引用卡片、来源跳转和知识助手绑定。
- SQLite migration 13 已实现本地阅读位置、页码/滚动/缩放恢复、书签和阅读笔记；写入采用 500 ms 合并，源 revision 变化后旧位置会标记失效。

### 部分完成

- Office 大文件仍是完整解析模型；限制能保护应用，但不等于渐进加载。
- 文档已有底层版本标识和陈旧缓存失效，但没有可见的版本历史、差异、同步状态和回滚。
- 现有笔记是页码/锚点级阅读笔记，不是真正的文本选择高亮、多人评论或审阅协作。
- PDF 有搜索，DOCX 有来源定位；尚未形成统一目录、PDF 缩略图和跨格式大纲体验。
- 阅读状态保存在本机 SQLite，可随 Fox 备份恢复，但没有跨设备同步。

### 未在 Fox 桌面端完成

- 扫描 PDF OCR、表格结构 OCR 和图片内容检索。
- 旧 `.doc/.ppt` 内置预览；目前使用下载/本机打开回退。
- EPUB、压缩包浏览、音视频转写、CAD/工程图预览。
- 知识库文件上传、删除、批量导入、重解析、重建索引和失败任务处理 UI。
- Chunk 列表、编辑、拆分、合并、禁用、单点命中测试和评估报表。

### 已有后端但 Fox 尚未产品化

Yuxi 已提供上传、文档处理、重解析、重建索引、删除、内容/Chunk、Query Test、查询参数和 Evaluation API。Fox 应复用这些接口建设桌面端运营界面，不应再造一套知识库后端；若接口权限或普通用户契约不足，再单独列出后端改造需求。

## 5. Agent 应用对比

对照本地可审查的 Craft Agents、Kun 与 Yuxi：

| 顺序 | 优先级 | 紧急度 | 需要优化的能力 | 原因与目标 |
| --- | --- | --- | --- | --- |
| A1 | P0 | 高 | **Agent 工作闭环** | 先把目标、计划、Todo、执行、变更审查和完成验收串成一条任务流。这直接决定 Fox 能否稳定完成复杂工作，是当前最重要差距。 |
| A2 | P0 | 高 | **长期记忆** | 提供可查看、可编辑、可删除，并按项目和 Agent 隔离的记忆；否则长任务和重复协作仍依赖会话上下文。 |
| A3 | P1 | 高 | **会话生命周期** | 增加归档、收藏、状态、fork/resume 和分支来源，避免复杂任务只能沿一条不可回退的会话继续。 |
| A4 | P1 | 高 | **运行可观测性与评估** | 补首 token、步骤耗时、队列、重试、工具成功率和回归测试集，优先解决“失败了但不知道为什么”。 |
| A5 | P1 | 中 | **原生子 Agent** | 建立父子任务、并发上限、取消传播、产物回传和失败汇总；先完成单 Agent 闭环，再开放并行委派。 |
| A6 | P1 | 中 | **扩展源协议** | 在现有 Skills、stdio MCP 上补 HTTP/SSE MCP、OpenAPI Source 和 Hook 生命周期，提高接入外部系统的效率。 |
| A7 | P2 | 中 | **模型自动路由与降级** | 按任务能力、上下文、多模态和健康度选模型，并在供应商故障时降级；费用路由不是当前重点。 |
| A8 | P2 | 低 | **自动化与后台任务** | 增加定时/事件触发、幂等、失败通知和递归保护。需要建立在任务闭环与可观测性之上。 |
| A9 | P3 | 低 | **远程 Fox Runtime** | 支持断线续跑和多设备查看，但当前已有 Yuxi 远程 Agent，可最后评估是否值得重复建设。 |

Fox 的优势是桌面本地执行、权限边界、原件预览和友好的过程展示；当前短板集中在长生命周期任务，而不是单轮聊天。

## 6. 知识库应用对比

对照本地 FastGPT 与 Yuxi，以及成熟 RAG 产品的共同形态：

| 顺序 | 优先级 | 紧急度 | 需要优化的能力 | 原因与目标 |
| --- | --- | --- | --- | --- |
| K1 | P0 | 高 | **知识库运营入口** | 在 Fox 内完成上传、批量导入、删除、重解析、重建索引、任务进度和失败重试。没有这层，知识库仍需频繁跳回后台。 |
| K2 | P0 | 高 | **检索过程与参数可视化** | 展示混合检索、阈值、Top K、Rerank、元数据过滤和实际命中内容，直接影响“为什么没有查到资料”的排障效率。 |
| K3 | P0 | 高 | **Chunk 全生命周期管理** | 增加 Chunk 列表、编辑、拆分、合并、禁用和单点命中测试，是提升检索质量最直接的操作层。 |
| K4 | P1 | 高 | **解析与 OCR 任务管理** | 展示解析方式、队列、进度、失败原因和 OCR 重试；复用 Yuxi 解析/OCR 能力，不在 Fox 重造解析后端。 |
| K5 | P1 | 中 | **检索与回答评估** | 接入问题集、召回率、答案正确率、引用命中率和版本对比，避免知识库优化只靠人工感觉。 |
| K6 | P1 | 中 | **版本、权限与审计** | 展示来源 revision、更新历史、角色、共享范围和操作记录；企业使用前需要，但不阻塞个人基础使用。 |
| K7 | P2 | 中 | **连接器与增量同步** | 后续增加网页、API、云盘等来源，并显示来源健康度、同步计划、冲突和删除传播。 |
| K8 | P2 | 低 | **图谱构建与质量治理** | 当前浏览与查询已经可用；构建入口、实体合并、抽取配置和质量评估可以在检索闭环稳定后建设。 |

原件浏览、常用格式预览、引用卡片和来源跳转已经是 Fox 的优势，不需要作为近期重做项目。

## 7. 优先实施顺序

1. **第一批，立即做**：A1 Agent 工作闭环、A2 长期记忆、K1 知识库运营入口、K2 检索可视化、K3 Chunk 管理。
2. **第二批，核心稳定后做**：A3 会话生命周期、A4 可观测性与评估、K4 解析/OCR 管理、K5 检索评估、K6 版本权限审计。
3. **第三批，扩展能力**：A5 子 Agent、A6 扩展源、A7 模型路由、K7 连接器同步、K8 图谱治理。
4. **最后评估**：A8 自动化、A9 远程 Runtime。

文档预览的剩余增强和长尾格式按当前决定暂缓，不进入上述近期排期；现有 PDF、Office、文本、图片、下载、来源定位、书签与阅读笔记继续维护稳定性即可。启动与大 Chunk 仍属于横向性能工作，不与 Agent/知识库产品优先级竞争，遇到首屏回归时持续治理。

A1-A6 的 Craft、Hermes、Kun、Claude 对比、Fox 数据模型、协议、UI、恢复策略和逐阶段验收标准，见 [Agent 能力实施方案](../../07-路线图/Agent能力实施方案.md)。当前明确不实施 A7-A9。

## 你要做什么

Fox 桌面端（`apps/desktop`，React 19 + Tauri 2）要新增「伙伴」页面，同时改造工作页的伙伴分组。需求以同目录的《伙伴页面方案.md》为准，界面以 `index.html` 原型为准。主要包括以下几项：

1. 顶部模式切换改为「工作｜伙伴｜资料」，「助手」改名「工作」。
2. 新增伙伴页的左侧栏，包括新建、置顶大头像、伙伴列表、已归档、行菜单、行内重命名和收起状态。侧栏不放搜索框，也没有分组标题。
3. 工作页的伙伴分组去掉「+」，只显示小狐和常用伙伴（最多 3 个），并支持「管理常用伙伴」浮层。
4. 新伙伴的首次问候增加引导卡。
5. 来自伙伴的通知卡片和弹出通知显示头像。
6. 全局搜索新增「伙伴」分类。

## 主题和深色模式由你负责

原型只做了暖纸主题的浅色模式。实现时，石墨、暖纸、雾蓝三套主题的浅色和深色共 6 种组合都要逐一检查：

- 只用现有的 `--fox-*` 和主题变量，不写死颜色、圆角、阴影和字号。缺少的 token 加到 `globals.css`，例如方案中的 `--fox-sidebar-companion-row-height` 和 `--fox-sidebar-companion-avatar-size`。
- 头像上的状态点、未读点要有一圈侧栏底色描边。深色下描边要跟随侧栏底色，不能是白色。
- 选中行、悬停、浮层、弹出通知在深色下不能出现白色光晕阴影，做法参考 `.dark .fox-mode-tabs` 现有的处理。
- 「等待确认」使用 `--warning`，「失败」使用 `--destructive`。深色下这两种颜色的文字对比度要达到 4.5:1。
- 6 种组合都截图，和原型的浅色截图逐帧对比，把差异列出来。

## 实现要点

### 模式与路由

- `AssistantMode`（`src/features/chat/fox-shared.tsx`）扩展为 `'work' | 'companions' | 'knowledge'`，并新增 `companions` 视图。模式仍然由视图推导。
- `fox-sidebar.tsx` 按模式渲染三种侧栏内容。`SidebarModeTabs` 增加第三个标签，`.fox-mode-tabs` 的宽度调整为 148px。收起时把三个模式图标竖排，并删除现有的单个切换按钮。
- 模式图标：工作用 `square-kanban`，从 `https://animate-ui.com/r/icons-lucide-square-kanban.json` 引入到 `components/animate-ui/icons/square-kanban.tsx`，做法同仓库里已有的图标。伙伴用已经写好的 `components/animate-ui/icons/cat-paw.tsx`，不要改它的形状和动画。两个图标都要在 `components/fox-ui/animated-icons.tsx` 和 `animated-icons-implementation.tsx` 注册。`cat-paw` 不在 lucide 里，静态回退需要一个同形状的静态 SVG 组件（几何数据见 `cat-paw.tsx` 的 `PAD`、`TOES`、`PLACE`、`TOE`）。不要用 lucide 的 `PawPrint` 作回退，它只有三个趾垫。暗色模式下图标用 `currentColor`，不需要单独处理。
- 每个模式记住上次的位置（工作页记对话，伙伴页记选中的伙伴），切回时恢复。

### 工作页伙伴分组

- `features/companions/chat-controls.tsx` 中的 `ContactSidebar` 改为只显示小狐和常用伙伴。删除标题旁的「+」及其下拉菜单，改为一个「…」，菜单项为「管理常用伙伴…」「打开伙伴页面」。
- 行菜单只保留「伙伴资料」「在伙伴页面中查看」「从常用中移除」。小狐没有最后一项。
- 管理常用伙伴的浮层用现有的 Popover 组件实现，向右展开（`side="right"`）。拖动排序使用已安装的库，不要新增依赖。
- 界面文案中的「Fox」「联系人」「小 Fox」统一改为「伙伴」。代码中的 `companion` 不改名。

### 伙伴页侧栏

- 新建一个组件，例如 `features/companions/companion-sidebar.tsx`。行结构和尺寸按原型的 `.crow` 实现：56px 行高，40px 头像，悬停时用侧栏统一的移动高亮（`data-sidebar-motion-item`）。
- 状态：`activeRunStatus` 为运行中时显示绿点；`pendingActionCount > 0` 时显示橙色「!」和「等待你确认：…」；定时任务失败时预览改为红字。免打扰（`reminderMode` 为 muted）时名称后显示 `bell-off`，徽章变灰。
- 行菜单（右键与「…」相同）按方案第 5.2 节实现。重命名改为在行内编辑，保存时调用现有的资料更新命令。
- 已归档列表：如果后端没有恢复命令，就补一个 `companion_unarchive`。恢复时检查重名。
- 置顶伙伴按原型的 `.ptiles` / `.ptile` 做成大头像网格，规格见方案第 5.1 节的表格：每块 76 × 92px，56px 头像，间距 4px，一排 3 个，最后一行居中。小狐始终是第一块（读取时把默认伙伴视为置顶，不依赖 `pinned_at`；`companion_set_pinned` 对默认伙伴返回错误）。置顶的伙伴不在下面的列表里重复。大头像右键打开与行相同的菜单，悬停不显示「…」。
- 网格下面直接是其他伙伴的行，按最近消息时间倒序，不加「置顶」「全部伙伴」标题，也不要排序菜单。
- 不做侧栏搜索框。

### 全局搜索中的伙伴

- 规则见方案第 5.6 节，界面见原型 `search` 帧。
- Rust：`src-tauri/src/database/repositories/app_management.rs` 的 `global_search` 新增一段查询 `companion_profiles`，条件为 `archived_at IS NULL AND deleting_at IS NULL`，`display_name` 或 `duty` LIKE（转义沿用现有写法）。返回 `kind = "companion"`，`workspace_view = "companions"`，`entity_id` 为伙伴 id。伙伴结果最多 5 条，单独放在最前，其余结果仍按原规则排序和截断。私聊消息不进搜索，`commands/mod.rs` 里现有的断言保持通过。
- 前端：`GlobalSearchRecord.kind` 增加 `'companion'`，`globalSearchKindLabel` 返回「伙伴」。`fox-sidebar.tsx` 的分组按固定顺序输出，「伙伴」排第一；伙伴结果显示 28px 头像（从伙伴列表按 id 取，取不到用默认头像）。`openGlobalSearchResult` 遇到 `companion` 时切到伙伴页并选中该伙伴。占位文字改为「搜索对话、伙伴、项目、资料、文件或任务」。

### 常用伙伴的数据

- 迁移：在 `companion_profiles` 新增 `work_shortcut_order INTEGER NULL`。
- 新增命令 `companion_set_work_shortcuts(ids)`：最多 3 个，不包括默认伙伴，不能包含已归档的伙伴。不符合时返回错误，不截断。列表接口返回 `workShortcutOrder`，并在 `features/companions/api.ts` 中补充类型和调用。

### 首次问候与引导卡

- 修改 `src-tauri/src/database/repositories/companions.rs` 中的问候文字，规则见方案第 6.3 节。
- 引导卡作为问候消息的结构化数据保存。先查 `messages` 表和消息投影（`contact_bubbles`）是否支持元数据，再决定用元数据还是新增消息类型。前端在问候气泡下渲染引导卡（原型中的 `.guide`）。
- 点击选项时，以用户身份发送对应的句子。用户发出第一条消息后，引导卡收起为一行（原型中的 `.guide-done`）。
- 已有伙伴不补发问候。同步更新 Rust 测试 `new_companions_persist_one_greeting_without_a_run` 和前端测试 `tests/contact-chat.test.tsx`。

### 通知头像

- 伙伴相关的通知记录写入 `sourceType = 'companion'` 和 `sourceId = companionId`。找出现有的联系人消息、待确认、定时任务结果通知是在哪里写入的，然后补上这两个字段。
- `notification-center-implementation.tsx` 中的 `renderNotificationItem`：当来源是伙伴时，左侧改为 28px 头像，未读点移到头像右上角。`ToastStack` 的弹出通知左侧改为 32px 头像。其他来源的卡片不变。
- 点击通知后的跳转规则见方案第 7 节。

## 约束

- 本期不改右侧栏（`ContactSideCard`）、聊天区和输入框。
- 不新增 npm 依赖。Rust 侧只新增方案中列出的字段和命令。
- 文件保持 LF 换行，有测试按 LF 匹配 CSS 文本。
- `mock.module` 是进程级的：测试中 mock 时展开真实模块，并在 `afterAll` 里还原。
- 工作区有用户未提交的改动，在它们的基础上继续，不要还原或 stash。
- 不要提交，也不要推送。

## 验收

在仓库根目录运行：

```
bun test ./apps/desktop/tests
```

在 `apps/desktop` 目录下运行：

```
node scripts/generate-profile-avatars.mjs
node node_modules/typescript/bin/tsc
node node_modules/vite/bin/vite.js build --config vite.config.ts
node scripts/check-bundle-budget.mjs
node scripts/check-build-isolation.mjs --mode=release
```

同时运行涉及的 Rust 测试（`cargo test` 并按 companions 过滤）。

新增或更新的测试至少要覆盖：

- 三个模式的切换，以及每个模式恢复上次的位置。
- 工作页分组没有「+」；小狐固定在第一行；常用伙伴的上限、顺序和持久化。
- 伙伴页的置顶大头像（小狐始终第一、超过 3 个换行、置顶的伙伴不在列表里重复、取消小狐置顶被拒绝）、侧栏没有搜索框和分组标题、已归档入口的显示条件、行菜单项，以及小狐没有归档和删除。
- 全局搜索：按名称和职责命中伙伴，「伙伴」分类排第一，已归档的伙伴搜不到，私聊消息搜不到，点击后切到伙伴页（Rust 和前端各一条）。
- 行内重命名的保存、取消和重名报错。
- 恢复归档。
- 新伙伴的问候和引导卡；点击选项后发送消息；引导卡收起；已有伙伴不受影响。
- 伙伴通知显示头像，其他来源的通知保持原样。

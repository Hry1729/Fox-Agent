# 伙伴页面方案

> 状态：P0、P1 已实现。P2 保留实施方案。
> 适用版本：Fox 0.1.x
> 维护范围：`apps/desktop/src/features/chat/shell`、`apps/desktop/src/features/companions`、`apps/desktop/src/features/notifications`、`apps/desktop/src-tauri/src/database/repositories/companions.rs`
> 最后更新：2026-11-16

## 1 结论

1. 顶部模式切换从「助手｜资料」改为「工作｜伙伴｜资料」，「助手」改名「工作」。
2. 新增独立的伙伴页面。左侧栏参考 OpenMausBot 的机器人列表，伙伴的新建、管理、归档都在这里完成。
3. 工作页保留「伙伴」分组：固定显示小狐，再加上用户选的常用伙伴，最多 3 个。分组标题旁没有「+」，不能在工作页新建伙伴。
4. 工作页的对话里可以调用任意伙伴，不受常用名单限制。
5. 通知沿用现有通知卡片。来自伙伴的卡片，左侧显示伙伴头像。顶部「伙伴」标签不加角标。
6. 每个新伙伴第一次打开时都会主动打招呼，并附一张引导卡。
7. 每个页面的引导另行设计，不在本方案范围内。

原型：同目录 [index.html](index.html)，只做了暖纸主题的浅色模式。其他主题和深色模式由实现时按 token 自查，要求见 [实现提示词](实现提示词.md)。

### 1.1 与《小 Fox 独立智能体改造方案》的关系

[小 Fox 独立智能体改造方案](../../handoff/xiaofox-20261112/spec.md) 中的默认配置、从专家创建、通过对话完善配置、定时任务和子 Agent 规则不变。以下三处由本方案取代：

| 原方案 | 本方案 |
| --- | --- |
| 长期协作者统称「小 Fox」 | 界面统称「伙伴」，默认伙伴仍叫「小狐」。代码中的 `companion` 不改名 |
| 创建入口只在联系人列表「小 Fox」标题右侧的加号里 | 创建入口移到伙伴页的「新建伙伴」，工作页不再提供 |
| 1.2 节「不新增小 Fox 管理中心」 | 新增伙伴页面，管理功能集中在这里 |

## 2 术语

| 名称 | 含义 | 代码 |
| --- | --- | --- |
| 伙伴 | 用户长期使用的独立智能体，有自己的私聊、配置、记忆和工作目录 | `companion` / `CompanionRecord` |
| 小狐 | 安装后自带的默认伙伴，也是管家。始终置顶，不能取消置顶、归档、删除或隐藏 | `isDefault = true` |
| 常用伙伴 | 用户选择显示在工作页「伙伴」分组里的伙伴 | 新增 `workShortcutOrder` |
| 私聊 | 每个伙伴固定的一条对话 | `conversationId` |

## 3 顶部模式切换

- 三个标签依次为：工作（`square-kanban`）、伙伴（`cat-paw`）、资料（`book-copy`）。选中的标签显示图标和文字，另外两个只显示图标，悬停时出现 tooltip。
- 三个都是动画图标，和现有标签一样由 `AnimatedIconTrigger` 在悬停时播放：
  - 工作：Animate UI 的 `square-kanban`（`https://animate-ui.com/r/icons-lucide-square-kanban.json`），看板三列依次弹动，0.6 秒。
  - 伙伴：自绘的 `cat-paw`，已放在 `apps/desktop/src/components/animate-ui/icons/cat-paw.tsx`。一只空心猫爪，一个掌垫加四个趾垫（lucide 的 `paw-print` 只有三个），向左倾斜 10°，线宽跟随图标的 `strokeWidth`。动画：从上方以 1.6 倍大小落下，压扁到 0.86 倍后回弹再落定，0.5 秒。逐帧见原型 `icons` 帧。
  - 资料：沿用现有的 `book-copy`。
- `.fox-mode-tabs` 的宽度从 116px 调整为 148px，搜索按钮和通知按钮的位置不变。
- `AssistantMode`（`apps/desktop/src/features/chat/fox-shared.tsx`）从 `'assistant' | 'knowledge'` 扩展为 `'work' | 'companions' | 'knowledge'`，并新增伙伴页视图 `companions`。当前模式由视图推导，这一现有规则保持不变。
- 每个模式分别记住上次打开的位置。切回工作页时回到上次的对话；切到伙伴页时回到上次选中的伙伴，第一次进入时默认选中小狐。
- 侧栏收起时，三个模式图标竖排在顶部，选中的一个使用选中背景。现有的「切换到资料」单个按钮随之删除。
- 快捷键（候选）：`Ctrl+1`、`Ctrl+2`、`Ctrl+3`。

## 4 工作页

### 4.1 结构

从上到下依次为：模式切换、新建对话 / 专家 / 插件、伙伴、项目、对话。各区间距、三条对齐线和行高沿用 `globals.css` 中现有的 `--fox-sidebar-*` token。

### 4.2 伙伴分组

- 标题为「伙伴」，右侧只放一个「…」，位于动作列。菜单项：「管理常用伙伴…」「打开伙伴页面」。
- 第一行固定是小狐，后面按用户设定的顺序排列常用伙伴。
- 行样式沿用现有的富行：44px 高，32px 头像，名称加最新消息预览，右侧显示未读数。运行中时，头像右下角显示绿点；等待用户确认时，预览改为橙色的「等待你确认：…」。
- 悬停时，「…」出现在动作列。菜单项：「伙伴资料」「在伙伴页面中查看」「从常用中移除」。小狐没有最后一项。
- 点击一行，在工作页的主区域打开该伙伴的私聊，模式不切换。
- 只有小狐一行时，不显示任何提示文字。

### 4.3 管理常用伙伴

- 从分组标题的「…」打开一个浮层，宽 280px，挂在动作列下方。
- 内容依次为：搜索框；已选列表（每行有拖动把手和「移除」，小狐固定在第一行，标为「默认」，不能移除也不能拖动）；其他伙伴列表（每行一个「添加」）。浮层标题右侧显示「已选 2 / 3」。
- 选满 3 个后，「添加」不可点击，悬停提示「最多 3 个常用伙伴」。
- 修改立即保存，不需要确认按钮；按 Esc 或点击浮层外关闭。
- 伙伴页的行菜单里另有一项「显示在工作页」开关，与浮层写入同一个字段。

### 4.4 工作对话中调用伙伴

工作页的输入框可以 @ 所有未归档的伙伴，不受常用名单限制。@ 的含义、派活规则、上下文和权限见《[小狐管家与伙伴协作方案](小狐管家与伙伴协作方案.md)》第 5.4 节，属于 P1，本期原型不涉及。

## 5 伙伴页

### 5.1 左侧栏结构

从上到下依次为：

1. 模式切换行，与工作页相同。
2. 「新建伙伴」行。样式同工作页的「新建对话」，图标为 `user-plus`。点击后弹出菜单，包含「新建伙伴」（直接创建，详见第 6 节）和「从专家创建…」（打开现有的专家选择对话框）。
3. 置顶伙伴：大头像网格，参考 OpenMausBot 的 `SidebarTiles.tsx`，规格见下表。小狐始终是第一个大头像，所以这块总会显示。
4. 其他伙伴：按 5.2 节的行样式逐行排列，按最近消息时间倒序。小狐和其他置顶的伙伴只出现在上方网格里，不在这里重复。
5. 列表底部一行「已归档」，右侧显示数量。点击后左侧栏切换为已归档列表；只有存在已归档伙伴时才显示这一行。
6. 底部用户栏，与工作页相同。

伙伴页不放搜索框，也没有「置顶」「全部伙伴」这类分组标题。找伙伴用顶部的全局搜索，见 5.6 节。

置顶伙伴的大头像：

| 项目 | 规格 |
| --- | --- |
| 排列 | 在 236px 的轨道内换行排列，每块 76 × 92px，间距 4px，一排正好放 3 个。最后一行不满 3 个时居中。网格上下外边距 6px / 8px |
| 头像 | 56px 圆形，新增 token `--fox-sidebar-companion-tile-avatar-size` |
| 名称 | 头像下方 6px，`--fox-type-ui`，中等字重，居中，单行省略；悬停时 tooltip 显示全名 |
| 状态 | 运行中：头像右下角 12px 绿点；等待确认：头像右下角橙色「!」；未读：头像右上角 11px 圆点，不显示数字；免打扰时圆点改为灰色。状态点都带 2px 侧栏底色描边 |
| 悬停、选中 | 整块使用侧栏的悬停和选中底色，圆角 `--fox-radius-control` |
| 点击 | 打开该伙伴的私聊，和点击列表行相同 |
| 菜单 | 右键单击（键盘为 Shift+F10 或菜单键）打开与列表行相同的菜单，「取消置顶」在里面。大头像悬停时不显示「…」 |
| 顺序 | 小狐固定第一个。其他置顶伙伴可拖动把手，或聚焦把手后按方向键排序。没有保存顺序时，沿用置顶时间倒序 |
| 数量 | 不设上限，超过 3 个换行 |

### 5.2 伙伴行

参考 OpenMausBot 的高级行（`Sidebar.tsx:714-910`），按 Fox 的 token 调整：

| 项目 | 规格 |
| --- | --- |
| 行高 | 56px，新增 token `--fox-sidebar-companion-row-height` |
| 头像 | 40px 圆形，新增 token `--fox-sidebar-companion-avatar-size`，左边缘落在图标列 |
| 第一行 | 名称：`--fox-type-ui`，中等字重；时间在右侧，`--fox-type-caption`，`--fox-muted` |
| 第二行 | 预览：`--fox-type-meta`，`--fox-muted`，单行省略；未读数在右侧，用现有的未读徽章 |
| 运行中 | 头像右下角显示 10px 绿点，外加 2px 侧栏底色描边；预览为「正在处理：…」 |
| 等待确认 | 头像右下角显示 16px 橙色「!」；预览为橙色的「等待你确认：…」 |
| 失败 | 预览为红色的「失败：…」 |
| 免打扰 | 名称后显示 12px `bell-off` 图标，未读徽章改用灰色 |
| 悬停 | 背景用侧栏统一的移动高亮；时间换成「…」，位于动作列 |
| 选中 | 使用侧栏的选中样式 |

右键单击与点击「…」打开同一个菜单：

- 伙伴资料：打开右侧的 `ContactSideCard`
- 显示在工作页（勾选项）
- 置顶 / 取消置顶
- 重命名：在行内变成输入框，Enter 保存，Esc 取消
- 标记为未读 / 标记为已读
- 分隔线
- 归档
- 删除…：沿用现有的删除确认

小狐没有「置顶 / 取消置顶」「归档」和「删除…」，「显示在工作页」固定勾选且不可修改。也不提供隐藏小狐的入口（OpenMausBot 允许隐藏 MausBot，Fox 不跟随：管家是总入口，藏起来用户就找不到了）。

### 5.3 主区域

- 主区域显示选中伙伴的私聊，沿用现有的联系人聊天组件。右侧栏沿用 `ContactSideCard`，本期不改。
- 伙伴页没有不选任何伙伴的空页面：默认打开上次选中的伙伴，没有记录时打开小狐。

### 5.4 已归档列表

- 左侧栏切换为已归档列表，顶部一行包含返回按钮、标题「已归档」和数量，与通知面板的结构相同。
- 每行使用与伙伴行相同的头像和名称，第二行显示「归档于 11 月 3 日」。悬停时，动作列显示「恢复」图标按钮和「…」，两个按钮的总宽度等于 `--fox-sidebar-actions-pair-width`。「…」里只有「删除…」。
- 恢复后，该伙伴回到伙伴列表，此前是否为常用、是否置顶保持不变。
- 点击已归档的伙伴，可以只读查看它的私聊，输入框位置显示「已归档 · 恢复」。

### 5.5 侧栏收起

- 从上到下依次为：三个模式图标、「新建伙伴」图标、32px 伙伴头像，头像都居中在侧栏的中轴上。头像顺序与展开时相同：先置顶伙伴，再其他伙伴。
- 未读用头像右上角的 8px 圆点表示，运行中和等待确认的标记与展开时相同。
- 头像超出可视高度时，列表可以滚动，用户栏固定在底部。

### 5.6 全局搜索中的伙伴

伙伴页不单独放搜索框，统一使用模式切换行右侧的全局搜索按钮（快捷键不变）。

- 搜索结果新增「伙伴」分类，排在所有分类的最前面。
- 按伙伴的名称（`display_name`）和职责（`duty`）匹配，命中的字高亮。已归档和正在删除的伙伴不出现。
- 每条结果：左侧 28px 头像，第一行名称，第二行职责（职责为空时显示「伙伴」），右侧时间。
- 点击后切到伙伴页，选中这个伙伴，打开它的私聊。在工作页里点击也一样切到伙伴页。
- 伙伴结果最多 5 条，单独取出排在最前面，不参与其他结果的按时间排序和截断。
- 私聊消息仍然不进全局搜索，沿用现有规则。
- 输入框占位文字改为「搜索对话、伙伴、项目、资料、文件或任务」。

## 6 新建与首次问候

### 6.1 新建

- 「新建伙伴」直接创建一个伙伴，规则见《小 Fox 独立智能体改造方案》第 3.1 节。默认名称改为「Fox」，重名时依次编号为「Fox 2」「Fox 3」。
- 创建成功后切换到伙伴页，选中新伙伴，打开私聊，光标放进输入框。
- 「从专家创建…」使用现有的专家选择对话框，确认后的行为同上。

### 6.2 现状

问候语写在 Tauri 后端的 `companions.rs:864-882`。它在创建伙伴的同一个事务里插入，是一条 `assistant` / `text` 消息，固定文字，不调用模型：

- 直接创建：「你好，我是{name}。我可以帮你处理文件、整理资料和日常问题。有什么需要我帮忙的？」
- 从专家创建：「你好，我是{name}。我的职责：{专家描述第一句}。有什么需要我帮忙的？」。描述为空或超过 80 字时，中间一句改为「我可以协助你处理相关工作。」

这条问候只有一句话，没有引导。测试：Rust `new_companions_persist_one_greeting_without_a_run`，前端 `tests/contact-chat.test.tsx`（「没有运行记录的问候使用持久气泡身份」）。

### 6.3 改造：问候加引导卡

参考 OpenMausBot 的 `initialGreetingMessage` 和 setup card（`server/initial-greeting.ts`）。问候仍然是一条固定文字、不调用模型的消息，后面附一张引导卡。

直接创建时：

> 你好，我是{name}。我刚来，还没有固定的职责，你想让我先帮你做什么？
> 你也可以直接告诉我：「以后你叫小周」「主要帮我准备周报」「每周五下午提醒我交材料」，我会记下来。

引导卡标题为「先给我定个方向」，下面是四个选项：

| 选项 | 点击后以用户身份发送的消息 |
| --- | --- |
| 整理文件和资料 | 以后主要帮我整理文件和资料 |
| 写材料和汇报 | 以后主要帮我写材料和汇报 |
| 定期提醒和跟进 | 以后主要帮我做定期提醒和跟进 |
| 处理表格和数据 | 以后主要帮我处理表格和数据 |

- 点击选项后，这句话作为用户消息发出，走《小 Fox 独立智能体改造方案》第 4 节的配置更新流程，把它保存为长期职责。
- 用户发出第一条消息后，引导卡收起为一行灰字「已选择：…」；如果用户没有点选项而是自己输入，就显示「已开始对话」。之后不再出现引导卡。

从专家创建时：

- 问候改为「你好，我是{name}。我的职责是{专家描述第一句}。」，第二句与直接创建相同。
- 引导卡标题改为「可以先让我做这些」。选项取专家包里的示例任务，最多 3 个；专家包没有示例任务时，不显示引导卡。

数据：

- 引导卡作为问候消息的结构化附件保存。候选做法是在 `messages` 的元数据中写入 `{ "companionGuide": { "title": "…", "options": [{ "label": "…", "message": "…" }] } }`；如果没有元数据列，就新增 `kind = 'companion_greeting'`。最终做法以现有消息投影能力为准。
- 只对新建的伙伴生效。已有伙伴不补发问候，也不补引导卡。
- 小狐在首次启动时同样发送问候和引导卡，选项见《[小狐管家与伙伴协作方案](小狐管家与伙伴协作方案.md)》第 4.1 节。

## 7 通知

- 通知中心里来源是伙伴的卡片（私聊消息、待确认、伙伴的定时任务结果），把左侧 16px 的来源图标换成 28px 圆形头像。未读点移到头像右上角，外加 2px 底色描边。
- 卡片第一行是伙伴名加时间，第二行是消息预览或状态，例如「等待你确认：发送「采购合同修改意见」」。其他来源的卡片不变。
- 应用内弹出的通知（`ToastStack`）同样在左侧显示 32px 头像。
- 数据：通知记录必须带上伙伴 ID，例如 `sourceType = 'companion'`、`sourceId = companionId`。界面从伙伴列表中取头像；伙伴已删除时，使用默认头像和记录里保存的名称。
- 点击通知：如果当前在工作页，且这个伙伴是小狐或常用伙伴，就在工作页打开它的私聊；否则切换到伙伴页并选中它。
- 不给顶部的「伙伴」标签加角标。系统级通知的行为不变。

## 9 数据与接口

- 迁移：在 `companion_profiles` 新增 `work_shortcut_order INTEGER NULL`。`NULL` 表示不显示在工作页；小狐不需要写这个字段，读取时固定排在第一位。
- 新增 Tauri 命令 `companion_set_work_shortcuts(ids: Vec<String>)`：按传入的顺序写入，最多 3 个，不包括默认伙伴。超过上限或包含已归档的伙伴时返回错误，不做截断。
- 伙伴列表接口返回 `workShortcutOrder`。
- 伙伴列表接口返回 `pinnedOrder`。命令 `companion_set_pinned_order` 接收当前活动、已置顶的非默认伙伴完整顺序。排序独立于工作页常用伙伴。
- 伙伴列表返回 `lastMessageAt`、`latestFailureSummary`、`latestBubbleId` 与 `latestDeliveryOrder`。行菜单通过现有阅读位置命令标记已读和未读。
- 小狐始终置顶：读取时把 `is_default = 1` 的伙伴视为置顶并排在第一位，不依赖 `pinned_at`。`companion_set_pinned` 对默认伙伴返回错误，做法同 OpenMausBot `server/default-bot.ts` 的 `defaultBotRefusal`。
- 恢复归档使用 `companion_restore`，恢复时检查重名。归档私聊通过会话详情接口查看。
- 重命名：使用现有的资料更新命令，校验规则不变（1 到 40 字，活动伙伴中不能重名）。
- 前端在 `features/companions/api.ts` 中补充上述字段和调用；`fox-sidebar.tsx` 按模式渲染三种侧栏内容。
- 全局搜索：`app_management.rs` 的 `global_search` 新增一段查询 `companion_profiles`（`archived_at IS NULL AND deleting_at IS NULL`，`display_name` 或 `duty` LIKE），返回 `kind = "companion"`、`title = display_name`、`subtitle = duty`、`workspace_view = "companions"`、`entity_id = 伙伴 id`。前端 `GlobalSearchRecord.kind` 增加 `'companion'`，`globalSearchKindLabel` 返回「伙伴」。

## 10 验收

- 顶部显示三个模式；切换后左侧栏内容正确，并回到该模式上次的位置；收起时三个图标居中。
- 工作页伙伴分组没有「+」。小狐固定在第一行，不能移除。常用伙伴最多 3 个，顺序可以调整，重启后保持不变。
- 伙伴页可以新建伙伴、从专家创建、置顶、重命名、标记未读、归档、恢复、删除。小狐不能归档和删除。
- 伙伴页侧栏没有搜索框和分组标题。置顶伙伴显示为大头像，一排 3 个，第 4 个换到下一行并居中；取消置顶后回到下面的列表。
- 小狐始终是第一个大头像，菜单里没有置顶、归档和删除；调用接口取消小狐的置顶会返回错误。
- 拖动其他置顶伙伴或聚焦把手后按方向键，可以调整网格顺序。重开后顺序仍在，小狐始终第一。
- 普通伙伴行显示最近消息时间，失败时显示摘要。菜单可标记已读和未读。
- 打开独立归档列表，可查看归档日期和只读私聊。恢复后伙伴回到活动列表。
- 收起伙伴侧栏后，仍可打开新建菜单。名单超出高度时只滚动头像列表，底部用户栏保持可见。
- 全局搜索输入伙伴的名称或职责，「伙伴」分类排在最前；点击后切到伙伴页并打开私聊。已归档的伙伴搜不到，私聊消息搜不到。
- 新建伙伴后，第一条消息是问候加引导卡。点击选项后作为用户消息发出，并保存为职责；发送后引导卡收起。已有伙伴不受影响。
- 来自伙伴的通知在通知中心和弹出通知里都显示头像，点击后按第 7 节的规则跳转。
- 三条对齐线（轨道 12、图标列 20、动作列距右 14）在两个页面上一致，展开和收起状态都检查。
- 浅色、深色和三套主题都检查一遍，深色下不能出现白色光晕阴影。

# 设计系统

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：Fox Desktop 视觉语言、基础组件和交互反馈<br>
> 最后更新：2026-07-29

## 目标与范围

本文定义当前 Fox 前端的视觉基础与组件使用约束，帮助工程师在新增页面时保持一致。它不是独立设计稿，也不替代组件源码和视觉验收。

## 当前实现

Fox 使用三层样式体系：

1. shadcn/ui 与 Radix UI 提供可访问的交互原语；
2. `globals.css` 定义语义色、字体、圆角和深浅主题；
3. `workbench.css`、`workspace-pages.css` 负责产品布局与业务组件。

复杂 Agent 内容优先复用 `components/ai-elements`，品牌性动效仅放在引导页、运行提示和少量关键反馈中。

## 设计令牌

### 字体

- 主字体：`HarmonyOS Sans SC`。
- 回退：`Segoe UI Variable`、`Segoe UI`、系统无衬线字体。
- 正文目标字号为 14px；代码、注释、元数据和紧凑辅助信息可使用 12px。
- 页面大标题、卡片标题和正文必须形成层级，禁止依靠全局 `font-weight: bold` 代替层级设计。
- 字间距保持 0；不要按视口宽度缩放字号。

当前历史 CSS 中仍存在早期 8-11px 的规则，后续改动应优先向 12/14px 体系收敛，而不是继续复制旧数值。

### 颜色

业务代码应优先使用语义变量：

| Token | 浅色主题含义 |
| --- | --- |
| `--fox-canvas` | 主内容画布 |
| `--fox-sidebar` | 底层导航背景 |
| `--fox-card` | 卡片与弹层表面 |
| `--fox-panel` | 次级区域、弱背景 |
| `--fox-blue` / `--fox-accent` | 主强调色，`#3978c5` |
| `--fox-blue-soft` / `--fox-accent-soft` | 淡蓝选中与弱提示，`#e8f4ff` |
| `--fox-hover` | 中性悬浮背景 |
| `--fox-border` | 常规边框 |
| `--fox-text` | 主文字 |
| `--fox-muted` | 次要文字 |
| `--fox-faint` | 元数据和弱提示 |

深色主题会重定义这些变量。业务组件不得假设浅色背景，也不要直接把粉色、紫色或单一蓝色铺满大面积界面。

### 圆角与阴影

- shadcn 基准圆角为 `0.625rem`。
- 操作型卡片通常保持 8-10px；实体卡片遵循现有卡片组件。
- 页面区域不是卡片，不要为每个 section 添加浮动阴影。
- 主内容区依赖与底层背景的轻微层级，而非重阴影。
- 悬浮态使用边框色、轻微背景和最多 1-2px 位移，避免粉色覆盖和夸张阴影。

## 组件规则

### 基础组件

新增交互优先从 `components/ui` 选择：

- 命令使用 `Button`；图标动作使用 `size="icon"` 并提供 Tooltip 或 `aria-label`。
- 枚举选项使用 `Select`、`DropdownMenu` 或 Tabs。
- 二元配置使用 `Switch` 或 Checkbox。
- 需要阻断页面操作的编辑使用 `Dialog`；临时上下文操作使用 Popover/DropdownMenu。
- 异步结果使用页面错误、行内状态和 Toast 分工反馈。

不要自行绘制已有的通用图标，统一使用 Lucide。Button、Select 和状态胶囊应保持统一控制高度，避免同一设置行上下跳动。

### AI Elements

对话页面已经复用以下能力：

- Message 与 MessageActions；
- ChainOfThought 与 Tool；
- Confirmation；
- Sources 与 InlineCitation；
- Attachments 与 Artifact；
- PromptInput、Context、Terminal、FileTree。

新增 Agent 表现前先检查 `components/ai-elements`。项目内组件允许封装业务语义，但不要复制一份相似实现后各自演进。

### 实体卡片

智能体和知识库共享 `entity-card.tsx` 的结构：标题区、固定信息区、统计区和底部状态区。标题和简介有稳定高度，保证不同内容长度下卡片对齐。

卡片必须满足：

- 整卡可点击，并有键盘焦点样式；
- 内部主操作阻止冒泡；
- 标题截断、简介最多两行；
- 悬浮色使用淡蓝与中性色，不使用淡粉色；
- 空描述也要保持视觉居中，不通过硬塞占位文案实现。

## 交互状态

```mermaid
stateDiagram-v2
  [*] --> Default
  Default --> Hover: 指针进入
  Hover --> Focus: 键盘或点击聚焦
  Default --> Focus: Tab 聚焦
  Focus --> Active: 执行动作
  Active --> Loading: 异步请求
  Loading --> Success: 成功反馈
  Loading --> Error: 失败反馈
  Success --> Default
  Error --> Default: 重试或关闭
  Default --> Disabled: 条件不满足
```

- Hover 不能代替选中态；选中态需要结构化标识，如边框、图标或状态文字。
- Loading 禁止重复提交，按钮应保留稳定尺寸。
- Success 反馈优先短 Toast；重要持久状态必须同时在页面中可见。
- Destructive 操作使用明确文案、危险色和确认步骤。

## 动画规范

- 动画用于表达状态变化和空间关系，不作为持续装饰。
- 运行中图标可以动画；完成后应静止。
- 引导页允许更强的品牌动效；工作台保持克制。
- 支持 `prefers-reduced-motion`，重要功能不能依赖动画才能理解。
- 避免无上限的高频 Canvas/WebGL 渲染；非可见页面应停止动画。

## 可访问性与输入

- 所有纯图标按钮提供可读名称。
- Dialog、DropdownMenu、Select 使用 Radix 焦点管理，不绕过其语义结构。
- 键盘焦点不能只靠颜色难以辨认。
- 文本不得被按钮、Badge 或固定宽度容器裁断；长模型名、路径和文件名使用自适应宽度或省略并提供 title。
- 全局右键菜单目前被禁用，因此需要复制、打开、下载等操作必须提供显式按钮。

## 异常与边界

- 第三方预览器样式必须限定在查看器容器内，避免污染全局组件。
- 深色主题下直接写死的浅色背景可能失去对比度。
- Toast 只适合短反馈，不能承载必须保留的错误诊断。
- hover 与 active 选择器较多，修改语义 Token 后必须检查侧栏、设置、智能体详情和知识库卡片。

## 测试与验证

视觉改动至少检查：

1. 1280px 以上桌面宽度；
2. 1180px 以下折叠布局；
3. 浅色和深色主题；
4. 键盘 Tab、Enter、Escape；
5. 最长中文标题、英文模型名和 Windows 路径；
6. Loading、Disabled、Error、Empty 状态；
7. `pnpm.cmd --dir apps/desktop build`。

## 已知限制

- 历史样式仍存在低于 12px 的字号和局部特例，尚未完全 Token 化。
- 当前没有 Storybook、视觉回归快照或集中式组件文档站。
- 部分业务样式集中在大 CSS 文件中，选择器覆盖关系需要谨慎维护。
- 深色主题和窄屏布局的自动化覆盖仍不足。

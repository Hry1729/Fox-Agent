# 简化文件交付方案

决策日期：2026-10-18。状态：已确定产品方向，交由原 agent 实施；本文不是实现或验收完成声明。

## 1. 本次决定

暂停以内容核验作为普通生成任务的默认交付门槛。先采用 DeepSeek Harness 的显式交付方式：模型生成文件后，通过一个工具声明交给用户的最终文件，Host 保存真实文件声明，界面显示文件卡片。

用户选择的结果区顺序固定为：

1. 模型正文。
2. 最终交付文件卡片。
3. 过程文件，默认折叠。
4. 点赞、复制等现有消息操作图标。

不显示“已编辑 N 个文件”、增删行数、改动详情或 diff 汇总。保留当前聊天结构、主题、小狐身份和现有操作按钮，不重新设计整个工作台。

旧方案与验收记录已冻结在 [交付内容核验方案冻结目录](../归档/交付内容核验方案-20261018/README.md)。现有五项问题卡后端扩展不再作为本轮交付前置条件。

## 2. 交付与核验分开

新流程：用户请求 → 模型用正常工具生成文件 → 调用文件交付工具 → Host 校验文件可交付并持久化声明 → 前端显示卡片 → 模型正常结束。

工具声明表示“这些文件交给用户”，不表示内容符合要求。界面不显示“核验通过”，不要求用户点击接受风险才能完成，也不由于内容随机性触发自动修复循环。

关闭 v2 开关不足以实现本决定。旧 v1 检查、recognition 识别门槛、evaluate_stop、协调器和停止处理中的相关门槛都需审查。新任务默认路径不能因文件内容、合同冻结或需求识别结果而进入自动修复、失败或 awaiting_delivery_review。

正常执行错误、工具权限等待、用户取消、预算限制等与交付内容无关的机制保持原义。模型必要时仍可用现有正常澄清方式提问，不新建内容核验专用问题协议。

## 3. 文件交付工具

建议名称 `present_files`；实施时优先复用或收敛已存在的等价工具，避免两个功能重叠的交付工具。对模型暴露一个清晰入口。

建议输入：

```json
{
  "files": [
    { "path": "reports/summary.md", "description": "汇总报告" },
    { "path": "preview/index.html", "description": "交互预览" }
  ]
}
```

调用者的会话、Run 和轮次由 Host 绑定，不信任模型自填身份。工具只声明已经存在的文件，不负责生成、转换或补写内容。普通无文件回答不需要调用。

### Host 检查

- 解析路径，复用当前项目与授权访问边界。
- 确认目标存在，是可访问的普通文件。
- 沿用符号链接、路径逃逸及原生打开的已有安全规则。
- 校验参数格式与合理的文件数量限制。

不检查文本内容、字数、章节、来源合并结果、尾部换行、格式语义或空文件是否合格。零字节文件只要符合文件访问条件即可声明，不能因此进入未确认审查。

文件缺失或无权访问时，工具返回具体错误供模型处理，不创建成功卡片，也不触发独立的内容核验修复循环。建议批次全部校验成功后再写入声明，避免部分成功却整批报错；如采用其他语义，必须返回明确的逐项结果。

工具调用重试按 Host 工具调用身份去重。同一轮重复声明同一路径不重复堆卡片，可更新说明；不同轮次的历史声明分别归属原轮次。正常消息结束或失败不得把其他轮次的文件自动挂到当前回复。

## 4. 数据与历史

声明由 Host 持久化，前端读取真实记录，不从 Markdown 路径、文件扩展名或模型“已完成”字样推断最终交付。

最小记录包括会话、Run、回复轮次、工具调用身份、文件路径、显示名、可选说明与声明时间。具体表和事件优先复用现有产物体系，在保留最终文件与过程文件区别的前提下增加必要字段。

声明保存的是文件引用，本轮不新增文件版本快照系统。重新打开时访问当前文件；文件被移动、删除或无法访问时，卡片给出明确提示，不静默替换成同名其他文件。历史卡片不依赖 lastRun 才能显示，应绑定所属回复。

最终文件与过程文件按归一化后的文件身份去重：同一轮已明确交付的文件不在过程文件列表重复出现。模型没有声明的中间文件仍保留在现有过程文件区域，默认折叠。不能把所有写过的文件自动当最终交付。

## 5. 卡片展示

- 每张卡显示类型图标、文件名和简短说明。
- 点击沿用现有预览、打开、定位能力；先核查能力，不凭文件扩展名承诺不支持的预览。
- 多文件使用适配宽度的网格，窄窗口单列，无横向溢出。
- 无最终交付文件时不显示空卡片区域。
- 卡片无需附带核验结果、接受风险按钮或内核说明。
- 打开失败可重试，记录仍保留；正文复制与点赞等操作维持现有行为。
- 过程文件默认折叠，用户主动展开；不增加改动详情区域。

## 6. 新旧路径切换

新建普通生成任务默认采用简化文件交付。旧内容核验代码可保留为冻结实现，不要求在本轮大规模删除。但必须确认它不再隐式接入新任务，不能只隐藏 UI 或绕过一个状态判断。

既有等待 Run、冻结合同和接受审计保持原样，不批量迁移成通过或完成。可保留明确的旧路径只读或历史处理入口，不能把旧等待状态自动续跑。新声明与旧产物记录的显示兼容应单独列明。

实施前记录原 agent 是否已开始问题卡工作。有在途 WIP 时先保存归属和差异，仅停止重叠方向，不覆盖别人的文件。以当前实测的集成提交为起点，隔离实施，不合入 main、不推送。

## 7. 验收范围

1. 模型经正常入口真实生成文件、调用交付工具，最终回复下出现正确卡片。
2. Markdown、HTML、图片以及当前支持的文档类型能按现有能力打开或预览。
3. 文件内容不符合旧核验规则时，新流程仍不进行内容审查；合法零字节文件可声明。
4. 普通无文件回答自然结束，不强制声明交付文件。
5. 不存在、目录、未授权路径被工具明确拒绝，无成功卡片。
6. 重复调用和工具重试不重复插卡；多轮声明归属正确。
7. 切换会话和重启后仍能读取声明；新 Run 不遮蔽旧回复的交付卡。
8. 后续删除或移动文件时，旧卡片准确报不可访问。
9. 顺序严格为正文、交付文件、默认折叠的过程文件、现有操作图标；没有改动详情。
10. 原有工具权限、取消和普通执行失败语义不变。
11. 旧等待记录和接受审计未被改写；新任务不因旧 recognition、v1/v2 内容核验进入等待或修复。

使用独立数据、项目目录与端口；绑定实际后端构建、前端源码和工具事件。不要用模拟预览证明持久化和真实模型路径。

## 8. 本轮不做

不实现完整问题卡的五项扩展，不做内容打分，不做自动验收或人工接受流程，不做改动详情，不扩展模型识别算法，不做历史数据重写，不清理旧源码、快照或验收证据。

本方案取代当前普通生成任务的内容核验默认方向；原核验研究保留，未来是否以可选能力重新启用另行决定。

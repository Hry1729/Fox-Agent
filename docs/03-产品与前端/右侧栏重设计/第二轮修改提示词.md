## 4. 文件树显示不全（后端）

**原因**：`apps/desktop/src-tauri/src/commands/mod.rs:383-539` 的 `collect_project_files` 全局最多收 2000 条（`PROJECT_FILE_LIMIT`），深度上限 8，按名字排序、一个目录钻到底再看下一个；点开头的缓存目录排在最前面，先把名额用完。用 `D:\python\projects\Fox` 做项目根时，2000 条几乎全是 `.pnpm-store` 和 `.t`，`Fox/`、`docs/` 一条都进不来。截断后不返回任何标记，前端也不提示。其他问题：只按写死的名单忽略目录（`mod.rs:387-405`），不读 `.gitignore`，同名的源码目录 `build` / `dist` / `target` 被整个藏掉；任意子目录读失败整棵树报错（`mod.rs:497-509` 的 `?`）；junction / 符号链接直接跳过；文件列表不自动刷新。

**要做的**：

1. 新增按层加载的命令，如 `project_files_children(conversationId, path)`：只返回这一层，每项带 `hasChildren`。文件页展开文件夹时再请求下一层，不再有全局名额。根目录默认展开一层。
2. 新增后端搜索命令，如 `project_files_search(conversationId, query, limit)`：遍历全项目（按忽略规则），返回最多 `limit` 条匹配和 `truncated`。文件页的搜索框改用它，加 200ms 防抖。
3. 忽略规则用 `ignore` crate（ripgrep 用的那个）。两个 `Cargo.lock` 里目前都没有它，只有 `walkdir`；这是这一轮唯一允许新增的依赖，汇报里写明。读 `.gitignore` / `.ignore`，再加一份默认排除：`.git`、`node_modules`、`.pnpm-store`、`.uv-cache`、`.venv`、`__pycache__`、`target`（只在有 `Cargo.toml` 的目录下）等。不要只按名字排除 `build` / `dist`。
4. 单个子项 `read_dir` / `metadata` 失败时跳过，不让整次请求失败。
5. 排序：目录在前、文件在后，同类按名字（不区分大小写）。
6. 旧的 `project_files_list` 还被 `@` 提及（`composer/use-mention-files.ts:11`）、`companions/contact-side-card.tsx:119`、`companions/profile.tsx:34` 使用：保留这个命令，但改成按层广度优先（顶层目录一定先进来）、用同一套忽略规则，响应里加 `truncated`。
7. 自动刷新：本对话有新的写文件 / 命令工具调用完成时，刷新已展开的目录（不用整树重载）。
8. 命令改成不阻塞主线程（`spawn_blocking` 或 async）。

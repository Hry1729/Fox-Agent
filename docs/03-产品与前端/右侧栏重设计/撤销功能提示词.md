# 按轮撤销 · 替换文件历史版本 · 实现提示词

把下面整段交给负责实现的 agent。它取代原来的《版本记录优化提示词》（已删除）。

---

## 背景

用户不需要「文件历史版本」：项目文件有 git 就够了。用户要的是和别的 agent 一样的「撤销」：一轮回答改坏了文件，一键回到这一轮之前。

现状：

- Fox 没有按轮次撤销文件。「编辑并重新发送」走 `run_rewind`（`commands/mod.rs:3193-3337`、`database/repositories.rs:6086-6345` 的 `rewind_run`），只截断对话和运行记录，**文件不回滚**。前端入口是 `use-desktop-conversation.ts:1474` 的 `rerunFromMessage`。
- 唯一的文件恢复是「历史版本」：按单个文件、单个版本恢复（`runtime_host/managed_files.rs`、`database/repositories/managed_files.rs`）。它每次写入存两份完整副本，不去重、不清理；外部后端（pi、Codex、DeepSeek）的写入一条都不记。
- pi 本身也没有文件撤销，只有 `/tree`、`/fork` 这类对话分支；它的示例扩展 `git-checkpoint.ts` 用 `git stash create` 做检查点，不含未跟踪的新文件。Claude Code 的 `/rewind` 是参照对象：每轮开始前一个检查点，可以选「恢复代码和对话 / 只恢复对话 / 只恢复代码」，只追踪它自己的文件编辑工具，不追踪 bash 命令。

## 目标

1. 新增按轮撤销：每轮回答改过的文件，可以一键恢复到这一轮开始前的样子。
2. 「编辑并重新发送」可以同时把文件恢复到那条消息之前。
3. 删除文件历史版本功能（界面、命令、表、副本目录），把仍然依赖它的地方改成不依赖。

## 1. 记录：每轮的文件检查点

一轮 = 一个 run。

### 存什么

新表 `turn_file_checkpoints`（新迁移，不改旧迁移），每行是「某一轮里第一次改某个文件之前的样子」：

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `conversation_id`、`run_id` | 外键，对话删除时级联 |
| `storage_path` | 规范化后的绝对路径，和 `(run_id, storage_path)` 一起唯一 |
| `display_name` | 相对项目根目录的路径 |
| `existed_before` | 这一轮之前文件是否存在；不存在表示是这一轮新建的，撤销时删除 |
| `before_hash`、`before_size` | 改之前的内容；新建文件为空 |
| `after_hash`、`after_size` | 这一轮结束时的内容（结束时补写，见下）；文件被删掉为空 |
| `capture_source` | `host_write` / `office` / `external_permission` |
| `skipped_reason` | 没能存下内容时的原因（例如文件太大），这一行不能撤销 |
| `created_at`、`undone_at` | |

内容按哈希存一份：`<数据目录>/turn-checkpoints/objects/<sha256 前两位>/<sha256>`，同样的内容只存一次。只存「改之前」的内容，不存每次写入后的内容。

同一轮里同一个文件改多少次都只在**第一次**改之前存一次。

### 在哪里捕获

- **Fox 自己执行的写入**（`write_file`、`edit_file`）：`runtime_host/managed_files.rs:486-559` 的 `execute_admitted_file`，在 `capture_before` 钩子（`:518`）里改成写检查点。`context.run_id` 已经在里面。
- **fox-office 写入**：`office.rs:413-426` 和 `commands/mod.rs:9090-9150` 现在的登记点，同样改成写检查点。
- **外部后端**（pi、Codex、DeepSeek 经 ACP）：文件由它们自己的进程写，Fox 只看到权限请求。在 `external_policy.rs:159` 的 `answer_pi_request` 判定「允许」且类别是写入 / 编辑 / 删除时，按请求里的路径先写检查点再放行。
  - 自动放行（不发权限请求）的写入抓不到。这种轮次如果检测到有文件类工具调用但没有检查点，就不显示撤销，汇报里写清楚哪些模式覆盖不到。
  - 先去查 ACP 的 `tool_call` / `tool_call_update` 里有没有带文件 diff（`oldText` / `newText`、`locations`）。如果后端会发，可以作为第二个来源；Fox 现在没有解析它，加不加由你判断，汇报里说明。
- **命令**（`run_command`、bash）造成的改动不追踪，和 Claude Code 一样。

### 一轮结束时

run 进入终态（完成、失败、取消）时，对这一轮的每一行检查点读一次当前文件，补写 `after_hash` / `after_size`。撤销时用它判断文件「之后又被改过」。

### 限制

- 单个文件超过 50 MB：不存内容，写 `skipped_reason`。
- 不在项目根目录里的路径照常记录（权限已经放行的写入）。

## 2. 撤销：界面

### 回答下面

改过文件的回答，底部操作栏多一项：`改了 N 个文件 · 撤销`。没改文件、或这一轮抓不到改动（见上）就不显示。已经撤销过的显示 `已撤销文件改动`，不可点。

点「撤销」弹出确认（用现有的 popover / 确认框组件，不新造）：

- 标题：`撤销这一轮的文件改动`
- 文件列表：每行文件名 + 动作，`恢复` 或 `删除`（这一轮新建的）。
- 如果后面几轮也改过这些文件：撤销会把这些文件恢复到**这一轮之前**，后面几轮对它们的改动也一起没了。列表上方一行 `后面 2 轮也改过其中的文件，会一起恢复`。
- 冲突：文件当前内容和记录的最后一个 `after_hash` 不一致（用户自己改过，或别的任务改过），这一行标 `之后又被改过`，默认不勾选；勾选后覆盖前先把当前内容存一份到检查点目录。
- 这一轮跑过命令：底部一行 `命令造成的改动不会撤销`。
- 按钮：`撤销` / `取消`。

这几行是确认框里必须有的事实，不算说明文字；除此之外不加任何提示语。

撤销完成后，在对话里插入一条系统消息 `已撤销 N 个文件的改动`（用现有的系统事件样式），这样模型下一轮也知道文件回去了。

### 编辑并重新发送

编辑一条用户消息准备重新发送时，如果这条消息之后的轮次改过文件，编辑框下方多一个勾选项：`同时撤销之后的文件改动（N 个文件）`，默认勾选。有冲突的文件按上面的规则列出来让用户选。

勾选时：`run_rewind` 新增参数 `restoreFiles: bool`（和要覆盖的冲突文件列表），在截断对话**之前**按轮次从新到旧恢复文件；恢复失败就整体中止，对话不截断，报错给用户。不勾选时行为和现在一样。

### 右侧栏

- 文件预览头部去掉「历史版本」按钮和下拉菜单。
- 文件树里的 `新建` / `已修改` 标记改成从检查点表算：本对话里出现过、且没被撤销的路径；`existed_before=false` 为新建，否则为已修改。

## 3. 撤销：后端

新命令（命名跟现有风格走）：

- `turn_file_changes(conversationId, runId)`：返回这一轮的文件列表、每个文件的动作、是否冲突、后面哪些轮也改过、这一轮有没有跑命令、能不能撤销及原因。界面和撤销用同一个判断函数，保证能选的就能撤。
- `undo_turn_files(conversationId, runId, overwrite: string[])`：
  1. 找出这一轮及之后所有轮次里出现过的文件，每个文件取**最早一轮**（不早于这一轮）的检查点作为目标内容。
  2. 逐个检查冲突：当前内容 ≠ 最后一轮记录的 `after_hash` 且不在 `overwrite` 里 → 跳过。
  3. 恢复前先把当前内容存一份对象。恢复用原子写（复用 `tool_host` 现有的原子替换）；目标是「不存在」的就删除文件，删掉后变空的父目录不删。
  4. 写入前校验对象内容的 sha256，不一致就拒绝这个文件。
  5. 被恢复的检查点行写 `undone_at`。
  6. 返回每个文件的结果。
- 撤销本身不创建 run、不调模型、不授予权限。会话正在运行时拒绝撤销。
- 复用 `managed_files.rs:718` `restore_blocker` 里校验对象完整性的思路，但不再依赖版本表。

## 4. 保留和清理

- 每个对话保留最近 50 轮有文件改动的检查点，更早的删除（行和没人引用的对象）。
- 超过 30 天的检查点删除。
- 永久删除对话时删掉它的检查点和只被它引用的对象；归档、回收站不删。
- 清理在后台跑：启动后延迟一次，之后每天最多一次，不阻塞界面。
- 被清理掉的轮次不再显示撤销；编辑重发时，范围里有已清理的轮次，勾选项文案改成 `同时撤销之后的文件改动（N 个文件，更早的已清理）`，只恢复还有记录的。

## 5. 删除文件历史版本

### 必须保留并挪走的

这些现在放在 `managed_files.rs` 里，但和版本无关，挪到合适的模块（例如 `runtime_host/admitted_files.rs`），去掉版本登记：

- `execute_admitted_file`（去掉 `record_after`，`capture_before` 改成写检查点）。注意 `native_approval_scope.rs:358-371` 有测试断言「备份目录不可用时写入失败」：改成「检查点目录不可用时写入失败」，语义保持。
- `execute_observed_reader`、`HostFileTargetResolver`、`hash_file`、`VerifiedWriteTarget` / `verify_office_write`。

### 依赖版本表、需要换掉的行为

| 位置 | 现在 | 改成 |
|---|---|---|
| `kernel_display.rs:17-39` `verified_office_artifact` | Office 产物要有版本行才算已验证（`repositories.rs:5354` 依赖它） | 用 Office 写入时 Host 自己算的 sha256，存在 `artifacts.sha256` 上 |
| `artifact_delivery_view.rs:220-270` | 用版本行判断产物过期 | 比较 `artifacts.sha256` 和当前文件哈希 |

### 直接删除

- IPC 注册 `lib.rs:537-538`，`commands/mod.rs:4198-4375` 的版本列表 / 恢复命令。**不要动** `commands/mod.rs:2515`、`:2575` 的 `remove_managed_file`，那是删除文件功能，不是版本。
- `managed_files.rs` 剩下的版本逻辑，`database/repositories/managed_files.rs`，相关导出。
- 前端：`desktop-client.ts:456`、`:808-822`，`companions/files.tsx`，`contact-side-card.tsx:11-15,91-95`，`fox-right-panel.tsx:31-34,154-158,188,257,672,713-718,805-810`，`managed-file-presentation.ts`，`workbench.css:11663` 起的版本相关样式。
- 测试：只测版本功能的删掉（`managed-files-unified`、`managed-files-panel-dom`、`managed-file-restore-identity`、`steering-and-managed-files` 等，先 `rg managed_file|managedFile` 全部找出来）；测试里顺带用到版本的，改成测检查点或去掉那部分断言。

### 数据库和磁盘

- 新迁移：建 `turn_file_checkpoints`；删 `managed_file_versions`。`kernel_restore_requests` 先确认是不是只服务于版本恢复，是就一起删，不是就保留。不改历史迁移。
- `migrations.rs:9895` 的测试在数一张会被删掉的表，改成按迁移版本判断。
- 迁移成功后，后台删掉 `%APPDATA%\com.fox.agent\managed-file-backups\` 整个目录（本机现在 776 个孤儿副本，4.6 MB）。删除失败只记日志，不影响启动。
- 旧版本数据不迁移到检查点：它们不是按轮记录的，迁过来也对不上轮次。

## 约束

- 不新增依赖。
- 检查点写失败时，这次写入不执行（和现在备份失败的行为一致），不能出现「改了但撤不回」还显示撤销按钮的情况。
- 所有新增界面文字只用上面给出的这些，不加解释性提示语。
- 不提交、不推送。

## 验收

`apps/desktop/src-tauri` 下 `cargo test` 全过，新增测试至少覆盖：

- 一轮里同一文件改 3 次，只存 1 个检查点、1 个对象。
- 新建文件的轮次撤销后文件被删除；修改文件的轮次撤销后内容和哈希回到改之前。
- 第 1 轮和第 3 轮都改了同一文件，撤销第 1 轮：文件回到第 1 轮之前，第 3 轮的检查点也标记已撤销。
- 用户在一轮结束后手动改了文件：撤销时标冲突、默认跳过；带 `overwrite` 时覆盖，且覆盖前当前内容被存下来。
- 对象被篡改（哈希不对）时拒绝恢复这个文件。
- 运行中的会话拒绝撤销。
- 外部后端：模拟一次放行的写入，生成 `external_permission` 检查点，可以撤销；被拒绝的请求不生成。
- 编辑重发 `restoreFiles=true`：文件先恢复再截断；恢复失败时对话不截断。
- 超过 50 轮 / 30 天的清理；永久删除对话后对象回收，归档不删。
- 迁移后 `managed_file_versions` 不存在，Office 产物验证、交付过期检测、`VersionDrift` 仍按新规则工作。

前端：`bun test ./apps/desktop/tests` 全过；新增撤销确认框、编辑重发勾选项、文件树标记的测试。

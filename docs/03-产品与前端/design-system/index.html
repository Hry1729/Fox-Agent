Fox / Design System / Specimen 01

Fox 设计体系 为桌面端智能体工作台建立的一套可执行视觉规范

这套体系不是另起一套视觉，而是把 Fox 当前代码里已经成立的选择收拢成规则： 三套配色主题、两级明暗、一套字号阶梯、4px 间距、随主题变化的圆角， 以及“内容优先、界面退后”的克制界面。页面本身使用同一组令牌渲染， 右上角的主题切换会同时改变文档与示例。

01

原则

当细节没有明确答案时，用下面五条判断。它们来自现有页面反复做出的选择， 也解释了为什么 Fox 看起来比同类工具更安静。

01

内容优先，界面退后

文档、对话、任务和数据是主角。导航、工具栏和状态只提供方向，不与内容争夺注意力。能用留白分开的，不再加一层容器。

02

每套主题只有一个强调色

品牌色只出现在选中、焦点、进度和链接上。红、绿、黄只表示状态，并且必须同时有文字或图标说明，不能只靠颜色传达信息。

03

用留白和细线分层

层级首先来自间距、字号和背景差，而不是边框与阴影。普通卡片默认无阴影；只有浮层、菜单和对话框可以浮起来。

04

少而确定的档位

字号、字重、圆角、间距、控件高度都从固定档位取值。新代码只引用令牌，不再写 9px、10.5px、7px 圆角这类一次性数值。

05

状态必须可读

状态使用“6px 圆点 + 文字”，危险和警告只出现在真正出问题的那一项上。所有可交互元素都有可见的键盘焦点，文字缩放后布局不崩。

06

层级

界面靠背景差和留白分层，阴影只用来表达“浮在上面”。 普通卡片默认无阴影；凸起控件一档、菜单一档、对话框一档，不使用内高光。

sm · 凸起控件 输入区、被拖起的卡片、分段控件的选中项。
md · 菜单与浮层 Select、Dropdown、Popover、Tooltip。
lg · 对话框 Dialog、AlertDialog、Sheet，以及临时浮起的输入区。

表面层级

shell → background → card → popover

窗口外壳--shell
内容底色--background
卡片与内容块--card
浮层与对话框--popover

深色模式不能套用浅色阴影：阴影色 --fox-shadow-color 随主题和明暗变化， 深色下提高不透明度，避免出现发白的边缘。

07

动效

动效只表达状态变化、层级或因果，不做无意义的装饰。 常规切换 120–160ms，浮层出现 240ms；离开比进入更快，进入用 ease-out。

120ms悬停、按下、颜色与描边变化
160ms默认状态切换、展开与收起
240ms浮层出现、较大的空间移动

缓动曲线

ease-out / standard

--fox-ease-out: cubic-bezier(.16, 1, .3, 1)
--fox-ease-standard: cubic-bezier(.2, 0, 0, 1)

入场与位移

hover to preview

列表项错开 30–50ms；移动应保持方向连续，不突然跳变。

当系统开启 prefers-reduced-motion 时，本页与产品都应把动画降到接近 0ms， 并保留静态可读的最终状态。

无障碍

检查清单

before shipping

  • 正文对比度 ≥ 4.5:1；大字号、图标、描边 ≥ 3:1。
  • 状态不只靠颜色，必须有文字或图标。
  • 所有操作可用键盘完成，焦点顺序与视觉顺序一致。
  • 文字缩放到 70% 与 140% 时无溢出、无截断。
  • 图片有替代文本；装饰图使用空 alt。
  • 尊重 prefers-reduced-motion，保留最终静态状态。
关于 14 / 15px 正文

网页正文的通用下限是 16px，但 Fox 是桌面高密度工具，正文使用 14px、对话 15px。 这是有意的产品取舍：保留更大的信息密度，同时用 1.6–1.75 行高和克制的行长保证可读性。 若面向弱视力或投屏场景，使用产品内的文字缩放，而不是单独放大某一页。

问题清单

下面是从当前代码静态检索出的主要问题：不是审美偏好，而是会造成主题失效、 字号失控或维护成本上升的结构性偏差。完整证据与修复顺序见 AUDIT.md。

4P0 · 系统级，优先修
6P1 · 一致性与可访问性
3P2 · 维护与文档同步
P0

根字号 14px 让 Tailwind 的 rem 刻度整体偏小

globals.css:63 设置根字号 14px；Tailwind 的 --spacing 与 --text-xs 仍按 rem 计算，于是 gap-2 变成 7px、text-xs 变成 10.5px。全项目有 150 处 text-xs、107 处 text-sm，与 4px 网格和 11px 下限同时冲突。

P0

637 处硬编码 font-size，仍有 90 余处低于 11px

CSS 中仍存在 8 / 8.5 / 9 / 9.5 / 10 / 10.5px 的字号，例如 workbench.css:4549 的 8.5px。令牌注释声称最小 11px，但代码没有 enforcement。

P0

硬编码颜色绕过主题

themes.css 之外约 79 处十六进制颜色，TS/TSX 中约 82 处。典型如 file-tree.tsx:176 的 #e8f4ff、TaskItem.tsx:29 的 text-blue-600、workspace-pages.css:25 的 #7656d8，切到暖纸或雾蓝时不会跟随。

P0

CSS 单体与 !important 覆盖

workbench.css 约 304KB、workspace-pages.css 约 217KB，后者大量规则压成单行；23 个样式文件使用 !important，仅 workspace-pages.css 就有 263 处。样式靠权重竞争，而不是分层。

P1

圆角随主题变化，但缺少嵌套与几何约束

卡片圆角在石墨 / 暖纸 / 雾蓝分别是 8 / 16 / 12px，同一组件在三套主题下的几何差异明显。需要把“内层圆角 = 外层 − 内距”写成组件规则并逐一验证。

P1

字体令牌自相矛盾

globals.css:181 把卡片标题与区块标题都定为 16px，card.tsx:40 实际用 13px 的 --fox-type-ui，workbench.css:5952 又在局部把 section 改成 18px；local-knowledge.css:1053 引用了从未定义的 --fox-type-section-title。

P1

Button lg 与控件高度令牌不一致

button.tsx:31 的 lg 固定 h-10（40px），而 globals.css:130 定义 --fox-control-lg: 36px；同一套尺寸体系里出现两个 lg。

P1

文字缩放只覆盖令牌

text-scale.ts 只写入 --fox-text-scale；Tailwind 字号类与硬编码 px 不缩放。用户把文字调到 140% 时，页面会出现部分文字变大、部分不变的分裂。

P1

AlertDialog 层级低于 Dialog

alert-dialog.tsx:39,61 使用 z-50，dialog.tsx:41,67 使用 z-[100]。从对话框内触发“放弃修改”确认框时，存在被遮挡的结构性风险，需要在真实运行中验证。

P1

警示色小字对比度不足

--warning 在浅色主题下用于 12px 文字时对比度偏低，需要统一使用 --fox-warning-text（混合前景色后的可读版本），而不是直接使用 --warning。

P2

加载了未使用的 Bold 字重

globals.css:9 引入 Bold，但字重令牌最高 600，没有 700 的用法；同时两处字体栈不一致（globals.css:15 与 :312）。

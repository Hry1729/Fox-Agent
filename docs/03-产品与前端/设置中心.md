# 设置中心

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：`apps/desktop/src/features/settings`、`apps/desktop/src/features/workspace/management-navigation.ts`、设置侧栏（`apps/desktop/src/features/chat/shell/fox-sidebar.tsx`）<br>
> 最后更新：2026-10-25

## 结论

- 设置侧栏有 **7 个入口**，分三组：偏好（通用、对话）、能力（模型、Agent、插件、资料库）、系统（数据与关于）。标签、分组和图标定义在 `fox-sidebar.tsx` 的 `settingsContextGroups`。
- 除「通用」外，6 个页面都用统一布局 `SettingsPageLayout` / `SettingsGroup` / `SettingsRow`（`settings-layout.tsx`）：一个页面标题加一句说明，下面是以细线分隔的分组和行，不用卡片。「通用」仍是旧的 `SettingsScaffold` + `Card` + `PreferenceRow` 结构。
- 复杂对象（模型服务、通用助手、专家、项目、连接器、技能、资料库服务、生命周期 Hook）在右侧 `Sheet` 中编辑；「添加服务」是居中的 `Dialog`。
- 危险操作统一用应用内确认框 `confirmDialog`（`components/ui/confirm-dialog.tsx`，基于 AlertDialog），不再调用浏览器原生 `confirm` / `prompt` / `alert`；`apps/desktop/tests/no-native-confirm.test.ts` 扫描整个前端，出现原生弹窗即失败。
- 旧的设置路由（快捷键、项目权限、使用统计、维护、关于、技能、MCP）仍然有效，会重定向到新页面的对应分组并滚动到该分组。

## 目标与范围

本文说明设置中心的入口、每页的分组和控件、配置保存在哪里，以及旧路由如何落到新页面。面向需要新增或修改设置项的前端工程师。

不在范围内：首次启动向导的视觉细节（见 `首次启动设置/`）、各设置项背后的 Tauri 命令实现（见 `docs/02-架构/`）。

## 页面结构

### 通用（旧布局）

页面说明：「调整个人资料、外观和通知方式。」由 4 张卡片组成：

| 卡片 | 内容 |
| --- | --- |
| 个人资料 | 头像和用户名；「编辑信息」打开 `UserProfileDialog`；未登录资料库账户时显示「登录账户」 |
| 外观 | 「明暗模式」：浅色 / 深色；「配色主题」：石墨 / 暖纸 / 雾蓝（`color-theme.ts`，默认石墨）；「文字大小」：70%–140% 滑杆加步进（`text-scale.ts`）；「过程详情」：简洁 / 标准 / 详细（`process-display-mode.ts`） |
| 通知 | 「测试通知」按钮；「桌面通知」「提示音」（开启后可选音色）「未读红点」「减少打扰」四个开关 |
| 开始设置 | 「重新设置」→「打开向导」，进入 `onboarding` |

说明：

- 明暗模式只有浅色和深色两项，没有「跟随系统」。
- 「过程详情」的 Select 有四个值 `compact` / `standard` / `detailed` / `verbose`，后两者的显示文字都是「详细」（代码现状）。
- 通知偏好通过 `desktopClient.getNotificationPreferences` / `saveNotificationPreferences` 保存在宿主；开启桌面通知时会先请求系统通知权限，被拒绝则提示「系统通知权限未开启」并保持关闭。

### 对话

页面说明：「调整消息输入方式和常用快捷键。」

| 分组 | 行 | 控件 |
| --- | --- | --- |
| 消息输入 | 发送方式 | 分段控件「Enter 发送」/「Ctrl/Cmd + Enter 发送」，旁边提示换行键；中文输入法选字时 Enter 只确认候选字 |
| 消息输入 | 拼写检查 | 开关，使用系统 WebView 的拼写检查 |
| 快捷键 | 新建对话 / 添加项目 / 打开设置 / 切换侧栏 / 搜索 | `ShortcutRecorder` 录制，默认 `mod+n` / `mod+o` / `mod+,` / `mod+b` / `mod+k`（`shortcut-model.ts`）；分组右侧「恢复默认」打开确认对话框「恢复默认快捷键」 |

快捷键冲突时提示「快捷键已用于“〈动作〉”」，可选择替换。录制时 Esc 取消、Backspace 清除。

### 模型

页面说明：「管理模型服务和 Fox 默认使用的模型。」右上角「添加服务」。

| 分组 | 内容 |
| --- | --- |
| 默认 | 「默认模型」Select，选项为「服务名 · 模型名」；没有服务时显示「添加服务后可选择」 |
| 服务 | 每个服务一行：图标、名称、「默认」标记、`N 个模型 · 主机名`（未填 Key 时显示「未填写 API Key」）、状态（已连接 / 不可用 / 未检测 / 未连接 + 延迟）。分组右侧显示「N 个服务，M 个已连接」 |

每行的「⋯」菜单：重命名（`promptDialog`）、设为默认、测试连接、删除（`confirmDialog`，destructive）。点击行本身打开编辑 Sheet。

**添加服务（居中 Dialog）**：标题「添加服务」，依次是：

1. 服务模板：「自定义服务」或预置模板（OpenAI、DeepSeek 官方、DashScope、Aliyun Coding Plan、智谱、Z.AI、XiaomiMiMo、Kimi Code、Moonshot、MiniMax、OpenRouter、ModelScope、OpenCode、SiliconFlow 等，完整列表见 `providerPresets`）和服务名称；
2. 基础连接：服务地址、API Key、「测试连接」；
3. 模型：模型列表和「添加模型」；
4. 协议与高级（默认折叠）。

底部「取消 / 添加」。服务地址与已有服务重复时直接在字段下提示（`provider-errors.ts`，宿主侧 `model_providers.base_url` 唯一）。

**编辑服务（右侧 Sheet）**：标题为服务名和协议、模型数；内容为基础连接、模型、协议与高级；底部「删除服务 / 取消 / 保存」。

**协议与高级**展开后包含：

- 「Fox 连接协议」：`Chat Completions · Fox / pi` 或 `Anthropic Messages · Fox / pi / DeepSeek`；
- 供应商图标（「自动识别」或手选）；
- 「默认服务」开关；
- 已保存 Key 时的「清除已存 API Key」开关；
- 外部 Agent 用的协议配置（`provider-protocol-editor.tsx`）。

**添加模型 / 编辑模型**是叠在 Sheet 或 Dialog 上的应用内对话框：模型 ID、显示名称、上下文长度、最大输出、图片输入、设为默认；编辑时可「删除模型」，服务至少保留一个模型。

模型服务层级：服务（地址、协议、Key）→ 模型（ID、上下文、输出、多模态、默认）。全局默认 = 默认服务中的默认模型。

### Agent

页面说明：「配置通用助手、专家、新会话使用的 Agent 和项目权限。」

| 分组 | 内容 |
| --- | --- |
| 通用助手 | 一行，点开「Fox 通用助手」Sheet：助手名称、助手介绍、工作要求、开场建议（每行一条，最多 6 条）。只影响之后新建的通用助手对话 |
| 默认 | 「默认模型」，说明「新对话和专家未指定模型时使用」；没有模型时显示「添加模型服务」 |
| 外部 Agent | 仅桌面运行时显示（`agent-backend-settings.tsx`）：「新会话使用的 Agent」Select（默认 Fox，不可用项带原因）；Codex / DeepSeek / pi 各一行「〈Agent〉 默认权限」；「新外部会话使用完全访问」开关，默认关闭 |
| 专家 | 专家列表，右侧「专家中心」；点专家行打开编辑 Sheet（基本 / 能力两个分页），可「添加技能」「添加连接器」；内置专家和已安装专家包只读，可「复制为本机专家」；资料库服务专家只能查看 |
| 项目权限 | 「新项目权限」：只读 / 询问 / 允许，默认「询问」，只影响之后加入的项目；下面是项目列表，点项目打开项目 Sheet（执行方式、目录、版本状态、目录占用、关联对话、生成文件、最近对话、最近生成；「归档项目」「打开目录」）。行菜单有打开目录、迁移目录、归档；路径不存在时标「路径失效」 |
| 已归档项目 | 有归档项目时才出现，每项可「取消归档」 |

三种执行方式的说明文字：

- 只读：「Agent 只能读取项目文件。」
- 询问：「写入文件或运行命令前先询问。」
- 允许：「允许在项目内写入文件和运行命令；命令、连接器与项目外写入仍单独审批。」

路由带专家 id（`settings-ai` + entityId）时，页面会直接打开该专家的 Sheet。前端 Select 不是安全边界，路径和权限由 Tauri 侧校验（见 `docs/02-架构/项目与权限架构.md`）。

### 插件

页面说明：「管理技能、连接器和工具调用策略；所有调用仍经过 Fox 审批和审计。」右上角「添加连接器」。这是设置里唯一的插件入口。

| 分组 | 内容 |
| --- | --- |
| 技能 | 扫描 Fox 数据目录 `skills/*/SKILL.md`。每行有启用开关；点开技能 Sheet 查看说明、简介、需要的工具、来源、指令。校验失败的技能不能启用。技能只注入指令，不获得新的工具权限 |
| 连接器 | 本机 MCP（stdio）、HTTP MCP、OpenAPI。每行有启用开关和菜单（健康检查、编辑 / 查看、删除）；内置 CLI 连接器只能启停和健康检查。删除用 `confirmDialog`，会同时清除已保存的凭证 |
| 策略 | 「生命周期 Hook」→「管理」打开 Sheet（`<LifecycleHooksSection showHeader={false} />`）；「工具插件」→「插件中心」跳到插件中心的工具页 |

连接器 Sheet 字段：名称、扩展类型、命令、参数（每行一项）、环境变量或请求 Header（已保存的值不回显）、「清除登录信息」。凭证只存系统凭证库；HTTP MCP 和 OpenAPI 禁止自动重定向，超时 15 秒，响应上限 10 MB（Sheet 内的说明文字）。

从专家 Sheet 点「添加技能 / 添加连接器」进入时，页面顶部显示「返回〈专家名〉」，点击回到该专家的 Sheet。

### 资料库

页面说明：「管理本机资料库的存储位置、资料库服务连接和账户。」

| 分组 | 内容 |
| --- | --- |
| 本机存储 | 「存储位置」显示路径和可写状态，「修改位置」打开 `StorageLocationDialog`（来自 `local-knowledge-pages.tsx`）；「向量模型」→ 资料库的向量模型页；「任务队列」→ 资料库的任务页 |
| 本机资料库 | 本机资料库列表（名称、索引状态、文件数），点行进入该资料库的设置；右侧「打开资料库」 |
| 资料库服务 | 一行显示服务名、地址、状态和延迟，右侧「测试」；点行打开资料库服务 Sheet：服务名称、API 地址、访问令牌、「测试连接」，底部「取消 / 保存」 |
| 账户 | 已登录时显示用户名、部门、角色和「已登录」；未登录时「资料库账户」→「登录账户」（需先连接服务） |

存储降级时页面顶部显示红色提示（`degradedReason`，如「知识库路径不可写：〈路径〉」）和「修改存储位置」按钮；对话框中可「恢复默认位置」。新位置需要重启时提示「新位置已记录，重启 Fox 后生效。」

## 首次设置向导

`workbench.tsx` 启动时若 localStorage 没有 `fox.onboarding.status`，初始视图为 `onboarding`。`OnboardingPage` 三步：

1. 连接模型服务（跳到「模型」）；
2. 连接资料库服务（跳到「资料库」，可跳过）；
3. 开始使用 Fox。

退出时写入 `completed` 或 `skipped`。「通用 → 开始设置 → 打开向导」可重新进入。

## 配置保存位置

| 位置 | 内容 |
| --- | --- |
| localStorage | `fox.theme`（浅色 / 深色）、`fox.preferences.colorTheme`、`fox.preferences.textScale`、`fox.preferences.processDisplayMode`、`fox.preferences.sendKey`、`fox.preferences.spellcheck`、`fox.preferences.defaultPermission`、`fox.preferences.shortcuts.v1`（快捷键）、`fox.onboarding.status`、`fox.layout.*` |
| SQLite（经 Tauri 命令） | 个人资料、通知偏好、模型服务与模型、资料库服务配置、项目与逐项目权限、技能启用状态（按 Agent，`skill_set_enabled`）、连接器、生命周期 Hook、外部 Agent 设置、使用统计 |
| 系统凭据存储 | 模型 API Key、资料库访问令牌、连接器环境变量和 HTTP Header |
| 知识库服务 | 远程专家、远程资料库、账户信息 |

规则：

- 只影响当前 WebView 外观或输入习惯的偏好可以放 localStorage；需要随备份保留或被宿主读取的配置必须写 SQLite。
- 凭据不得进入前端状态持久层或 SQLite 明文字段。表单只表达「已保存 / 替换 / 清除」。
- 安全判断必须在 Tauri 侧再校验。
- localStorage 偏好不在 `.foxbackup` 覆盖范围内。

## 交互约定

- 危险操作用 `confirmDialog({ destructive: true })`；需要输入用 `promptDialog`。两者在未挂载 Provider 或被取消时都返回 false / null，调用方不会误执行。
- 下拉菜单中打开对话框要用 `runAfterMenuClose`，避免菜单与对话框焦点冲突（模型、连接器行菜单）。
- 下拉选择统一用 `components/ui/select.tsx`。
- 页面标签和用户文案统一称「资料库」「资料库服务」；代码中的 `yuxi` 名称只作为实现名保留。

## 已知限制

- 「通用」页尚未迁到 `SettingsPageLayout`，视觉与其余 6 页不一致。
- 「过程详情」中 `detailed` 与 `verbose` 显示同一文字「详细」，用户无法区分。
- 明暗模式没有「跟随系统」。
- `ServicePage`（连接资料库）、`ModelServicePage`（连接模型服务）、`LoginPage` 仍是旧布局的独立子页。
- 部分偏好只在 localStorage，换设备或恢复备份后会丢失。

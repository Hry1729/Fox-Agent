# 插件中心体验

> 状态：生效<br>
> 适用版本：Fox 0.1.x<br>
> 维护范围：`apps/desktop/src/features/plugins`、`apps/desktop/src-tauri/src/commands/plugin_center.rs`<br>
> 最后更新：2026-10-25

## 结论

- 插件中心是「助手」模式左侧栏的「插件」入口（`WorkspaceView = 'plugins'`），在主内容区打开，不属于设置。
- 当前页面**只展示已安装的条目**：标题「插件」+ 搜索框，下方四个分页「内置工具 / 技能 / 连接器 / 策略」。前三页是只读卡片，「策略」页内嵌生命周期 Hook 管理。
- 页面里不能安装、开关或配置使用范围。启用和配置统一在 **设置 → 插件**（见 [设置中心](设置中心.md#插件)）。
- `plugin-center-page.tsx` 中仍保留了目录（精选 / 全部 / 分类 / 安装按钮）和「使用范围」对话框的代码，但因为 `showInstalled = true` 写死，这些代码走不到（见「代码现状」）。

## 目标与范围

说明插件中心当前的页面结构、数据来源和与设置页的分工，面向修改插件中心或设置 → 插件的前端工程师。

不在范围内：MCP 进程管理、技能扫描、工具执行的 Host 实现（见 `docs/02-架构/`）。

## 页面结构

`PluginCenterPage` 在 `showInstalled` 分支渲染（`plugin-center-page.tsx`）：

| 区域 | 内容 |
| --- | --- |
| 页头 | `h1`「插件」；非「策略」页时右侧有搜索框，占位文字「搜索〈分页名〉」（如「搜索技能」） |
| 分页 | `Tabs`：内置工具（`tool`）、技能（`skill`）、连接器（`mcp`）、策略（`policy`）。默认打开「内置工具」 |
| 内容（前三页） | `fox-plugin-installed-grid` 网格，卡片为 `InstalledPluginCard` |
| 内容（策略） | `<LifecycleHooksSection />`，包在 `fox-settings-layout fox-plugin-policy` 中 |

分页名来自 `pluginKindLabel`：`tool` → 内置工具，`skill` → 技能，`mcp` → 连接器。「策略」只是页面分页，不会作为 kind 发给网关。

### 已安装卡片

每张卡片显示：

- 图标（`card.icon` 映射到 lucide 图标，缺省为 `PackagePlus`）和名称；
- 一行说明：正常时显示 `description`；有问题时改为红色提示并带 `role="alert"`，内容依次取 `incompatibilityReason`、`lastError`，或 `runtimeStatus === 'error'` 时的「运行时报告异常，请检查 Host 日志。」；
- 两个标签：来源（内置 / 官方 / 社区 / 本机，`pluginOriginLabel`）和类型（`pluginKindLabel`）。

卡片没有开关、按钮或菜单，点击卡片没有动作。

### 搜索与空状态

- 搜索只在当前分页内过滤，匹配 id、名称、说明、分类、类型标签和来源标签（不区分大小写）。
- 排序：`installed` 在前，`update_available` 其次，其余在后；同级按名称 `zh-CN` 排序（`sortPluginCards`）。
- 首次加载显示骨架「正在加载已安装插件…」。
- 无结果：有搜索词时「没有匹配的〈分页名〉。」，否则「暂无已安装〈分页名〉。」。空状态说明文字仍是「安装插件后，可以在这里管理启用状态和使用范围。」，与当前页面能力不符（代码现状）。
- 加载失败：显示「插件加载失败」和错误信息，带「重试」按钮。

### 进入方式

- 左侧栏「插件」：默认「内置工具」分页。
- 设置 → 插件 → 策略 →「工具插件」→「插件中心」：`navigate('plugins', 'tool')`，打开「内置工具」。
- 设置 → 数据与关于 → 诊断中的「插件」检查项：「查看插件」跳到插件中心。
- `workspace-shell.tsx` 把 `entityId` 为 `tool` / `skill` / `mcp` 时作为 `initialKind`；没有路由能直接打开「策略」分页（组件支持 `initialTab='policy'`，但 `workspace-shell.tsx` 没有传）。

## 数据来源

插件卡片是聚合视图，不是新的事实源。Tauri 侧 `plugin_center.rs` 的 `aggregate_plugin_cards` 合并：

| 类型 | 来源 |
| --- | --- |
| 目录条目 | `plugin_catalog_entries`、`plugin_installations` 表 |
| 连接器 | `mcp_servers` 与 MCP 插件来源记录 |
| 技能 | `skills::scan_skills` 扫描技能目录 |
| 内置工具 | `builtin_tool_names`，分类和说明来自 `builtin_tool_category` / `builtin_tool_description` |

Tauri 命令：

| 命令 | 前端调用 | 用途 |
| --- | --- | --- |
| `plugin_installations_list` | `pluginInstallationsList` | 聚合后过滤掉 `not_installed`，页面显示的就是它 |
| `plugin_catalog_list` | `pluginCatalogList` | 目录分页（默认 24 条，上限 100）。当前页面每次加载仍会调用，但结果只用于不可达的目录分支 |
| `plugin_set_activation` | `pluginSetActivation` | 设置启用状态；插件中心页面目前没有可触发它的入口 |

前端网关（`tauri-gateway.ts`）：

- 在 Tauri 中用 `createTauriPluginGateway`，浏览器预览用 `createMockPluginGateway`（`gateway.ts`）。
- `install` / `uninstall` / `update` 直接抛出 `plugin.operation_unavailable`：「〈操作〉需要等待 Host 操作命令接入。」
- `operationsList` 和 `agentScopeList` 固定返回空数组。

数据契约在 `model.ts`：`PluginKind`（`mcp` / `skill` / `tool`）、`PluginOrigin`、`PluginInstallStatus`（6 种）、`McpRuntimeStatus`、`PluginActivation`（`global` / `per_agent` / `not_applicable`）。`per_agent` 的 wire 字段兼容 `enabledAgentCount` 和 `enabled_agent_count`。

## 与设置 → 插件的分工

| 需求 | 位置 |
| --- | --- |
| 查看已安装的内置工具、技能、连接器及异常原因 | 插件中心 |
| 管理生命周期 Hook | 插件中心「策略」页，或 设置 → 插件 → 策略 →「生命周期 Hook」→「管理」（同一个 `LifecycleHooksSection`） |
| 开关技能、查看技能说明和指令 | 设置 → 插件 → 技能 |
| 添加 / 开关 / 健康检查 / 编辑 / 删除连接器 | 设置 → 插件 → 连接器 |
| 给专家添加技能或连接器 | 设置 → Agent → 专家 Sheet →「添加技能」「添加连接器」 |

## 代码现状

以下是代码中的实际情况，按事实记录：

1. **目录分支不可达。** `const showInstalled = true` 写死（注释：「Host 尚未提供包校验、依赖安装、回滚与清理命令前，正式页面只暴露已安装插件」），`if (showInstalled)` 之后的目录页（「精选〈类型〉」「全部〈类型〉」、分类筛选、刷新、「添加插件」、`CatalogPluginCard` 的安装 / 更新按钮）永远不会渲染。
2. **开关和范围配置被置空。** `InstalledPluginCard` 接收 `busy`、`onToggle`、`onConfigure`，但函数体里 `void busy; void onToggle; void onConfigure`，卡片不渲染任何控件。因此 `handleToggle`、`handleConfigure`、`handleScopeToggle` 没有调用路径。
3. **`ScopeDialog` 打不开。** 它只在 `scopePlugin` 非空时渲染，而唯一设置 `scopePlugin` 的是 `handleConfigure`，见上一条。即使能打开，Tauri 网关的 `agentScopeList` 也只返回空数组。
4. **多余的目录请求。** `reload` 同时请求 `catalogList` 和 `installationsList`，前者结果在已安装视图中不使用。
5. **未使用的属性。** `onAddPlugin`、`onConfigureAgent` 只在不可达代码中使用；`workbench.tsx` 也没有向 `WorkspaceShell` 传 `pluginGateway` 或 `onConfigurePluginAgent`。
6. `index.ts` 仍导出 `PluginCard`（即 `CatalogPluginCard`）和 `ScopeDialog`。

## 安全边界

- 插件中心是只读聚合视图，不改变 MCP、技能或工具的运行权限。
- 连接器凭证只存系统凭证库，卡片不显示凭证内容。
- 技能只注入指令，不获得额外工具权限；实际调用仍受项目权限、专家工具白名单和审批限制（见 [设置中心](设置中心.md#插件) 与 fox-guide `03-插件中心/02-MCP-Skills-工具.md`）。
- 远端市场、签名下载、安装 / 更新 / 卸载在前端网关中明确返回不可用，不伪造成功。

## 已知限制

- 插件中心不能安装、开关插件或配置使用范围；空状态文案仍提到这些能力。
- 无法通过路由直接打开「策略」分页。
- 目录、安装、范围配置相关代码保留但不可达，修改时需要同时决定是删除还是接通。

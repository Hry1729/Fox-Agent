# Fox 连接器接入评估

本文评估 Fox 侧开发工作。普通用户要点几下、谁需要管理员放行、哪些项目适合首批接入，见[用户授权筛选与首批名单](连接器用户授权筛选.md)。

2026 年 11 月 25 日。范围取自[连接器候选清单](连接器候选清单.md)的 108 项。这里按每项在 Fox 中完成**第一项有用操作**所需的工作分级。依据是 Fox 当前代码、平台文档和维护者仓库。本次仅做接入调研，108 项均待 Fox 桌面端实测。

| 分级 | 数量 | 做到什么就能开始试 |
| --- | ---: | --- |
| A 可直接配 | 34 | 已有兼容的本地 MCP 或远程服务。准备所需令牌、运行环境或数据库连接信息，填入现有表单即可开始联调。 |
| B 有现成实现，有前置条件 | 56 | 通常无需重写业务接口。还要处理 OAuth、租户审批、席位、第三方桥接或版本兼容等具体条件。 |
| C 需要 Fox 适配 | 15 | 针对清单中的目标体验，已查到的路线需要 Fox 接事件、路由会话，或把现有 SDK、CLI、Skill、进程内适配器封装成独立工具。 |
| P 集成平台 | 3 | 可承接一批应用的授权或工具调用。选型时应单独评估用户绑定、服务成本和分发条件。 |

**分级衡量的是首次接入的工作量。** 用户侧的目标是连接一次账号，以后直接在 Fox 对话里操作该系统。B 类的前置条件由不同角色承担。Fox 负责接入平台、保存和续期凭证、调用工具。用户首次选择账号并授权。仅当所在企业有审批规则时，才需要管理员放行。席位、部署环境等条件按具体条目判断。

### 飞书文档的连接体验

以用户在 WorkBuddy 连接飞书的体验为参考。用户在 Fox 点「连接飞书」，在飞书官方授权窗口核对账号和权限，点同意后自动回到 Fox，看到「已连接」及对应账号。应用注册、回调地址、工具配置和凭证续期由 Fox 负责。用户取消授权时，回到目录仍可再次连接。

授权有效期间，用户直接在 Fox 对话里说「把这段总结追加到《产品周报》」。Fox 更新用户有编辑权限的文档，并返回文档链接。验收时分别检查首次授权、重启后继续使用，以及写入后能从飞书读回同一段内容。普通用户完成整条流程所需的手动配置项为零。

## Fox 侧会影响判断的三处

1. **设置和安装。** 现有「设置 → 插件」能配置 stdio、Streamable HTTP 和 OpenAPI 3.x，凭证可存为进程环境变量或 HTTP 请求头。插件中心桌面网关的安装命令仍未接通，因此 A 类按“手工可试”估算。旧 SSE 端点需要兼容桥接。仅有 REST 文档时，还得准备 Fox 能解析的 OpenAPI 定义，例如先展开外部引用。[设置表单](../../../../apps/desktop/src/features/settings/settings-plugins-page.tsx) · [桌面网关](../../../../apps/desktop/src/features/plugins/tauri-gateway.ts) · [MCP 传输](../../../../apps/desktop/src-tauri/src/mcp.rs) · [OpenAPI 解析](../../../../apps/desktop/src-tauri/src/mcp_openapi.rs)
2. **授权和用户确认。** 现有 MCP 表单没有通用的 OAuth 登录、回调和续期入口。单人试点可以让本地服务管理登录，或在厂商允许的情况下用 `mcp-remote` 桥接。公开分发还要满足厂商的客户端注册要求。Google Workspace 官方的部分写操作会要求客户端展示确认表单，Fox 当前初始化时发送空的客户端能力。读取、写入和重启后的续期应分别验。Google 六项也可先共用社区的本地 Workspace MCP。[OAuth 桥接](https://github.com/geelen/mcp-remote) · [Google 官方配置](https://developers.google.com/workspace/guides/configure-mcp-servers) · [Google 用户确认](https://developers.google.com/workspace/guides/mcp-elicitation) · [社区 Workspace MCP](https://github.com/taylorwilsdon/google_workspace_mcp)
3. **目录可见与真实调用。** 连接测试可以列出工具。Fox Kernel 的专用只读执行路径还检查工具是否同时声明 `readOnlyHint: true` 和 `destructiveHint: false`。上游即使有搜索工具，缺少声明时该路径也会拒绝执行。每个首批候选都应在目标桌面版本用真实对话调用一次，核对返回内容，再决定目录是否显示“可用”。[传输与发现](../../../../apps/desktop/src-tauri/src/mcp.rs) · [Kernel 只读执行](../../../../apps/desktop/src-tauri/src/mcp/owned.rs)

Octop 对筛选尤其有用。它把厂商服务标为 `remote`，把依赖自身 Python 进程的实现标为 `gateway`，还会把多个上游服务聚合成 `internal`。下面优先选能独立运行的方案。例如，企查查可以按业务域直接配厂商端点，腾讯 ima 和微信读书则找到了其他维护者提供的独立 MCP。飞猪、美团等条目的 C 级针对目录中的独立连接器，若只需要原厂 Skill，可以另按技能路线评估。[Octop 模式说明](https://github.com/TencentCloud/Octop/blob/main/docs/connectors.md) · [企查查分域端点](https://github.com/TencentCloud/Octop/blob/main/docs/connectors-qcc.md) · [微信读书官方 Skill](https://github.com/Tencent/WeChatReading)

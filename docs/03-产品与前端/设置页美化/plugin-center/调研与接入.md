## Fox 当前实现

| 入口 | 当前行为 | 原型中的位置 |
| --- | --- | --- |
| 插件中心 | 工具、技能、连接器和策略四个入口。运行时聚合内置工具、已扫描的技能、MCP 配置和目录记录。桌面网关目前只开放已安装项的查询和启用等操作。安装、更新和卸载的 Host 命令仍待接入。 | 插件、技能、连接器共用分组双列和详情抽屉。Hooks 保留独立策略入口。 |
| 设置 → 插件 | 能重新扫描本地技能，管理内置网页搜索，并添加、编辑、测试和启停 MCP 配置。连接器表单支持 stdio MCP、HTTP MCP 和 OpenAPI。 | 手动添加入口放在列表上方，已添加的演示项显示「已配置」，详情保留「未测试」。 |
| 内置能力 | Word、Excel、PowerPoint 带各自的 `SKILL.md`，通过 Fox Office 提供工具。网页搜索提供 Tavily、Brave Search、Exa 和 SearXNG 配置。 | 技能区展示三项内置样例，并允许用本地文件演示导入和配置助手范围。研究里的 Tavily 和 Brave MCP 是独立接入选项。 |

代码依据：[插件中心页面](../../../../apps/desktop/src/features/plugins/plugin-center-page.tsx)、[桌面网关](../../../../apps/desktop/src/features/plugins/tauri-gateway.ts)、[设置入口](../../../../apps/desktop/src/features/settings/settings-plugins-page.tsx)、[聚合与启用](../../../../apps/desktop/src-tauri/src/commands/plugin_center.rs)、[MCP 传输](../../../../apps/desktop/src-tauri/src/mcp.rs)、[内置技能](../../../../apps/desktop/src-tauri/src/skills.rs)、[搜索服务](../../../../apps/desktop/src-tauri/src/search_service.rs)。

当前连接器表单通过系统凭证库保存 stdio 环境变量或 HTTP 请求头。现有入口可用于验证有令牌或本地进程的候选。一键 OAuth 需要补齐账号授权、回调和令牌刷新流程。消息通道需要另接入站事件与会话路由。

原型数据保存在当前浏览器。添加连接器、导入技能、配置助手范围和选择搜索服务都是演示操作。目录来源核对基于公开材料，完成 Fox 联调后才能确认可用性。

## 筛选时可以先验证什么

| 候选 | 最小验证 | 依赖 |
| --- | --- | --- |
| GitHub | 搜索一个授权仓库，读取一个 Issue 或 PR，重启后再次验证。 | 官方远程 MCP 或本地实现。先核对只读工具集和凭据方式。 [官方 MCP](https://github.com/github/github-mcp-server) |
| Linear、Notion、Slack | 各验证一次查询和权限失效后的重新授权。 | 核对每个平台的 OAuth 客户端注册、回调和可访问范围。 [Linear](https://linear.app/docs/mcp) · [Notion](https://developers.notion.com/guides/mcp/overview) · [Slack](https://docs.slack.dev/ai/slack-mcp-server/) |
| 飞书 | 读取一份文档和一张多维表格。若需要在飞书对话，再验证一次机器人收发。 | 官方 CLI 或 OpenAPI MCP。按飞书与 Lark 的区域和身份配置验证。 [飞书 CLI](https://github.com/larksuite/cli) · [OpenAPI MCP](https://github.com/larksuite/lark-openapi-mcp) |
| Google Drive | 搜索文件名并打开一份用户可访问的文档。 | Google 官方 MCP 仍需预览资格和 Agent 类型 OAuth 客户端。若预览条件不满足，可验证 Drive API。 [Workspace MCP](https://developers.google.com/workspace/guides/configure-mcp-servers) · [Drive API](https://developers.google.com/drive/api/guides/about-sdk) |
| QQ、微信 | 分别验证扫码或机器人凭据、私聊或群聊支持范围、收发和重连。 | QQ 使用开放平台的机器人。微信以 iLink Bot 为切入点。两者都需要消息桥接与会话路由。 [QQ 开放平台](https://q.qq.com/wiki/develop/api-v2/) · [腾讯 iLink 源码](https://github.com/Tencent/openclaw-weixin) · [Octop 通道](https://docs.octop.cloud/en/guide/concepts/channels) |

目录建议从两个场景开始。研发场景选 GitHub 和 Linear，验证远程 MCP 与账号授权。中文办公场景选飞书，验证文档和表格的区域与用户权限。QQ 和微信可共享一套消息路由设计，按各平台分别验证。

「已配置」「可用」「已启用」建议分别表示已保存设置、连接测试通过、允许助手使用。目录里的「已选候选」只记录筛选结果。技能可以先沿用当前本地扫描，只在导入时展示所需工具和使用范围。

## 目录范围

候选按即时通讯、文档与网盘、项目与研发、邮件与日程、设计与经营、数据与检索、集成平台浏览。纳入依据包括平台官方文档、公开实现，以及能定位到具体条目的开源目录。路径标为 Octop 实现的条目仍需核对服务端点和认证。集成平台的代码许可与其托管服务条件也需分别核对。

界面参考 [affectUI Integrations](https://www.affectui.com/screens/integrations) 的分组密度与操作位置，使用 Fox Paper 色调、分类侧栏和筛选流程。原型沿用 Fox 的 Lucide 图标。品牌标识来自 Iconify 的 [SVG Logos](https://iconify.design/icon-sets/logos/)、[Simple Icons](https://iconify.design/icon-sets/simple-icons/)、[IconPark](https://iconify.design/icon-sets/icon-park/)、[Arcticons](https://iconify.design/icon-sets/arcticons/) 和 [VS Code Icons](https://iconify.design/icon-sets/vscode-icons/)。

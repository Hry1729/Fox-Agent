Fox 图标动效评估

两个问题：现有 11 个动画图标能否换成一个库，以及全应用 175 个 lucide 图标里哪些该动、哪些不该动。结论基于 animateicons.in（@animateicons/react v0.12.0，676 个 lucide 动效图标）与仓库里每个图标的实际调用位置。

01现有动画图标能否被替代

仓库里 11 个动画图标来自 animate-ui。animateicons 覆盖了其中 8 个同名图标，可以直接替换；剩下 3 个库里没有，需要变通。替换后即可只保留一个图标体系（lucide + animateicons）。

Bell→BellIcon直接替换通知中心，6 个文件在用。
Blocks→BlocksIcon直接替换插件 / 模块入口。
MessageCirclePlus→MessageCirclePlusIcon直接替换新建对话按钮。
PanelLeft→PanelLeftIcon直接替换左侧栏开合。
Search→SearchIcon直接替换全应用调用最多的动效候选，29 处。
Settings→SettingsIcon直接替换设置入口。
SunMoon→SunMoonIcon直接替换主题切换。
Users→UsersIcon直接替换成员 / 协作。
PanelRight≈PanelLeftIcon需变通库里没有 PanelRight。侧栏开合是成对动作，可改用 PanelLeft 水平翻转（scaleX(-1)），或保留现有实现。
Maximize≈ExpandIcon需变通库里没有 Maximize / Maximize2。语义最近的是 Expand（四角向外），可同时覆盖这两个现有图标。
Minimize≈ShrinkIcon需变通同上，对应 Shrink（四角向内）。
换库前需要知道的几点。animateicons 的图标渲染出来是 <div> 而不是 <svg>， 所以现在写在 svg 上的 className、 strokeWidth、currentColor 继承关系都要重新核对； 它自带 motion 运行时（不额外依赖 motion 包），单个图标 tree-shaking 后约 4–5 kB，而 lucide 单个约 1 kB。两个库都基于 motion，仓库现有的 AnimatedIconTrigger（hover / tap 触发）可以整体换掉， 但如果需要动画循环或联动 AnimatedIconTrigger 的 animateOnHover 与 AnimateIcon 上下文，得确认接口是否对应。

02哪些图标适合改成动效

下面把 175 个图标逐个判定。建议改为动效的是动作或状态变化驱动的图标，数量少、位置关键，动效能确认「操作已发生」；保持静态的是方向、状态、文件类型、高频外壳等——它们动起来要么语义冲突，要么同屏实例太多造成干扰。点按钮筛选。

03判定依据

不是凭图标好不好看，而是看它在应用里被放进什么位置。同样的图形，在「触发动作」的位置该动，在「陈述状态」的位置就不该动。

建议改为动效的四类。一是不可逆或高风险操作（删除、清空）——动效承担确认职能； 二是异步过程的进行中状态（加载、思考、生成、录音）——动效本身就是状态指示； 三是会被反复点击的动作按钮（播放、暂停、发送、刷新）——点击后需要即时反馈； 四是外部事件到达（通知铃铛）——动效替代了「去看一眼」。
保持静态的七类。方向箭头（动效即位移，指代会含混）；状态事实（通过 / 警告 / 离线，本身没有发生的瞬间）； 高频外壳操作（同屏几十个，一个动全体乱）；文件类型标识（查表产生，一屏十几个，外框须稳定以便扫读）； 布局状态（画布静止态，没有可类比的物理动作）；身份与偏好取值（动就等于提示值变了，会是假信号）； 名词性实体（服务器、数据库、文件夹，是标签不是动作，找不到自然且信息量对等的动作）。

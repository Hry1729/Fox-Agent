# A0 工作闭环使用指南

> 状态：A0 Alpha<br>
> 适用版本：Fox `0.1.x`<br>
> 最后更新：2026-08-03

## 什么时候进入工作模式

当请求需要实现、修复、重构、迁移、构建或验证，并且通常涉及多个步骤、多个文件或修改后的测试时，Fox 会创建一个 Goal，并将工作拆成有顺序的 Task。解释、摘要、检索、列目录等一次性只读请求继续使用普通对话，不会显示 Goal 区域。

目标或验收条件含糊、操作风险较高时，Fox 会先请求确认。此时 Run 处于 `awaiting_confirmation`，尚未发送给 Runtime；选择“继续执行”会恢复同一个 Run，选择“暂不执行”会取消这次尚未派发的请求。确认状态保存在 SQLite，刷新或重启不会自动放行。用户明确“只讨论方案”或“暂不修改”时继续使用普通对话。

目标处于 `proposed` 时不会提前创建 Task。用户确认后，Host 先把同一个 Goal 激活并恢复原 Run，Runtime 再基于 Host 注入的目标快照创建带真实 UUID 的有序 Task。界面和模型都不需要用户提供 Conversation ID 或项目绝对路径；项目工具中的 `.` 表示当前授权项目根目录。

## 查看进度

工作模式区域显示：

- 当前 Goal、已完成 Task 数和 Task 总数。
- 每个 Task 的状态、尝试次数和阻塞原因。
- 支撑 Task 结论的工具调用、文件变更、测试、Artifact 或用户确认 Evidence。
- Evidence 的 `unverified/valid/stale/missing/invalid` 有效性。

回复结束后工作图仍会保留。刷新或重启时，界面先从 SQLite 恢复 Goal、Task 和 Evidence，再合并新的 Runtime Event；Event 不是事实源。

## 状态含义

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| `queued` | Task 已创建，尚未开始 | 通常无需操作 |
| `in_progress` | Runtime 正在处理 | 可查看当前过程，必要时取消 Run |
| `blocked` | 等待信息、权限或外部条件 | 阅读阻塞原因并补充信息 |
| `interrupted` | App、Sidecar 或 Run 在完成前中断 | 确认现场后重试；attempt 会增加 |
| `completed` | 已完成且至少绑定一条 Evidence | 检查 Evidence 是否仍有效 |
| `skipped` | Goal 调整后不再需要 | 无需操作，历史仍保留 |

Task 显示 completed 不等于 Evidence 永久有效。文件删除会使 Evidence 变为 missing，工作区变化可能使其变为 stale；历史不会被静默删除，可重新验证或重做 Task。

## 中断与恢复

1. App 关闭或 Sidecar 崩溃时，不会把运行中的 Task 自动标记为 completed。
2. 下次启动会审计非终态 Task；终态 Run 持有的 Task 会转为 interrupted。
3. 重试从原工作图继续，`attempt` 增加，旧 Evidence 保留，新 Evidence 追加。
4. 用户取消 Goal 时，Goal 变为 cancelled，活动 Task 中断，历史与 Evidence 保留。

如果刷新后状态仍异常，请记录 Conversation ID 和 Run ID。开发/支持人员先运行 `diagnose_work_state`，再按需使用 `export_work_trace` 导出工作图与 12 类 Work Event；导出不含对话正文、项目文件或凭证。

## A0 边界

A0 只提供最小 Goal -> Task -> Evidence 闭环。Runtime 已接入 Pi Coding Agent 的扩展生命周期，但不使用 Pi 示例中的本地 todo 作为事实源。A0 不包含 Task 级审批、Plan 修订和版本历史、独立 Reviewer、Acceptance 实体、完整 Span 树、长期 Memory 或并发子 Agent。工具写入和高风险操作仍使用现有 Host 权限/审批机制，这不等同于 Task 审批。

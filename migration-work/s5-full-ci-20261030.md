## Capability JSON root cause

The sampler was not at fault. The 7 earlier requests genuinely lacked the capability section.

Actual HTTP before the fix:

- System prompt chars `1875`.
- No `Host runtime availability for this frozen manifest/profile:` heading.
- No `<fox_context>`.
- The system prompt was the Pi SDK default (`You are an expert coding assistant ...`), not the Fox composed prompt.
- The same run's `run.request_snapshot.promptDiagnostics` already showed a `host_runtime_availability` fragment (1304 rendered chars) and total composed prompt `29980` chars. The facts were composed but never handed to the SDK.

Exact source defect: `composeFoxPrompt` returned `prompt`, hashes and diagnostics, but not `stablePrefix` or `dynamicTail`. `pi-runtime.mjs` passed `promptComposition.stablePrefix` / `.dynamicTail` into `createFoxPlanningExtension`; both were `undefined`. The extension therefore set an empty `customPrompt` and no `fox_context` dynamic section, so Pi fell back to its default prompt.

Fix `2ccd2a97` returns both halves:

```js
stablePrefix: stable,
dynamicTail: contextText,
```

No manifest/profile validation was removed, no Host permission was relaxed, no tool was opened, and no duplicate capability registry was added. Test `host-runtime-capabilities.test.mjs` now asserts the split halves, not only the joined prompt.

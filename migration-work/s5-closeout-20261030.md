## 29K 失败归因与性能

旧失败 Run `f1f14eb3-743d-4344-9afc-d52fe4b71499` 的 Kernel 预算估算为 40603，大于配置窗口 29000。它只有当前一条用户消息，没有可压缩历史，因此返回 `kernel.context_compaction_no_candidates`。系统提示与工具定义的固定成本不会被历史摘要消除。该次失败由既有 Kernel 预算保护触发，相关生产实现从 S5 基线至本候选无变化；没有放松预算保护。

旧 256K 成功样本同时改变了输出预留和系统提示，不能用两个样本推定通用最低上下文窗口。完整分项与三个精确实现测试见 fallback 报告。首次 0-match 日志保留且不计通过。

本轮 Native 压缩准备也保留了未命中记录。临时 26K 配置被入口以 `model.context_window_too_small` 拒绝，没有模型请求。恢复 29K 后，虽然 usage 已超过 `29000 - 6144 = 22856`，SDK 的 `prepareCompaction` 仍返回空：近期内容未超过保留的 5220 tokens，没有可摘要的切点。只读 SDK 模拟确认 160 行合成材料形成切点后，再通过正常会话提交；Run `ea493821` 实际触发 threshold 压缩。未改写原生文件或压缩设置，纯函数结果本身不计运行通过。证据为桌面 `v3-effective-compaction-threshold.json` 及后续准备、执行记录。

离线性能沿用 [s5-performance-summary-20261029.json](s5-performance-summary-20261029.json) 的 `9540b68e` 历史结果：每格 30 个热样本、每路径 5 个冷样本，负载 1/2/3/4，契约相同，未超过 10% 退化门槛。负载 3/4 指提交数，经过夹具两槽队列，不是 3/4 个 Native Run 同时活跃。

只读映射确认，原报告 3780 条工具记录均为不需审批的 Host `read`；Native 与 Kernel 都进入既有只读执行器。文件 Create 凭据及 `present_files` 修复不进入该六读链路，夹具内容哈希仍匹配原记录。原 `sourceUnchanged=true` 只表示当次测量前后一致，不能解释为当前所有源码或二进制未变。详见 fallback 目录的 `performance-source-map.md`。

这保留了初始离线门槛证据，最终包没有新的性能测量。夹具使用 source runtime、debug Host 和固定时序的本机 SSE，不能推定文件创建/交付、审批、压缩恢复、SRT 命令、真实 Provider 延迟、最终 NSIS 启动/FPS 或业务性能。

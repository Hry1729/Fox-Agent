## 1. 交付摘要

本次交接覆盖两层前端改造：

1. 主线基线已经完成 FoxOps 工作区、扩展管理、智能体管理、数据总览、登录页和主导航的整体重构。
2. 当前 `feat/chat-ai-elements` 分支在不修改后端 API、SSE 和消息协议的前提下，把聊天主区迁移到 shadcn-vue / AI Elements Vue 体系，并完成消息、推理、工具调用、来源、加载态、建议词、审批和输入区外壳的统一。

当前分支相对 `origin/main` 包含 4 个阶段提交：设计与实施计划、AI Elements 基础组件引入、消息数据适配层、conversation/message 接线。此次最终交付又补齐工具调用、输入区、来源/审批/空态、滚动容器、媒体地址校验、构建依赖与测试。

## 2. 已完成的改造

### 2.1 主线前端基线

- 新增个人工作区页面，覆盖文件导航、预览、编辑、上传、下载和删除等流程。
- 重构扩展管理的信息架构，统一 Tools、MCP、Skills 和知识库相关列表/详情页面。
- 新增智能体管理与数据总览页面，并调整管理员权限入口。
- 更新登录页、主侧栏、路由层级、工作标签页和页面过渡体验。
- 补齐对应 API 封装、Pinia 状态、工具函数和 Node 契约测试。

### 2.2 聊天主区 AI Elements 迁移

- 在 `src/components/ui` 和 `src/components/ai-elements` 引入 shadcn-vue / AI Elements 源码组件，并用 `chat-ai-elements` 作用域隔离主题变量，保留 Element Plus 作为全站外壳。
- 新增消息适配层，将现有 `displayItems` 映射为 user/assistant/system 角色和 text、reasoning、tool-group、sources、artifacts 等消息片段；原有 SSE、Pinia 和业务事件继续复用。
- 用 `Conversation`、`Message`、`Reasoning` 重建消息区；保留 Mention 渲染、Markdown、复制、反馈、重试、附件、模型名和流式滚动。
- 修复 StickToBottom 高度链和滚动容器识别，避免空态、长消息和流式输出时消息区失去内部滚动。
- 用 `Suggestion`、`Loader`、`Shimmer` 统一空态快捷问题和回答加载态。

### 2.3 工具调用与交互卡片

- 新增 `ElementsToolCall.vue` 和 `toolElementsAdapter.js`，把 running/completed/failed 映射为 AI Elements 的 `input-streaming`、`input-available`、`output-available`、`output-error` 状态。
- `ToolCallRenderer.vue` 收敛为统一入口；已注册的计算器、图表、文件、命令、知识库、MySQL 等领域渲染器继续复用，未知工具回退到通用 `BaseToolCall`。
- `BaseToolCall.vue` 改用 Elements `Tool`、`ToolHeader`、`ToolInput`、`ToolOutput`，同时保留自定义标题和结果插槽。
- `RefsComponent.vue` 改用 Elements Sources；知识库分组、网络来源和外链数据结构不变。
- `ApprovalCard.vue` 改用统一 Alert/Button 外观；单选、多选、其他输入、确认和拒绝回调不变。
- 新增 `ElementsPromptShell.vue`，仅替换输入区 chrome；原 Mention 编辑器、附件、模型选择、发送和停止逻辑继续由 `MessageInputComponent` 驱动。

### 2.4 媒体、素材与开发体验

- 新增 `mediaSrc.js` 及类型声明，过滤空字符串、站点根路径、`about:blank`、`undefined/null` 字符串和仅域名 URL，避免头像/图片错误请求当前页面。
- 用户头像、智能体头像、消息头像、下拉头像和图片预览统一使用安全媒体地址。
- 新增登录背景视频 `public/videos/login-bg.mp4`（约 31 MB）及当前聊天效果截图 `chat-current.png`。
- Vite 恢复官方 `vue-stream-markdown`，并把 nanoid、shiki、vue-stream-markdown、vue-stick-to-bottom、motion-v 加入依赖预构建，降低 HMR 后 `Outdated Optimize Dep` 504。
- `nanoid` 固定到兼容 Node 20 的 5.x；避免 nanoid 6 的 Node 22 最低版本与项目 `node >=20.19.0` 声明冲突。

## 6. 迁移到新设备

### 6.1 推荐方式：Docker Compose

1. 解压源码包到目标目录。
2. 根据仓库示例创建本机 `.env`；压缩包不会包含真实 `.env`、密钥、数据库卷或用户数据。
3. 安装并启动 Docker Desktop。
4. 在项目根目录运行 `docker compose up -d`。
5. 运行 `docker compose ps`，并检查 API、worker、web 日志。
6. 打开前端后，优先验证登录、创建/切换会话、流式回答、停止、工具调用、来源、审批、附件和图片预览。

### 6.2 仅前端本地运行

```bash
cd foxops-web
pnpm install
pnpm dev
```

要求 Node `>=20.19.0`、pnpm `>=8.8.0`。部署前务必设置真实 API 地址；本次本机直接执行 Vite build 时日志显示默认 API URL 为 Apifox mock 地址，不能直接作为生产配置使用。

### 6.3 建议验收命令

```bash
cd foxops-web
node --test tests/chat-prompt-shell.test.mjs tests/chat-tool-elements-adapter.test.mjs tests/media-src.test.mjs
pnpm exec eslint src/components/ToolCallingResult/ElementsToolCall.vue src/components/chat/ElementsPromptShell.vue src/utils/chat/toolElementsAdapter.js src/utils/mediaSrc.js tests/chat-prompt-shell.test.mjs tests/chat-tool-elements-adapter.test.mjs tests/media-src.test.mjs
pnpm exec stylelint src/components/ToolCallingResult/ElementsToolCall.vue src/components/chat/ElementsPromptShell.vue --allow-empty-input
pnpm exec vite build
```

# FoxOps 门户首页完整迁移方案

## 1. 迁移目标

迁移 Yuxi `/` 公共门户的真实功能和品牌配置，用 ArtDesignPro/FoxOps 风格重做视觉。首页承担服务可达性检查、品牌展示、产品说明、实时开源数据和进入 Chat 的入口，不依赖登录态才能访问。

## 2. 路由和页面状态

- 路由 `/`，公开访问，可 keep-alive。
- 首次加载显示“正在连接服务”；先检查健康，再加载品牌信息。
- 服务/配置失败显示页面级错误与重试，而非白屏。
- GitHub 外部数据失败只隐藏对应实时统计，不阻断首页。

## 3. 顶部导航

- Logo、组织名来自品牌配置；缺失时有 FoxOps 默认值。
- 可选 GitHub/文档入口来自品牌或部署配置，外链安全打开。
- 主按钮根据登录态显示“进入工作台/登录”，但统一走安全导航。

## 4. Hero 区

- 品牌标题、多个副标题和徽章文案从 `/api/info` 配置读取。
- 副标题轮播和徽章打字动画尊重 `prefers-reduced-motion`，卸载时清理定时器。
- 主操作“开始使用”：未登录保存 redirect 后去登录；已登录进入 Chat。
- 次操作打开文档/了解更多，URL 可配置，不固定 Yuxi 文档站。

## 5. 产品视觉与实时统计

- 保留智能体 Harness → RAG 引擎 → 知识库的产品流程表达，可用 CSS/图标重建。
- 流程图是说明性视觉，不伪装成实时运行状态。
- GitHub 仓库接口请求设置超时和 AbortController；展示 Star、Fork、Issue 等已有字段。
- 仓库地址、统计开关应品牌可配置；FoxOps 不应继续默认展示 Yuxi 仓库，除非明确保留致谢。
- 数值进行 K/M 格式化，缺失时不展示虚假 0。

## 6. 页脚与合规

- 品牌版权、年份、用户协议、隐私政策、备案/组织信息由配置提供。
- 用户协议和隐私链接缺失时不显示空链接。
- 首页不能泄露内部服务地址、管理员入口或部署信息。

## 7. API 与状态

- `healthApi.checkHealth()`：核心服务可达性。
- `infoStore.loadInfoConfig()`：组织、Logo、标题、副标题、背景、协议和外链。
- 可选 GitHub REST：非核心、可取消、超时约 3 秒、失败静默降级为不显示统计。
- 用户状态仅用于 CTA 跳转，不在首页重复初始化全部业务 store。

## 8. 响应式和可访问性

- 桌面双栏 Hero，窄屏单栏；图形不得挤压标题和按钮。
- 图片有 alt，装饰背景 `aria-hidden`；按钮和链接有可见焦点。
- 低性能/减少动态效果环境关闭粒子、轮播和打字动画。
- 背景与文字满足亮/暗主题对比度。

## 9. 验收清单

- [ ] 未登录用户可访问，健康检查、加载、错误、重试状态齐全。
- [ ] 品牌名称、Logo、标题、副标题、背景和链接均来自配置。
- [ ] CTA 在登录/未登录状态下跳转正确并安全恢复 redirect。
- [ ] 外部 GitHub 请求失败不影响首页，仓库不被硬编码为 Yuxi。
- [ ] 产品流程、实时统计、页脚和协议入口完整。
- [ ] 移动端、暗色模式和减少动态效果可用。

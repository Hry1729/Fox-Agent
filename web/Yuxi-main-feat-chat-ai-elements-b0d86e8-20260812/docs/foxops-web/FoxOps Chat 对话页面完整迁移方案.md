# FoxOps Chat 对话页面完整迁移方案

## 1. 本方案的真实基线

FoxOps 已经直接运行在 ArtDesignPro 框架中，Chat 页面位于 `foxops-web/src/views/chat/agent/index.vue`，路由为 `/chat`。本页不迁移 Yuxi 的 `AppLayout.vue`、导航框架、主题系统或全局组件，只补齐 Yuxi Chat 的业务能力，并复用 ArtDesignPro 的 Layout、菜单、工作标签、权限守卫、Element Plus 和 `vue-element-plus-x`。

线程定位继续采用当前实现的 `/chat?thread_id=<id>`，不强制改成路径参数。

## 2. 当前已经完成的部分

以下能力已存在于当前 FoxOps 代码，应以“校验和完善”为主，不再让实现模型重复重写：

- 会话列表：加载、滚动分页、搜索、时间/名称排序逻辑、置顶、重命名、删除、新建和切换。
- 智能体：列表初始化、当前智能体展示、切换限制、会话绑定、管理弹窗入口。
- 消息：历史加载、按对话轮次分组、用户/AI 消息、Markdown、推理块、工具调用组、错误/中止提示。
- 运行：创建 run、SSE 流式处理、平滑输出、停止生成、页面重新可见时恢复运行。
- 人工介入：`useApproval`、审批/提问事件恢复、`ApprovalCard`、提交/拒绝后 resume run。
- 模型：对话级模型选择、从历史 human metadata 恢复 `model_spec`、创建 run 时提交。
- 附件：临时上传弹窗、确保线程、线程附件列表、多 `attachment_file_ids` 提交、删除回滚。
- 来源：知识库来源和 Web 来源通过 `RefsComponent` 展示。
- 智能体状态：真实调用 `getAgentState`，展示 Token、Todos、Files、Artifacts、子智能体运行。
- 文件与产物：右侧文件工作区、Artifact 卡片、保存后打开文件区。
- 消息操作：复制、反馈、重新生成、自动标题。
- 生命周期：切换线程停止旧订阅、恢复活动 run、卸载清理可见性监听和当前订阅。

## 3. 当前仍需完成或重点核验

### 3.1 路由与会话同步

- 当前切换线程会写入 `?thread_id=`，但新建会话、删除当前会话后切到下一条、首次自动选择会话时也必须同步 query。
- 浏览器前进/后退改变 query 时，需要反向切换当前线程；目前主要在 `onMounted` 读取一次。
- 直接访问一个未包含在首批分页结果中的合法线程 ID 时，应请求线程详情或继续加载，不能直接忽略。
- 线程不存在、无权限、已删除时显示明确状态并清理失效 query。
- 保持 ArtDesignPro `keepAlive` 后，重新进入 Chat 不得重复注册 SSE 或保留错误线程。

### 3.2 `@` 提及

- `MentionDropdown.vue` 和 mention API 已存在，但当前 `XSender` 只显示“@ 提及资源”的 placeholder，尚未看到输入区实际挂载和 token 处理。
- 需要接入触发位置、关键词查询、键盘上下选择、确认插入、关闭、删除和发送 payload 转换。
- 提及对象覆盖后端真实支持的智能体、子智能体、知识库或资源类型，不只插入一段不可解析文本。

### 3.3 文件能力声明与附件语义

- `useAgentStreamHandler` 仍收到 `supportsFiles: ref(false)`；应由当前智能体/后端能力声明计算，不能硬编码。
- 附件按钮的显示/禁用、允许类型、大小和数量必须随智能体能力变化。
- 当前已能提交多个文件 ID，但还需核验历史消息中的附件是否按所属消息展示，而不仅是线程输入区顶部的总附件列表。
- 图片消息、AI 生成文件、上传失败重试、解析中/解析失败状态需要与 Yuxi 一致。
- 发送成功后的附件保留/清理规则必须明确，避免每一轮都重复携带线程全部附件。

### 3.4 消息与产物关联

- 当前 Artifact 只挂在“最后一轮且流式完成后的助手消息”上；需按后端 message/run 关联，历史 Artifact 不能全部挤到最后一条。
- 工具组、推理、正文、来源、附件、错误和审批在历史重载后要与实时完成后的结构一致。
- 重新生成当前通过向前搜索用户消息再次创建 run；需核验是否符合 Yuxi 的分支/重试语义，避免保留错误的后续消息。
- Markdown 使用 `v-html`，必须确认渲染器已做 XSS 清洗；链接协议、图片 URL 和代码高亮也需安全处理。

### 3.5 人工审批完整性

- 当前审批主链路已实现，不再标记为“缺失”。
- 继续核验多问题表单、不同题型、审批风险信息、提交中防重复、后端拒绝后的恢复。
- 刷新页面和切换会话后，待审批状态应从 thread state 恢复。
- `cancel` 当前等价提交字符串 `reject`，需要确认后端对所有审批类型都接受该值。

### 3.6 状态面板和错误反馈

- `fetchAgentState` 当前捕获异常后静默忽略；状态面板需要加载失败、重试和权限反馈。
- 状态面板与文件面板同时打开时的宽度、遮挡和移动端抽屉行为需要验证。
- 运行结束、审批恢复、切换线程后状态应自动刷新，不完全依赖手工按钮。
- 子智能体运行应能定位对应任务/消息；Todo、文件和 Artifact 空态分别处理。

### 3.7 滚动与长会话

- 当前 `BubbleList` 设置 `auto-scroll=true` 且 watch 流式消息时主动滚底；用户向上阅读时不应被强制拉回。
- 增加“有新消息/回到底部”提示，只在用户接近底部时自动跟随。
- `virtual=false` 对长会话存在性能风险；先验证真实长记录，再决定是否启用虚拟列表。
- 会话侧栏移动端目前固定高度，需要检查实际 ArtDesignPro header/worktab 高度下的可用性。

### 3.8 智能体管理入口边界

- Chat 内的 `AgentEditModal` 可保留快速编辑，但完整智能体管理应进入独立业务页面，避免 Chat 复制一套管理功能。
- 只有 `can_manage` 的智能体显示编辑入口；内置/只读智能体不能仅靠前端按钮隐藏来授权。

## 4. 目标组件边界

- `views/chat/agent/index.vue`：页面编排、路由线程同步和面板开关。
- `store/modules/chatThreads.js`：列表、分页、当前线程、CRUD。
- `hooks/agent/useAgentRunStream.js`：运行创建后的订阅、恢复和停止。
- `hooks/agent/useAgentStreamHandler.js`：SSE 事件归一化。
- `hooks/agent/useApproval.js`：审批状态机。
- `utils/messageGrouping.js`：历史和实时消息分组。
- `components/chat/*`：模型、提及、审批、附件、状态、文件、产物、来源和反馈展示。
- `api/agent.ts`、`api/thread.ts`、`api/mention.ts`、`api/model.ts`：Yuxi 后端适配。

不要把这些能力重新塞回一个超大页面，也不要复制 ArtDesignPro 已有的 Layout/主题/路由框架。

## 5. 推荐完成顺序

### P0：保证当前主链路稳定

1. 补全 query 与当前线程的双向同步。
2. 核验 SSE 完成/取消/断线/恢复和 keep-alive 生命周期。
3. 修复附件重复携带、能力声明和历史消息附件关联。
4. 给状态请求和页面初始化增加可见错误态。

### P1：补齐仍未接入的业务交互

1. 把 `MentionDropdown` 真正接入 `XSender`。
2. 按 run/message 关联历史 Artifact、来源和文件。
3. 完善审批类型、表单、刷新恢复和拒绝语义。
4. 限制 Chat 内智能体编辑权限，并连接完整管理页。

### P2：体验与质量

1. 智能滚动、长会话性能、移动端面板。
2. Markdown 安全、可访问性、暗色主题。
3. 真实后端端到端回归。

## 6. 验收清单

- [ ] 新建、切换、删除、刷新、前进后退时 `thread_id` 与当前线程始终一致。
- [ ] 历史与实时消息的正文、推理、工具、来源、错误、审批、附件和 Artifact 结构一致。
- [ ] 多附件只在应参与的运行中提交，历史附件能定位所属消息。
- [ ] `@` 提及可以查询、键盘选择、插入并被后端识别。
- [ ] 发送、停止、断线恢复、刷新恢复和待审批恢复均无重复消息。
- [ ] 状态/文件/Artifact/子智能体面板使用真实数据，并有加载与错误状态。
- [ ] 用户向上阅读时不会被强制滚底，长会话性能可接受。
- [ ] Chat 复用 ArtDesignPro 框架，没有重新实现全局 Layout、菜单、主题或工作标签。

# FoxOps 系统设置页面完整迁移方案

## 1. 迁移目标与边界

迁移 Yuxi `SettingsModal.vue` 的业务设置能力，而不是照搬 ArtDesignPro 自带的主题设置面板。FoxOps 可采用独立设置页或大尺寸抽屉，但必须保留账户、沙盒环境变量、基础配置、用户管理、部门管理五个权限页签及 API Key 管理。

ArtDesignPro 的主题/布局偏好属于“界面偏好”，Yuxi 的系统配置属于“业务设置”。两者入口和标题需明确区分，避免用户把主题面板误认为系统管理。

## 2. 路由、入口和权限

- 建议独立路由 `/system/settings`，同时允许头像菜单、状态栏和全局导航以 `?tab=` 打开指定页签。
- `account`、`agent-env`：任意登录用户。
- `base`、`users`：`admin` 与 `superadmin`。
- `departments`：仅 `superadmin`。
- 非法或无权 tab 自动选择当前用户第一个可用页签；路由守卫和后端授权均需保留。
- 从旧模态框迁为页面后，返回行为、深链接和刷新恢复必须可用。

## 3. 页面结构

- 桌面端左侧设置导航，右侧内容；移动端顶部下拉/标签或分段页面。
- 页面头展示“系统设置”、当前组织和权限说明，可放刷新按钮。
- 页签切换保留已加载数据；有未保存修改时阻止静默离开。
- Yuxi Star 提示卡属于品牌推广，可按 FoxOps 品牌策略保留、替换或移除，不得阻塞业务设置。

## 4. 账户设置

- 头像：当前头像、像素回退头像、上传/更换；仅图片且小于 5MB；上传中态与失败提示。
- 用户名：行内编辑、2–20 字符等后端规则、保存/取消、与当前值相同不发请求。
- 手机号：可选、中国大陆手机号格式校验，保存空值语义与后端一致。
- 只读资料：UID、角色、所属部门；角色显示超级管理员/管理员/普通用户。
- 刷新资料调用当前用户接口并同步全局 user store、头像菜单和页面展示。

## 5. API Key 管理

- 列表展示名称、Key 摘要、创建时间、过期时间、最后使用和启用状态。
- 创建：名称必填，过期时间可空；成功后的 secret 只展示一次。
- secret 支持复制并有复制成功/失败反馈；关闭弹窗后不可再次从前端恢复。
- 支持重新生成、启用/禁用、删除；再生成和删除都需风险确认。
- 接口沿用 `/api/user/apikey`，不在日志、DOM 属性或错误追踪中泄露 secret。

## 6. 沙盒环境变量

- 使用键值编辑器加载、编辑和保存当前用户智能体沙盒变量。
- 支持刷新、脏数据判断、保存中态和离开提醒。
- 校验：最多 200 项；键符合 `[A-Za-z_][A-Za-z0-9_]*`、最长 128；值最长 32768。
- 规范化键值，拒绝重复/空 key；错误定位到具体行。
- 使用 `/api/user/agent-env` 获取和更新；敏感值按后端能力决定是否遮罩，不在 toast 中回显。

## 7. 基础配置

- 管理员可见；超级管理员可编辑全局默认模型项。
- 模型配置：默认对话模型、快速模型、Embedding 模型、Reranker、内容审核模型（启用内容审核时）。
- 模型选择器使用真实供应商模型列表和 `model_spec`，不可使用 ArtDesignPro mock options。
- 其他开关与值按 `configStore.config._config_items` 描述动态呈现，调用单项/批量系统配置更新接口。
- 服务链接：Neo4j、API 文档、MinIO、任务监控等只在配置/部署确实提供时显示；不要把 `localhost` 硬编码为生产地址。
- 修改成功同步 config store；失败回滚控件，不制造“视觉已保存、后端未保存”。

## 8. 用户管理

- 用户列表支持刷新、搜索用户名/ID/手机号、部门筛选和角色筛选。
- 卡片/表格展示头像、用户名、UID、手机号、角色、部门、创建时间、最后登录。
- 新增用户：用户名、自动/校验 UID、手机号、密码/确认密码、角色、部门。
- 编辑用户：用户名/手机号、角色、部门；可选择是否修改密码。
- `admin` 只能管理允许范围内用户；只有 `superadmin` 可授予管理员和跨部门选择。
- 当前用户不可删除自己；普通管理员不可编辑/删除超级管理员；超级管理员角色保护。
- 删除二次确认；列表刷新不清空不相关筛选；分页以接口能力为准，不用假分页掩盖大量数据。

## 9. 部门管理

- 仅超级管理员访问，展示部门名称、描述、管理员/人数、创建信息等后端字段。
- 支持刷新、新增、编辑、删除。
- 新增部门同时创建部门管理员：部门名称/描述、管理员 UID、密码/确认密码、可选手机号。
- UID 3–20 位字母/数字/下划线并异步查重；手机号格式校验。
- 编辑部门只修改名称和描述，不误重建管理员。
- 删除确认文案必须说明：用户迁移到默认部门，部门配置和部门 API Key 清理；以后端真实事务结果为准。

## 10. API 与状态管理

- 账户：当前用户、资料更新、头像上传。
- API Key：list/create/regenerate/update/delete。
- 环境变量：get/update。
- 系统配置：`GET /api/system/config`、单项及批量更新。
- 用户：列表、校验、创建、更新、删除。
- 部门：列表、创建、更新、删除。
- API 统一放 `foxops-web/src/api`；页面用 user/config 等 Pinia store 同步全局状态。
- 每个页签独立 loading/error/dirty，不能用一个全页 loading 阻塞所有设置。

## 11. 验收清单

- [ ] 五个页签按 user/admin/superadmin 权限准确出现，URL 不能越权。
- [ ] 账户资料和头像更新后全局同步。
- [ ] API Key secret 仅一次展示，创建/再生成/启停/删除可用且不泄密。
- [ ] 环境变量完整校验、保存、刷新和离开提醒。
- [ ] 默认模型及系统项接真实配置，服务链接不硬编码生产 localhost。
- [ ] 用户搜索/筛选/增删改及角色保护正确。
- [ ] 部门增删改、管理员创建和删除影响提示完整。
- [ ] ArtDesignPro 界面偏好与 FoxOps 业务设置在命名和入口上清晰分离。

## 1. 你的任务

FoxOps 基于 Yuxi 二次开发。后端复用 Yuxi（FastAPI + LangGraph），前端**用 Art Design Pro 重建整套 UI**（不复用 Yuxi 的 Vue 前端）。

你的工作：
1. 在 foxops-web 里**复刻 Yuxi 的界面**（对话/知识库/管理后台等），用 Element Plus 重做
2. **新增 FoxOps 页面**（故障码管理/工作台/安全提示卡）
3. 对接 Yuxi 后端 `/api`

**前后端同步开发**：你复刻 Yuxi 界面（调 Yuxi 现有 API）的同时，后端在扩展 FoxOps 业务（故障码等）。前期你主要复刻 Yuxi 界面 + 用已通 API；FoxOps 专用 API（故障码）后端做好后你再接。

## 4. 开发环境搭建

### 后端（Yuxi，docker 跑）
在 `D:\python\projects\Yuxi-main` 目录：
```bash
docker compose up -d
```
后端跑在 `http://localhost:5050`，API 前缀 `/api`。改后端代码会自动热重载。

### 前端（foxops-web，本地跑）
```bash
cd D:\python\projects\Yuxi-main\foxops-web
pnpm install
pnpm dev          # 自动打开，默认 http://localhost:8080
```

### 配置 API 对接
找到 art-design-pro 的 axios 实例（通常在 `src/api/` 或 `src/utils/`），把 baseURL 改成 `http://localhost:5050/api`；或用环境变量（`.env.development`）配 `VITE_API_URL=http://localhost:5050/api`。

### 登录测试
后端管理员账号密码在 `D:\python\projects\Yuxi-main\.env`（`YUXI_SUPER_ADMIN_NAME` / `YUXI_SUPER_ADMIN_PASSWORD`）。用它能登录 Yuxi 后端测试。

## 6. 逻辑层搬移（直接搬，不重写）

Yuxi 前端的**逻辑层跟 UI 库解耦**，可以直接搬到 foxops-web。这是省力的关键。

| 层 | Yuxi 文件（web/src/） | 搬到 foxops-web | 处理 |
|----|----------------------|-----------------|------|
| 流式 chunk 处理 | `composables/useAgentStreamHandler.js` | `src/hooks/` | 直接搬（只换 `message` 提示 antd→ElMessage） |
| 发起 SSE | `composables/useAgentRunStream.js` | `src/hooks/` | 直接搬 |
| HITL 审批 | `composables/useApproval.js` | `src/hooks/` | 直接搬（后期用） |
| 流式平滑 | `composables/useStreamSmoother.js` | `src/hooks/` | 直接搬 |
| 消息处理 | `utils/messageProcessor.js`、`messageGrouping.js` | `src/utils/` | 直接搬 |
| 滚动控制 | `utils/scrollController.js` | `src/utils/` | 直接搬 |
| API 调用 | `apis/agent_api.js`、`thread_api.js` 等 | `src/api/` | 搬逻辑，改用 axios |
| 状态 | `stores/agent.js`、`chatThreads.js` 等 | `src/store/` | 直接搬（Pinia 一致） |
| Markdown 渲染链 | markdown-it + highlight.js + katex + dompurify | `src/utils/` | 装依赖后直接搬 |

**搬移要点**：
- 这些是 `.js`，art-design-pro 是 TS 项目。**先直接搬 .js 跑通**（TS 项目能 import .js），后续渐进转 .ts
- API 层要从 Yuxi 的自封装改成 axios（art-design-pro 的方式）
- `useAgentStreamHandler` 处理的 chunk 格式跟 Yuxi 后端 SSE 完全对应，FoxOps 复用 Yuxi 后端，所以这套逻辑直接适用

## 8. 后端对接

### API
- 基址：`http://localhost:5050/api`
- Yuxi 的接口封装在 `web/src/apis/`（参考它调哪些接口），你用 axios 重新封装到 `foxops-web/src/api/`

### 认证
- 登录：`POST /api/auth/token`（OAuth2PasswordRequestForm），返回 JWT
- 后续请求：`Authorization: Bearer <token>`
- 角色：user / admin / superadmin（沿用 Yuxi 角色级权限）

### SSE（流式对话）
- 对话流式走 Yuxi 的 agent_run + SSE 事件流
- 前端用 `useAgentRunStream`（搬过来）发起，`useAgentStreamHandler` 处理 chunk
- 事件格式：`init`/`loading`/`stream_event`/`finished`/`interrupted`/`error` 等（`useAgentStreamHandler` 已处理）

### 参考接口
看 Yuxi 的 `web/src/apis/` 了解有哪些接口：`agent_api`（智能体/对话）、`thread_api`（会话）、`knowledge_api`（知识库）等。

## 9. TypeScript 注意事项

art-design-pro 是 TS 项目，Yuxi 前端是 JS。搬移时：
- **先直接搬 .js 跑通**：TS 项目能 import .js，别为了转 TS 卡住复刻进度
- **后续渐进转 .ts**：优先给 API 层、store 加类型，composables 可保留 JS
- **Vue SFC**：`<script setup>` 用 JS 或 TS 都行，新写的页面用 TS
